# MSG-544: 계정 설정 — 담당자 정보 수정 · 비밀번호 변경 · 아이디(공식 이메일) 변경 요청

## 기획 요약

운영자가 콘솔 사이드바 "계정 설정"(`/org/settings`)에서 자기 계정을 관리한다. 담당자 이름·연락처는 자체 수정(`PATCH /api/org/profile`), 비밀번호는 현재+새 비밀번호로 변경(`POST /api/auth/password/change`), 아이디(공식 이메일)는 기관 인증의 근거라 읽기 전용 + 변경 요청(`POST /api/org/email-change-request`) 후 관리자 승인 대기 안내만 가능하다. MSG-541 스텁(`OrgSettingsPage`)을 실화면으로 교체하며, 542(비밀번호 폼 자산)·545(`use-org-profile-query`)의 재사용 전제를 상환하는 티켓이다.

## 코드베이스·API 실측 (스펙의 전제)

- **`GET /api/org/profile`** → `OrgProfileResponseDto` = `email`(읽기 전용)·`contactName`·`contactPhone`(**null 가능** — 미입력 계정). 조회 훅은 **`features/org-account/api/use-org-profile-query.ts`가 이미 있다**(MSG-545 — 544 재사용 전제로 배치, 언랩+비로그인 미발사). 이 티켓은 조회 훅을 새로 만들지 않는다.
- **`PATCH /api/org/profile`** = 생성 SDK `updateProfile` / `updateProfileMutation`. body `OrgProfileUpdateRequestDto` = `contactName`(**2~20자** — users.nickname 저장)·`contactPhone`(**숫자로 시작·끝, 숫자·하이픈 9~20자**). 두 필드 모두 required(부분 PATCH 아님 — 항상 두 값 전송). **응답이 변경 후 `OrgProfileResponseDto`** — 성공 시 프로필 캐시를 응답으로 직접 갱신할 수 있다(사이드바 이메일 표시와 캐시 공유).
- **`POST /api/auth/password/change`** = `changePassword` / `changePasswordMutation`. body `PasswordChangeRequestDto` = `currentPassword` + `newPassword`(**영문·숫자 각 1+ 8~64자 — 542 `password-policy`와 동일 정책**). openapi description 실측: 성공 시 **강제 변경 상태가 풀리고** 남은 재설정 링크 폐기, **다른 기기 세션은 유지**(로컬 세션 정리 불필요 — reset과 다름). 소셜 계정은 **2445** 거절. **현재 비밀번호 불일치 developCode는 미문서화**(실측 — 문서화된 코드는 2445뿐) → 542 선례대로 `authErrorMessage`(서버 message) 표출, 코드 분기 없음.
- **`POST /api/org/email-change-request`** = `requestEmailChange` / `requestEmailChangeMutation`. body `OrgEmailChangeRequestDto` = **`requestedEmail` 1필드뿐**(사유 필드 없음 — 실측). 응답 200 unknown(데이터 없음). description 실측: 접수만 하고 관리자 승인 시 실제 변경, **대기 중 요청이 있으면 새 값으로 갱신 — 마지막 요청이 유효**(재요청 허용).
- **요청 상태 조회 API 없음(실측)** — email-change 관련 조회는 admin 쪽 `GET /api/admin/email-change-requests`뿐이고 org 쪽 pending 조회가 없다. "관리자 승인 대기" 안내는 **요청 직후 세션 로컬 표시만 가능**하다(추정 2).
- **542 재사용 자산 (전부 import만 — 파일 수정 없음)**: `pages/org/ui/PasswordInput`(보기 토글 — props는 Input 호환)·`NewPasswordFields`(새 비밀번호+확인+게이지+힌트 한 묶음, `password/confirmation/onChange/hasError` props)·`AuthInfoCard`(안내 카드 골격), `features/auth/model/password-policy`(`validateNewPassword`·`newPasswordError`·`PASSWORD_RULE_HINT`)·`email-format`(`isEmailFormat`), `pages/org/auth-error.ts`(`authErrorMessage` — 네트워크/빈 message 분기).
- `features/auth/api/use-password-mutations.ts`(542)는 initial·reset-request·reset 3종만 있다 — **change가 없어 이 파일에 `useChangePassword` 1훅 가산**이 이 티켓의 유일한 542 파일 수정이다(오케스트레이터 허용 범위, 병렬 티켓 비소유 파일).
- 사이드바 "계정 설정" 메뉴는 **이미 배선돼 있다**(`console-config.tsx:65` → `CONSOLE_ROUTES.orgSettings` — 셸 파일 수정 불필요). `app/console-routing.smoke.test.tsx`가 라우트별 렌더를 단정한다 — 자기 라우트 줄만 접촉 가능(웨이브 규칙).
- 재사용 ui-web: `Button`·`Input`·`Skeleton`·`RetryNotice`·`DialogShell`(모달 채택 시)·`Toast`·`cn`. `useDocumentTitle`·`formatDocumentTitle`(문서 제목 관례). 테스트: `console-session`·`stub-fetch`·`envelope-response`.
- MSG-544 브랜치는 로컬·리모트 모두 없음(신규 생성). develop 최신 c3928e3(웨이브 1 머지 완료).

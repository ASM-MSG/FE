# MSG-430: [모바일] 도감 개편 2 — 뱃지 진열장·대표 뱃지 지정·기록 잔디

## 기획 요약

apps/mobile 도감의 뱃지 탭은 아직 목(`MOCK_BADGES` — id·name만 있고 획득 상태·아트 없음)이고,
기록 탭은 "준비 중" 껍데기다. 이 티켓은 **웹에 이미 머지된 두 기능을 모바일로 이식**한다 —
MSG-413(대표 뱃지 지정 실연동)과 MSG-414(업로드 잔디 `/dex/history` + 1년 모달, 커밋 `ea055bc`).
따라서 문구·파생 규칙·API 계약의 정본은 티켓 문장이 아니라 **웹 실구현**이고, 이 스펙은 그 계약을
그대로 옮기되 RN 제약(SVG 렌더·grayscale 부재·중첩 스크롤·라우팅)에서만 명시적으로 갈라진다.

MSG-425가 3탭 셸(`dex-screen.tsx`)을 소유하며 **교체 지점 2줄**을 주석으로 박아뒀다 —
`<BadgeShelf />` → `BadgeTabBody`, `<DexTabPlaceholder label="기록" />` → `RecordTabBody`.
셸·상단 통계 헤더(`dex-header-summary`)·탭바(`dex-tab-bar`)·에러 상태(`dex-error-state`)는 무수정이 목표다.

## 설계 쟁점 결론 (구현 전 확정)

### 쟁점 1 — 뱃지 SVG 아트 24종을 RN에서 어떻게 렌더할 것인가 → **react-native-svg `SvgXml` + 문자열 카탈로그**

**조사 사실**
- `apps/mobile/package.json`에 `react-native-svg` **15.15.4가 이미 있다**(런타임 dep). `react-native-svg-transformer`는 없다.
- `expo-image ~57.0.1`이 dep + `app.config.js` plugins에 등록돼 있으나 **소스 import 0건**(미사용).
- `metro.config.js`는 `transformer`를 전혀 건드리지 않는다. `resolver.resolveRequest`만 커스터마이즈(MSG-419 client-config 치환) + `withNativeWind` + `withStorybook` 이중 래핑.
- `vitest.config.ts`는 **"순수 모델(RN import 없는 로직)만 테스트"** 전제 — asset/svg 스텁이 아예 없다.
- 리포 선례: `features/auth/ui/kakao-login-button.tsx`가 `react-native-svg`의 `Svg`/`Path`로 인라인 렌더하며 주석에 **"metro svg transformer 신규 도입 없이 react-native-svg로 렌더 — 단순성 우선"**이라 명시.
- 웹 에셋 24종은 148×148 viewBox, 각 11~18KB(총 404KB), `path`/`g`/`mask`/`linearGradient`/`radialGradient`만 사용 — **`<text>`·폰트·래스터(`data:image`) 없음**(텍스트는 전부 path로 아웃라인됨). react-native-svg가 전부 지원하는 요소들이다.

**결론**: 웹의 `.svg` 24개를 **문자열 상수 TS 모듈로 기계 변환**해 `apps/mobile/src/entities/badge/assets/*.ts`에 두고,
`react-native-svg`의 `SvgXml`로 렌더한다. `resolveBadgeArt`는 웹과 동일한 우선순위(서버 `iconUrl` > 로컬 카탈로그 > null)를 지킨다.

생성 명령(재현 가능해야 한다 — 아트 갱신 시 동일하게 재실행):
```
# 각 파일이 export const BADGE_ART_XML = `<svg …>`; 한 줄짜리 모듈이 된다
# (SVG 본문에 백틱·${ 가 없음을 확인함 — 이스케이프 불필요)
```

**기각 사유**
| 안 | 기각 이유 |
|---|---|
| (a) `react-native-svg-transformer` 도입 | 새 devDep + `metro.config.js` transformer 3종 수정(`babelTransformerPath`·`assetExts` 필터·`sourceExts` 추가)이 필요하다. 그런데 이 파일은 `withNativeWind`(nativewind v4 = `react-native-css-interop`)로 감싸져 있고 nativewind도 babel transformer를 소유한다 — **두 transformer 체이닝 순서가 실패하면 앱 전체 스타일 또는 번들이 죽는다.** 화면 1개 이식 티켓이 감당할 블라스트 반경이 아니다. 리포 선례(kakao)도 명시적으로 이 길을 피했다 |
| (b) `expo-image` + `require('./x.svg')` 에셋 | expo-image의 SVG 지원은 사실이나(Android Glide `SVGModule`, iOS 모두 ✅), **`expo-asset`이 SVG를 네이티브 번들 대상에서 제외**한다(`ACCEPTED_TYPES`에 `.svg` 없음, `isImageType`가 svg 제외). dev(Metro HTTP)에서는 뜨고 릴리스 빌드에서 깨질 수 있는 형태라 채택 불가. expo-image 최초 사용처가 되는 점도 리스크 |
| (c) 서버 `iconUrl`만 + 폴백 도형 | `badges.icon_url`이 현재 **전량 NULL**(웹 `badge-art.ts` 주석). 진열장이 민무늬 원으로만 차서 티켓 요구("실제 메달 아트")를 못 지킨다 |
| (d) SVG 24종을 JSX로 인라인 코드젠 | 파일당 path 33개 + mask/gradient. 24개 TSX 생성물은 리뷰 불가 + react-doctor svg 정밀도 게이트에 좌표 수천 개가 걸린다 |
| (e) PNG 변환 후 RN `Image` | 가장 안전하지만 **로컬에 svg→png 변환기가 없다**(rsvg/inkscape/magick/sharp 전무, `qlmanage`만 존재). 변환 도구 도입은 (a)와 같은 크기의 결정이고, 벡터를 잃고 웹과 아트 소스가 갈린다. **(a')이 실기에서 실패할 경우의 폴백으로만 남긴다** |

**트레이드오프(리스크로 이월)**: 번들에 ~404KB의 문자열이 실린다(gzip 기준 ~120KB 추정). `SvgXml`은 마운트 시 XML을 파싱한다 — 동시 표시 8~24개 × 14KB. 실기에서 뱃지 탭 진입 체감 지연이 있으면 (e)로 전환한다.

**미획득(잠금) 표현**: 웹은 `grayscale-100 opacity-40`인데 **RN에는 크로스버전 안전한 grayscale이 없다**
(RN 0.76+ `filter: [{grayscale:1}]`는 Android에서 API 31+ RenderEffect 의존 — minSdk 24인 이 앱에서 기기별로 갈린다).
→ **미획득 = `opacity 0.4` 단독** + 라벨을 `text-foreground-muted`로 낮춘다. 메달 아트가 흰 배경을 포함해 40% 투명이 바랜 회색으로 읽힌다. Figma 오탐 방지 목록에 등재.

### 쟁점 2 — 1년 기록 화면의 내비게이션 → **expo-router 라우트 `src/app/dex/history.tsx` 신설**

**조사 사실**
- 라우트 루트는 `apps/mobile/src/app/`(레포에 `apps/mobile/app/`은 없다). dex 관련 파일은 `src/app/dex.tsx` 하나뿐이고 `src/app/dex/` 디렉토리는 없다.
- `_layout.tsx`는 전역 `<Stack screenOptions={{ headerShown: false }} />` 하나뿐(개별 `Stack.Screen` 선언 없음). `app.config.js`에 `typedRoutes: true`.
- 셸은 **ScrollView 하나**를 소유하고 본문만 갈아끼우며, `AppHeader title="개인 도감"`도 소유한다. 하드웨어 뒤로가기는 "갤러리 열림"일 때만 가로채고 아니면 `false`를 반환해 라우터에 넘긴다.
- MSG-425 주석의 경고는 **`/dex/:tab` 탭 세그먼트**에 대한 것이다("탭 세그먼트를 추가하면 MSG-430과 소유권이 충돌") — 상세 화면 라우트는 그 경고 대상이 아니다.
- Figma 1년 화면(14857:404)은 **자체 헤더 `‹` + "업로드 기록"**을 갖고 하단 탭바를 유지하는 **전면 화면**이다(웹의 모달과 구조가 다르다).

**결론**: `src/app/dex/history.tsx`를 새로 판다. 근거 —
1. 오버레이/시트로 가면 셸의 `AppHeader` 타이틀·뒤로가기를 갈아끼워야 하고 `BackHandler` 분기도 확장해야 한다 → **"셸 무수정, 교체 2줄" 목표가 깨진다**. 라우트로 가면 `dex-screen.tsx` 수정은 선언된 2줄로 정확히 유지된다.
2. 라우트는 자체 ScrollView를 갖는다 → 셸 ScrollView 안에 또 세로 스크롤을 넣는 문제가 원천 소멸(쟁점 4와 연결).
3. 하드웨어 뒤로가기·제스처 백을 라우터가 공짜로 처리한다.
4. `typedRoutes`로 `/dex/history`가 타입 생성되고, 웹의 URL 세그먼트(`/dex/history`)와 경로 문자열이 일치한다.

**충돌 검증과 우발 계획**: expo-router에서 `dex.tsx`(→ `/dex`)와 `dex/history.tsx`(→ `/dex/history`)는 서로 다른 경로라 공존한다(충돌은 `dex.tsx` ↔ `dex/index.tsx`처럼 **같은 경로로 해석되는 두 파일**일 때만 발생). 구현 첫 스텝에서 dev 서버 기동으로 라우터 경고 유무를 확인하고, 만약 경고·충돌이 뜨면 **`src/app/dex.tsx` → `src/app/dex/index.tsx`로 파일 이동**한다(파일 내용 2줄짜리 래퍼라 이동만으로 끝나며, `dex-screen.tsx` 자체는 여전히 무수정). 이 우발 경로를 밟았는지 여부를 빌드 리포트에 적는다.

### 쟁점 3 — "뱃지 전체 보기" 목적지 → **새 화면 없이 탭 안에서 인라인 확장(웹 미러)**

웹 `BadgeTabBody`는 기본 프리뷰 8개(`BADGE_PREVIEW_LIMIT`, 4열×2행)를 보여주고, 헤더의 "전체 보기"와
하단 풀폭 버튼 "뱃지 전체 보기"가 **둘 다 같은 동작**(`setExpanded(true)`)이며 확장 후에는 둘 다 숨는다(접기 없음).
모바일 셸이 이미 세로 ScrollView를 소유하므로 확장분은 페이지 스크롤로 자연히 흡수된다 — 새 라우트도, 내부 스크롤 컨테이너도 필요 없다.
카탈로그가 8개 이하면 링크·버튼을 애초에 렌더하지 않는다(웹 `showExpand` 규칙 동일).

### 쟁점 4 — 잔디 히트맵의 가로 스크롤 → **24주 탭은 스크롤 없음, 53주는 상세 라우트 안에서만 가로 스크롤**

Figma 실측: 기록 탭 잔디 카드 342×153, 셀 9px·간격 3px, 24주 격자 폭 **285px**, 요일 라벨 열 18px + 6px 간격
= 309px ≤ 카드 내폭 314px. → **탭의 24주 잔디는 가로 스크롤이 필요 없다**(중첩 스크롤 충돌 자체가 발생하지 않는다).

1년(53주)은 같은 셀 규격으로 53×12−3 = **633px**이라 가로 스크롤이 필수인데, 이는 **쟁점 2의 별도 라우트 안**이다.
그 화면의 세로 ScrollView 안에 `ScrollView horizontal`을 넣는 것은 축이 직교해 제스처 충돌이 없다(RN 표준).
초기 스크롤 위치는 **오른쪽 끝(오늘)**으로 둔다(GitHub 관례 + Figma 힌트 문구가 "← 좌우로 넘겨"라 왼쪽으로 되감는 방향을 전제).
Figma 1년 카드는 셀을 7.44px로 축소해 그렸으나, 구현은 탭과 같은 9px/3px 토큰 규격을 쓰고 스크롤로 처리한다(오탐 방지 등재).

### 쟁점 5 — 낙관적 갱신/실패 롤백 → **웹 `use-badge-mutations.ts` 그대로. 낙관 갱신은 애초에 없다**

웹 구현을 읽은 결과 **낙관적 캐시 갱신이 존재하지 않는다**. 구조는:
- 선택 상태는 컴포넌트 로컬 `selection: number[]`(배열 순서 = 랭크 = PUT `badgeIds` 순서)
- "하단 프로필 미리보기 즉시 반영"은 **로컬 selection이 그리는 것**이지 캐시 낙관이 아니다 → 롤백 개념이 필요 없다
- `mutate`는 in-flight 가드(pending 중 재발사 무시), 성공 시에만 `findMyBadges` invalidate + `onSaved()` → 편집 종료
- **실패 시 아무것도 되돌리지 않는다** — 편집모드·selection이 그대로 남고 인라인 에러 문구가 뜨며 저장 버튼을 다시 누를 수 있다(티켓 "실패 시 편집 상태를 유지하고 재시도" 그대로)
- `mutateAsync`는 노출하지 않는다(가드 우회 경로 차단)

→ 모바일도 동일 구조로 포팅한다. 차이는 import 경로뿐: 웹은 생성물 직접 경로에서 `replaceFeaturedMutation`·`findMyBadgesQueryKey`를 가져오는데, 모바일은 **`shared/api/query-options` 배럴**(웹 생성 react-query 산출물 재수출)에서 가져온다. 새 fetch·새 QueryClient 금지 규칙 준수.

## 추정 및 질문 (사용자 확인 필요 — 승인 게이트용)

- **A1. 미획득 뱃지의 라벨** — 웹은 이름 대신 **"미획득"**을 쓴다("미획득 뱃지 이름은 스포일러"라는 MSG-123 규칙). 그런데 모바일 Figma(14799:26410)는 미획득 메달 아래에도 **실제 이름**("탐험가 I", "기록러 I", "축제 입문", "한 달 개근")을 그렸고, 티켓도 "각 뱃지 아래에 이름이 보인다"라고만 쓴다. **제안: 모바일 시안+티켓을 따라 이름을 표시**(웹과 의도적 차이). 웹 규칙(스포일러 방지)을 모바일에도 적용하려면 지정 필요.
- **A2. 미획득 표현이 "회색조"가 아니라 "40% 투명"** — RN에 크로스버전 안전한 grayscale이 없다(쟁점 1 결론). **제안: opacity 0.4 단독.** 완전한 회색조가 꼭 필요하면 `filter: [{grayscale:1}]`을 추가로 얹을 수 있으나 Android 12 미만에서는 무시돼 기기별로 보이는 게 갈린다 — 그 편차를 감수할지 지정 필요.
- **A3. "연도 선택" UI** — 티켓은 1년 화면에 "연도 선택"이 있다고 쓰고 Figma에도 `최근 1년 ▾` 셀렉터가 있으나, **`GET /api/collections/upload-history`는 기간 파라미터를 받지 않는다**(전량 응답). 웹은 이 이유로 캐럿을 떼고 정적 라벨 "최근 1년"만 남겼다(MSG-414 A5, 승인됨). **제안: 웹과 동일하게 정적 라벨.** 동작 없는 드롭다운 시늉을 유지하려면 지정 필요.
- **A4. 기록 빈 상태 문구** — 티켓은 "기록이 없으면 빈 상태 문구가 보인다"고 요구하는데 **웹에는 그런 문구가 없다**(MSG-414 A7에서 "전부 lv0 잔디 + 0일 메타, 별도 안내 없음"으로 승인). 모바일 Figma에도 빈 상태 프레임이 없다. **제안: 티켓을 따라 잔디 카드 아래에 안내 1줄을 신설** — 문구안 **"아직 업로드 기록이 없어요. 첫 영상을 올리면 여기에 쌓여요."**(기존 도감 빈 상태 "아직 수집한 격자가 없어요. 첫 영상을 올려 격자를 수집해 보세요."의 어투 승계). 문구 수정·위치 변경을 원하면 지정 필요.
- **A5. 편집 모드 뱃지 목록 범위** — 웹은 편집 시 **전체 카탈로그**를 노출한다(획득 뱃지가 프리뷰 8칸 밖에 있을 수 있어서). 모바일 Figma 편집 프레임은 8칸만 그렸다. **제안: 웹과 동일하게 전체 카탈로그**(셸 ScrollView가 흡수). 시안대로 8칸으로 제한하면 선택 못 하는 획득 뱃지가 생긴다.
- **A6. "완료" vs "대표 뱃지 저장"** — 웹 승인 결과 승계 제안: **저장 = PUT 커밋 + 성공 시 종료 / "완료" = 서버 호출 없이 종료(미저장 변경 폐기)**. 저장 pending 중에는 "완료"도 비활성(늦은 성공 콜백이 새 편집 세션을 닫는 레이스 차단 — 웹 codex 리뷰 반영분).
- **A7. 업로드 성공 시 잔디 무효화 범위** — 웹은 MSG-414 A8에서 업로드 확정·교체·삭제 3지점에 `upload-history` 무효화를 넣었다. 모바일은 확정만 존재한다(교체·삭제는 MSG-431). **제안: 기존 `features/upload/api/invalidate-grid-queries.ts`에 upload-history 무효화 1줄 추가**(파일 1개, 티켓 [동작 요구]에 없는 소폭 범위 확장). 범위를 엄격히 지키려면 제외 가능 — 그 경우 업로드 직후 잔디가 최대 staleTime(전역 30초)만큼 뒤처진다.
- **A8. 1년 잔디 초기 스크롤 위치 = 오른쪽 끝(오늘)** — Figma 힌트가 "← 좌우로 넘겨"라 왼쪽으로 되감는 방향을 전제한다고 읽었다. 왼쪽(1년 전)에서 시작하길 원하면 지정 필요.

## 검증이 잡은 결함 2건 (자동 게이트·parity가 전부 놓친 것)

### F1 — 뱃지 메달 24종이 하나도 렌더되지 않았다 (S1)

**스펙의 전제가 스테일했다.** 웹 `badge-art.ts` 주석의 "`badges.icon_url`은 현재 전량 NULL"을 그대로 승계해 "로컬 카탈로그가 정본"이라는 설계를 세웠는데, 검증자가 운영 API를 직접 조회하니 **전 뱃지에 `iconUrl`이 채워져 있었고 그 값은 PNG**였다(`curl | xxd` → `8950 4e47`). `resolveBadgeArt`는 계약(L6)대로 `iconUrl`을 우선했고, 렌더가 그것을 SVG 전용 파서에 넘겼다:

```tsx
<SvgUri uri={art.uri} … />   // PNG → 파싱 실패 → null → 높이 0
```

**웹은 `<img src>`라 같은 전제 변화를 그냥 흡수한다.** 그래서 이 결함은 parity 테스트로도, 타입으로도, 자동 게이트 어디로도 잡히지 않았다 — **"웹 순수 모듈 포팅 + parity"라는 이 하네스의 안전망이 렌더 계층에서는 작동하지 않는다**는 것을 보여준 첫 사례다.

수정은 형식 판별을 **뷰가 아니라 타입 계약에 올렸다**: `BadgeArt`의 종류를 `"uri"|"xml"` → `"svg-uri"|"image-uri"|"xml"`로 갈랐다. 이 타입의 JSDoc은 이미 "RN은 렌더 경로가 갈리므로 종류를 돌려준다"고 선언해 놓고 정작 `"uri"` 한 갈래로는 렌더 경로가 미결정이었고, **그 미결정 자체가 F1의 발생 지점**이다. 갈라 두면 분기 누락이 타입 오류가 된다(뷰 안 URL 분기는 그 보호가 없다). `isSvgUri`(쿼리스트링·해시 제거 후 확장자, 대소문자 무시, 확장자 없으면 래스터)는 순수 함수로 빼고 5건 + 회귀 방지 1건 테스트를 붙였다. `resolveBadgeArt` 우선순위와 L6 계약, `SvgXml` 로컬 폴백, 민무늬 원 `null` 폴백은 전부 무변경.

### F2 — 잔디 요일 라벨이 세로로 잘려 `수`·`금`이 `스`·`그`로 읽혔다 (S8·S10)

캡션 줄상자가 **14px**(`typography.caption` 11/14)인데 셀 높이 **9px** View로 감쌌다. 코드 주석은 "글자는 넘치게 둔다"고 했으나 **Android 기본 클립에서 그 전제가 성립하지 않는다.** 월 라벨이 이미 쓰던 절대 배치 관례로 통일했고, 오프셋 23.5/47.5/71.5px는 셀·stride·타이포 토큰 파생이라 새 임의값 0건이다. `lineHeight` 압축·stride 확대는 14px 줄상자가 9/12px 어디에도 안 들어가 클립이 축소된 형태로 남아 기각, `overflow-visible`은 Android에서 신뢰 불가라 기각.

## 검증 사고 1건 — 워처 꺼진 Metro가 거짓 실패를 만들었다

재검증 초반 **F1·F2가 둘 다 "미해소"로 관측됐는데, 앱이 재작업 이전 코드를 돌고 있었다.** 1차 검증 때 `CI=1`로 띄운 Metro가 살아 있었고 **`CI=1`은 파일 워처를 끈다.** 직접 curl한 번들에는 새 심볼이 다 들어 있어서(다른 transform 파라미터 → 별도 그래프 빌드) 함정이 교묘했다.

결정적 단서는 **앱 재기동 전후 스크린샷이 전체 화면 픽셀 단위로 동일**했던 것이다 — F1 수정은 `SvgUri`(높이 0) → `Image`(56px)라 레이아웃이 반드시 바뀌어야 한다. Metro를 워치 모드로 재기동하자 둘 다 즉시 해소됐다. **모바일 실기 검증에서 `CI=1` Metro는 쓰지 말 것.**

## 후속 권장 (지라 환류 대상 — 이 티켓 범위 밖)

1. **(우선) `icon_url`이 채워진 사실의 파급 정리** — 웹 SVG 24종(368KB)과 모바일 문자열 카탈로그(307KB)가 **양쪽 모두 폴백 전용**이 됐다. 총 ~675KB의 정본 결정은 웹까지 걸친 별건이다
2. **서버 카탈로그 23종 vs 로컬 24 code 불일치** 확인 — L6은 웹과의 일치만 단정한다
3. **`SvgXml` 경로가 실기에서 한 번도 실행되지 않았다** — 스펙 최대 리스크였던 307KB 파싱 비용은 여전히 미검증이다. 강제 실행법: `badge-medal.tsx`의 `resolveBadgeArt(badge.code, badge.iconUrl)`를 `(badge.code, null)`로 한 줄 바꿔 리로드하면 24종 전부가 `SvgXml` 경로로 떨어진다

## 커밋 전 codex 리뷰 환류 (P2 1건)

codex 리뷰가 **`/dex/history`에서 하단 내비의 활성 탭이 하나도 표시되지 않는다**는 것을 잡았다. `AppBottomNav`의 판정이 `TAB_ROUTES[key] === pathname` 정확 일치인데, **`/dex/history`가 이 앱 최초의 탭 자식 라우트**라 그 구멍이 처음 드러난 것이다.

`widgets/bottom-nav/app-bottom-nav.tsx` 2곳을 고쳤다 — 활성 판정을 세그먼트 경계 접두 매칭으로 넓히고(`/dexfoo` 오탐은 `/` 요구로 차단, `/upload`의 "활성 탭 없음"은 보존), `handleSelect`에 **자식 라우트 재탭 → 탭 루트 복귀** 분기를 함께 넣었다. 후자가 없으면 넓힌 판정 탓에 도감 탭 재탭이 무동작이 된다.

화면마다 override를 다는 대신 위젯의 판정 규칙을 고친 이유는, 원인이 화면이 아니라 규칙에 있어서 override 방식이면 **다음 자식 라우트에서 같은 결함이 재발**하기 때문이다.

자동 게이트 5종을 재실행해 전량 통과했다(mobile 575 tests · typecheck · lint · format · `check:duplication` exit 0).

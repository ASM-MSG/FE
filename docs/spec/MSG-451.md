# MSG-451: 지도 홈·도감 잔손질 5건 — 축제/팝업 칩 줌아웃 집계·칩 최근접 진입·격자 상세 중 불러오기·클러스터 이름·대표 뱃지 교체

## 기획 요약

지도 홈과 도감에서 걸린 잔손질 5건을 한 티켓으로 정리한다. 3~5번은 기존 순수 함수의 판정 한 줄
수준이고, 1번만 MSG-437(서버 완료)의 웹 렌더링 레인이라 신규 조회 연동이 붙는다. 축제·팝업 칩이
켜진 저줌에서 미션 격자를 계속 그리던 것을 도감과 같은 행정 단위 집계 마커로 바꾸고(1), 칩을 누르면
지도 중심에서 가장 가까운 대상으로 이동해 상세를 연다(2). 격자 상세 중에도 "장소 불러오기"를
노출하고(3), 겹쳐 합쳐진 집계 마커의 이름 소실을 고치며(4), 대표 뱃지 3개째 선택을 FIFO 교체로
바꾸고 "완료" 문구를 실제 동작(미저장 종료)에 맞춰 "취소"로 정정한다(5).

## 추정 및 질문

**사용자 확인 필요:**

1. **미션 집계 마커 색** — Figma `14599:7025`를 조회한 결과 **미션용 클러스터 노드가 없다**(도감 점령
   클러스터만 존재). MSG-437의 "색만 미션용으로 구분"에 따라 **활성 칩 테마 색**(`bg-theme-festival`
   `#AF52DE` / `bg-theme-popup`)을 채움에 쓰고 나머지(크기 3단·흰 링 3px·이름 위 개수 아래)는 도감
   마커 그대로 간다
2. **마커 접근성 문구** — 도감은 "{지역명} 점령 격자 N개". 미션은 "{지역명} 지역축제 N개" /
   "{지역명} 팝업스토어 N개"로 칩 라벨을 쓴다
3. **상세를 연 미션의 셀은 저줌에서도 계속 그린다** — AC 2의 "미션 격자 비움"은 **목록 상태**에만
   적용한다. 상세는 자기 경계로 그리는 기존 규칙(`use-home-overlays`)이 있어, 여기까지 비우면 2번이
   최근접으로 이동한 직후 화면이 비어 버린다
4. **최근접 판정 좌표** = 대상 `shape.bbox`의 중심. 코스도 같은 기준(스팟 평균이 아니라 bbox 중심)
5. **경로추천 칩의 자동 진입은 `moveTo`만** 쓴다(줌 유지). 목록 카드를 직접 클릭했을 때의 기존
   `fitBounds`(코스 전체가 보이게)는 그대로 둔다 — 자동 진입과 수동 선택의 이동 방식이 다르다
6. **미션 집계 조회에도 로그인 게이트**를 건다 — 개별 조회(`/api/missions/active`)가 익명 401로
   실측된 선례(2026-08-15)를 따른다. 명세에 인증 요구가 명시돼 있지 않아 실측으로 확정한다
7. **병합 이름 가나다순**은 `localeCompare(_, "ko")`, 이름 null인 멤버는 정렬 최후순 — 이름 있는
   멤버가 있으면 항상 그쪽이 앵커가 된다
8. **미션 집계 bbox는 뷰포트** — 확정 영역이 아니다. 도감 집계(MSG-410 추정 1, 승인됨)와 같은 이유:
   저줌에서는 "장소 불러오기"가 노출되지 않아 확정 영역으로 묶으면 갱신 수단이 없다

### 검증 재작업 1회 — 콜드 첫 활성화 미발동

새로고침 직후 지역축제 칩 클릭 시 최근접 진입이 일어나지 않았다. **원인이 둘이었고, 1회차 진단은
절반만 맞았다.**

1. 칩 진입 줌(500m)에 도달한 시점의 미션 목록은 아직 *직전 확정 영역*(더 좁은 화면) 기준이고,
   그 응답이 이미 resolved(0건)라 `isPending`이 false다. "대상이 없어도 재시도하지 않는다"는
   의도로 그 시점에 활성화를 소진해, 확정이 넓어져 1건이 도착해도 이미 늦었다.
2. 확정 신호만 추가한 수정은 테스트에서 여전히 실패했다. `mapQueryPolicy`의 `keepPreviousData`
   때문에 확정으로 쿼리 키가 바뀌어도 **직전 영역 목록이 `isPending:false`인 채 한 박자 더**
   반환된다(깜빡임 방지용 의도적 정책이라 정책 자체는 그대로 둔다).

해소: `useChipEntry`가 확정을 마친 칩을 반환하고, `useActiveMissionsQuery`가 `isPlaceholder`를
노출하며, `useNearestEntry`가 **확정 신호 + 그 영역 기준 목록 도착(`listSettled`)** 을 함께 기다린다.
회귀 테스트 3개 추가(확정 전 목록 비어도 미소진 · 확정 전 미이동 · 이전 칩 확정 잔존 시 대기).

팝업 칩이 콜드에서도 성공했던 것은 확정 전 좁은 영역에도 대상이 있었기 때문으로, 정상 동작의
근거가 아니라 같은 결함의 반대 사례였다 — **부작용은 미발동만이 아니라, 확정 후 더 가까운 대상이
도착해도 엉뚱한 대상으로 가는 것**이었다.

### 검증 재작업 2회 — 최근접 진입에서 선택 제거 (사용자 환류)

"가까운 데로 이동하는 것까지는 좋은데, 특정 팝업스토어가 클릭된 상태가 되는 건 빼 달라."
칩의 목적은 "이 근처에 뭐가 있나"를 보여주는 것이고 **어느 것을 볼지는 사용자 몫**이라는 판단이다.

`useNearestEntry`가 `select` 콜백을 아예 받지 않도록 했다 — 줌 명령을 받지 않는 것과 같은 이유로,
수단이 없으면 실수도 없다. `NearestEntryTarget`에서 `missionId`도 제거(이동에는 좌표만 필요),
`use-home-chip-entry`의 `useMissionSelectionStore` 배선 제거. 테스트 10개를 이동 기준으로 재작성.

재검증에서 **이동은 살아 있고 선택만 사라진 것**을 교차 확인했다 — 축제 칩은 지도를 서면에서
광안2동으로 옮기면서도 좌측을 목록으로 유지했고, 팝업 칩은 10건 목록을 그대로 뒀다.

### 테스트가 잡은 결함 1건 (구현 중)

`mergeOverlappingMarkers`가 병합 결과 객체를 새로 조립하면서 `theme`을 빠뜨려, 겹쳐 합쳐진 미션
마커만 도감 색(`bg-primary`)으로 렌더될 상황이었다. 저줌에서 마커는 자주 겹치므로 실사용에서 바로
드러났을 결함이다.

# MSG-534: 행사방 개요 위치 카드 클릭 무반응 — 통합 배선 누락 수정

## 기획 요약

행사 웨이브(MSG-516~521) 통합 검증에서 확인된 결함. 칩 → 행사방 개요까지는 스펙대로 동작하지만, 개요의 **위치 카드 클릭이 완전 무반응**이라(콘솔 에러 0·네트워크 0·스토어 `location` null 유지 실측) 위치별 영상 상세(518)·미니 패널(520)·업로드 CTA(521)에 UI로 도달할 방법이 없다. 상세 진입의 유일한 설계 경로가 이 카드다.

원인은 새 로직 부재가 아니라 **배선 누락**이다. `selectLocation`(store)·`toEventLocationSelection`(변환기)은 MSG-518이 완성해 뒀는데 프로덕션 호출처가 0곳이다. MSG-518 확정 결정 "클릭 배선은 517/518 중 나중에 머지되는 쪽이 잇는다"를 양쪽 워크트리가 모두 상대 몫으로 기록한 채 종료한 병렬 통합 틈새 — 티켓 단위 검증으로는 잡을 수 없었던 유형이다. **원인 재조사 불필요**(재현·코드·스토어 3중 확증 완료), 이 스펙은 배선 지시서다.

## 추정 및 질문

- **질문 1 — 결정 완료 (2026-08-31 사용자: A안 승인)**: **아카이브 위치 행 배선은 "1~2줄"이 아니다.** MSG-519가 그렇게 예약했으나 현재 코드는 두 곳에서 막는다:
  1. `features/event/model/event-room-mode.ts:29` — `UPLOAD_GRACE`/`ARCHIVED`면 `selectedLocationId`를 **보기도 전에** `archive`를 반환한다. 주석이 의도를 명시한다: *"종료 행사는 위치 선택이 남아 있어도 아카이브다 — 유령 영상 목록 방지 (MSG-519 AC 1·2)"*. 즉 행에 `selectLocation`을 붙여도 **본문이 바뀌지 않는다**(무반응 결함의 아카이브판이 된다)
  2. `EventRoomBodySwitch`의 videos/empty 분기는 `EventLocationHeader`("+ 영상 올리기")와 `EventLocationEmptyState`("첫 영상 올리기")를 렌더한다 — 아카이브는 **업로드 CTA 미렌더가 AC 7**이고 본문 문구도 "새 영상은 올릴 수 없어요"다. 그대로 재사용하면 읽기 전용 계약을 깬다

  선택지:
  - **A안 (범위 유지)**: 아카이브 행 배선을 이 티켓에서 빼고 별도 티켓으로. 개요 카드 배선만 수행 → diff 10~20줄 유지, 사용자 발견 결함은 100% 해소(하류 518→520→521 전부 열림). 아카이브는 실데이터 0건 + 진입 UI 부재라 **현재 도달 자체가 불가능**해 체감 손실이 없다
  - **B안 (읽기 전용 관통)**: `eventRoomMode`에 archive+위치 선택 분기를 추가하고, videos/empty 본문에 `readOnly` 플래그를 관통시켜 업로드 CTA 2곳을 억제. MSG-519 AC 1·2·7 재해석이 필요하고 diff가 40~60줄로 늘며, 검증은 스텁으로만 가능(종료 행사 0건)
  - **C안**: 아카이브 전용 영상 목록 본문 신설 — 가장 크고, "지난 회차 진입 UI 없음"과 묶어 별도 티켓이 자연스럽다

  **권장: A안**. 티켓 [동작 요구]에 아카이브 행이 명시돼 있어 임의 제외하지 않고 질문으로 올린다. 오케스트레이터 지시의 "diff 10~20줄 소품·범위 확장 금지"와 [동작 요구]가 이 지점에서 충돌하며, A안이 그 충돌을 해소한다.

- **추정 1** (기준 3 한계): 서버 시딩에 행사 영상이 0건이라 클릭 후 도달 지점은 **항상 empty 모드**다. videos 모드(영상 카드 목록·미니 패널)는 이번 실동작 검증에서 확인 불가이며, 스텁·vitest로 대체한다 — 결함이 아니라 데이터 한계로 리포트에 기록한다.
- **추정 2** (구현 3(a)): 카드 뷰에 원본 DTO를 동반시키는 방식을 권장으로 골랐다. 티켓은 전달 방법을 지정하지 않았다 — 구현자가 (b)가 낫다고 판단하면 근거를 작업 로그에 남기고 바꿔도 무방하다.
- **추정 3** (a11y 형태): 접근명을 "{위치명}" 단독이 아니라 위치명 + 유형/영상 수 맥락을 포함하는 형태로 둔다(예: `aria-label="여의도 한강공원 위치 영상 보기"`). 티켓에 문구 지정이 없다.
- **추정 4** (마크업 형태): `<li>` 유지 + 내부 전체 행 button. `<li>` 자체를 button으로 바꾸지 않는 이유는 `<ul>` 시맨틱 보존이다. 시각 결과는 동일.

## 리스크

- **아카이브 배선 블로커**: 질문 1 참조 — 티켓의 "1~2줄" 전제가 코드와 불일치한다. MSG-519 작업 로그의 예약 문구가 실제 코드 구조를 반영하지 못한 채 남은 케이스로, `docs/STATUS.md` MSG-519 행의 "영상 연결은 518 머지 후"도 같은 낙관을 담고 있다. **승인 없이 B/C안으로 진행하면 범위가 3~5배로 불어난다.**
- **회귀 감시 지점 (배선이 여는 경로들)**: 이번 배선 하나로 MSG-518 본문·520 미니 패널·521 업로드 CTA가 **처음으로 실사용 경로에 올라간다**. 지금까지 스토어 직접 주입으로만 통과한 항목들이라, 실경로에서 처음 드러나는 결함이 있을 수 있다(특히 521 비로그인 게이트 → 로그인 후 재개). 검증은 위치 카드 클릭 → 빈 상태 → CTA 게이트 1경로를 반드시 밟는다.
- **격자 클릭과의 혼동 금지**: 지도 격자 클릭(MSG-517 AC 7)은 `highlightLocation`(표시 전용)이고 이번에 배선하는 것은 `selectLocation`(상세 진입)이다. **두 슬롯을 합치면 MSG-517 AC 7 회귀**(격자 클릭이 상세로 진입)가 난다 — 기준 7이 이를 고정한다.
- **검증 환경**: 시딩 행사가 **서울 여의도** 1건뿐이라 홈 초기 화면(부산 서면)에서는 캡슐이 보이지 않는다. 검증자는 지도를 여의도로 이동해야 하며(geolocation 패치 또는 드래그 — 검색은 로그인 게이트), 이는 결함이 아니라 뷰포트 기반 설계 그대로다. dev 서버는 `--strictPort 5173`(네이버 지도 키 제약).
- **탭 가시성**: 이번 티켓 기준에 계측형(주기·프레임률) 항목은 없어 3-A 전제 조건의 부담은 낮다. 다만 브라우저 검증 시작 시 `document.visibilityState === "visible"` 확인은 절차대로 수행한다.
- **Figma 오탐 방지**:
  - 카드의 **시각 결과는 변하지 않는다** — chevron은 MSG-517이 이미 그려 뒀고 이번 변경은 요소 타입(li → li>button)과 포커스 링뿐이다. Figma 15518:5932 대비 신규 편차가 보이면 그것이 결함이다(기준 4).
  - 기존 오탐 목록은 그대로 유효 — 개요의 배너 이미지·D-day 뱃지·"부산 전역" 요약 미구현(대응 DTO 필드 없음), 아카이브의 배너 이미지·"종료" 뱃지·지역 표기·위치 썸네일 미렌더. 이번 티켓이 건드리지 않는다.

# MSG-412: 격자 검색 연동

## 기획 요약

홈 검색바(placeholder "장소, 격자 검색" — 격자 부분이 이 티켓)에 "서면 A-14" 형식 격자 검색을
추가한다. 서버 검색 API가 없으므로 `GET /api/zones`(구역 사각형 48건)를 세션 1회 캐시하고,
입력을 로컬에서 역파싱(구역명 + 칸 코드 → gridId)해 매치를 제시한다. 격자 결과 선택 시 지도를
그 격자로 이동하고 격자를 하이라이트한다. 격자 클릭 시 이름 표시(`getCell`)는 이미 연동돼 있어
범위 밖 — 이 티켓은 검색 연동만이다.

**코드베이스 현황 확인 결과**: 생성 SDK에 `getZones` + `getZonesOptions/QueryKey` +
`ZoneResponseDto`(zoneKey·name·regionCode·min/maxGridY·min/maxGridX·priority)가 **이미 있다**
— openapi 재생성 불요. 명명 의미는 서버 정본으로 문서화돼 있다: **행 A = 북단(maxGridY),
열 1 = 서단(minGridX)**. 격자 산술은 `entities/cell`(`cellCenterAt`·`cellCornersAt`·
`encodeGridId` — EPSG:5179 서버 정본)을 재사용한다. 하이라이트는 기존 `emphasizeCell`
(테두리 강조, MSG-328 카드 재생 강조와 같은 경로)로 게시할 수 있다. 장소 검색 DTO
(`PlaceSearchResponseDto`)도 `gridId`를 싣고 "선택 시 이동+하이라이트 한 번에"가 API 계약
주석이지만 현 구현(MSG-328)은 이동만 한다 — 추정 6 참조.

## 추정 및 질문

1. **[확인 필요] zones 캐시 시점 = "앱 기동"이 아니라 로그인 상태의 홈 검색박스 마운트 시 1회**
   — `/api/zones`는 bearer 필수라 비로그인 기동 시점 프리페치가 불가능하다(익명 401 관례).
   staleTime·gcTime Infinity로 "세션 내 1회 캐시"라는 티켓 의도는 동일하게 달성된다.
2. **[확인 필요] 구역명만 입력해도 구역 항목을 제시하고, 선택 시 구역 사각형 fitBounds** —
   티켓은 "서면 A-14" 형식만 명시했지만, 서버 SDK 주석("검색바에서 구역을 골라 지도를 옮기거나")
   이 구역 단위 선택을 전제한다. 부담이 크면 이 항목(AC 7)만 제외 가능 — 칸 코드 완성 전에는
   결과 0건이 되는 UX 공백이 생긴다.
3. **매칭 규칙**: 접두 일치 우선 → 포함 일치, 동순위 priority 오름차순·zoneKey 타이브레이크,
   상한 5건 — 티켓에 규정 없음. 48건 로컬 필터라 성능 무관, 순서 결정성만 보장.
4. **하이라이트 수명**: 마지막 선택 1건 유지, 새 격자 선택 시 교체. 별도 자동 해제(타이머) 없음
   — 재생 강조(playingGridId)와 같은 "상태가 있는 동안 유지" 관례. Escape·지도 클릭 해제가
   필요하면 알려달라(현안은 미포함).
5. **선택 시 줌 보장**: zoom < `GRID_MIN_ZOOM`(16, 축척 100m)이면 `GRID_MIN_ZOOM`으로 이동 —
   강조 전용 셀은 저줌 게이트(`gateFillCells`)에서 걷히므로 줌 보장 없이는 하이라이트가 안
   보인다. 이미 그 이상 줌이면 현재 줌 유지.
6. **[확인 필요] 장소 결과 선택에도 하이라이트 적용 여부** — `PlaceSearchResponseDto.gridId`가
   "선택 시 이동+하이라이트 한 번에"라는 API 계약 주석으로 실려 있으나 MSG-328은 이동만 구현했다.
   같은 하이라이트 인프라로 1줄 수준 확장이지만 티켓 범위("격자 검색 추가") 밖이라 **기본은
   미포함** — 포함 원하면 지시해달라.
7. **[확인 필요] `zone-naming.json` 픽스처 위치** — FE 레포에 없다(grep 0건). BE 레포 경로나
   파일 전달이 필요하다. 미확보 시 AC 2는 DTO 명세(행 A=북단·열 1=서단) 기반 자체 케이스로
   대체하고 픽스처 대조는 후속 보강으로 남긴다.
8. **행 문자는 A~Z 단일 문자 전제** — 구역 세로 27칸 이상(AA행)은 미지원. 서면 등 구역 사각형
   규모상 현실적으로 없다고 판단, 픽스처 확보 시 교차 확인.

## 리스크

- **zones 시딩 전이면 기능이 조용히 비활성** — 서버가 빈 배열을 반환하면 격자 섹션이 안 나온다
  (전 시스템 행정동 폴백과 정합, AC 3). 검증 시점에 시딩이 안 돼 있으면 화면 검증(AC 8~9)은
  fetch 스텁으로 대체한다(MSG-410 관례).
- **`zone-naming.json` 미확보 리스크** — 질문 7. 역산 산술이 서버 명명과 어긋나면 검색 결과
  라벨과 격자 클릭 이름(`getCell`)이 서로 다른 격자를 가리키는 결함이 되므로, 픽스처 대조가
  가장 확실한 방어다.
- **저줌 게이트 상호작용** — 강조 전용 셀(색 없음)은 `gateFillCells`가 저줌에서 걷어낸다.
  선택 시 줌 보장(추정 5)으로 해소하지만, 하이라이트 유지 중 사용자가 줌아웃하면 강조가
  사라지는 것은 기존 재생 강조와 동일한 기대 동작으로 수용한다.
- **`priority` 의미** — DTO 주석은 "겹침 결정성 우선순위"(명명용)다. 검색 정렬 타이브레이크로
  전용(轉用)하는 것은 추정 3 — 순서 결정성 확보가 목적이며 명명 산술에는 영향 없다.
- **Figma 오탐 방지**: ① 티켓에 Figma 노드 링크가 없어 노드 분석은 생략했다 — "검색/지역 필터"
  프레임의 확정 사항은 플레이스홀더 문구("장소, 격자 검색")뿐이고 이는 **이미 구현돼 있다**.
  ② 격자 결과 행의 전용 디자인은 프레임에 없다 — 기존 장소 결과 행 스타일 준용이 정답이며
  디자인 불일치로 판정하지 않는다. ③ "서면 A-14"·"48건" 등 수치·지명은 예시(플레이스홀더) —
  하드코딩 금지, 데이터는 zones 응답 유래.

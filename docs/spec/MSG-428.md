# MSG-428: [모바일] 줌아웃 클러스터 마커 — 동·구 지역 집계 연동

## 기획 요약

모바일 지도는 핀치 아웃이 기본 제스처인데 격자 표시 줌 미만에서는 개별 격자·점령 채움이 사라져 빈 지도가 된다. 웹이 MSG-410에서 FE 로컬 클러스터 산술을 **서버 집계(`GET /api/grids/aggregation`) 기반 지역 마커**로 대체했으므로, 모바일도 같은 계약·같은 순수 로직을 포팅해 저줌 구간을 지역 집계 마커로 채운다. 마커는 파란 원 + 흰 테두리에 위=지역명 / 아래=점령 격자 수, 단위별 크기 3단(동<구), 탭하면 다음 세부 단위 줌으로 카메라가 이동하고, 화면상 겹치는 마커는 개수 합계만 있는 하나로 병합된다.

**MVP는 부산 전용이라 시(SIDO) 단위는 제외**하고 동·구 2단계만 다루며, 구 단위 바닥에 줌 하한을 둬 "마커 하나만 남는 시 단위 화면"으로 나가지 못하게 한다. 서버 API 변경은 없다.

**플랫폼: apps/mobile (Expo/RN) 전용. `apps/web`은 참조·parity 앵커로만 읽고 한 줄도 수정하지 않는다.**

### 확인된 공백 — 이 티켓이 만드는 것

- 모바일에 `map-scale.ts`가 **없다**. 웹 `aggregation-unit.ts`는 `MAP_SCALE_500M_ZOOM`·`MAP_SCALE_8KM_ZOOM`·`MAP_SCALE_4KM_ZOOM`을 축척 표에서 역산해 쓰므로, 줌 숫자 하드코딩(14·10·11)을 피하려면 축척 표를 함께 포팅해야 한다.
- 모바일 `visible-grid.ts`의 `GRID_MIN_ZOOM = **15**`인데 웹은 `grid-overlay.ts`의 `GRID_MIN_ZOOM = **16**`이다(웹 주석: "250m(zoom 15)부터는 집계 마커 — MSG-357 후속, 15→16 상향"). **모바일이 상향분을 못 받은 드리프트**다. 그대로 두면 zoom 15에서 격자와 동 마커가 동시에 뜨고 티켓 요구("격자 채움이 사라지고 마커가 표시된다", "250m~500m는 동 마커")를 만족할 수 없다 → **상향이 전제**(질문 Q1).
- 클러스터 마커 UI가 ui-native에 없다 → **화면 로컬** `features/map-home/ui/cluster-marker.tsx`로 만든다.
- 집계 조회 훅이 모바일에 없다 → `features/map-home/api/use-grid-aggregation-query.ts` 신설(기존 `api/` 3종과 같은 자리).

### 축척 표 역산값 (웹 `map-scale.ts` 실측 — 포팅 후 동일)

`SCALE_BY_ZOOM`은 zoom 6=128km부터 zoom 21=5m까지 16단.

| 상수 | zoom | 축척 |
|---|---|---|
| `MIN_ZOOM` | 6 | 128km |
| `MAP_SCALE_8KM_ZOOM` | 10 | 8km |
| `MAP_SCALE_4KM_ZOOM` | 11 | 4km |
| `MAP_SCALE_1KM_ZOOM` | 13 | 1km |
| `MAP_SCALE_500M_ZOOM` | 14 | 500m |
| `GRID_MIN_ZOOM`(상향 후) | 16 | 100m |
| `MAX_ZOOM` | 21 | 5m |

→ `aggregationUnitForZoom`: zoom ≥16 `null`(개별 격자) / 14~15 `DONG` / 10~13 `SIGUNGU` / 6~9 `SIDO`.

## 리스크

- **R1 (기획-코드 모순 / 확정)**: 모바일 `GRID_MIN_ZOOM`(15)이 웹(16)과 어긋나 있어 티켓 요구를 그대로 구현할 수 없다 → Q1 상향으로 해소. 상향 시 기존 `visible-grid.test.ts` 경계 케이스가 함께 바뀐다.
- **R2 (외부 의존 · 미검증)**: 이 워크트리에 `node_modules`가 없어 `@mj-studio/react-native-naver-map@^2.9.0`의 **`minZoom` prop 존재를 코드로 확인하지 못했다**. 없거나 동작하지 않으면 폴백: `onCameraChanged`/`onCameraIdle`에서 `zoom < MAP_MIN_ZOOM`이면 `animateCameraTo(center, MAP_MIN_ZOOM)`로 되돌린다(경계 튕김 UX 열위 — 구현 시 prop 우선 확인).
- **R3 (외부 의존 · 미검증)**: 같은 이유로 `NaverMapMarkerOverlay`의 **`onTap` prop**을 확인하지 못했다. 없으면 마커 자체를 `Pressable`로 감싸는 방식으로 대체(v2.9.0에서 커스텀 뷰 마커 내부 터치가 네이티브로 전달되는지 구현 단계 실측 필요).
- **R4 (RN 고유)**: Android가 마커 커스텀 뷰 서브뷰를 평탄화해 원·테두리가 사라질 수 있다 → `collapsable={false}`(MSG-298 경로 번호 마커에서 이미 겪은 함정). 실패 시 폴백은 마커 `caption` 텍스트.
- **R5 (검증 환경)**: 2026-08-19 기준 에뮬레이터 dev client APK가 Metro에 붙지 않는다(임베디드 번들 로더). 착수 시 `npx expo prebuild && npx expo run:android`로 재빌드해야 화면 AC를 검증할 수 있다. 또한 Expo dev client 번들 포트 함정(콜드 스타트가 8081로 복귀)이 있으므로 번들 출처를 교차 확인한다.
- **R6 (성능)**: 동 단위 광역 뷰포트에서 마커가 수십 개까지 늘 수 있다. 병합이 상한을 눌러 주지만, 네이티브 마커 수가 프레임을 떨어뜨리면 `mergeOverlappingMarkers` 임계는 Figma 지름 정본이라 못 건드리므로 **렌더 최적화(키 안정화·`useMemo`)로 먼저 대응**하고, 그래도 부족하면 별도 티켓.
- **R7 (내부 부채)**: `gatedQueryStatus` 구현이 모바일에 2개 존재하고 "정본 미결"로 STATUS.md에 명시돼 있다. 이 티켓은 **`shared/api` 2인자 판(웹 parity)** 을 쓰기로 판단했고, 통합 자체는 이 티켓 범위 밖이다.
- **R8 (병렬 티켓)**: MSG-427과 `map-home-screen.tsx`를 공유한다. 이 티켓이 나중에 머지·리베이스한다. 완화책은 화면 diff ≤10줄(G3)과 신규 파일 위주 구성 — 충돌면은 `map-home-screen.tsx` import 블록 + `GridMap` prop 블록으로 국한된다. 또한 MSG-427이 `theme-selection`/`mock-theme-data`를 갈아엎을 수 있으므로, Q4 테마 게이트는 `useSelectedTheme()` **읽기만** 하고 테마 모듈을 수정하지 않는다.
- **R9 (타입)**: 생성 SDK의 `unit` 쿼리 파라미터 타입은 `string`(enum 아님)이다. `AggregationUnit` union을 그대로 넘기면 타입은 통과하지만, 오타 방어는 FE 상수 테이블이 유일한 방벽이다(L2가 고정).

### Figma 오탐 방지 (page-verifier 대조 기준)

1. **시(SIDO) 단위 프레임 `14863:20552`는 제외 범위다.** 구현에 시 마커가 없고 zoom 10 미만에 도달할 수 없는 것이 **정상**이다 — 결함으로 판정하지 말 것.
2. **하단 시트 내용은 이 티켓 범위 밖이다.** 클러스터 프레임(`14799:27103`·`14863:20393`)의 시트에도 `부산진구 부전동` + 영상 카드가 그려져 있지만 이는 격자 줌 시안(MSG-423 산출물)의 재사용이다. 클러스터 줌에서 시트가 격자 줌과 동일하게 보이는 것이 정상이며, "클러스터 줌 전용 시트 변화"는 요구되지 않았다.
3. **지도 타일 스타일이 시안과 다르다.** 시안은 Figma 목 타일이고 구현은 네이버 기본 지도다(커스텀 스타일 GL은 롤백된 상태 — `docs/spec/ADHOC-naver-custom-style-blocked.md`). 배경 색·도로 색 차이는 결함이 아니다.
4. **마커 텍스트 크기가 Figma 텍스트 박스 높이와 정확히 일치하지 않을 수 있다.** 토큰(`text-fm-caption`/`text-fm-body-strong`) 고정 매핑이 웹과 합의된 방식이다(Q6). 판정 기준은 **원 전체 지름 68/80**과 색·구성(이름 위/개수 아래)이지 텍스트 픽셀 높이가 아니다.
5. **마커 개수·지역명은 서버 실데이터다.** 시안의 `초읍동 5`·`부전2동 31`·`부산진구 118` 등은 디자인 시점 플레이스홀더이므로 **하드코딩하지 않는다**. 실기 화면의 지명·숫자가 시안과 다른 것이 정상이다.
6. **테마 칩 행이 클러스터 줌에서도 보인다** — 시안과 동일. 다만 칩을 **활성화하면** 마커가 사라지는 것은 시안에 없는 동작이며 의도된 것이다(Q4).

- **R2 해소**: `NaverMapViewProps.minZoom?: number` 존재 (`@mj-studio/react-native-naver-map/lib/typescript/module/src/component/NaverMapView.d.ts:227`). 카메라 줌 하한을 prop으로 직접 걸 수 있다 — `onCameraChanged` 폴백 불필요.
- **R3 해소**: `BaseOverlayProps.onTap?: () => void` 존재 (`types/BaseOverlayProps.d.ts:58`) — `NaverMapMarkerOverlay`가 상속. 마커 탭 핸들러를 prop으로 직접 받는다. `Pressable` 래핑 폴백 불필요.
- 드릴인 카메라 이동: `animateCameraTo(..., zoom?)` 시그니처에 목표 zoom 인자가 있다 (`RNCNaverMapViewNativeComponent.d.ts:179`).
- **주의**: `BaseOverlayProps`에도 동명의 `minZoom`/`maxZoom`이 있으나 이는 **오버레이 표시 줌 범위**이지 카메라 제약이 아니다. 줌 하한은 반드시 `NaverMapView`의 `minZoom`에 건다.

## 검토한 대안 (기각 사유)

- **`GRID_MIN_ZOOM` 15 유지 + 마커 하한을 14로** — 티켓의 "축척 250m~500m는 동 마커"와 어긋난다. 15 유지 + 두 층 동시 표시는 "격자 채움이 사라지고 마커가 표시된다"를 깨뜨린다.
- **`AggregationUnit`에서 SIDO 제거** — `aggregationUnitForZoom`·`AGGREGATION_SPAN_CAP_DEG`·`drillInZoomForUnit`·`MARKER_MERGE_PX` 네 시그니처가 웹과 갈라져 parity 전건 비교가 무너진다. 파생 단계 필터링도 "필터가 빠지면 되살아나는" 약한 배제라 기각. 줌 하한은 카메라가 SIDO 구간에 **진입 자체를 못 하게** 만든다.
- **스펙대로 마커 파생 `useMemo`를 화면에 배치** — 프리티어 포맷 기준 G3(≤10줄)를 초과. 훅으로 옮긴 결과 합성이 순수 팩토리로 내려가 커버리지가 오히려 늘었다.
- **웹 모듈 런타임 import / 공통 패키지 추출** — 웹 리팩터가 모바일 번들에 직결된다. `envelope`·`api-error`·`map-query-policy`가 세운 "복제 + parity 테스트" 관례를 따랐다.
- **`toLocaleString("ko-KR")` 그대로 사용** — Hermes Intl 가용성이 빌드 설정에 좌우돼 실기에서 서식이 조용히 달라질 수 있다.
- **`minZoom` 하드코딩 존치** — 검증은 "설계 흐름을 막지 않으므로 수용"으로 판정했으나 재작업 2회차에서 prop화했다. "지금은 안 깨진다"에 기댄 판정이라 상세 화면이 바뀌면 조용히 깨지고, 제약은 그것을 요구한 화면에서 선언하는 편이 옳다.
- **채움 게이트 판정용으로 raw zoom을 state로 유지** — `onCameraChanged`는 제스처 중 프레임마다 발화하므로 연속값 state는 60fps 리렌더 + `occupiedPolygons` 매 프레임 재계산을 만든다(MSG-423이 같은 이유로 부모 setState 디바운스를 기각). 판정 결과 불리언(`isBelowGridZoom`)만 들면 `Object.is`로 걸러지고 정확성 근거(같은 카메라 이벤트의 zoom으로 판정)는 보존된다.
- **`setState`를 `showCellGrid` 가드 안으로 이동** — 상세 화면의 리렌더는 0이 되지만 무관한 두 prop(`showCellGrid` ↔ 채움 게이트)을 결합시켜, `showCellGrid={false}` + `occupiedCells` 조합에서 게이트가 초기값에 고정되는 함정을 만든다.

## 확인불가 / 잔여

- **S1~S9 실기 미확인** — 에뮬레이터 2대를 병렬 웨이브 형제 세션들이 점유 중이라 dev client 재빌드(`expo prebuild` + `run:android`)가 그쪽 검증을 깨뜨린다. 정적으로 판정 가능한 부분(지름·토큰·배선 위치·분기)은 판정했고, 외부 SDK 런타임에만 걸린 잔여는 우선순위 **S4(`onTap` 실발화) → S3(Android 서브뷰 평탄화, `collapsable={false}` 적용됨) → S6(`minZoom`이 핀치·줌컨트롤 양쪽을 막는가)**.
- ~~**`minZoom` 부수효과 (수용, 후속 권고)**~~ → **해소됨 (재작업 2회차)** — `minZoom`을 `GridMap`의 옵셔널 prop(기본값 없음 = 하한 미적용, 종전 동작)으로 빼고 지도 홈만 `minZoom={MAP_MIN_ZOOM}`을 넘긴다. `features/grid-detail/**`은 **한 줄도 고치지 않고** 종전 동작이 복원됐다(`git diff -- apps/mobile/src/features/grid-detail` = 0줄). 화면 diff는 9 → 10줄로 G3(≤10) 유지.
- **승격 후보 (미실행)** — `ClusterMarker`. `ui-native/src/index.ts` diff 0줄 합의(MSG-420 독점)를 지켜 화면 로컬 유지. 두 번째 사용처(친구 지도 = `getFriendGridAggregates`)가 생기면 승격 판단하되, 지름 표와 병합 임계의 단일 출처 관계를 함께 옮겨야 한다.
- **`gatedQueryStatus` 정본 미결 (범위 밖)** — 모바일에 2개 구현(`shared/api` 2인자 / `model/home-sheet-state` 3인자)이 공존한다. 이 티켓은 웹 parity인 2인자 판을 썼다.
- **`MAP_SCALE_2KM_ZOOM` 미사용** — 전문 복제 방침(parity 앵커 성립)에 따라 남겼고 주석에 명시.
- **`unit` 쿼리 파라미터가 생성 SDK에서 `string`(enum 아님)** — 오타 방어는 FE 상수 테이블이 유일한 방벽이며 L2가 고정한다.

# MSG-541: 운영자·관리자 콘솔 기반

## 기획 요약

행사 운영자(ORG)·관리자(ADMIN) 콘솔 웨이브(MSG-541~555, 15티켓)의 공통 기반 티켓. openapi 스냅숏 갱신·재생성으로 신규 API를 생성 SDK에 반영하고, `/org`·`/admin` prefix의 lazy 라우트 골격 + 후속 14티켓의 스텁 라우트 전부를 선등록하며, 콘솔 공통 셸(아이콘 레일+사이드바+본문+로그아웃)과 인증·인가 골격(LOCAL 로그인 → role 노출, 콘솔 가드, mustChange 게이트, noindex)을 세운다. 각 콘솔 화면 실구현(542~554)과 유저 앱 진입 링크(555)는 제외 범위다.

**확정 아키텍처 (재논의 금지 — 웨이브 계획 세션 채택안):** 단일 SPA + `/org`·`/admin` prefix + lazy 청크 분리 + role 가드(ADMIN 아니면 404 위장) + robots noindex. 보안선은 서버 role 인가이고 FE 가드는 노출 억제만 담당한다. 콘솔 라우트는 MapShell 밖 별도 레이아웃이다.

## 코드베이스 대조 결과 (스펙의 전제)

- **openapi 스냅숏은 이미 신규 API 대부분을 담고 있다** — MSG-516 재생성(커밋 0b09284, 2026-08-31)이 admin/* 20경로·org/* 8경로·auth/password 4경로·`LoginResponseDto.role`·`UserProfileResponseDto.role`(USER|ORG|ADMIN, 필수 필드)을 이미 커밋했고 생성 SDK에도 전부 들어 있다(실측). **라이브 스펙과의 실델타는 `POST /api/auth/password/initial`(setInitialPassword) 1건뿐이다**(2026-09-01 curl 대조). 재생성 절차·독점 원칙은 그대로 수행하되, 이번 재생성의 기대 diff는 작다.
- **LOCAL 로그인 훅은 이미 있다** — `features/auth/api/use-auth-mutations.ts`의 `useEmailLogin`(MSG-352, DevLoginPanel 진입점)이 `POST /api/auth/login` SDK 직접 호출 + X-Device-Id 보관 + accessToken 스토어 저장까지 수행한다. `auth-pipeline.ts`의 `AUTH_ENDPOINT_PATHS`에 `/api/auth/login`이 이미 등재돼 재발급 루프 방지도 성립한다. **이 티켓의 신규 작업은 로그인이 아니라 role 노출과 가드다.**
- `getMe`(GET /api/users/me) 응답에 role이 있고 생성 타입(`types.gen.ts`)에 이미 반영됐다. `useProfileQuery`(features/profile)가 `getMeOptions()`로 이 API를 캐시하지만 `toProfileData`는 role을 매핑하지 않는다.
- `GET /api/auth/password/status` → `PasswordStatusResponseDto { mustChange: boolean }`, 생성 옵션 `getStatusOptions` 존재. 태그 설명: 상태·변경은 로그인 필수, 재설정 2종은 비로그인.
- `useRobotsNoindex`(shared/document-meta.ts, MSG-478)는 기존 robots 메타의 content만 갱신하는 훅 — 콘솔 레이아웃에서 그대로 재사용 가능. `public/robots.txt`의 Disallow 목록은 `app/seo-static.test.ts`가 배열로 고정 단정하므로 함께 갱신해야 한다.
- `AppLayout`은 SideRailNav·UploadModal·LoginModal·PushNoticeHost·**위치동의 게이트(MSG-407)**를 상주시킨다. 콘솔이 AppLayout 아래에 들어가면 ORG 계정도 locationConsent 게이트에 걸린다 — **콘솔 레이아웃은 AppLayout의 형제(최상위)로 둔다**(MapShell 밖 + AppLayout 밖).
- `react-router-dom ^7.18` — route-level `lazy` 지원. 현재 router.tsx에 lazy 사용처 0, vite manualChunks 설정 없음.
- ui-web `SideRail`(w-18=72px, logo 슬롯 + items + activeKey)이 Figma OpsRail(72px, 로고+Nav+하단 로그아웃)과 구조 일치 — 하단 슬롯만 없다.
- MSG-541 브랜치는 로컬·리모트 모두 없음(신규 생성).

## 구현 계획

- **브랜치**: `feat/MSG-541-console-foundation` (origin/develop에서 분기 — 웨이브 0 단독 선행)

- **1) openapi 재생성 (이번 웨이브 독점)**: `openapi-ts.config.ts` 주석 절차 그대로 — `curl -sS -o openapi/api-docs.json https://api.fillmap.kr/v3/api-docs`(원문 그대로, 재정렬 금지) → 루트 `pnpm openapi-ts` → `pnpm typecheck` → 스냅숏+생성물 함께 커밋. 기대 델타는 password/initial 1건(코드베이스 대조 결과 참조). role 필수 필드는 이미 반영돼 있어 타입 파괴 없음 예상 — typecheck로 확증.

- **신규 로직**:

# MSG-409: 알림 설정 화면 연동

> **v2 (2026-08-18)** — 사용자 승인 게이트 결과 반영: ① WEEKLY 라벨 = 시안("마케팅 · 혜택 정보") 기각, 서버 의미에 맞춰 **"주간 리포트"**로 교정(문구 확정은 아래 매핑 표 — 시안과 의도적으로 다른 지점, Figma 오탐 방지 등재), ② "알림 받기" 토글(MSG-408) 존치 + 아래 "알림 설정 ›" 행 추가 — **푸시 등록 진입점이 토글+배너 CTA 2곳이 됨(408 결정 1 "유일 진입점"의 완화, 사용자 승인)**, ③ 추정 7건 전부 기본값 승인.

## 기획 요약

설정 > 알림 설정 화면(설정 상세 셸)을 신설하고 카테고리 5종(BADGE·HOTZONE·REMIND·VIDEO·WEEKLY) 수신 토글을 알림 preferences API 2종에 실연동한다. `GET /api/notifications/preferences`는 기본 전부 on(off 행 부재 = true), `PATCH /api/notifications/preferences/{category} {enabled}`는 멱등이고 응답이 변경 후 전체 상태라 캐시를 직접 갱신한다(낙관적 업데이트 안전 — 티켓 명시). 브라우저 알림 권한이 꺼져 있으면 상단 안내 배너를 표시한다. 디자인은 Figma ver 13 프레임 `14783:3344`(설정 상세 패널 388px — 헤더 "‹ 알림 설정" + 권한 배너 + 그룹 2개 5행 + 각주).

MSG-408(develop 머지 완료)과의 경계: FCM 토큰 등록/해제·프로필 "알림 받기" 토글·PushNoticeHost는 408의 완성물이며 **다시 만들지 않는다**. 이 티켓은 그 위에 서버측 카테고리 preferences 화면을 얹는다 — 권한 배너의 CTA만 408의 `use-push-toggle` ON 플로우를 재사용한다.

## 카테고리 ↔ 시안 매핑 (정본 — 구현·검증 공용)

UI 순서 = 시안 순서. 서버 enum은 `CategoryPreferenceDto.category` 5종 고정.

| 그룹 | 순서 | category | 라벨 | 설명 |
|---|---|---|---|---|
| 활동 알림 | 1 | `VIDEO` | 내 격자에 새 영상 | 내가 점령한 격자에 새 영상이 올라오면 |
| 활동 알림 | 2 | `BADGE` | 뱃지 획득 | 새로운 뱃지를 얻으면 |
| 활동 알림 | 3 | `REMIND` | 스트릭 리마인더 | 오늘 기록이 없으면 저녁에 한 번 |
| 소식 | 4 | `HOTZONE` | 지역 축제 · 팝업 | 내 활동 지역에 이벤트가 열리면 |
| 소식 | 5 | `WEEKLY` | 주간 리포트 | 한 주의 수집 활동 요약을 주 1회 |

※ WEEKLY 문구는 결정 1(v2)로 확정 — 시안의 "마케팅 · 혜택 정보 / 이벤트와 혜택 소식 받기"를 **기각**하고 서버 카테고리 의미(주간)에 맞춰 교정했다. 시안과 의도적으로 다른 지점(Figma 오탐 방지 등재).

## 추정 및 질문

미해결 질문 없음 (v1 질문 2건 모두 결정 반영). 잔여 추정(전부 사용자 승인 완료 — 결정 3, 구현 세부 기본값):

1. **[추정] 상세 화면은 라우트 신설(`/profile/notifications`)** — 패널 내부 상태가 아니라 URL 정본(`/dex/:tab?` 선례: 새로고침·뒤로가기 보존, 사이드레일 재클릭 초기화와도 정합). 티켓은 진입 방식을 명시하지 않음
2. **[추정] 진입 행 = 프로필 설정 섹션 "알림 설정" 활성 행 신설, "알림 받기" 토글 아래** — 시안에 프로필 목록 화면이 없어 진입 접점은 추정. MSG-408이 대체했던 구 "알림 설정" 준비 중 행의 부활 위치
3. **[추정] 배너 노출 정본 = 408 토글 표시 정본과 동일(`checked=false` — 권한 미허용 또는 미등록)** — 티켓 문구는 "권한 거부 시 안내"지만, 권한 granted여도 토큰 미등록이면 푸시가 안 오므로 배너 조건을 "수신 불가"로 정의. 배너 CTA는 use-push-toggle ON 플로우 재사용
4. **[추정] 미지원 브라우저 = 배너를 CTA 없는 안내로 대체, 카테고리 토글은 활성 유지** — preferences는 서버 설정이라 브라우저 푸시 지원과 독립
5. **[추정] 낙관적 업데이트 채택 + 행 단위 busy 가드** — 티켓 "멱등이라 낙관적 업데이트 안전" 명시를 채택하되, 같은 행 연타 중첩은 busy로 차단(응답 전체 상태 기록과 낙관 반영의 경합 최소화)
6. **[추정] PATCH 오류 안내는 push-notice-store 스택 재사용** — 신규 토스트 인프라 금지(PR #60 리뷰 3 스택 단일화 결정 계승), 문구는 구현 시 확정("설정 변경에 실패했어요" 수준)

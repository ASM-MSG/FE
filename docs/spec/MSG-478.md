# MSG-478: 웹 SEO 기본 적용 — 메타·OG 태그, robots.txt·sitemap.xml, 라우트별 title, 검색 콘솔 등록

## 기획 요약

Vite CSR 웹(apps/web)의 정적 셸(`index.html`)에 검색·공유 미리보기용 메타(title·description·OG·Twitter·canonical·theme-color·robots)를 넣고, `public/robots.txt`·`public/sitemap.xml`을 추가하며, 라우트별 `document.title`을 의존성 없는 훅으로 세우고, 셸의 시맨틱(h1 하나·main/nav 랜드마크)과 에러 화면 `noindex`를 정리한다. OG 이미지·문구는 티켓 코멘트(2026-08-25)에 준비돼 있다. SSR/프리렌더·JSON-LD·CWV·PWA는 제외 범위이고, Search Console·네이버 서치어드바이저 등록과 카카오 공유 미리보기 확인은 코드 밖 완료 조건이다.

정본: 티켓 원문 + 코멘트(`00_ticket.md`). 오케스트레이터 지시(의존성 추가 금지·`api:generate` 금지·검증 프로파일 명시)를 반영했다.

## 리스크

- **CSR 404가 HTTP 200으로 응답**: CloudFront SPA 폴백 구성이면 무매칭 경로도 `index.html`을 200으로 준다. 이 티켓의 `noindex` 메타 토글(E1)이 그 보완이지만, 봇이 JS를 실행해야 반영된다(Googlebot은 렌더함, 네이버는 보장 안 됨). robots `Disallow`가 1차 방어. 상태 코드 자체를 404로 만드는 것은 인프라·프리렌더 영역(제외 범위).
- **MSG-474(비로그인 지도 홈 개방) 병렬 진행**: 현재 코드 기준으로 sitemap·robots를 확정했다. 474는 홈의 데이터 게이트를 여는 티켓이라 **라우트 목록은 바뀌지 않으므로** 이 스펙의 B1·B2는 유효하다. 단 474가 `MapHomePage.tsx`를 수정하므로 D1(h1 삽입)과 같은 파일에서 충돌할 수 있다 — 변경을 `<aside>` 첫 줄 1행으로 최소화하고, 머지 순서가 뒤면 rebase 시 확인.
- **메타 태그는 정적 셸에만**: 모든 라우트가 같은 `og:url=https://fillmap.kr/`·canonical을 공유한다(CSR 제약, 티켓 전제). 라우트별 OG는 프리렌더 티켓 몫.
- **`SITE_TITLE` 이중 정의**: `index.html`(정적)과 `shared/document-title.ts`(런타임)에 같은 문자열이 두 번 존재한다 — C1의 fs 대조 테스트가 드리프트를 잡는다. 문구를 바꿀 때는 두 곳을 함께 고친다.
- **네이버 지도 키 출처**: Lighthouse·브라우저 검증은 `--strictPort --port 5173`으로 띄워야 지도 타일이 뜬다(메모리). `vite preview`(4173)는 지도 인증 실패가 콘솔 에러로 잡힐 수 있어 SEO 점수 실측은 5173 dev 서버를 기본으로, preview는 정적 파일 서빙 확인용.
- **Lighthouse 실행 수단**: 레포에 lighthouse 없음. DevTools 패널을 기본으로 하고, CLI가 필요하면 `npx lighthouse`(package.json 무변경)로만 — 의존성 추가 금지 준수.
- **STATUS.md 갱신 대상**: 완료 시 shared/ 섹션에 `document-title`·`use-document-title`·`document-meta` 한 줄, ui-web `SideRail` prop 확장 한 줄, 라우트 표에 "정적 SEO 파일(public/robots.txt·sitemap.xml)" 비고.
- **Figma 오탐 방지**: 없음 — 디자인 변경이 없는 티켓(Figma 링크 없음, Figma 분석 생략). 추가되는 h1은 sr-only라 시각 결과 불변이고, 에러 화면은 태그만 바뀐다(스크린샷 동일해야 정상).

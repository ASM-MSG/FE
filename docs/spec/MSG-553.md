# MSG-553: 관리자 행사 심사 상세 — 지도 영역 검토 · 승인(지도 노출) · 반려(항목 코드+사유)

## 기획 요약

심사 큐(MSG-552)에서 고른 신청 하나를 `/admin/review/:submissionId`에서 지도 위 영역으로 검토하고 승인·반려를 확정하는 화면. 위치 사각형들이 격자 위에 라벨과 함께 오버레이되고 노출 범위(exposure) 점선 사각형이 함께 보인다. 승인은 즉시 유저 지도 노출이라 확인 모달을 거쳐 `POST .../approve`, 반려는 항목 코드 1개 이상 + 사유 필수로 `POST .../reject`. 성공 시 심사 큐로 복귀하고 목록·카운트가 갱신된다. 제외: 심사 큐 목록(552), 승인 후 관리(554), 운영자 쪽 결과 표시(549).

## 코드베이스·API 대조 결과 (스펙의 전제 — 전부 2026-09-04 실측)

**API (generated 실측 — 재생성 금지)**
- **상세**: `getSubmission1`(GET /api/admin/event-submissions/{submissionId}) — 552가 이미 훅으로 감쌌다(`features/admin-review/api/use-submission-detail-query.ts` — 그대로 재사용). 응답에 title·organizerName·startsOn/endsOn·status·`locations[]`(order·zoneName·zoneCell·regionName — 전부 null 가능·`cellCount`·`areaRects[]`)·**`exposureRect`**·rejection·history가 있다.
- **exposureRect는 서버 제공이다(FE 파생 불요)** — "전 위치 셀 합집합의 경계 사각형 — 조회 시점 계산이고 저장하지 않는다"(DTO 주석). 티켓 특이사항의 "FE 파생인지 실측" 질문의 답. MSG-554의 exposureCenter 파생(cellCenterAt)과 같은 재료다.
- **승인**: `approve2`(POST .../approve) — **요청 본문이 없다**(`body?: never` 실측). `EventSubmissionApproveRequestDto`는 존재하지 않고 updatedAt 에코도 없다 — MSG-551의 낙관 잠금(requestedAt 에코) 선례와 달리 **에코 재료 자체가 없으며, 동시 처리 경합은 서버 409(13450)가 흡수**한다("동시 승인의 늦은 쪽은 409"). 응답 `EventSubmissionApproveResponseDto` = submissionId·approvalNo(APR-2026-XXXX)·status. 전이·이력·미션 등재가 한 트랜잭션(절반 반영 없음). 에러: 404(13430) 없음 · 409(13450) 심사 중 아님/동시 승인 늦은 쪽 · 409(13451) 종료일 경과 · **409(13452) 격자 겹침 — 서버 doc이 "다음 조작은 AREA 반려"라고 명시**(reject3 주석에서 실측).
- **반려**: `reject3`(POST .../reject) — body `EventSubmissionRejectRequestDto { reasonCodes: string[], reasonText: string }`. **코드는 PERIOD·AREA·IMAGE·INFO 4종만, 1개 이상, 중복 불가, 사유 본문 필수**(DTO·doc 주석). 메일 미발송(운영자가 콘솔에서 확인 — MSG-549 몫). 응답 200 data 없음(unknown). 에러: 404(13430) · 409(13450) 심사 중 아님 · 400(13454) 코드 위반(FE는 정적 4종 + 1개 이상 게이트라 방어 불요).
- 생성 뮤테이션 옵션 존재: `approve2Mutation`·`reject3Mutation`(@tanstack/react-query.gen). 큐 무효화 키는 `getSubmissionsQueryKey`·`getSubmission1QueryKey`(552·554 선례).

### 검토한 대안 (기각 이유)

- **라벨 캡슐 = Marker HTML 아이콘** ← 커스텀 `OverlayView`(레포 선례 없음, 좌표 투영 직접 처리) / 지도 밖 범례(스펙의 폴백일 뿐, 영역↔라벨 대응에 시선 이동 요구)를 기각. `MapCanvas`의 미션 이름표(MSG-395)가 검증한 경로이고 토큰 클래스가 지도 DOM에 그대로 먹는다. **브라우저에서 성공 — 폴백 미발동, AC 6은 채택안 기준 판정.**
- **preflight 훅 상태 2개 유지**(`authFailed` + `sdkStatus`) ← 단일 `status`로 접기를 기각: 인증 실패 뒤 늦게 resolve된 로드가 `failed`를 `ready`로 덮는 회귀가 생긴다(원본 두 캔버스가 상태를 갈라 둔 이유). 이식은 "복제 수준"이 계약.
- **`cornersBounds`를 `entities/cell`에 신설(가산)** ← 로컬 복제(3번째 복제)와 세 소비처 전부 이관(`features/search`·`features/map-home`+모바일 미러 수정 = 병렬 웨이브 경계 위반)을 기각.
- **exposure 폴리곤을 위치 사각형 앞에 선언**(아래에 깔림) ← 뒤에 선언하면 점선이 위치 채움 위를 덮어 경계 판독을 흐린다.
- **진입 fitBounds는 `fittedRef`로 1회(onInit)** ← 매 `onIdle` 재맞춤은 관리자의 패닝·줌을 되돌려 AC 7을 깬다.
- **반려 미충족 안내 = disabled + 상시 캡션** ← 클릭 시 토스트는 티켓 리터럴("있어야 활성화")과 어긋나고, disabled면 클릭 이벤트가 없어 안내 경로 자체가 없다.
- **위치 색은 `semantic.primary/accent/warning` 3색 modulo** ← Figma hex 정확 일치는 토큰 규칙 위반(hex 리터럴 금지), 스펙이 "정확 일치 비요구" 확정.

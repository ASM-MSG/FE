# MSG-411: 영상 삭제·공개 전환·신고 연동

## 기획 요약

내 영상 액션 3종을 실 API로 연동한다 — 삭제(`DELETE /api/videos/{videoId}`), 공개 범위 전환(`PATCH /api/videos/{videoId}/visibility`), 신고(`POST /api/videos/{videoId}/reports` — 기존 `submitReport` 목업을 실호출로 전환). 진입점은 영상 더보기(⋯) 메뉴이고, 삭제·공개 전환 성공 후 도감·격자 쿼리를 무효화한다. 중복 신고(developCode 11409)는 "이미 신고한 영상" 안내로 매핑하고, 신고 완료 문구에는 "즉시 내려가지 않음(관리자 승인 시 블라인드)"을 반영한다.

## 코드베이스 대조 결과 (스펙 전제)

- **티켓의 "진입점 CellMoreMenu" 전제와 코드 불일치**: `widgets/cell-detail`(CellDetailSheet·CellMoreMenu·ReportDialog)은 MSG-327/328에서 배선이 빠져 **현재 어느 라우트에서도 렌더되지 않는다** (소비처 grep 0건, DexPanel 주석으로 확인). 더보기 메뉴는 살아 있는 표면(도감 갤러리 카드 등)에 새로 부착해야 한다.
- 생성 SDK에 3종 모두 존재 (`shared/api/generated/sdk.gen.ts`): `delete_`(DELETE /api/videos/{videoId} — "격자의 내 영상이 모두 사라지면 점령 롤백"), `setVisibility`(PATCH — PUBLIC·PRIVATE·FRIENDS, 같은 값 재전환 멱등), `report`(POST — reason 5종 INAPPROPRIATE·PRIVACY·SPAM·COPYRIGHT·OTHER, detail은 OTHER만 필수, 재신고 409, 자기 영상 400, 없는/블라인드 영상 404).
- **목록 응답에는 visibility가 없다**: `CollectedVideo`(collections/videos)·`GridVideoResponseDto` 모두 visibility 미포함. 단건 `getPlayback` 응답(`VideoPlaybackResponseDto`)에만 visibility가 있다 → 메뉴의 현재값 ✓ 표시는 메뉴 오픈 시 `useVideoPlaybackQuery` 단건 조회로 확보한다.
- `GalleryVideoCard` 루트가 통째로 `<button>`(카드 클릭=미니 패널 재생) — 더보기 버튼을 중첩하면 invalid HTML이라 카드 구조 개편이 필요하다.
- 무효화 인프라: `features/upload/api/invalidate-grid-queries.ts`(점령·격자 상세·격자 영상 2종·격자 통계)가 이미 있고, 도감 쿼리는 전부 생성 queryOptions 기반이라 생성 키 함수로 정확 무효화 가능.
- 에러 계약: `shared/api/api-error.ts`의 `normalizeApiError`가 `developCode`(11409)를 노출한다.

## 추정 및 질문 (사용자 확인 필요)

5. **[추정] 같은 공개 범위 재선택은 미발사**: 서버는 멱등이지만 불필요 요청을 줄이기 위해 메뉴만 닫는다.

7. **[추정] 삭제 확인 카드의 공개 범위 문구**: 목록 응답에 visibility가 없어 playback 단건 조회 성공 시에만 "· 전체 공개"류 문구를 붙이고, 미확보 시 생략한다.

## 리스크

- **티켓-코드 모순**: 티켓이 진입점으로 지목한 CellMoreMenu(widgets/cell-detail)는 렌더되지 않는 죽은 배선 — 진입점 신규 부착이 실제 작업이다 (추정 1·2로 해소).
- **중복 신고 코드 이중 표기**: 생성 SDK 주석은 "재신고 409", 티켓은 developCode 11409 — status 409와 developCode 11409를 모두 같은 분기로 매핑해 어느 쪽이 와도 안내가 뜨게 한다.
- 자기 영상 신고는 서버 400 — mine 분기로 진입점 자체를 막지만, 방어적으로 400도 일반 에러 토스트로 수렴.
- `invalidateGridQueries` 재사용은 features/upload → features/video-actions 간 cross-feature import — 기존 코드베이스에 상당 사례가 없으면 키 목록을 video-actions 쪽에 복제하는 대안으로 전환(구현 시 판단, 결과를 작업 로그에 기록).
- 병렬 워크트리(MSG-408·410)와의 충돌 — 범위 밖 파일 목록을 구현·검증 단계에서 게이트로 사용.
- 검증 시 실삭제 금지(비가역) — 브라우저 검증은 메뉴·모달 오픈과 취소 경로까지만, DELETE·PATCH·POST 발사는 vitest stub-fetch 판정.

# MSG-423: [모바일] 지도 홈 시트 1열 전환·상단 칩 UI 개편 + 격자/영상 조회 연동

플랫폼: **apps/mobile (Expo / React Native)**. 에픽 MSG-291 하위.

## 기획 요약

모바일 지도 홈 바텀시트가 2열 미니카드 그리드인데, "영상 목록은 1열"이 정본으로 확정됐다(웹 좌측 패널과 동일). 상단 카테고리 칩도 웹 개편분(MSG-252/395)과 크기·라운드·그림자·선택 시 채움 규칙이 어긋나 있다. 동시에 시트·지도가 쓰는 목 데이터(`mock-grid-videos`·`mock-theme-data`의 점령 셀)를 MSG-419가 깔아둔 API 기반 위에서 실 서버 조회로 교체하고, 지도 이동/줌이 멈추면 현재 위치 기준으로 재조회한다. 실패 시 목 폴백은 금지이고 실패 상태 + 재시도를 노출한다.

### 실 API 연동 계약

> 웹과 **같은 생성 SDK·같은 쿼리키**를 쓴다. 모바일은 `apps/mobile/src/shared/api/query-options.ts`(생성 TanStack 옵션 barrel)와 `sdk.ts`(생성 타입 barrel)에서만 가져오고, **새 fetch·새 QueryClient를 만들지 않는다**(MSG-419 산출물 재사용). 봉투 언랩은 모바일 `shared/api/envelope.unwrapEnvelope`를 `select`로 조합한다.

| 용도 | 오퍼레이션 (생성 옵션 함수) | 파라미터 | 쿼리키 | 정책 |
|---|---|---|---|---|
| 지도 점령 격자 | `getOccupiedInViewportInfiniteOptions` (`GET /api/grids`) | `query: { swLat, swLng, neLat, neLng }` — **뷰포트 bbox** | 생성 옵션 기본(`getOccupiedInViewport` + query) | `useInfiniteQuery`, `initialPageParam: { query: viewport }`(빈 문자열 커서 400 회피 — 웹 실측), `getNextPageParam` 상한 5페이지, `mapQueryPolicy`(staleTime 5s + `keepPreviousData`) |
| 시트 헤더 동 이름 | `reverseGeocodeOptions` (`GET /api/regions/reverse-geocode`) | `query: { lat, lng }` — **지도 중심**, 500ms 디바운스 | 생성 옵션 기본 | `mapQueryPolicy` — 이동 중 직전 동 이름 유지(헤더 깜빡임 방지) |
| 시트 1열 카드 목록 | `getRegionGridsOptions` (`GET /api/regions/{regionCode}/grids`) | `path: { regionCode }`, `query: { sort: "LATEST", limit: 20 }` | 생성 옵션 기본 | `entityQueryPolicy`(staleTime 5s, `keepPreviousData` **없음** — 동이 바뀌면 이전 동 카드가 남으면 안 됨) |

- **뷰포트 파라미터 형태**: 플랫폼 중립 `Bounds { sw: LatLng, ne: LatLng }` → `viewportQueryArgs(bounds)` → `{ query: GridsRequest, enabled }`. `bounds === null`(지도 준비 전)이거나 한 변 span > 0.5도면 `enabled: false`
- **갱신 시점**: `GridMap`의 `onCameraChanged`(sw/ne + zoom 이미 계산됨)를 신규 `onViewportChange` prop으로 부모에 올리고, **500ms 디바운스**로 "이동 종료"를 판정한다. 라이브러리에 `onCameraIdle` 계열이 있으면 그것을 우선 쓰고 디바운스는 백업으로 둔다
- **인증 게이트**: 세 쿼리 모두 보호 API(웹에서 익명 401 실측)라 `features/auth/model/auth-store`의 `isAuthenticated`가 false면 발사하지 않는다. 비로그인 시 시트 문구는 **추정 3** 참조
- **상태 판정 규칙** (요구 6·7 — 목 폴백 절대 금지):
  - `error` = 세 쿼리 중 하나라도 `isError` → 실패 문구 + 재시도(세 쿼리 동시 `refetch`)
  - `loading` = 실패 없음 ∧ 하나라도 미도착 → 로딩 상태
  - `empty` = 전건 도착 ∧ 카드 0건 → 빈 문구
  - `list` = 전건 도착 ∧ 카드 ≥1건
  - 우선순위 **error > loading > empty > list**. 실패 분기에 목 데이터 경로가 존재하지 않는 것을 L7이 고정한다

### `map-home-screen.tsx` 구조 설계 (MSG-427·MSG-428 인계)

이 티켓이 이 파일을 소유하므로, 후속 두 티켓이 **다른 줄을 만지도록** 층을 분리한다.

```
MapHomeScreen
├─ [상태] viewport(useState) ─────────── 확장점 ①
│    GridMap.onViewportChange → 디바운스 → { center, zoom, bounds }
├─ [조회] useOccupiedGridsQuery(bounds)
│         useReverseGeocodeQuery(center)
│         useRegionGridsQuery(region?.regionCode)
├─ [지도] <GridMap
│           occupiedCells={실 API 파생}          ← 상시 점령 층
│           themeCells / hatchCells / route      ← 확장점 ② (MSG-427)
│           clusters={…}                          ← 확장점 ③ (MSG-428, prop 신설 자리)
│           onViewportChange={…} />
├─ [상단] <SearchBar/> <Avatar/>
│         <ThemeChipsBar selected onToggle />     ← 확장점 ② 선택 상태만 소유
├─ [내 위치] bottom={locateBottomOffset(stage,…)} ← 확장점 ① stage 구독
└─ [시트] <HomeSheet onStageChange>
            {themeId ? <ThemeSheetContent/>       ← 확장점 ② (MSG-427이 이 한 줄만 교체)
                     : <DefaultSheetContent/>}
```

인계 규약(스펙에 명문화해 후속 티켓이 인용):
- **확장점 ①** — 뷰포트·줌은 화면이 단일 소유하고 아래로 내려준다. MSG-428 클러스터는 같은 `viewport.zoom`을 구독하고 새 상태를 만들지 않는다
- **확장점 ②** — 테마 관련 상태는 `theme-selection.ts`(모듈 싱글턴) 하나뿐이고, 화면은 `themeId`를 읽어 **시트 콘텐츠 스위치 한 줄**과 **지도 테마 prop 3개**만 분기한다. MSG-427은 `ThemeSheetContent`와 그 model만 갈아끼운다
- **확장점 ③** — `GridMap`의 오버레이 prop을 층별로 유지(`occupiedCells` / `themeCells`·`hatchCells`·`route` / 신설 `clusters`). 층을 섞지 않는다
- 조회 훅은 전부 `features/map-home/api/`에 있고 화면은 훅 호출만 한다 — 화면에 `useQuery` 직접 호출을 두지 않는다

## 추정 및 질문 (원본 — 위 표로 종결됨)

**Q1 (최우선) — 시트 1열 카드의 데이터 계약이 "격자 카드"인가 "영상 카드"인가?**
티켓 요구 1은 "**영상**이 한 줄에 하나씩"이라고 쓰는데, Figma 정본(14799:25653)의 카드 메타 2줄은 `서면 A-14` / `138개 영상` = **격자** 카드이고 이는 웹 좌측 패널 `RegionGridCard`와 정확히 일치합니다. 헤더도 행정동 이름이라 행정동 기준 조회를 가리킵니다.
- **A안(권장·본 스펙의 기준)** — 웹 좌측 패널 미러: `reverse-geocode`(동) + `regions/{regionCode}/grids?sort=LATEST&limit=20`(카드). Figma·웹 정본과 100% 일치. 대신 포팅 대상 `grid-videos`에 이번 티켓 소비처가 없어집니다(포팅 보류 또는 소비처 없는 선포팅 중 택일 필요)
- **B안** — 뷰포트 점령 격자의 gridId들로 `grids/{gridId}/videos`를 조합(웹 `use-multi-grid-videos-query` 미러)해 **영상** 카드 목록. 요구 1의 문구에 더 충실하지만 카드 메타가 `@닉네임 · 3일 전`이 되어 **Figma와 어긋납니다**

**Q2 — 지도 위 점령 격자 렌더를 어디까지 하나?**
모바일 격자 체계는 아직 구 위경도 스텝(`GRID_LAT_STEP 0.0009`)이고 서버·웹은 **EPSG:5179 100m**입니다. 두 체계는 원점·회전이 달라 서버 점령 격자를 그대로 그리면 모바일 격자선과 어긋나 보입니다.
- **A안(권장)** — `proj4`를 추가하고 5179 디코드 3종만 옮겨, 서버 gridId를 **5179 셀 중심 → 모바일 격자 인덱스**로 정규화해 기존 격자선에 정렬시킵니다. 오차: 셀 크기 차(100m vs 약 103m)로 드물게 인접 셀로 스냅될 수 있는 **표시 근사**
- **B안** — 모바일 격자를 이번에 5179로 전면 이관(`{col,row}`→`{gridX,gridY}`, `bounds`→`corners`, 격자선·탭·라우트 id 파급). 정확하지만 티켓 규모가 배 이상이 되고 [제외 범위]의 "격자 상세 기존 유지"와 충돌 소지
- **C안** — 점령 격자는 조회만 하고 지도 렌더는 후속 티켓. 요구 5가 부분 충족에 그침

**Q3 — 시트의 정렬 칩(인기순/최신순)을 없애도 되나?** Figma 정본에 없고 서버 정렬은 `sort=LATEST` 고정입니다. 없앤다는 전제로 `sort-grid-videos.ts`를 삭제 계획에 넣었습니다.

**Q4 — 뷰포트를 전역 스토어로 둘까요?** 모바일에 `zustand`가 없고 지도-화면이 부모-자식 직결이라 화면 로컬 `useState`로 충분하다고 봤습니다(포팅 대상 `viewport-store`는 타입만 이관). 후속 티켓의 편의를 위해 `zustand`를 도입할지 판단이 필요합니다.

**Q5 — 칩 선택 시 해제 수단.** Figma v2(14851:390)에서는 칩 행이 유지되고 해제 X가 **시트 헤더**에 있는데, 시트 헤더의 테마 상세는 [제외 범위](MSG-427)입니다. 이번 티켓은 **선택된 칩 재탭 = 해제**(웹 `toggle` 미러, L10)만 두고 헤더 X는 MSG-427에 넘기려 합니다.

### PR #72 리뷰 반영 (2026-08-19)

**게이트 미판정 상태가 빈 상태로 새던 결함.** `gatedQueryStatus`가 "조회하지 않기로 확정"과 "아직 모른다"를 구분하지 못하고 둘 다 도착으로 접어, 카드 0건이 `empty`("이 지역에는 아직 영상이 없어요")로 표시됐다. 무한 로딩을 막으려던 장치가 정반대의 틀린 상태를 노출한 셈이다.

미판정 경로는 둘이다. **경로 ①(리뷰 지적)** 보안 저장소 재수화 전 — `isAuthenticated`는 부팅 직후 무조건 false이고 그 갭을 메우라고 `hydrated`가 따로 있는데(`auth-store` JSDoc: "false면 '아직 모른다'"), 이를 보지 않아 로그인된 사용자의 콜드 진입에서 `empty` → `loading` → `list`가 깜빡였다. **경로 ②(리뷰에 없던 것)** 지도 뷰포트 미확정 — `map-home-screen`의 `viewport`가 `useState<Viewport | null>(null)`이라 **첫 프레임에는 세 게이트가 전부 닫히고**, 인증과 무관하게 매 콜드 스타트가 `empty`가 된다. 리뷰가 제안한 `settled = hydrated`만으로는 ②가 잡히지 않는다 — 재수화가 지도 씨딩보다 먼저 끝나면 `hydrated=true`인데 `viewport`는 여전히 null이라 다시 `empty`로 떨어지는 경합이 남는다.

수정은 `gatedQueryStatus(query, active, settled)`의 3번째 인자를 **필수**로 두고 `isResolved: (!active && settled) || data !== undefined`로 바꾸는 것이다. 훅별 `settled`는 occupied가 `hydrated && bounds !== null`, geocode가 `hydrated && debounced !== null`, region-grids가 `hydrated`다(마지막 훅에 뷰포트 축이 없는 이유는 역지오코딩 미도착이면 그 훅 자신이 미도착이라 시트가 이미 로딩이고, 도착 후에도 null이면 행정동 밖이 확정돼 `empty`가 옳기 때문이다).

회귀 테스트는 "세 쿼리가 전부 미판정이고 카드 0건이면 `empty`가 아니라 `loading`"을 직접 단정한다 — 수정 전 실패 메시지는 `expected 'empty' to be 'loading'`으로, 경로 ②를 정확히 잡았다. 테스트 291 → **295**.

**남은 관찰(범위 밖)** — 웹 `gatedQueryStatus`는 여전히 2인자다. 웹 auth 스토어는 동기(localStorage)라 경로 ①은 성립하지 않지만, 경로 ②에 대응하는 웹 쪽 미판정 창이 있는지는 확인하지 않았다.

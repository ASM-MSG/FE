# MSG-422: [모바일] 회원가입 약관 동의 게이트 — 카카오 로그인 직후 동의 저장

> v2 (2026-08-18) — **사용자 승인 완료.** Q1·Q2는 아래 승인 결과대로 확정, Q3·Q4 및 추정 5~9는 스펙 추정대로 승인.
>
> **승인 결과**
> - **Q1 확정**: 위치기반 동의 1건만 `PUT /api/users/me/location-consent {consented:true}`로 저장하고, 만14세·서비스 이용약관·개인정보·마케팅은 클라이언트 게이트 조건으로만 강제한다. "필수 동의 3종의 이력이 서버에 남지 않는다"는 법적 리스크(리스크 1)를 수용하며, 동의 항목·시각·버전 저장 API를 **BE에 환류**한다(Phase 4 지라 코멘트).
> - **Q2 확정**: 하단 캡션("선택 항목 동의는 나중에 프로필 편집에서 바꿀 수 있어요.")을 **렌더하지 않는다**. Figma 대조 시 의도된 차이로 기록하고 검증에서 결함으로 판정하지 않는다.
> - **Q3 확정**: `isForwardNavigation`은 포팅하지 않는다. parity 대상은 `shouldShowConsentGate` 하나.
> - **Q4 확정**: 포팅 함수는 `apps/mobile/src/features/auth/model/consent-gate.ts`에 둔다.

## 기획 요약

카카오 동의 화면은 "카카오가 필맵에 정보를 제공해도 되는가"까지만 다루므로, 서비스 이용약관·개인정보 수집·위치기반서비스 이용약관·만 14세 이상 확인은 사업자가 직접 받아야 한다(위치기반서비스 약관은 위치정보법상 필수 별도 동의). 로그인 성공 후 서버가 미동의로 응답하면 앱 대신 **전면 약관 동의 화면**을 띄워 미동의 사용자를 차단하고, 필수 4개 동의 후 회원가입 CTA로 동의를 서버에 저장한 뒤 앱으로 진입시킨다. 뒤로가기는 로그인 중단(로그아웃)이고, 로딩·조회 실패 중에는 게이트를 띄우지 않는다(앱 전체 잠김 방지). 웹 MSG-407 위치정보 동의 게이트의 판정 로직을 RN으로 포팅해 동등성을 유지한다.

## 구현 계획

- **브랜치**: 현재 브랜치 **`feat/mobile-signup-terms-consent-gate`** 그대로 사용 (사용자 생성 브랜치가 정본 — 원격에 MSG-422 이름 브랜치 없음 확인). target `develop`.

### 재사용 (신규 작성 금지)

- **`@fillmap/ui-native`** (index.ts 무수정, 전부 기존 export):
  - `Checkbox` — circle(모두 동의) / glyph(항목 5행). `label` 또는 `accessibilityLabel` 중 하나가 타입상 필수
  - `Button` — CTA. `variant="primary"` `size="lg"` `disabled` 지원(비활성 시 `bg-background` + `text-foreground-muted`), `className="w-full"`
  - `AppHeader` — h48 + `onBack` 시 좌측 `ChevronLeft`("뒤로 가기" a11y 라벨) + 중앙 타이틀. Figma 헤더와 1:1
- **`apps/mobile/src/shared/api`** (MSG-419 — 새 fetch·새 QueryProvider 금지):
  - `sdk.ts` / `query-options.ts` barrel에서만 생성물 import (`getMeOptions`·`getMeQueryKey`·`updateLocationConsentMutation`·`logout`)
  - `envelope.ts`의 `unwrapEnvelope`를 `select`에 조합 (api-smoke 선례)
  - `query-provider.tsx`는 이미 `_layout.tsx` 최상위에 마운트됨 — 재마운트하지 않는다
  - `api-error.ts`의 `ApiError`로 오류 문구 파생
- **`apps/mobile/src/features/auth/model`** (MSG-419): `useAuth()`(→`isAuthenticated`·`hydrated`), `authStore.logout()`, `configure-auth` 파이프라인(Authorization·`X-Device-Id` 헤더 자동 주입 — 로그아웃 훅에서 헤더를 손으로 넣지 않는다)

## 리스크

1. **[법무] 필수 동의 3종의 이력이 서버에 남지 않는다** — 만 14세 이상 확인·서비스 이용약관·개인정보 수집 동의는 저장 API가 없어 앱을 지우고 재설치하면 동의 사실이 사라지고, 분쟁 시 동의 증빙이 불가능하다. 위치기반서비스 동의만 서버에 기록된다. **BE 환류 필요**(동의 항목·시각·버전 저장 API). 이 티켓은 FE 화면·게이트까지만 해결한다.
2. **[검증 경로] 모바일 카카오 로그인이 아직 스텁이다** — `apps/mobile/src/features/auth/model/kakao-login.ts`의 `startKakaoLogin()`은 `__DEV__` 로그만 찍는 no-op이고, 실제로 토큰을 얻는 유일한 경로는 `/dev/api-smoke`의 `useDevSocialLogin()`(`POST /api/auth/dev/social-login`)이다. 따라서 "카카오 로그인 직후"라는 티켓 문구의 트리거는 이 티켓에서 실물로 재현할 수 없다. **완화**: 게이트 조건을 "카카오 콜백"이 아니라 "인증 상태 + getMe"로 잡았으므로 어느 로그인 경로로 토큰이 들어와도 동일하게 동작한다. 검증은 dev social-login으로 수행하고, 카카오 실연동 티켓에서 자동으로 이어진다.
3. **[스플래시 잠김] 게이트가 `Stack`을 대체하면 `app/index.tsx`가 마운트되지 않는다** — `index.tsx`는 모듈 스코프에서 `SplashScreen.preventAutoHideAsync()`를 호출하고 `hideAsync()`는 컴포넌트 effect에서만 호출한다. 게이트가 `Stack`을 통째로 대체하면 스플래시가 영구히 걷히지 않아 게이트가 아예 안 보이는 사고가 난다. AC 6으로 명시했고, 게이트 화면 마운트 시 `hideAsync()`를 직접 호출해 막는다.
4. **[테스트 공백] 모바일에 RN 렌더 테스트 인프라가 없다** — 체크 상호작용·CTA 활성·요청 발사·뒤로가기 로그아웃은 vitest로 단정할 수 없고 시뮬레이터 육안 확인이 전부다. **완화**: 상태 파생을 전부 순수 함수(`signup-consent.ts`)로 빼서 AC 13~17을 vitest로 덮고, 화면은 그 함수를 호출하는 얇은 층으로 유지한다. 인프라 도입은 이 티켓 범위 밖(MSG-292 확정 4 유지).
5. **[동시 편집] `app/_layout.tsx`를 수정한다** — MSG-419가 소유했던 파일이고 MSG-420은 병렬 충돌 회피로 손대지 않았다. 두 티켓 모두 develop 머지 완료라 지금은 충돌이 없지만, 병렬 웨이브로 다른 모바일 티켓이 동시에 돌면 이 파일이 충돌 지점이다.
6. **[게이트 정본의 의미 축소] 게이트 해제 판정이 `locationConsent` 하나에 걸린다** — 위치 동의만 true가 되면 나머지 3개 필수 동의를 실제로 받았는지와 무관하게 게이트가 열린다(서버가 구분하지 못하므로). 웹에서 이미 `locationConsent=true`가 된 계정은 앱에서 이 화면을 한 번도 보지 않는다.

### Figma 오탐 방지 (검증에서 결함으로 판정하지 말 것)

- **하단 캡션 미렌더** — "선택 항목 동의는 나중에 프로필 편집에서 바꿀 수 있어요."는 Q2 추정에 따라 렌더하지 않는다(인앱 변경 수단 부재로 거짓 문구). 승인 결과에 따라 확정.

- **미체크 원형이 아웃라인(흰 배경 + `hairline-strong` 테두리)이다** — Figma 미동의 프레임은 회색 필에 가깝게 보이지만, MSG-420 검증 환류에서 회색 필 + 흰 체크가 대비 1.4:1로 판독 불가라 아웃라인형으로 정정된 결정을 그대로 승계한다.
- **체크박스 터치 영역이 시각 크기(26px/20px)보다 크다** — `hitSlop=12`로 44px 이상 확보(WCAG 2.5.8). 디자인 박스와 히트 영역 불일치는 의도.
- **"보기"가 라우트 이동이 아니라 게이트 내부 전면 뷰다** — 게이트가 네비게이터를 대체하는 구조라 라우트 이동이 불가능하고, 가능하더라도 잠금이 새는 경로가 된다.
- **로그아웃 보조 버튼을 추가하지 않는다** — 웹 MSG-407은 이탈 수단이 없어 텍스트 버튼을 디자인 외로 추가했지만, 모바일 Figma에는 헤더 `‹`가 이미 있고 하드웨어 뒤로가기도 있어 불필요하다.
- **CTA 파랑(`#0066CC`)은 브랜드 색 불일치가 아니다** — design-tokens `semantic.primary`와 정확히 일치한다(`bg-primary` 그대로 사용).
- **화면 상단 여백을 Figma 픽셀로 고정하지 않는다** — `SafeAreaView` + 토큰 여백(`login-screen.tsx` 선례. Figma 수치는 상태바 포함값).

## 재작업 1회차 — P0: 로그인 직후 게이트 미표시

1회차 검증에서 **앱 실행 중 로그인이 성립해도 게이트가 뜨지 않는** 결함을 잡았다(18초 6프레임 md5 동일, 3회 재현). 콜드 스타트(첫 마운트에 이미 인증됨)는 정상이고 실행 중 false→true 전이만 죽어 있었다 — 티켓의 표제 시나리오가 정확히 후자라 **신규 가입자는 게이트를 한 번도 못 본다**.

**근본 원인은 게이트가 아니라 로그인 성공 핸들러의 `queryClient.clear()`였다.** `clear()`는 Query를 destroy·제거하는데, 구독 중이던 옵저버의 새 Query 재부착은 그 옵저버의 **다음 렌더**(`useBaseQuery`의 `observer.setOptions`)에서만 일어난다. `api-smoke`는 mutation pending이 풀리며 한 번 더 렌더돼 재부착됐지만, 루트의 `AppShell`은 인증 스토어 외 재렌더 트리거가 없어 조용히 취소된 `pending/fetching`에 영구 고정됐다. 계측 로그의 옵저버 카운트(`removed obs:2` → `added obs:0` → `observerAdded obs:1` → `success obs:1`)가 결정적 증거이고, 프록시에 찍힌 200도 게이트가 아니라 api-smoke의 쿼리였다.

수정은 `shared/api/reset-session-cache.ts`(`resetQueries()` — Query 객체를 유지해 옵저버가 떨어지지 않고 활성 옵저버를 재조회) 신설 후 로그인 경로 교체. **게이트 코드는 무수정**이라 AC 2(로딩·실패 시 게이트 미표시)의 진리표를 느슨하게 만들지 않았다. 로그아웃 경로의 `clear()`는 존치했다 — 거기서는 재조회가 곧 401이라 `clear()`가 옳다. 기각한 대안 4종은 `docs/decisions/DECISIONS.md` 해당 행 참조.

## 검토한 대안 (기각 이유)

- **동의 5종 전부 서버 저장** — 기각: OpenAPI 66 path 전수 조사 결과 위치기반 외 저장 엔드포인트·필드가 존재하지 않는다(`getMe` 응답의 동의 필드는 `locationConsent` 불리언 하나). 사용자 승인으로 위치 1건만 저장하고 나머지는 클라이언트 강제. **법무 리스크와 BE 요청은 지라 환류.**
- **게이트를 신규 라우트로** — 기각: 딥링크·`router.push`가 겨냥할 대상이 생겨 잠금이 샌다. `_layout.tsx` 조건 렌더로 `Stack` 자체를 대체하면 게이트 중 네비게이터가 아예 마운트되지 않는다(웹 MSG-407 선례). "보기" 전문 뷰도 같은 이유로 라우트가 아닌 게이트 내부 전면 뷰.
- **`isForwardNavigation` 포팅** — 기각: `window.history.state.idx` 전용 판별이라 RN에 대응 개념이 없고, 게이트가 네비게이터를 대체하는 구조에서는 "앞으로가기" 이벤트 자체가 없다. parity 대상을 `shouldShowConsentGate` 하나로 한정(사용자 승인).
- **하단 캡션 렌더** — 기각: 인앱 동의 철회·변경 수단이 실제로 없어(웹 MSG-407 결정 1) 거짓 안내가 된다. 미렌더(사용자 승인, Figma 대비 의도된 차이).
- **필수 항목 초기 체크됨(웹과 동일)** — 기각: Figma 미동의 프레임이 전부 미체크 + CTA 비활성이다. 정본을 따라 웹과 의도적으로 다르게 간다.
- **`hasTermsView: boolean`** — 기각: 라벨 정본 문구가 `AppHeader` 1줄에서 잘린다. `termsTitle: string | null`로 "보기 유무 + 전문 헤더 제목"을 한 필드에 담았다(AC 8 단정은 null 판정으로 유지).

## WAIVED · 확인불가 · 후속

- **약관 전문 콘텐츠 = "준비 중" 자리표시** — 기획/법무 몫(티켓 제외 범위). 문서 확정 시 `consent-terms-view.tsx` 본문만 교체하면 된다.
- **[P2 후속] "모두 동의" 행의 라벨 탭 무반응** — 원형 글리프만 눌린다(항목 5행은 라벨까지 탭됨). AC 위반이 아니고 실측 터치 영역이 약 63dp로 WCAG 2.5.8을 충족하며 a11y 노드도 이름·역할·상태를 전부 노출해 재작업 사유로 삼지 않았다. 행 간 일관성 관점의 개선 여지로 남긴다.
- **[BE 환류] 동의 이력 저장 API 부재** — 만 14세 확인·서비스 이용약관·개인정보 수집 동의는 저장할 곳이 없어 재설치 시 동의 사실이 사라지고 분쟁 시 증빙이 불가능하다. 동의 항목·시각·버전을 남기는 API 필요.
- **[MSG-419 영역] `api-smoke`의 "토큰 비우기"가 아직 `clear()`를 쓴다** — 실기 확인 결과 그 시점 게이트 옵저버는 `enabled:false`라 "활성 구독 중 파괴" 조건이 성립하지 않아 결함이 재현되지 않았다. 미수정.
- **[검증 환경] `/dev/api-smoke`로 콜드 스타트를 직행하면 스플래시가 안 걷힌다** — `index.tsx`가 마운트되지 않아서다. MSG-422 범위 밖이지만, 게이트 화면이 자체 `hideAsync()`를 부르는 AC 6의 존재 이유가 실증됐다.
- **[미해소 가능성] `expo-secure-store` 토큰 콜드 스타트 유실** — 1회차에서 관측됐으나 2회차 콜드 스타트 2회 모두 세션이 살아남아 미재현. 1회차 관측은 손상된 검증 프록시 구간이었을 가능성이 높다.

## codex 리뷰 (커밋 전 1회)

초점 4개 전부 PASS — ① 게이트 조건이 정확히 "인증됨 ∧ getMe 성공 ∧ `locationConsent===false`"이고 로딩·실패는 `isSuccess=false`라 게이트가 뜨지 않는다 ② 로그인은 `resetQueries()`로 활성 옵저버를 보존·재조회하고 로그아웃은 의도적으로 `clear()`를 유지한다(인증 쿼리 재조회 회피) ③ 두 뒤로가기 경로가 같은 콜백을 타고 그 콜백이 `logout()` 호출 전에 ref를 동기로 세워 중복 요청을 막는다 ④ 게이트가 루트 `Stack`을 대체하므로 라우트·딥링크·push·탭 어느 것도 마운트된 채로 남지 않는다.

**Medium 1건 반영** — 로그아웃 시 이전 사용자 캐시 노출 창. `authStore.logout()`은 상태 전이(토큰 null)를 동기로 끝내고 보안 저장소 정리만 await하는데, 그 await를 먼저 기다리면 비로그인 전환 후 `queryClient.clear()` 전까지 이전 사용자 데이터가 렌더될 수 있었다. `const cleared = authStore.logout(); queryClient.clear(); await cleared;`로 같은 tick에서 비우도록 순서를 고쳤다 — await는 유지해 저장소 정리 실패가 미처리 거부로 새지 않게 했다. 실행 순서만 바뀌고 수행 내용·네트워크 거동·1회 가드는 불변이며, 수정 후 자동 게이트 재실행 전부 그린(vitest 248·typecheck·oxlint 0건·oxfmt).

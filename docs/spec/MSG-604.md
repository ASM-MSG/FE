# MSG-604: [모바일] iOS 푸시 — Firebase Messaging으로 FCM 토큰 발급 (A안)

## 기획 요약
iOS에서 `expo-notifications`가 주는 APNs 원시 토큰 대신 Firebase Messaging의 FCM 등록 토큰을 서버에 등록한다. 서버·Android·토글/동기화 흐름은 무변경.

## 코드베이스 현황
- 토큰 접점은 `notifications-adapter.readDevicePushToken` 한 곳(MSG-429 격리 경계). `push-registration-flow`·훅·테스트는 어댑터를 주입받아 무변경.
- iOS 빌드 경로: MSG-601이 `expo run:ios`로 시뮬레이터 빌드 확립(Xcode 26.6, iPhone 17 Pro). `ios/`는 gitignore(prebuild 산출물).
- `expo-build-properties`는 이미 플러그인 등록(Android maven). `google-services.json`은 커밋돼 있어 plist도 같은 취급.

## 리스크
- R1 `expo-notifications`와 RNFirebase messaging이 iOS에서 둘 다 원격 알림 등록·델리게이트를 잡는다. 충돌 시 FCM `getToken`이 "No APNS token" 오류 → 실측으로 확인, 필요하면 `messaging().setAPNSToken` 또는 expo 핸들러 조정.
- R2 정적 프레임워크 전환이 다른 pod(네이버 지도·카카오)와 충돌할 수 있다 → 빌드로 확인.
- R3 Android prebuild에 google-services gradle 플러그인이 중복 적용될 수 있다(expo-notifications도 적용) → 빌드로 확인.

## 작업 로그
- **의존성**: `@react-native-firebase/app`·`messaging` 26.4.0. RNFirebase 26의 SPM 기본 경로는 정적 링크와 공존 불가(pod install 거부) → `ios.disableSPM` + `expo-build-properties ios.useFrameworks: "static"`.
- **토큰 경로**: iOS는 expo-notifications가 받은 APNs 토큰을 `setAPNSToken`으로 Firebase에 넘긴 뒤 `getToken`. RNFirebase의 `registerDeviceForRemoteMessages`는 expo AppDelegate 구독자와 공존 시 콜백을 못 받아 타임아웃(실측). Android 경로 무변경.
- **Info.plist**: `UIBackgroundModes: remote-notification`을 `ios.infoPlist`로 직접 추가(플러그인 미주입).
- **검증**: 시뮬레이터(Apple Silicon)에서 APNs 등록·FCM 토큰(142자) 발급·서버 등록·재등록·포그라운드 배너까지 확인. FCM 경유 수신은 실기기 없어 확인불가 — 토큰을 워크스페이스에 남겨 Firebase 콘솔 테스트 권장.
- **검토한 대안**: ① 동적 프레임워크(`useFrameworks: dynamic`) — 네이버 지도·카카오 pod 호환 재검증 비용, 기각. ② RNFirebase만으로 권한·표시까지 대체 — 기존 expo-notifications 계층(권한 3상태·포그라운드 핸들러·테스트)이 크고 검증됨, 기각. ③ 서버 APNs 직접 발송(B안) — 사용자 기각.
- **진단 편의**: `enablePush`·어댑터 catch에 `__DEV__` 경고 추가(반환 계약 불변). 이번 결함 2건이 화면 문구만으로는 구분 불가능했다.

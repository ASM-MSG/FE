# MSG-535: [웹] 아카이브 위치 행 클릭 배선 — 읽기 전용 상세 본문

## 기획 요약

종료 행사 아카이브(`EventArchiveBody`)의 위치 행은 현재 표시 전용이라, 안내 문구("위치를 선택하면 당시 영상을 볼 수 있어요" — `EventArchiveBody.tsx:62`, MSG-519가 이미 실어 둔 약속)가 거짓이다. 행을 클릭 가능하게 배선하고(MSG-534 개요 카드 button화 패턴 준용), `event-room-mode.ts:29`의 아카이브 우선 반환을 풀어 위치 선택 시 **읽기 전용** 영상 목록/빈 상태 본문을 렌더한다. 진단은 MSG-534 스펙 단계에서 확정 — 원인 재조사 불필요, 이번 스펙의 몫은 **B안 vs C안 설계 결정**이다.

## 설계 결정: B안 채택 (코드 실측 비교)

두 안이 공통으로 갚아야 하는 것: ① `EventArchiveBody` 행 button화 + `selectLocation` 배선, ② 아카이브+위치 선택 시 본문 전환, ③ 업로드 CTA 2곳 억제, ④ 스모크. 차이는 ②·③의 구현 위치다.

| 축 | **B안 — mode 분기 + readOnly 관통** | **C안 — 아카이브 전용 본문 신설** |
|---|---|---|
| 구조 | `eventRoomMode`: 아카이브 status + 위치 선택 → videos/empty. `readOnly` 플래그를 BodySwitch → 헤더·빈 상태에 관통 | `event-room-mode` 무수정(archive 유지), `EventArchiveBody`가 내부에서 store `location`을 구독해 자체 위치 본문 렌더 |
| 프로덕션 diff (실측 추정) | **~50~70줄** (8파일 접촉, 전부 프롭 추가·분기 순서 교체 수준) | **~100~130줄** (신설 1파일 + EventArchiveBody 확장, 접촉 파일은 3~4개로 적음) |
| 클론 | 0 — 영상 리스트·"더 보기"·미니 패널 배선(`onVideoSelect`)·로딩/실패 게이트가 기존 한 곳(videos case·use-event-room-body) 그대로 | 3곳 신규 — 영상 카드 리스트+더 보기(~35줄), 위치 헤더(CTA 제거판 ~25줄), 빈 상태(~15줄). nose 중복 감사 baseline 등재 필요, MSG-518/520 후속 변경 시 이중 유지보수 |
| 활성 경로 리스크 | 헤더·빈 상태·BodySwitch에 프롭 추가 — 기본값 `false`로 활성 경로 렌더 무변경(기존 스모크 green이 증명, AC 9) | 0 접촉 — 회귀 리스크 최소 |
| MSG-519 AC 1·2 | 재해석 필요 (아래) + `event-room-mode.test.ts` 2개 테스트 교체 | 원문 유지 (mode는 계속 archive) |
| readOnly 누락 리스크 | 관통을 한 곳이라도 놓치면 아카이브에 업로드 CTA 노출 — 스모크 AC 5·6으로 커버 | 원천 없음 (활성 본문 미사용) |
| 제외 범위 정합 | 독립 | C안의 자연 명분("지난 회차 진입 UI와 묶기")이 티켓 제외 범위라 반쪽 채택이 됨 |

**권장: B안.** 결정적 축은 클론이다 — 영상 목록 본문은 MSG-518(더 보기)·MSG-520(미니 패널 배선)이 계속 손대는 자리라, C안은 그 진화를 두 벌로 만든다(MSG-517 검증에서 클론 8건이 이미 baseline 관리 대상이었고, "같은 꼴 3개↑면 재검토" 조건부 존치 상태). B안의 활성 경로 접촉은 전부 기본값 있는 프롭 추가라 기존 스모크(green 유지)로 회귀가 기계적으로 잡히고, diff도 더 작다. C안의 유일한 구조적 강점(AC 1·2 원문 보존)은 아래 재해석으로 해소된다.

### MSG-519 AC 1·2·7 정합 재해석 (티켓 [동작 요구] 2)

- **AC 1·2 "유령 영상 목록 방지"**: 유령의 실체는 "종료 행사에 **활성 행사용(업로드 가능) 본문**이 렌더되는 것"이다. MSG-519 시점엔 읽기 전용 위치 본문이 없었으므로 "위치 선택 무시"가 유일한 방어였다. 이번 티켓이 읽기 전용 본문을 만들면 위치 선택은 유령이 아니라 정당한 열람이 된다. **진입 보장은 유지**: 방 `open()`은 위치가 null이므로(다른 방 open 시 리셋 — `event-room-store.ts:66`) 아카이브 첫 화면은 여전히 개요다. `event-room-mode.test.ts`의 "위치 남아 있어도 archive" 2개 테스트(14·42행)는 "아카이브 + 위치 선택 → videos/empty(읽기 전용은 소비처 몫)"로 교체한다.
- **AC 7 "업로드 유도 0"**: 폐기가 아니라 **확장 적용** — 아카이브 개요뿐 아니라 아카이브 위치 상세에서도 CTA 2곳 미렌더(수용 기준 5·6). readOnly 관통이 그 구현이다.

## 추정 및 질문

1. **아카이브 빈 상태 문구 (추정 — 확인 요망)**: readOnly 빈 상태는 "이 위치에 남은 영상이 없어요" / 부문구 "행사 기간에 올라온 영상이 없었어요" + CTA 미렌더로 제안. Figma 정본 프레임이 없어 FE 문구 결정이다.
2. **영상 섹션 제목 유지 (추정)**: 활성과 같은 `eventLocationSectionTitle`("{위치명 앞토막} 현장 영상") 재사용 — "당시 영상" 별도 표기는 헤더 타이틀("지난 행사 기록")이 이미 맥락을 주므로 diff 최소화 우선.
3. **격자 안내 배너 유지 (추정)**: `use-event-overlay-publish`가 `room !== null`만 보므로 아카이브 방에서도 위치 오버레이가 지도에 게시된다(실측 — status 게이트 없음). 배너("이 위치의 행사 격자 N개")도 아카이브 위치 상세에 그대로 렌더.
4. **MSG-520 미니 패널 무변경 (추정)**: 아카이브 영상 카드 클릭 → 미니 패널(재생·도움돼요·댓글 입력 포함) 그대로 — MSG-519 안내 문구("영상과 댓글은 볼 수 있지만")와 정합. 종료 행사에 helpful/댓글 POST를 서버가 거부하는지는 미실측 — 거부 시 기존 에러 처리 경로로 수렴하고, 상호작용 억제는 후속 판단.
5. **status 전이 엣지 (추정)**: 같은 방 재open은 위치를 유지하므로(스토어 계약), 열람 중 상세 refetch로 LIVE→UPLOAD_GRACE 전이 시 개요가 아닌 **읽기 전용 위치 상세**로 착지할 수 있다. CTA가 즉시 사라지므로 유령 아님 — 허용.

# MSG-429: [모바일] AI 자동 블러 확인 + 블러 완료 푸시·인앱 알림

## 기획 요약

MSG-424가 블러를 업로드 위저드에서 떼어내 **서버 후처리**로 보내면서, 완료를 알리고 결과를 확인시키는 경로가 통째로 비었다. 업로드 완료 오버레이는 이미 "잠시 후 AI가 영상 블러 처리를 마치면 알림으로 알려드릴게요"라고 약속하는데(`upload-complete-view.tsx`, Figma 14824:493) **그 약속을 지키는 코드가 없다.** 동시에 MSG-302가 만든 `blur-screen.tsx`·`blur-preview.tsx`·`app/upload/blur.tsx`는 아무도 진입하지 않는 고아로 남아 있다.

이 티켓은 ① 그 고아 화면을 **알림 진입 확인 화면**으로 재배치하고(CTA만 위저드 전진 → 닫기로 교체, 내용은 존치), ② 블러 완료를 감지해 알리는 경로 — **인앱 알림(폴링 워처, 웹 MSG-329 미러)** 와 **기기 푸시(expo-notifications + FCM 토큰 등록, 웹 MSG-408 미러)** — 를 깐다.

## 선행 티켓 상태 판정 (티켓이 명시 요구한 확인)

티켓 [제외 범위]는 "푸시 수신 기반은 MSG-418 몫"이라고 적고 있으나 **그 전제는 성립하지 않는다.**

| 근거 | 내용 |
|------|------|
| MSG-418 실물 | 제목 "미션 장소 근처를 지나가면 촬영을 권하는 알림(앱 전용)", 상태 **해야 할 일**, 담당 **성민(BE)** |
| MSG-418 본문 | "알림이 **기기 로컬 생성**이면 서버 outbox/FCM 파이프라인을 **타지 않음**" · "프론트엔드 협의가 먼저인 **기획 성격의 티켓**" |
| MSG-419 [제외 범위] | "**FCM 푸시 토큰 등록은 블러 알림 티켓에서**" ← 이 티켓을 지목 |
| 코드 | `apps/mobile`에 `expo-notifications` 의존성·권한·토큰·수신 핸들러가 **전무**. `app.config.js:54` 주석의 MSG-418 귀속은 **오귀속** |

**판정**: MSG-418은 이 티켓의 선행이 아니며, 기다려도 푸시 기반이 오지 않는다. FCM 클라이언트 기반은 MSG-419가 이 티켓에 넘긴 몫이므로 **이 티켓이 흡수한다**(기준 11~15). 단 **실제 발송은 BE 몫**이라 실수신 E2E는 검증 범위 밖이다(리스크 R1, 웹 MSG-408이 같은 판정).

## 수용 기준

### A. 블러 확인 화면 재배치 (`/upload/blur`)

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| 1 | `/upload/blur?videoId={id}`로 진입하면 **업로드 플로우 스토어가 아니라 `getPlayback(videoId)` 응답**으로 프리뷰가 그려진다 — 재생 소스는 `playbackUrl`, 길이 뱃지는 `durationSec`. 알림 진입 시점에 로컬 플로우는 이미 초기화돼 있어(`settleUploadSuccess`의 `reset()`) 스토어 참조는 항상 빈 화면이 된다 | 화면+로직 | vitest(쿼리 옵션·파생) + 실기 |
| 2 | `videoId`가 없거나 숫자가 아니거나 조회에 실패하면 크래시·무한 스켈레톤 없이 안내 문구 + [확인]만 보인다 (딥링크·콜드 스타트 방어) | 로직 | vitest (파라미터 파싱 순수 함수) |
| 3 | 화면에 "영상 전체에 블러 적용됨" 배지와 다크 토스트("AI 자동 블러 완료" / "영상 전체에 블러 처리가 적용됐어요")가 보이고, **블러 개수는 화면 어디에도 표시되지 않는다** (MSG-302 정책 존치) | 화면 | 실기 + Figma 대조 |
| 4 | CTA 라벨이 **"확인"**이고(Figma 14799:26098), 누르면 화면을 닫아 이전 위치로 돌아간다. `/upload/preview`로 전진하지 않는다 | 화면+로직 | vitest(복귀 목적지 순수 함수) + 실기 |
| 5 | 스택이 비어 있는 진입(푸시 콜드 스타트)에서 [확인]·하드웨어 뒤로가기는 지도 홈(`/home`)으로 대체 복귀한다 — 빈 스택에서 `back()`만 부르면 아무 일도 일어나지 않아 사용자가 갇힌다 | 로직 | vitest |
| 6 | 블러 영역 추가·제거·조정 UI가 없다 | 화면 | 코드 감사 + 실기 |
| 7 | 업로드 위저드 전이(select→analyzing→highlight→preview)는 이 티켓 이후에도 `/upload/blur`를 거치지 않는다 (기존 `upload-wizard.parity.test.ts` 무회귀) | 로직 | vitest |

### B. 인앱 알림 — 폴링 워처 (웹 MSG-329 미러)

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| 8 | 업로드 확정 성공(`settleUploadSuccess`) 시 `videoId`와 시작 시각이 대기 목록에 기록되고, **앱을 완전히 종료했다 켜도 목록이 유지**된다(AsyncStorage). 손상된 저장값은 빈 목록으로 폴백한다 | 로직 | vitest |
| 9 | 대기 항목마다 30초 간격으로 `getPlayback`을 조회해 `READY`면 완료 통지, `FAILED`면 실패 통지, 15분 무전이면 지연 통지를 띄우고 **각각 대기 목록에서 제거**한다. 조회 실패(네트워크·5xx)는 전이가 아니며 다음 간격에 재조회한다 (`processing-poll.ts` 기존 포팅분 사용) | 로직 | vitest |
| 10 | 앱이 백그라운드 → 포그라운드로 복귀하면(`AppState` `active`) 대기 목록을 재수화하고 **즉시 1회 조회**한다 (웹 `visibilitychange` 대응) | 로직 | vitest |
| 11 | 인앱 통지는 **루트 상주**라 어느 화면에 있든 보인다. 완료 통지의 [확인하기]는 `/upload/blur?videoId=`로, 실패 통지의 [다시 업로드]는 `/upload`로 이동하고, [닫기]로 사라진다. 지연 통지에는 주 행동이 없다 | 화면 | 실기 |
| 12 | 실패 통지 문구가 **영상이 비공개 상태로 남는다**는 사실을 알린다 (티켓 동작 요구 8) | 화면 | 실기 + Figma 오탐 방지 |
| 13 | READY 전이 시 해당 격자 쿼리를 무효화한다 — 서버 READY 필터가 풀린 시점이라 확정 시점 무효화만으로는 격자 화면이 낡은 채로 남는다 (웹 `invalidateGridQueries` 선례, 모바일 동명 파일 기존분 재사용) | 로직 | vitest |

### C. 기기 푸시 — expo-notifications + FCM 토큰 (승인 조건부, Q1)

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| 14 | 프로필 "알림 받기" 토글 **ON** 시 OS 알림 권한을 요청하고, 허용되면 FCM 기기 토큰을 `POST /api/notifications/tokens {fcmToken, platform:"ANDROID"}`로 등록·보관한다. **OFF** 시 `DELETE /api/notifications/tokens`로 해제하고 보관을 비운다. MSG-426의 preferences 5종 일괄 PATCH 동작은 **그대로 유지**된다(추가이지 대체가 아니다) | 로직 | vitest |
| 15 | 권한이 거부(또는 dismiss)되면 토큰 등록이 일어나지 않고 토글은 OFF로 유지되며 설정 안내가 보인다. **이 상태에서도 인앱 통지(기준 9·11)는 그대로 동작한다** (티켓 동작 요구 7) | 로직+화면 | vitest + 실기 |
| 16 | 블러 완료 푸시를 탭하면 `/upload/blur?videoId=`로 진입한다. 앱 종료 상태에서 알림으로 실행된 경우(콜드 스타트)에도 같은 화면에 도달한다. payload에 `videoId`가 없으면 알림 탭은 홈 유지(무동작)로 안전 폴백한다 | 로직 | vitest(payload→라우트 파생 순수 함수) + 실기(발송 수단 확보 시) |
| 17 | 로그아웃 시 보관된 FCM 토큰을 함께 정리한다 — `/api/auth/logout` body에 `fcmToken` 동봉 + 로컬 보관 비움(성공·실패 무관). 보관 토큰이 없으면 기존과 동일하게 body 없이 호출한다 (웹 MSG-408 기준 9 미러) | 로직 | vitest (`use-logout` 기존 테스트 확장) |

**검증 프로파일**: **화면** — 화면 재배치(A)·통지 UI(B)가 시각 결과를 기준으로 하고 Figma 정본 노드(14799:26064)가 있다. 로직 기준이 다수 섞이지만 규칙대로 넓은 쪽으로 판정한다. 단 **푸시 실수신 E2E는 검증 범위에서 제외**한다(BE 발송 수단 필요 — R1).

## 리스크

- **R1 — 푸시 실수신 E2E 불가.** 블러 완료 FCM 발송은 BE 몫이고 이 워크트리에서 발송할 수단이 없다. 기준 16의 실기 판정은 "확인불가"가 될 가능성이 높다(웹 MSG-408이 같은 이유로 같은 판정). **인앱 통지(B)가 완료 확인의 보장 경로**이므로 푸시가 안 와도 기능은 성립한다 — 이것이 A+B를 C보다 먼저 두는 이유다.
- **R2 — 네이티브 재빌드 필요.** `expo-notifications`는 네이티브 모듈이라 `npx expo prebuild -p android` → `npx expo run:android`가 필수다. 티켓 [참고]가 이미 dev client 재빌드를 요구하고 있어 추가 비용은 아니지만, **빌드 실패 시 C 전체가 실기 미검증으로 남는다.**
- **R3 — MSG-426 토글의 의미 확장.** 한 스위치가 서버 preferences 5종 + OS 권한 + FCM 토큰 3가지를 동시에 좌우하게 된다(웹 MSG-408·409와 동일 구조). 부작용: 권한이 거부된 기기에서 preferences만 켜지는 부분 상태가 가능하다 — 표시 정본을 "권한 granted && 보관 토큰 존재"로 두고(웹 미러) preferences는 별도로 저장한다.
- **R4 — `getPlayback`은 조회수를 증가시킬 수 있다**(DTO 주석: "조회수(이번 조회 증가 전 스냅샷)"). 30초 폴링이 자기 영상의 조회수를 부풀릴 수 있다. 웹 MSG-329가 같은 API로 같은 폴링을 하고 있어 **웹과 동일한 기존 리스크**이며 이 티켓에서 새로 생기는 문제가 아니다 — 지라 환류 대상.
- **R5 — RN 렌더 테스트 인프라 없음**(`vitest.config` 정책). 통지 호스트·확인 화면의 렌더 회귀 안전망은 실기뿐이므로, **판정 로직을 전부 순수 모델로 빼서**(`processing-notice`·`blur-entry`·`push-route`) vitest가 잡게 한다 — MSG-424가 세운 방침 그대로.
- **R6 — `expo-notifications` import가 vitest를 죽일 수 있다.** MSG-426이 겪은 `expo-secure-store` 파싱 실패(`SyntaxError: Unexpected token 'typeof'`)와 동형이다. 그래서 어댑터(`api/notifications-adapter.ts`)를 격리 경계로 두고 모델·훅 옵션 팩토리는 그것을 주입받는다.
- **R7 — 대기 목록 무한 성장 방어.** 앱이 15분 만료 전에 종료되고 다시 안 열리면 항목이 남는다. `isPollExpired`가 재진입 시 즉시 만료 판정을 하므로 자기 정리되지만, 저장 항목 상한(예: 20건)을 두어 병적 성장은 막는다.

- **Figma 오탐 방지** (정본 `14799:26064` 대조 시 결함으로 판정하지 말 것):
  1. **중앙 재생 버튼** — Figma의 `video-preview`(14799:26071)에는 재생 버튼이 없다. 구현은 존치한다(추정 4).
  2. **프리뷰 비율** — Figma는 342×420(≈1:1.23), 구현은 `aspect-[4/5]`(1:1.25). MSG-302가 정한 값을 존치한다.
  3. **인앱 통지 UI에 대응 Figma 노드가 없다** — 모바일 정본에 블러 완료 통지 프레임이 없다(웹은 14798-5449). ui-native `Toast` + `Button` 조합으로 앱 관례를 따라 조립하며, 이는 디자인 누락이지 구현 편차가 아니다.
  4. **🔔 아이콘 미재현** — 업로드 완료 화면의 선례(MSG-424)를 그대로 승계한다.
  5. **하단 탭바 없음이 정상** — 확인 화면은 전체 화면이다.

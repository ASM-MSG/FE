# MSG-426: [모바일] 프로필·설정 개편 — 알림 받기 토글·계정 삭제·기본 이미지 되돌리기 + preferences API

에픽 MSG-291 하위 · 브랜치 `feat/mobile-profile-settings-revamp` (생성·체크아웃 완료) · target `develop`

## 기획 요약

모바일 `프로필/설정` 화면이 MSG-306 시절의 **카드형 행**(테두리+surface-soft) 구조로 남아 있어 Figma ver 6 개편분(플랫 행 리스트)과 어긋나고, 계정 삭제 진입점이 없다. "알림 설정 ›" 상세 이동 행을 **단일 토글**로 바꿔 서버 알림 설정(preferences)에 실연동하고, 계정 섹션에 빨간 `계정 삭제` 행 + 확인 모달 + `DELETE /api/users/me`를 붙이며, 로그아웃 버튼을 하단 전폭으로 바꾼다. `프로필 편집`에는 `기본 이미지로` 버튼(+ 안내 문구)을 추가해 `DELETE /api/users/me/profile-image`에 연결하고, 위치정보 사용 섹션은 제거한다(동의 관리는 설정 행으로 일원화).

지라 MCP 조회 성공 — 원문(`MSG-426`, 상태 "해야 할 일", 담당 최규호)과 `00_ticket.md` 대조 결과 **모순 없음**. 차이는 아래 리스크 R1에 병기.

## API 계약 (sdk.ts 생성분 실측)

모바일은 `apps/mobile/src/shared/api/sdk.ts`·`query-options.ts`가 웹 생성물을 그대로 재수출한다(MSG-419). **아래 4종 전부 생성돼 있어 신규 생성·직접 http-client 호출이 필요 없다.** 함수는 `shared/api/sdk`, mutation/query 옵션·키는 `shared/api/query-options`에서 가져온다.

### 1) 알림 설정 조회 — `GET /api/notifications/preferences`
```ts
// sdk.gen.ts:565 / react-query.gen.ts:836,843
getPreferences(options?): RequestResult<GetPreferencesResponses>
getPreferencesOptions() / getPreferencesQueryKey()
```
- 응답 `200: ApiResponseDtoNotificationPreferenceResponseDto` = `{ developCode, message, data: { preferences: CategoryPreferenceDto[] } }`
- `CategoryPreferenceDto = { category: 'BADGE'|'HOTZONE'|'REMIND'|'VIDEO'|'WEEKLY'; enabled: boolean }`
- 명세 주석: "off 행 부재면 true (opt-out 기본 전부 on)" → 누락 카테고리는 `true`로 병합

### 2) 알림 설정 저장 — `PATCH /api/notifications/preferences/{category}`
```ts
// sdk.gen.ts:429 (함수명은 제네릭한 `update`) / react-query.gen.ts:603 `updateMutation`
update(options: { path: { category: string }; body: { enabled: boolean } })
```
- `UpdateData = { body: NotificationPreferenceUpdateRequestDto; path: { category: string } }`
- `NotificationPreferenceUpdateRequestDto = { enabled: boolean }`
- 응답 `200`은 GET과 동일한 **전체 5종 상태** — 낙관 값 보존 병합(`recordServerPreferences` 상당)이 가능하다
- ⚠️ 함수명이 `update`로 극히 일반적이다. import 시 `import { update as updatePreference }` 별칭을 쓸 것

### 3) 회원 탈퇴 — `DELETE /api/users/me`
```ts
// sdk.gen.ts:455 / react-query.gen.ts:642 `deleteMeMutation`
deleteMe(options: { headers: { Authorization: string } })
```
- ⚠️ **`DeleteMeData`가 `headers.Authorization`을 필수로 요구한다**(명세가 명시 헤더 파라미터로 선언). 웹은 `deleteMeFn({ headers: { Authorization: "" } })`로 빈 값을 넘기고 실값은 인증 파이프라인 `beforeRequest`가 Bearer로 덮어쓴다 — 모바일 `auth-pipeline`도 동일하게 주입하므로 같은 우회를 그대로 쓴다
- 응답 `200: unknown` (본문 계약 없음)

### 4) 프로필 이미지 삭제 — `DELETE /api/users/me/profile-image`
```ts
// sdk.gen.ts:63 / react-query.gen.ts:105 `removeProfileImageMutation`
removeProfileImage(options?)   // 인자 없음
```
- 응답 `200: ApiResponseDtoUserProfileResponseDto` — 웹은 응답을 쓰지 않고 `getMeQueryKey()` invalidate로 갱신한다(동일 채택)

### 5) 프로필 조회 — `GET /api/users/me` (기준 12·13·15의 전제, 추정 E2 참조)
```ts
getMe(options?) / getMeOptions() / getMeQueryKey()
// 응답 data: UserProfileResponseDto (email·nickname·profileImageUrl·createdAt)
```

### 디자인 토큰
- **`#DC2626`은 `palette["red-600"]`로 이미 존재**(`packages/design-tokens/src/colors.ts:42`) → 클래스 **`text-red-600`**. 신규 토큰 등록 불필요.
  - 원문 JSDoc: "밝은 배경 위 error 텍스트용 진한 단계 — red-500(#EF4444)은 흰 배경 대비 3.76:1로 AA 미달, 텍스트 용도만 이 값(4.54:1)". **규약: 텍스트=`red-600`, 채움=`error`(red-500)**
  - `semantic`에 대응 별칭 없음 → 원시 토큰 직접 사용이 정당(규칙 2 예외, `ActionSheetItem danger` 선례 `packages/ui-native/src/action-sheet.tsx:110`)
  - 로그아웃 버튼은 **채움**이므로 `Button variant="danger"`(=`bg-error`) 그대로 — red-600으로 바꾸지 않는다
- 나머지 색·간격은 기존 시맨틱 토큰(`text-foreground`·`text-foreground-muted`·`bg-background`·`gap-*`·`px-5`)

## 추정 및 질문 (원본 — 위 결정으로 종결됨)

### E1. 기본 이미지 플레이스홀더 구현 방식 — **선택 필요**
Figma는 연회색 원 + 사람 실루엣을 보여주지만, ui-native `Avatar`는 `src?: string`(URI)와 `fallback?: string`(텍스트)만 받는다. 웹은 `entities/profile/assets/default-profile-image.png`를 `src`로 넘기는데, **모바일에는 그 에셋이 없고** RN `Image`는 번들 에셋을 `require()` 소스로 받아야 해 URI 문자열로는 못 넘긴다.
- **(a) 권장** — `packages/ui-native/src/avatar.tsx`에 optional `fallbackIcon?: ReactNode` 비파괴 추가, 호출부에서 `lucide-react-native`의 `User` 아이콘 주입. 미지정 시 렌더 불변이라 회귀 표면 0. MSG-421 선례가 있음
- (b) — features/profile 로컬 `DefaultAvatarIcon` 컴포넌트를 만들어 `Avatar` 대신 조건부 렌더 (ui-native 무수정, 대신 아바타 렌더 경로가 두 갈래)
- (c) — 웹 PNG를 `apps/mobile/src/entities/profile/assets/`로 복사 (에셋 중복 + Avatar가 URI만 받으므로 여전히 컴포넌트 수정 필요)

### E2. 프로필 실데이터 연동 범위 — **가장 큰 스코프 판단**
현재 모바일 프로필은 **전부 mock**(`MOCK_PROFILE` + `profile-store`)이라 `profileImageUrl`이 항상 `null`이다. 그러면 기준 15("올린 사진이 삭제되고")가 **실제로는 관찰 불가**하고, 기준 13의 이메일·가입일도 가짜 값이다. 티켓에 "프로필 조회 실연동"이라는 요구는 없다.
- **권장** — 최소 연동: `getMeOptions()` 기반 `use-profile-query`(웹 `useProfileQuery` + `toProfileData` 포팅)를 추가해 **닉네임·이메일·가입일·프로필이미지URL 4개만** 서버에서 받고, 스트릭·수집률·앱버전은 mock 유지(내 활동 API 연동은 범위 밖). `profile-store`는 폐기하고 닉네임 갱신은 `getMe` invalidate로 대체
- 대안 — mock 유지: 구현은 가볍지만 기준 12·13·15가 "코드는 있으나 실동작 미검증"으로 남고, 검증 단계에서 결함으로 오탐될 소지가 큼

### E3. 계정 삭제 후 캐시 정리 방식
웹은 `queryClient.clear()`를 쓴다. 모바일에는 MSG-422가 신설한 `resetSessionCache`(=`resetQueries()`)가 있지만, 그 파일 주석이 **"로그아웃 경로에는 쓰지 않는다 — 거기서는 재조회가 곧 401이므로 clear()가 맞다"**고 못박고 있다. 계정 삭제는 로그아웃과 같은 성격(세션 종료 + 즉시 라우팅)이므로 **`clear()` 채택을 권장**한다(기존 `useLogout`도 `clear()`). `reset-session-cache` 재사용 지시는 티켓의 선행 산출물 안내였으나, 위 주석과 충돌하므로 이쪽을 우선한다는 판단이다.
- 부수 항목: 웹은 `deviceIdStorage.clear()`도 한다. 모바일 `deviceId`는 `authStore` 상태의 일부이고 `authStore.logout()`이 보안 저장소를 정리하므로 별도 호출 불필요로 본다 (구현 시 `token-storage` 실제 정리 범위 확인 필요)

### Q1. 단일 토글 ↔ 5개 카테고리 매핑 규칙 — **명시적 결정 필요**
서버 preferences는 **카테고리 5종(BADGE·HOTZONE·REMIND·VIDEO·WEEKLY)뿐이고 "전체 수신" 단일 필드가 없다**. 티켓은 단일 토글을 요구하고 세분 설정을 제외 범위로 둔다. 제안:
- **표시**: 5종 중 **하나라도 `enabled`면 ON** (`some`)
- **끄기**: 5종 전부 `{enabled:false}` PATCH
- **켜기**: 5종 전부 `{enabled:true}` PATCH
- **원자성**: `Promise.all`로 병렬 발사, 하나라도 실패하면 스냅숏으로 **전체 롤백** + 실패 안내(기준 5). 단, 이때 서버에는 일부만 적용된 상태가 남을 수 있다(부분 성공) → 다음 진입 시 GET이 정본이므로 자동 수렴
- 대안: 표시를 `every`(전부 켜져야 ON)로 하면 부분 상태가 OFF로 보여 "껐는데 알림이 온다"는 반대 혼란이 생긴다
- 부작용 고지: 웹에서 카테고리별로 세밀하게 설정한 사용자가 앱에서 토글을 한 번 켜면 **5종이 전부 on으로 덮어써진다**. 수용 여부 확인 필요

### 실기가 잡은 결함 1건 (수정 완료)

**`프로필 편집`의 [취소]/[저장] 버튼이 보이지도, 눌리지도 않았다.** 화면 하단에 테두리 윗선 몇 px만 그려지고 본체가 클리핑됐으며, 접근성 트리가 보고한 좌표(y2186~2236)를 탭해도 반응이 없었다. 스크롤로도 닿지 않았다.

원인은 `ScrollView contentContainerClassName="grow"` 안의 자식이 `flex-1`이었던 것이다. `flex-1`은 `flexBasis: 0`이라 자식 높이가 **뷰포트로 고정**되고, 콘텐츠(아바타 + 버튼 2종 + 캡션 + 입력 + gap·padding)가 그보다 길어지자 `mt-auto` 버튼 행이 컨테이너 밖으로 밀려났다. 컨테이너 높이가 뷰포트와 같아 스크롤 범위도 0이라 스크롤로 복구되지도 않고, 클리핑된 영역이라 터치도 먹지 않는다.

`flex-1` → `grow`로 교체했다. `grow`는 `flexBasis: auto`라 높이가 `max(콘텐츠, 뷰포트)`가 되어, 짧으면 `mt-auto`가 하단 고정을 그대로 하고 길면 스크롤이 생긴다. 수정 후 두 버튼이 온전히 렌더되고 [취소] 탭이 `프로필/설정`으로 복귀함을 실기로 확인했다.

**교훈**: 자동 게이트·정적 Figma 대조·codex 리뷰 셋 다 이 결함을 잡지 못했다. RN 렌더 테스트가 없는 모바일에서 `mt-auto` + ScrollView 조합은 실기 아니면 검증되지 않는다.

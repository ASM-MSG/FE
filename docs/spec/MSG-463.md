# MSG-463: 전체 지역 목록 20개 페이지 계약 대응 + 비로그인에서 상단 칩 정보 노출

## 기획 요약

서버 계약 변경 두 건의 프론트 QA 반영. ① `GET /api/regions/explore`가 전량 배열 → 20개 커서 페이지(`RegionExplorePageResponseDto { items, hasNext, nextCursor }` + `cursor` 쿼리)로 바뀌었다 — develop에는 첫 20개만 꺼내는 임시 봉합(`select`에서 `.items`)이 들어가 있고, 이 티켓이 그것을 **무한 스크롤**로 확장한다(사용자 확인 완료). ② 상단 칩 4종(핫구역·지역축제·팝업스토어·경로추천) API가 MSG-454로 익명 조회를 허용했으므로 프론트의 `enabled: isAuthenticated` 게이트를 풀어 비로그인에게도 지도 오버레이·좌측 목록을 보여준다. 단 `use-mission-progress-query`(사용자별 값)는 로그인 전용 유지, 미션 상세의 진행도 칸은 비로그인 분기(로그인 유도)를 넣는다.

## 구현 계획

- **브랜치**: 현재 워크트리 브랜치 `feat/msg-463-regions-pagination-anon-access` **그대로 사용** (신규 생성 안 함 — 기존 브랜치가 정본, 오케스트레이터 확정). 머지 완료된 `feat/MSG-463-openapi-regen-baseline`(PR #87)은 건드리지 않는다

- **0단계 (구현 첫 작업, 딱 1회)**: 서버 명세 재생성 —
  `curl https://api.fillmap.kr/v3/api-docs -o apps/web/openapi/api-docs.json` 후 `pnpm openapi-ts`.
  기대 diff는 `progress`(미션 상세)·`currentRegion`(역지오코딩)이 nullable이 되는 2줄 — 이 티켓의 비로그인 progress 분기에 필요하다. diff가 기대를 크게 벗어나면 진행 전 보고. 재생성 직후 typecheck로 낙진 확인(`use-mission-detail-query`는 이미 `?? null` 처리라 무풍 예상, `use-reverse-geocode-query`는 null 대응 여부 확인).

## 리스크

- **병렬 티켓 충돌 (하드 제약)**: MSG-462/464 병렬 진행 중 — `MapCanvas.tsx`, `use-home-panel-state.ts`, 썸네일 렌더 4곳은 **절대 수정 금지**. 게이트 해제는 전부 훅 파일 내부 변경이라 저촉 없음(확인: `isAuthenticated` 게이트가 MapCanvas에 없음), 진행도 분기 배선은 `MapHomePage → HomePanelSwitch → 패널` props 경로만 쓴다.
- **명세 재생성의 부수 diff**: `pnpm openapi-ts` 재생성이 기대한 2줄(nullable) 외 서버 변경을 끌고 올 수 있다 — diff 확인 후 범위 밖 변경이 크면 사용자 보고 후 진행.
- **중복/누락(AC 3의 화면 판정)은 서버 커서 안정성에 의존** — FE는 이어붙임 무결성만 보장한다. 브라우저 검증에서 중복이 실측되면 서버 레인(MSG-460) 이슈로 보고하고 FE 중복 제거를 임의 추가하지 않는다.
- **비로그인 첫 화면의 확정 영역**: 칩 데이터의 bbox인 `committedBounds`는 비로그인에서도 `useCommittedRegionBootstrap`이 영역만 선확정(`commitBounds`)하므로 채워진다 — 확인 완료, 리스크 아님(브라우저 검증에서 재확인).
- **기존 게이트 테스트 반전 누락**: 훅마다 "비로그인 미발사" 단언 테스트가 있을 수 있다 — 게이트 해제 시 반전 갱신 필수(누락 시 vitest가 잡아준다).
- **Figma 오탐 방지**: Figma 분석 생략(디자인 변경이 티켓 제외 범위 + 신규 UI는 기존 컴포넌트 재사용 뿐) — 검증 단계에서 Figma 대조를 결함 사유로 쓰지 않는다. 진행도 칸의 로그인 유도 문구·하단 로딩/재시도 행은 Figma에 없는 이 티켓의 신규 상태다.

# MSG-421: [모바일] 온보딩 리뉴얼 — 3단 진행바·히어로 카드 구성으로 교체

## 기획 요약

MSG-292가 만든 기존 온보딩 3장(흰 배경 + 앱 스크린샷 축소 일러스트 PNG)은 내용이 뭉개져 읽히지 않는다는 팀 피드백을 받았다. 각 장이 **하나의 메시지만 크게 전달**하도록 구조를 교체한다 — 상단 3분할 진행바 + 헤드라인 2줄 + 설명 1줄 + 히어로 카드 + 하단 CTA. 1·2장 우상단에는 "건너뛰기"가 있고 누르면 온보딩을 끝내고 로그인으로 간다. API 연동은 없고 완료 여부만 기존 AsyncStorage 플래그로 남긴다. **신규가 아니라 교체 티켓**이다.

### 신규 (features/onboarding 내부)

- `model/onboarding-steps.ts` — **순수 모델(신규, test-first)**. 3장의 헤드라인/설명/CTA 라벨 데이터 + 파생 4종: `ctaLabelOf(index)`, `isSkipVisible(index)`, `progressOf(index) → {total, current}`, `nextActionOf(index) → number | "done"`. RN·라우터 import 없음(모바일 vitest는 순수 모델만 실행 — MSG-292 확정 4).
- `ui/onboarding-screen.tsx` — **전면 재작성**(파일 경로·export 이름 유지 → `app/index.tsx` import 경로 불변). 골격만 소유하고 히어로는 장별 컴포넌트에 위임. props: `onDone`(기존) + `onSkip`(신규).
- `ui/fill-hero-card.tsx` — 1장 히어로(미니맵 + 채운 셀 + 강조 셀 + "+1 격자" 배지 + meta 행 + 19% 원형).
- `ui/record-hero-card.tsx` — 2장 히어로(`VideoCard` 래핑 + AI 칩 + blur-note).
- `ui/explore-hero-card.tsx` — 3장 히어로(칩 행 + 테마 격자맵 + 미션 이름표 + 보상 행).
- `model/onboarding-steps.test.ts` — L1~L5 커버(테스트 템플릿: 로직/순수 함수형).

> **ui-native export 추가 없음** — 위 4개는 전부 온보딩 화면 전용 조합이라 `packages/ui-native/src/index.ts`를 건드리지 않는다(오케스트레이터 제약 3). 히어로 3종은 온보딩 연출 일러스트로 도메인 결합이 강해 승격 대상도 아니다. "+1 격자" 배지와 19% 원형은 각 히어로 파일 안의 비공개 로컬 요소로 둔다(사유는 "신규 로컬 컴포넌트" 절 참조).

### 라우팅 (`app/index.tsx`)

현재 구조(스플래시 유지 → `getOnboardingCompleted()` 판정 → `completed ? <Redirect href="/home"/> : <OnboardingScreen onDone={…}/>`)를 유지하고 콜백만 하나 늘린다.

- `onDone` (3장 "시작하기"): 기존 그대로 — `setOnboardingCompleted()` → `setCompleted(true)` → `<Redirect href="/home" />`.
- `onSkip` (1·2장 "건너뛰기", 신규): `setOnboardingCompleted()` → `goToLogin()` (= `router.replace("/login")`).
  - **완료 플래그를 저장한다**(결론). 근거: 티켓의 "한 번 완료하면 재시작 시 다시 뜨지 않는다"는 온보딩을 **의도적으로 끝낸 사용자**에게 다시 보이지 않는다는 뜻이고, 건너뛰기는 그 명시적 종료 행위다. 저장하지 않으면 로그인 후 앱을 재실행할 때마다 온보딩이 되살아난다(잔소리 패턴). MSG-292가 "중간 이탈은 1장부터"로 정한 것은 **강제 종료·앱 킬** 케이스이지 명시적 건너뛰기가 아니다 → 규칙 충돌 아님. (질문 Q1으로 승인 대상)
- `_layout.tsx`(MSG-419 소유)는 **무수정** — 온보딩은 QueryProvider 아래 `/` 라우트에서 그대로 렌더된다. 인증 부트스트랩과도 무관(온보딩은 API를 호출하지 않는다).

### 재작업 1회차 — 검증이 잡은 결함

초회 검증에서 **S11(a11y)만 실패**했다. `uiautomator dump`(TalkBack 실제 순회 트리) 실측:

| | 재작업 전 | 재작업 후 |
|---|---|---|
| 1장 이름 없는 clickable | 8개(GridCell) | **0개** |
| 3장 가짜 버튼 | 3개(`핫구역`·`지역축제`·`팝업스토어`) | **0개** |
| 진행바 접근성 노드 | 없음 | `[63,153][1017,161]` focusable |

원인은 두 가지였고 **둘 다 코드 리뷰로는 잡을 수 없는 종류**였다.

1. **`importantForAccessibility`가 이 스택에서 통째로 무시된다.** 최초 구현은 `accessibilityElementsHidden` + `importantForAccessibility="no-hide-descendants"`로 장식을 숨겼다고 판단했으나 실제로는 아무 효과가 없었다. 대조 실험(일반 텍스트 행·className 없는 순수 `View`에도 무효)으로 RN 0.86.2 Fabric의 문제이지 NativeWind 탓이 아님을 규명했다.
2. **뿌리 원인은 장식에 상호작용 컴포넌트를 재사용한 것.** `GridCell`·`Chip`은 `Pressable` + `accessibilityRole="button"`을 계약으로 내장한다. 형태가 닮았다는 이유로 정적 일러스트에 끌어다 쓰자 탭 동작 없는 가짜 버튼 11개가 낭독됐다.

수정: 미니맵 칸·테마 칩을 온보딩 로컬 `View`로 대체(시각 계약은 동일 클래스 값으로 유지), 일러스트·보상 행을 각각 `accessible` + `accessibilityLabel`로 묶어 낭독 단위를 1개로 축약, `SegmentedProgress`에 `accessible` 추가. 결과적으로 각 장의 포커스 대상은 4개(진행바·건너뛰기·일러스트 라벨·CTA)로 정리됐다.

부수 효과로 활성 칩의 체크 아이콘이 사라져 Figma와 오히려 일치하게 됐고(오탐 방지 3번 자연 해소), `!bg-theme-hot`·`!bg-primary/60`도 불필요해져 소멸했다. `!bg-foreground`(2장 다크 썸네일)만 남는다.

함께 정리: 1장 미니맵 4행째가 `h-42` 클리핑으로 영영 안 보이던 문제를 데이터 3행 축소로 해소(정의한 8칸 전부 노출), 그 결과 고정 높이가 사라져 스케일 `42` 철회.

### 검토한 대안 (기각 사유)

- **2장 다크 썸네일을 `overlay`에 `absolute inset-0` 배경 레이어로 처리** — 재생 원 **아래**에 깔려야 해서 VideoCard 렌더 순서를 바꿔야 하고, 그러면 "기존 호출부 렌더 불변"이라는 비파괴 조건이 깨진다. important 수식자를 택했다.
- **VideoCard 재사용을 포기하고 온보딩 로컬 카드로 재구현** — 티켓이 명시한 선행 산출물 재사용 요구에 반한다. 기각.
- **2장 히어로를 폴백 회색 썸네일 + AI 칩 하단 이동으로 타협**(스펙 Q2 1안) — ui-native를 안 건드리는 대신 이 장의 핵심 연출인 다크 카드가 사라진다. "스크린샷이 뭉개져 읽히지 않는다"는 이 티켓의 출발점을 다시 부르는 선택이라 사용자가 2안(비파괴 optional props)을 승인했다.
- **히어로 카드 2종의 중복을 온보딩 내부로 공통 추출** — 검증에서 `nose query`로 확인한 결과 신규 패밀리 전부 `similar · 공유 라인 0 · ~0 removable`이고, 두 카드 간 중복 2쌍도 이미 9~10멤버짜리 앱 전역 패밀리의 연장이라 추출해도 패밀리가 남는다. 격자 셀 렌더 루프는 서로 로직이 달라 추출 대상이 아니다.
- **진행바 낭독을 WAIVED 처리** — `SegmentedProgress` 1줄 비파괴 수정으로 해결되므로 유예할 이유가 없었다.

### WAIVED · 확인불가

- **WAIVED 없음.**
- **확인불가 1건 (판정 무관)**: TalkBack의 **발화 텍스트 자체**는 캡처하지 못했다(덤프 스키마에 `roleDescription`/`RangeInfo`가 없고, adb 합성 입력이 TalkBack 탐색을 구동하지 못함). 진행바 낭독은 ⓐ 덤프 구조 ⓑ TalkBack 실행 시 접근성 포커스 사각형이 진행바 bounds에 놓이는 것을 스크린샷 픽셀로 검출 ⓒ RN `ReactAccessibilityDelegate.kt` 직독(`PROGRESSBAR`는 className이 아닌 `roleDescription`을 붙이며, `RangeInfo` 가드에 `{0,3,1~3}`이 통과) 3중 근거로 판정했다.
- **장식 그룹은 완전 무음이 아니라 라벨 1개로 낭독된다.** 이 스택에서 완전 숨김이 불가능해 택한 차선이며, 일러스트 대체 텍스트의 표준 패턴이기도 하다. 완전 무음은 RN 업그레이드 후 `importantForAccessibility` 재시도가 필요하다.

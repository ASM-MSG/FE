# MSG-395: 상단 칩 UI 새로운 버전으로 수정

## 기획 요약

지도 홈 상단 테마 칩 4종(핫구역·지역축제·팝업스토어·경로추천)이 지금은 전부 같은
`ThemeFeedPanel`(셀 라벨 섹션 + 영상 1열, `MOCK_CELLS` 기반)로 동작한다. Figma ver 13
[C-1안]이 칩마다 다른 좌측 패널·지도 표현·클릭 흐름을 정의했고, 서버에도
`GET /api/missions/active`가 열려 축제·팝업·코스가 `type`+`shape`로 통합 제공된다.

칩 4종을 각각의 새 화면으로 교체하고, 지역축제·팝업스토어·경로추천의 mock
(`MOCK_THEME_CELLS`·`MOCK_ROUTE`)을 실 미션 API로 전환한다. 핫구역은 격자 나열이 아닌
**행정동 단위 요약**으로 바꾸고, 격자 클릭 시 격자 상세로 내려간다.

## 수용 기준

### 공통 · 전환

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| 1 | `/api/missions/active` 응답을 `type`으로 3버킷으로 분류한다 — EVENT·THEME → 지역축제, POPUP → 팝업스토어, COURSE → 경로추천. 알 수 없는 type은 어느 버킷에도 넣지 않는다 | 로직 | vitest |
| 2 | 미션 `shape`에서 격자 id 집합을 파생한다 — `CELLS`는 `cells[].gridId`, `BOX`는 `polygon`을 덮는 100m 격자 중 중심이 폴리곤 내부인 것, `PATH`는 `spots[].gridId` | 로직 | vitest |

## 추정 및 질문

1. **핫구역 동 영상 목록의 출처** — 동 단위 "전체 영상" API가 없다(`/api/collections/videos`는
   내 수집 영상만). **그 동의 핫구역 격자 중 핫스코어 상위 5개**의 `getGridGlobalVideos`를
   합쳐 최신순으로 나열하는 것으로 추정했다. 상한 5는 요청 수를 묶기 위한 값이다
2. **동 요약 스탯의 모수** — `영상 N개 · 조회 N`은 위 표본(상위 5격자 합)의 개수·조회수 합이다.
   서버에 동 단위 집계가 없어 표본 기준임을 문구로 드러내지 않는다(Figma에도 없음)
3. **현재 행정동 결정** — 지도 중심 좌표의 `reverse-geocode` 결과를 쓴다(기존 `region-header`
   관례). 칩 활성 중 지도를 옮기면 헤더가 라이브로 따라간다
4. **`BOX`(EVENT) 격자 파생** — 서버가 격자 목록 대신 경계 폴리곤만 주므로, 폴리곤 bbox를
   덮는 100m 격자 중 **중심이 폴리곤 내부**인 것을 타일로 삼는다. Figma의 "축제별 m×n 칸"이
   이 방식으로 재현된다고 추정
5. **`영상 N`(미션 카드 우측)** — **확정(사용자)**: 백엔드가 API 개편 중이며 개편에
   `videoCount`가 포함된다. 그때까지 **목 수치**로 표시한다. `missionId` 기반 결정적 값
   하나(`mission-video-count.ts`)로 격리해 재렌더마다 값이 흔들리지 않게 하고, 파일 상단에
   교체 지점임을 명시한다. 미션 **상세**의 `올라온 영상 N개`는 실제 조회한 피드 길이를 쓴다
   (목 아님) — 상세는 이미 영상을 받아오므로 실수치가 공짜다
6. **`순환/비순환형`** — 코스 DTO에 필드가 없다. `line` 시작점과 끝점의 근접 여부(100m 이내)로
   판별한다고 추정
7. **`전체 보기`(핫구역 동 요약)** — 기존 홈 관례대로 칩을 해제하고 패널 안 전체 지역
   리스트를 연다 (`openRegionList`)
8. **`저장` 버튼** — 대응 API가 없어 기존 `CellActionRow`처럼 no-op으로 둔다 (제외 범위 명시)
9. **미션 상세의 영상 피드** — 미션 격자들의 전역 영상을 합쳐 최신순. 격자 수가 많은 미션은
   상위 5격자로 제한한다 (추정 1과 동일한 상한)

## 리스크

- **미션 진행도가 FE 계산이다** — 서버 완료 판정(MSG-223)과 어긋날 수 있다. 표시 전용이고,
  서버 필드가 생기면 `mission-progress.ts` 한 곳만 교체하도록 격리한다
- **백엔드 API 개편이 진행 중이다** (사용자 확인) — 미션 응답에 `videoCount` 등이 추가될
  예정이다. 개편 결과에 따라 `mission.ts`·`mission-video-count.ts`의 매핑이 바뀔 수 있으므로
  DTO 접점을 이 두 파일로 모으고 UI는 FE 표시 모델만 본다
- **`/api/missions/active` 실응답 미확인** — 생성 타입만 보고 스펙을 썼다. `shape`가 `unknown`
  기반 유니온이라 런타임 판별이 필요하고(type 필드로 분기), 실데이터에서 `polygon` 좌표
  순서·`line` GeoJSON 형식이 예상과 다르면 구현 단계에서 보정한다
- **요청 수** — 동 요약·미션 상세가 격자별 영상 조회를 합산한다. 상위 5 상한과 TanStack
  Query 캐시 공유로 묶지만, 실측에서 과하면 상한을 낮춘다
- **`ThemeFeedPanel` 제거로 기존 테스트가 사라진다** — 삭제 대상 테스트가 커버하던 동작
  (칩 클릭 → 패널 전환, Escape 닫힘)은 신규 패널 스모크로 동등 이상 재확보한다
- **Figma 오탐 방지**:
  1. **활발한 시간대 그래프 위치** — Figma(14629-3839)는 동 요약 하단에 그렸으나 **격자 상세**로
     옮긴다. 시간대 API가 격자 단위이고 동 합산은 요청이 격자 수만큼 나간다 (사용자 확정)
  2. **`14641-343`의 격자 코드 불일치** — 헤더는 `부전 B-07`, 칩은 `부전 D-07`로 디자인 자체가
     어긋나 있다. 서버 `zoneName`+`zoneCell`을 정본으로 하나의 값만 쓴다
  3. **지명 플레이스홀더** — Figma 지도 배경의 `안산체력인증센터`·`예체능대학`과 축제 목록의
     서울·통영·광주·포항 항목은 디자인 시점 임시 데이터다. MVP 지역은 부산 서면이고
     실데이터를 그대로 렌더한다 (하드코딩 금지)
  4. **`14599-14734`(신안) 계열 요소 미구현** — 칩 위 개수 배지, 지도 클러스터 핀은 [신안]
     프레임에만 있고 사용자가 지정한 [C-1안] 흐름에는 없다. 이번 범위 밖
  5. **동 요약의 조회수·업로더 핸들** — `/api/collections/videos`에 없는 필드는 표시를 생략한다
     (기존 `FeedVideo` null 허용 계약). Figma의 `조회 1,400`이 안 보이는 카드가 있을 수 있다
  6. **칩 바 자체는 현행 유지** — 아이콘·색·활성 스타일을 바꾸지 않는다 (제외 범위)

### 검토한 대안 (기각 이유)

- **shape 판별을 `type`으로**: 명세가 POPUP의 shape를 규정하지 않아 팝업이 통째로 빈 격자가 된다 → 필드 유무로 런타임 판별
- **미션 격자 전개 후 교집합**: BOX 81칸 × 170미션 = 좌표 변환 수만 회, 사용자 렉의 직접 원인
- **칸 수 상한만 두기**: 상한이 걸리면 타일이 잘려 데이터가 거짓말이 된다 → 뷰포트 클리핑
- **동 요약 영상을 격자 전량 조회**: 요청이 격자 수에 비례 → 상위 5격자 표본
- **`영상 N`을 목록에서 실조회**: 미션 수 × 격자 수 → 서버 `videoCount` 도착 전까지 결정적 목
- **스팟 이름을 gridId로 표시**: `39064_112221`은 이름이 아니다 → 코스 상세에서만 `getCell` 6~8건
- **`cn` 우회(내 컴포넌트만)**: 239곳에 같은 함정을 남긴다 → `extendTailwindMerge`로 근본 수정
- **상태 배지를 ui-web `Chip`으로**: active 시 Check 아이콘 강제 + primary 단색이라 테마 4색 불가

### 확인불가 · 잔여

  미션 진행도가 구조적으로 과소 집계되고, 같은 격자가 상세에선 `내 점령`·코스에선 `미방문`으로

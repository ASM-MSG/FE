# MSG-446: [모바일] 영상 재생 화면 신설 — 카드 탭 목적지 부재 해소

## 기획 요약
모바일에는 영상 재생 화면도 라우트도 없어서, 지도 홈 시트·격자 상세·도감 갤러리·미션 상세의 영상
카드가 전부 `onPress` 없이 정적 콘텐츠로 남아 있다. 목적지가 없는 상태에서 `onPress`를 붙이면
`VideoCard`가 `accessibilityRole="button"`을 켜 "가짜 버튼"이 스크린리더에 노출되기 때문에
MSG-421 실기 검증 이후 MSG-423·425·427·430·431이 **모두 같은 이유로 배선을 보류**했다.
이 티켓은 `GET /api/videos/{videoId}`(`getPlayback`) 기반 단일 재생 화면 `/video/[videoId]`를 만들고,
보류돼 있던 카드 3종(`FeedVideoList`·`GridVideoRow`·`GalleryVideoCard`)의 탭을 그 목적지로 배선해
다섯 티켓이 남긴 미배선을 일괄 해소한다.

## 추정 및 질문

1. **재생 컨트롤은 `expo-video` 네이티브 컨트롤(`nativeControls`)을 쓴다** — 커스텀 재생/일시정지 버튼을 만들지 않는다. [동작 요구]의 "재생/일시정지, 재생 시간"을 한 번에 충족하고, 플랫폼 접근성(스크러버 낭독)도 공짜로 따라온다. 커스텀 컨트롤은 시안이 없어 만들면 전부 추정이 된다.
2. **`mine`은 라우트 쿼리 파라미터로 넘긴다** — `getPlayback` 응답에 소유 여부 필드가 없고(닉네임만 있다), 세 진입점 모두 이미 `mine`을 알고 있다(`GridFeedItem.mine`·`GridVideoRow.mine`·도감은 상수 `true`). 메타 문구 분기(기준 4)에만 쓰고, **접근 판정에는 절대 쓰지 않는다**(기준 12 — 판정은 서버 몫).
3. **화면 제목은 격자명이다** — 서버에 영상 제목 필드가 없다. 웹 `VideoMiniPanel`과 같은 폴백 사슬(zone → region → "영상")을 쓴다.
4. **`getPlayback`은 조회수를 올린다**(명세: "이번 조회 증가 전 스냅샷"). 재생 화면에서는 **의도된 부작용**이라 MSG-431의 시트 게이트(`enabled: open`)와 달리 열자마자 부른다. 다만 `staleTime`(기준 1) 덕에 뒤로 갔다 같은 영상을 다시 열어도 TTL 이내면 재조회·재증가가 없다.
5. **자동 재생한다** — 카드 탭이라는 명시적 제스처 직후이고, [동작 요구]가 "누르면 … 영상이 재생된다"다. `useVideoPlayer(uri, p => p.play())`의 생성 콜백을 쓴다(소스가 null→URL로 바뀌면 플레이어가 재생성되는 expo-video 57 실측 동작 — `blur-preview.tsx` JSDoc에 기록됨). `replaceAsync`는 부르지 않는다(같은 사고 반복 방지).
6. **격자 상세 라우트(`/grid/[cellId]`)의 "대표 영상 미리보기"(`video-preview.tsx`)는 배선하지 않는다** — `deriveCellDetail` **mock**이 만든 길이 라벨만 있고 대응하는 실 `videoId`가 없다. 아래 목록(`GridVideoRow`)은 실 API라 그쪽만 배선한다. 이 mock 미리보기의 가짜 재생 버튼은 격자 상세 실연동 티켓 몫으로 지라에 환류한다.
7. **에러 문구**(기준 5) — 티켓이 문구를 주지 않아 다음으로 정한다: 403 `"비공개로 설정된 영상이라 볼 수 없어요"` / 404 `"삭제되었거나 볼 수 없는 영상이에요"` / 그 외 `"영상을 불러오지 못했어요"`(+다시 시도).

## 리스크

- **Figma 시안 없음** — 티켓 [참고]에 Figma 링크가 없고, Figma 정본 페이지에도 모바일 재생 화면 노드가 확인되지 않는다. 레이아웃은 기존 앱 관례(다크 16:9 플레이어 박스 + `AppHeader` + 메타 블록 — `blur-preview`·`upload-video-preview`·`VideoMiniPanel`)를 따르고, **Figma 대조 검증은 "시안 부재"로 판정**한다.
- **`mine` 파라미터의 신뢰도** — 딥링크·푸시로 직접 진입하면 `mine`이 없어 타인 영상 문구("@닉네임")로 낭독된다. 접근 제어와 무관한 표기 차이라 수용한다.
- **presigned URL 만료** — 재생 중 TTL이 지나면 스트림이 끊길 수 있다. `playbackStaleTime`은 **열 때** 만료 URL을 쓰지 않게 할 뿐 재생 중 갱신은 하지 않는다(웹도 동일). 영상 최대 길이가 30초라 실질 위험이 낮아 이번 범위 밖으로 둔다.
- **실기 확인 차단 가능성** — 카카오 로그인이 스텁이라(MSG-444 미완) 인증이 필요한 화면에 에뮬레이터로 진입하지 못할 수 있다. 막히면 `use-dev-login`(`/api/auth/dev/social-login`, MSG-419)으로 토큰을 받아 진입하고, 그마저 막히면 해당 화면 기준을 **확인불가**로 보고한다(추측으로 통과 처리하지 않는다).
- **Figma 오탐 방지**: ①재생 화면은 시안이 없으므로 "디자인 불일치" 판정 대상이 아니다 ②`VideoCard`의 재생 원(흰 원 + 파란 삼각)은 Figma(파란 원 + 흰 삼각)와 **의도적으로 다르다** — MSG-420·425에서 확정된 앱 카드 관례이며 이 티켓이 바꾸지 않는다 ③도감 갤러리 NEW 배지가 썸네일이 아니라 메타 줄 우측인 것도 기존 실측 결과 그대로다.

## WAIVED · 확인불가

- **기준 8 부분 통과**: 격자 상세 시트·미션 상세는 배선된 `FeedVideoList` **같은 파일**을 쓰지만
  직접 관찰은 못 했다 — 미션은 서버에 진행 중 미션이 0건이었다. `/grid/[cellId]` 라우트는 **앱 안에
  진입 경로가 없다**(MSG-427 C1이 시트로 대체) — 배선은 넣었고 코드 감사로만 확인했다.
- **기준 12 부분 통과**: 소유자 재생은 실기 확인. **타인 403 차단은 확인불가** — dev 계정이 하나뿐이라
  타인 시점을 만들 수 없다.
- **Figma 대조 없음**: 재생 화면 시안이 티켓에도 Figma 정본에도 없다. 레이아웃은 앱 관례를 따랐다.
- **환류 대상**: ①서버 `durationSec`(0:05)과 실제 파일 길이(00:12) 불일치 ②격자 상세 mock 대표
  미리보기의 목적지 없는 재생 버튼 ③미션 영상 목록 응답에 소유 플래그 부재.

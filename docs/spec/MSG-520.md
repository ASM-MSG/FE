# MSG-520: 행사 영상 미니 패널 — 기존 재생 로직 재사용 + 좋아요 · 댓글

## 기획 요약

행사방 위치별 영상 목록(MSG-518 `EventVideoCard`, 현재 비인터랙티브)에서 카드를 클릭하면 기존 미니 패널 재생 경험 그대로 영상이 열리고, 그 위에 행사 전용 좋아요(도움돼요)·댓글을 얹는다. 비로그인 상호작용은 로그인 모달 게이트, 실패는 사용자 언어 안내, 홈·도감 기존 미니 패널은 회귀 없이 유지한다. Figma 정본 15618:2924.

## API 스펙 판정 (스펙 단계 확정 항목 1 — 사용자 승인 대상)

**좋아요·댓글은 행사 한정이다.** hey-api 생성물(`shared/api/generated/sdk.gen.ts`) 실측:

| 기능 | 엔드포인트 | 비고 |
|---|---|---|
| 좋아요 추가 | `PUT /api/event-videos/{videoId}/helpful` (`addHelpful`) | 멱등 — 재시도가 수를 안 흔들도록 PUT. 응답 `{helpfulCount, helpfulByMe}` |
| 좋아요 취소 | `DELETE /api/event-videos/{videoId}/helpful` (`removeHelpful`) | 멱등. 같은 응답 DTO |
| 댓글 목록 | `GET /api/event-videos/{videoId}/comments` (`getComments`) | 둘째 페이지부터 용도(첫 페이지 20건은 상세에 내장). 커서 keyset, 오래된순. 익명 조회 가능 |
| 댓글 작성 | `POST /api/event-videos/{videoId}/comments` (`createComment`) | 본문 1~500자 |
| 영상 상세 | `GET /api/event-videos/{videoId}` (`getVideoDetail`) | **presigned playbackUrl + 메타 + helpful + 댓글 첫 페이지를 한 번에** 돌려준다. `interactionLocked` 포함 |

- 일반 영상(`/api/videos/**`)에는 좋아요·댓글 엔드포인트가 **없다** → 전역 적용은 불가능하고, 티켓의 "행사 한정 vs 전역" 질문은 **행사 한정으로 확정 제안**. 홈·도감 미니 패널에는 아무것도 추가하지 않는다(회귀 없음 = AC 11).
- 서버 용어는 "도움돼요"다(티켓의 "좋아요") — UI 라벨은 Figma대로 **"도움돼요"**.
- 필요 API 전부 기존 생성물에 있음 → **`api:generate` 재실행 불필요·금지 준수**(MSG-516 독점). 블로킹 없음.
- 에러 계약: 아카이브 행사(종료+30일)는 409 + developCode **13422**, 비노출 영상은 404 + **13406**. 상세 응답 `interactionLocked=true`가 입력 UI 비활성 재료(유예 기간(UPLOAD_GRACE)에는 계속 상호작용 가능 — 판정 주체는 서버 필드, FE 날짜 계산 0줄, MSG-519 선례).
- 조회수 주의: **재생 URL 발급(=상세 조회)마다 타인 조회수가 오른다** → 상세 쿼리는 invalidate 금지, 뮤테이션 결과는 `setQueryData` seed로만 반영한다.

## 추정 및 질문 (사용자 확인 필요)

1. **[확정 요청] 적용 범위 = 행사 한정** — 위 API 판정대로 좋아요·댓글은 `/api/event-videos` 전용이라 행사 미니 패널에만 얹고 홈·도감은 무변경. (티켓이 스펙 단계 확정으로 지정한 항목)
2. **[확정됨 2026-08-31] 더보기(⋯) = 재생 유틸리티 메뉴** — 사용자 결정: "기본 영상재생할 때 있는 것처럼 다운로드·재생속도·PIP 모드 있는 정도로만". ⋯은 렌더하되 항목은 다운로드/재생 속도/PIP 3종(AC 13), 소유자 액션(삭제·공개·신고)은 미탑재(원 제안의 기각 근거 ①~③ 유지 — 서버 mine 신호 추가 시 후속).
3. **[추정] "댓글 N" pill은 표시 전용** — 클릭 동작 정의가 티켓·Figma 어디에도 없다. 도움돼요만 버튼, 댓글 pill은 카운트 표시(비버튼)로 렌더.
4. **[추정] 도움돼요 비낙관 갱신** — 멱등 PUT/DELETE 응답(처리 후 재집계 값)을 그대로 seed. 낙관 업데이트 대비 코드가 단순하고 서버 재집계 값과 안 어긋난다(MSG-431 공개 전환 선례).
5. **[추정] 댓글 "더 보기" 버튼** — Figma에 없지만 서버가 커서 페이지네이션(첫 20건 내장)이라 `hasNext`일 때만 노출.
6. **[추정] 댓글 수정·삭제 제외** — 생성물에 `updateComment`/`deleteComment`가 있으나 티켓 동작 요구에 없다. 이번 범위 밖(작성·조회만).
7. **[추정] 선택 상태는 event-room-store 확장** — 기존 `video-mini-panel-store`는 FeedVideo 타입 계약이라 행사 DTO가 안 맞고, 행사 영상 선택은 방·위치 수명에 종속되므로 같은 스토어에서 back 체인으로 관리하는 편이 닫힘 규칙을 한곳에 모은다.

## 리스크

- **실데이터 부재**: 서버 승인 행사·영상 0건 → 실동작 검증은 fetch 스텁 경로, 실서버 상호작용(도움돼요 반영·댓글 저장·13422)은 **확인불가 판정**(BE 시딩 MSG-500 대기 — 시딩 후 재확인 권장). 스펙 단계 확정 항목 3 반영.
- **조회수 부작용**: `getVideoDetail` 재조회가 조회수를 올린다 — 뮤테이션 후 상세 invalidate를 쓰면 조회수가 부풀므로 반드시 `setQueryData` seed. 목록(`use-location-videos-query`)만 invalidate.
- **MSG-521 병렬 충돌면**: `use-event-room-body`/`EventRoomBodySwitch`를 양쪽이 만질 수 있다 — 520은 카드 클릭 배선 최소 diff, 빈 상태·업로드 계열 파일 불가침. 머지 순서가 뒤면 리베이스 시 해당 파일 diff 재확인.
- **`VideoMiniPanel` 리팩토링 회귀**: 재생 표면 추출이 기존 패널을 건드린다 — 기존 smoke(`video-mini-panel.smoke.test.tsx`) green 유지가 AC 11의 1차 방어선.
- **Figma 오탐 방지** (page-verifier 대조 기준):
  1. **조회수("조회 1") 미표시** — `EventVideoDetailResponseDto`에 viewCount가 없다(실측). 디자인과 의도적 차이.
  2. **더보기(⋯)는 재생 유틸리티 메뉴** — Figma가 암시하는 소유자 액션이 아니라 다운로드·재생 속도·PIP 3종(확정 항목 2, AC 13). 항목 구성이 디자인과 다른 것은 의도적 차이. presigned URL cross-origin이라 `<a download>` 파일명 지정이 안 먹을 수 있음(새 탭/저장 폴백 허용 — builder 재량), PIP 미지원 브라우저는 항목 숨김이 정상.

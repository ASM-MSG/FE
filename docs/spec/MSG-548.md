# MSG-548: 신청 전 최종 검토 — 요약 확인 · 제출 확인 모달 · 행사 등록 신청 제출

## 기획 요약

등록 위저드 스텝 4(review). 입력 전체를 기본 정보 카드·위치 영역 카드로 요약해 보여주고, "수정"으로 해당 스텝에 복귀할 수 있다. 사실 확인 체크박스를 체크해야 제출 CTA가 활성화되고, 확인 모달의 "제출하기"를 눌러야 `POST /api/org/event-submissions`가 발사된다. 성공 시 내 신청 목록으로 이동 + 접수 안내, 실패 시 오류 안내 + 재시도, 진행 중 버튼 잠금. 제출 후 목록·상세 화면은 제외 범위(이동 라우팅까지만 — MSG-549 머지분이 이미 존재).

## 코드베이스 대조 결과 (스펙의 전제 — 전부 실측)

**서버 계약 (generated 실측 — 재생성·수정 금지)**
- SDK `submit`(POST /api/org/event-submissions) + 생성 옵션 `submitMutation`(@tanstack/react-query.gen:480). 응답 봉투 data = `EventSubmissionSubmitResponseDto { id, submissionNo(FM-{KST연도}-{4자리}), status }`.
- `EventSubmissionCreateRequestDto`: type·title·organizerName·startsOn·endsOn·description·**imageS3Key 필수**, 유형 전용 `programDescription`/`operatingHours`/`participationMethod`(유형 밖 전송 = 13439), EVENT만 `parentOccurrenceId`(없는 회차 13440·종료 회차 13441), `locations?: EventSubmissionLocationRequestDto[]`(1~20, `{areaRects?}` — 이름 필드 없음, 배열 순서가 순번).
- **문서화된 developCode는 4종뿐**: 13433(종료일 과거)·13439(유형 밖 필드)·13440·13441(EVENT 회차). 위치 81칸 초과 등 locations 검증 코드는 스키마 주석에 없다 — FE가 상한을 이미 막고 있고(MSG-547), 미지 코드는 서버 message 폴백(MSG-542 선례).
- SDK 주석 실측: "EVENT의 위치는 대표 위치 정확히 1곳" — 위저드의 단일 위치 조립(`locations: [{areaRects}]`)이 세 유형 모두에 유효하다.

**확장점 인계 (546·547 머지분 실측)**
- `WizardStepSwitch.tsx` — review case가 `StepPlaceholder` JSX 1줄, 교체 지점 주석 명시. 이 티켓 소유.
- `submission-wizard-store.ts` — 548 슬롯 주석: "`toCreateDraft`(submission-form) + submitMutation", "제출 본문을 `locations: [{ areaRects }]`(1~20개 계약의 1개)로 조립". `toDraftState`가 **areaRects를 아직 노출하지 않는다**(547 의도적 이탈 — "548 착수 시 1줄 추가"가 인계 계약). MSG-550 확장점(mode·hydrate 주석)은 보존 대상.
- `submission-form.ts` — `toCreateDraft`가 유형 전용 필드 1개만 조립(13439 구조 예방), 반환은 `Partial<...>`, "locations는 547이, 실제 제출은 548이 채운다" 주석. `SUBMISSION_FORM_CONFIGS` 3벌의 라벨(titleLabel·organizerLabel·periodLabel·typeFieldLabel·descriptionLabel·badge)이 **요약 카드 라벨의 재료로 그대로 쓰인다**(Figma "주최 기관"·"축제 기간"·"주요 프로그램"·"축제 소개"·"유형 · 지역축제" 전부 일치).
- `submission-area.ts` — `unionCellCount`(합집합 중복 제거)·`rectSpan`·`rectCellCount`·`areaRowLabel` 재사용 — 위치 카드 산술 신설 불요.
- 요약 재료는 전부 스토어에 이미 있다: `common`·`typeFieldValues[type]`·`image.previewUrl/s3Key`·`parentOccurrence.name`·`areaRects`. previewUrl blob 해제는 페이지 언마운트 cleanup뿐이라 위저드 내 스텝 왕복에서 미리보기가 살아 있다(OrgSubmissionWizardPage 실측).
- `OrgSubmissionWizardPage` — review 스텝에서 `WizardProgress`를 본문 좌하단에 렌더(area만 미렌더). Figma 좌하단 등록 절차 카드(1~3 체크·4 강조)와 `toStepProgress` 파생이 정합 — **페이지 파일 수정 불요 가능성이 높다**(스위치가 알아서 review 본문을 그린다).
- 이탈 가드 함정: 성공 후 `/org/submissions`로 navigate하면 `WizardExitGuard`(useBlocker, dirty 기준)가 확인창을 띄운다 — **성공 시 reset() 후 navigate**로 dirty를 먼저 내려야 한다(스펙이 명시하는 함정).

**주변 자산**

- 접수 안내 선례: MSG-544 "완료 안내는 페이지 소유 자동 소멸 Toast 한 자리(뷰를 떠나며 성공하는 경로는 뷰 로컬 안내 불가)" + `use-auto-dismiss-toast`(features/video-actions — cross-feature 재사용 선례 MSG-411). 콘솔에 전역 토스트 호스트는 없다(실측 — PushNoticeHost는 AppLayout 소속, 콘솔은 형제 트리).

- 브랜치: `*MSG-548*` 로컬·리모트 모두 없음(실측) — 신규 생성. 베이스 develop `ee5ea76`(웨이브 1·2 전부 머지).

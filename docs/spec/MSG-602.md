# MSG-602: [모바일] 알림함 화면 + 미읽음 배지 (시안 없음 — FE 설계)

## 기획 요약
서버 MSG-434 API 4종을 앱에서 소비한다. 진입 구조는 BE PRD의 네이버 지도 패턴: 지도 홈 검색바 우측 프로필 아바타에 빨간 점(안읽음 > 0) → 프로필/설정 "알림함" 행("새 알림 N개" 캡션) → 알림함 화면(목록·읽음·모두 읽음). 딥링크 이동은 MSG-432 선행이라 없음.

## 작업 로그
- **시안 없이 설계**: 앱 시각 관례(AppHeader + 카드 목록, 신고 관리·차단 목록 화면)를 그대로 쓰고, 카테고리 색은 지도 홈 테마 칩 팔레트를 재사용해 색 언어를 맞췄다. 안읽음 표시는 배경(surface-soft) + 제목 옆 파란 점, 읽음은 흰 배경 + body 톤. 홈 빨간 점은 숫자 없이 존재 여부만(PRD).
- **읽음 정책**: 행 탭·모두 읽음만 읽음 처리한다. 알림함 진입 자동 읽음은 두지 않았다 — 사용자가 못 본 항목이 조용히 읽음이 되면 배지의 의미가 사라진다. 탭 이동은 MSG-432 이후.
- **배지 갱신**: unread-count를 화면 포커스·포그라운드 복귀에 재조회. 폴링 없음(PRD 비목표). 푸시 수신 이벤트 연동은 FCM data 계약(MSG-432) 뒤.
- **낙관 기록**: markRead는 캐시에서 그 항목이 안읽음일 때만 배지를 감산해 이미 읽은 행 재탭이 음수를 만들지 않는다. onSettled에서 unread만 무효화하고 목록은 무효화하지 않는다(스크롤·페이지 흔들림 방지, 읽음 표시는 낙관값이 곧 정답).
- **중복 게이트**: 접기 로직을 `shared/api/infinite-list`로 제네릭화(explore/location 4 copies 허용 중복의 3번째 용례 — 기존 둘 이관은 후속). 테스트 fixture 공용화. formatKstDate 리팩터로 web 복제 family가 changed → baseline in-place 교체.
- **검증**: vitest 19건 신규 + 게이트 전부 통과. Android 실기: 홈 빨간 점(20) → 프로필 "새 알림 20개" → 알림함 목록 → 탭 즉시 19 → 모두 읽음 → 홈 점 소멸. 빈 상태·당겨서 새로고침·이어받기 경계는 데이터/도구 제약으로 로직 테스트로 갈음.
- **검토한 대안**: ① AppHeader 우측 슬롯에 "모두 읽음" — 16px 박스라 텍스트 액션 부적합, 요약 행으로. ② 알림함 진입 시 자동 모두 읽음 — 기각(위). ③ 프로필 카드 안에 "새 알림 N개" 문구(PRD 웹 디자인) — 모바일 프로필 카드는 닉네임·가입일·편집 버튼으로 꽉 차 있어 설정 행 hint로 대체.
- **codex 리뷰(P2 1건) 반영**: 겹친 읽음 요청에서 스냅숏 롤백이 다른 요청의 성공분을 되돌리는 문제 → 실패 시 목록·개수 무효화로 교체, 교차 실패 테스트 추가(`inbox-mutations.test.ts`).

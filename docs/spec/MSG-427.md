# MSG-427: [모바일] 테마 칩 상세 흐름 — 핫구역 동 요약·축제/팝업 미션·코스 스팟 + 미션 API

## 기획 요약

MSG-423이 지도 홈의 칩 UI(`theme-chip`·`theme-chips-bar`·`theme-chip-view`)를 웹 스펙으로 끝냈지만, 칩을 눌렀을 때의 **시트 콘텐츠는 구 MSG-298 "테마 피드"(격자 섹션 + 대표 영상 카드)가 목 데이터 위에 그대로** 남아 있다. 이 티켓은 그 테마 피드를 웹 MSG-395·403이 확립한 **미션 구조**로 갈아끼운다 — 핫구역은 동 요약, 축제·팝업은 미션 카드/상세, 경로추천은 코스 카드/상세/포토스팟, 지도 격자 탭은 시트 안 격자 상세다. 데이터는 전부 서버 응답(`/missions/*`·`/hotzones`·`/grids/*`)이고 `mock-theme-data.ts`는 이 티켓에서 소멸한다.

**구조 교체 티켓이다.** 신규 화면을 붙이는 것이 아니라 기존 파일 6개(모델 4 + UI 2)를 제거하고 그 자리를 서버 연동 모델·UI로 대체하며, `map-home-screen.tsx`의 확장점 ②·③을 이 티켓이 소유한다(MSG-428이 뒤이어 리베이스).

### Figma 실측 요점 (구현 지시서)

- **헤더 구성이 상태마다 다르다.** 목록 3종(3·5·7)은 **뒤로가기도 X도 없고** `{테마 배지} · {N}개` 한 줄만 있다. 핫구역 요약(1)은 `{동 이름} + 핫구역 배지 + 전체 보기 + X`(뒤로가기 없음). 상세 4종(2·4·6·8·9)은 `‹ + 제목 (+ 상태 pill) + X`.
- **테마 색이 design-tokens와 정확히 일치**한다: `#FF3B30`/`#AF52DE`/`#FF9500`/`#34C759` = `palette["theme-hot"/"theme-festival"/"theme-popup"/"theme-route"]`. Figma는 raw hex라 변수 바인딩이 없지만 값이 같으므로 토큰만 쓰면 된다.
- **미션 영역은 격자 타일로 그려진다** — 테마색 옅은 채움 + 테마색 실선, 내 점령과 겹치는 칸은 **테마색 대각 빗금**(핫구역·축제·팝업·코스 4테마 공통). 폴리곤 통짜 렌더가 아니다.
- **경로추천만 경로선·번호 마커**를 갖는다 — 계단형 초록 폴리라인 + 28×28 초록 원 번호 마커 3개(흰 숫자 + 흰 링). 미션 이름표 마커는 **9개 프레임 어디에도 없다**.
- **활발한 시간대 그래프는 핫구역 동 요약(1)에만** 있고 격자 상세(2)에는 없다. 막대 **8개**(24개가 아니다) + 축 라벨 `0시·6시·12시·18시` + 헤더 `활발한 시간대` / `영상 4개 기준`.
- **action-row(영상 추가·공유·저장)** 는 핫구역 요약(1)·핫구역 격자 상세(2)에만 있고, 미션/코스 상세(4·6·8)와 **코스 스팟 격자 상세(9)** 에는 없다.
- 카드 치수: 축제 348×87(가로 74×56 썸네일) / 팝업 348×98(**세로 56×74 포스터**) / 코스 348×107(**썸네일 없음, 4px 진행 바**).
- 상세 스탯은 회색 박스(`#F5F7FA` ≈ `bg-surface-soft`) 3분할, 라벨 위 / 값 아래.
- 완료 조건 배너는 테마색 12% 틴트 배경 + 테마색 글자 (348×36).

## 서버 계약 ↔ 화면 요구 대조 (이 스펙의 핵심 산출물)

생성 SDK 실체: `apps/web/src/shared/api/generated/{types,sdk}.gen.ts` (모바일 `apps/mobile/src/shared/api/sdk.ts`가 재수출).

### 미션 엔드포인트 (생성물에 있는 것 전부 — 4종)

| SDK 함수 | 경로 | 파라미터 | 언랩 후 응답 |
|---|---|---|---|
| `getActiveMissionsInViewport` | `GET /api/missions/active` | `type`·`swLat`·`swLng`·`neLat`·`neLng` **전부 필수** | `MissionResponseDto[]` |
| `getMyProgress` | `GET /api/missions/progress` | `missionIds?: number[]` (상한 300) | `MissionProgressResponseDto[]` |
| `getMissionDetail` | `GET /api/missions/{missionId}` | path only | `MissionDetailResponseDto` |
| `getMissionVideos` | `GET /api/missions/{missionId}/videos` | `cursor?`·`size?`(1~50, 기본 20) | `GridVideoPageResponseDto` |

> 티켓 [참고]는 `/missions/`·`/missions/active`·`/missions/progress` 3종으로 적었으나, 생성물에 **플레인 `/missions/`는 없고** 대신 `/missions/{id}`·`/missions/{id}/videos`가 있다. 상세·영상 화면이 성립하는 것은 이 두 엔드포인트 덕분이다.

주요 DTO 필드: `MissionResponseDto{missionId, type, title, targetCount, startAt|null, endAt|null, shape, description|null, placeName|null, sourceUrl|null, operationTime|null, imageUrl|null, distanceMeters|null, durationMinutes|null, difficulty|null}` · `MissionProgressResponseDto{missionId, targetCount, filledCount, completed}` · `MissionDetailResponseDto{mission, progress, videoCount, spotStats[]{gridId, visited, videoCount}}` · `GridGlobalVideoResponseDto{videoId, thumbnailUrl, durationSec, viewCount, recordedAt, nickname}`.
`shape` 유니온은 판별자가 없어 **필드 유무로 런타임 판별**한다(`spots`→PATH / `cells`→CELLS / `polygon`→BOX). 명세가 POPUP의 shape를 규정하지 않아 `type` 표에 기대면 팝업이 통째로 빈 영역이 된다.

## 추정 및 질문

### 추정 (사용자 확인 필요)

1. **코스 스팟·핫구역 격자의 셀 표시는 `toOccupiedCells`와 같은 스냅 근사**를 쓴다 (5179 셀 중심 → 모바일 격자 인덱스). MSG-423 승인 Q2 A안의 연장이고, 좌표계 이원화(R2)의 귀결이다.
2. **`영상 N` 목 해시(웹 `mission-video-count.ts`)를 포팅하지 않는다.** 티켓이 "mock 의존 0건"을 요구하고, 서버는 상세(`videoCount`)와 스팟(`spotStats[].videoCount`)을 이미 준다. 웹은 이 둘을 받아 놓고도 UI가 목을 쓰는 미배선 상태다(R6) — 모바일은 실값을 쓴다. **다만 목록 카드의 영상 수만은 서버가 안 준다** → Q1
3. **상태 배지의 `now`는 화면 마운트 시점에 고정**한다(웹 `useMemo(() => new Date(), [])` 미러). 하루가 지나 배지가 바뀌는 경우는 홈 재진입으로 갱신된다.
4. **미션 목록 조회의 bbox는 현재 뷰포트**를 쓴다. 웹은 "확정 영역"(`committedBounds`)을 쓰지만 모바일에는 그 개념이 없다(MSG-423이 뷰포트 단일 소유로 갔다). 카메라 이동 종료(`onCameraIdle`)마다 재조회된다.
5. **핫구역 액션 행의 공유·저장은 대응 API가 없어 비활성 표시**(누를 수 있는 것처럼 보이지 않게, `accessibilityRole="button"` 미부여)로 둔다. 영상 추가만 `/upload` 배선.
6. **시간대 그래프는 Figma대로 8칸(3시간 단위)** 이다. 서버는 0~23시 24칸을 주므로 3칸씩 합산한다 — 웹 `hourly-uploads.ts`(24칸)와 파생이 갈리므로 parity 테스트는 "웹 24칸 → 모바일 8칸 축약" 관계로 쓴다.
7. **빈·실패 문구**는 웹 문구를 그대로 옮긴다(`아직 이 미션에 올라온 영상이 없어요`·`불러오지 못했어요` 등) — 티켓·Figma에 문안이 없다.
8. **미션 상세 영상 목록은 첫 페이지(기본 20건)만** 조회한다. 커서 무한 스크롤은 웹도 미구현이고 티켓 범위 밖이다.

### 질문 (승인 전 판단 필요)

- **Q1 — 미션 목록 카드의 "올라온 영상 수".** Figma는 일부 카드에 `영상 N`을 그리지만 `/missions/active` 응답에 `videoCount`가 없다. **(a)** 목록 카드에서 배지를 **생략**한다(티켓 [동작 요구]의 "올라온 영상 수" 일부 미충족, mock 0건은 지킴) / **(b)** 목록 미션마다 `GET /api/missions/{id}`를 호출한다(팝업은 Figma상 38건 — 비현실적) / **(c)** 웹처럼 결정적 목 해시를 포팅한다(티켓의 "mock 0건"과 정면 충돌). **권장: (a)** — 상세에서는 실값을 보여준다.
- **Q2 — 코스 포토스팟 이름.** 서버 `Spot`에 이름이 없다. Figma는 `국제시장 먹자골목` 같은 실명과 `송도 C-04 / 이름 없는 경유 지점`을 함께 보여준다. **(a)** 스팟마다 `GET /api/grids/{gridId}`를 호출해 격자 표시명을 얻는다(코스 상세 진입 시에만, Figma 기준 6~8건 — 웹 선례) / **(b)** 전부 격자 코드 + `이름 없는 경유 지점`으로만 표시한다. **권장: (a)** — Figma 화면이 (b)로는 성립하지 않는다.
- **Q3 — "활발한 시간대"의 위치.** **Figma는 핫구역 동 요약(화면 1)에 두고 격자 상세(화면 2)에는 두지 않는다.** 티켓도 동 요약이라고 쓴다. 그런데 `hourly-uploads` API는 **격자 단위**뿐이라 동 전체를 그리려면 격자 수만큼 요청이 나가고, 웹은 이 이유로 그래프를 **격자 상세로 옮겼다**(사용자 확정 이력). **(a)** Figma·티켓대로 동 요약에 두되 **표본 상위 5격자**의 시간대를 합산한다(요청 5회, 다른 요약 수치와 같은 표본 근거) / **(b)** 웹 선례대로 격자 상세로 옮긴다(Figma와 어긋남) / **(c)** 이번 티켓에서 뺀다. **권장: (a)** — 요약의 다른 수치가 이미 같은 5격자 표본 기반이라 근거가 일관된다.
- **Q4 — 미션 이름표 마커.** 티켓 [동작 요구]는 "지도에 미션 영역이 테마 색으로 표시되고 **이름표가 붙는다**"고 하지만, **Figma 9개 프레임 어디에도 이름표 마커가 없다**(웹은 hover/선택 시에만 그린다 — RN에는 hover가 없다). **(a)** 선택된 미션에만 이름표를 붙인다 / **(b)** Figma대로 이름표를 만들지 않는다. **권장: (a)** — 티켓 문구를 최소로 충족하면서 지도가 글자로 덮이지 않는다.
- **Q5 — 미션 영역 격자 타일 렌더의 범위.** Figma는 미션 영역을 **격자 타일 + 빗금**으로 그린다. 서버 EVENT/POPUP shape는 `BoxShape.polygon`(폴리곤)이라 타일로 펼치려면 모바일에 없는 `encodeGridId`·`viewportGridRange`·`pointInPolygon` 3종을 `entities`에 추가 포팅해야 하고, 웹에서 이 경로가 렉 사고를 낸 이력이 있다(뷰포트 클리핑으로 해결). **(a)** 3종을 포팅하고 웹처럼 **뷰포트 범위 안에서만** 타일을 펼친다(Figma 충실) / **(b)** 폴리곤을 `NaverMapPolygonOverlay`에 그대로 그린다(구현 최소, 빗금 표현 불가, Figma와 다름). **권장: (a)** — 빗금(내 점령 ∩ 미션)이 Figma의 4테마 공통 문법이라 (b)로는 재현되지 않는다. 단 이 선택이 작업량과 성능 리스크를 함께 키운다.
- **Q6 — 기존 `/grid/[cellId]` 라우트의 처분.** 격자 상세가 시트로 들어오면 이 mock 전용 화면(MSG-296/317, `mock-cell-details.ts` 기반)은 홈에서 도달 불가가 된다. **(a)** 무수정 존치(이번 범위 밖, 후속 정리 티켓) / **(b)** 이 티켓에서 함께 삭제(더보기 메뉴·신고 모달 등 MSG-317 기능이 함께 사라진다) / **(c)** 시트가 아니라 이 라우트로 계속 보내고 서버 연동만 한다(티켓 문구 "격자 상세 **시트**로 바뀐다"와 불일치). **권장: (a)**
- **Q7 — 핫구역 동 요약 수치의 표본 성격을 화면에 알릴 것인가.** `영상 N개 · 조회 N · 최근 24시간 +N개`는 동 전체가 아니라 **핫스코어 상위 5격자의 최근 20건씩** 합계다. 웹·Figma 모두 표시하지 않는다. 모바일도 같게 갈지 확인 필요.

## 리스크

- **R1 — 티켓 [참고]의 엔드포인트 목록이 부정확하다.** `/missions/`(플레인 목록)는 생성물에 없고, 대신 `/missions/{id}`·`/missions/{id}/videos`가 있다. 후자 둘이 상세 화면의 전제라 범위가 줄지도 늘지도 않는다.
- **R2 — 좌표계 이원화.** 모바일 격자선·격자 탭은 여전히 구 위경도 스텝 체계(`entities/cell/model/grid.ts`)이고 서버는 EPSG:5179다. 미션 스팟·핫구역 격자를 지도에 얹으려면 MSG-423의 스냅 근사(`toOccupiedCells`)를 계속 써야 하며, 셀 크기 차(100m vs 부산 위도 약 104m)로 드물게 인접 셀로 스냅된다. Q5를 (a)로 가면 이 근사와 5179 타일 렌더가 한 화면에 공존해 **격자선과 미션 타일이 반 칸 어긋나 보일 수 있다** — 전면 5179 이관은 여전히 후속 티켓이다.
- **R3 — 서버 격자 id 역인덱스의 취약성.** 모바일에 `encodeGridId`가 없어 "탭한 셀 → 서버 gridId"를 역인덱스로 푼다. 역인덱스에 없는 셀은 상세가 열리지 않는데, 이는 웹 `canOpenDetail` 게이트와 결과가 같아 기능 손실은 아니다. 다만 스냅 충돌(서로 다른 gridId 둘이 한 모바일 셀로 접힘)이 나면 둘 중 하나만 열린다.
- **R4 — `hoveredMissionId` 개념 부재.** 웹은 마우스 호버로 지도 이름표·타일 강조를 켠다. RN에는 hover가 없어 **선택된 미션에만** 강조를 준다(Q4).
- **R5 — `STATUS.md`가 웹 map-home 현황에 대해 스테일하다.** `mission*.ts` 8종·`course.ts`·`hot-region-summary.ts`·`grid-context-line.ts`·`panel-branch.ts`·`hourly-uploads.ts`·`use-home-missions.ts` 등 MSG-395/403 산출물 다수가 인벤토리에 없다. 이 스펙의 포팅 대상 목록은 **소스 실사** 기준이다.
- **R6 — 웹의 미배선 2건을 모바일이 앞질러 고친다.** 미션 상세 `올라온 영상`(서버 `videoCount` 미사용, 첫 페이지 길이 20에서 포화)과 스팟 행 `영상 N`(서버 `spotStats[].videoCount` 미사용, 목 해시)이 웹에 남아 있다. 모바일이 실값을 쓰면 **같은 수치가 웹·앱에서 달라 보인다**. 웹 보수는 이 티켓 범위 밖(`apps/web` diff 0줄)이므로 별도 티켓 제안이 필요하다.
- **R7 — 영상 카드 탭 미배선의 근거.** 모바일에는 재생 화면도 라우트도 없다(`app/`에 플레이어 없음). 목적지 없이 `onPress`를 붙이면 `VideoCard`가 `accessibilityRole="button"`을 켜 스크린리더에 "가짜 버튼"이 노출된다 — MSG-421 실기 검증이 잡았고 MSG-423·425가 같은 이유로 기각했다. 재생 화면 티켓이 생기면 그때 배선한다.
- **R8 — 실기 검증 환경.** 2026-08-19 기준 에뮬레이터의 dev client APK가 Metro에 붙지 않는다(임베디드 번들 로더). 착수 시 `npx expo prebuild && npx expo run:android`로 dev client 재빌드가 선행돼야 하며, 실패하면 화면 프로파일 검증이 성립하지 않는다.

## 검증이 잡은 결함 2건

### 1. Hermes `Array.prototype.toSorted` 미구현 — 지도 홈 마운트 즉시 크래시 (차단)

실기 검증에서 `Render Error — undefined is not a function` / `hot-region-summary.ts (22:14)`. `useHotRegionSummary`가 칩 선택과 무관하게 항상 호출돼 **지도 홈 전체가 불능**이었다. 프로덕션 3곳(`hot-region-summary.ts` · `course.ts` · `use-multi-grid-videos-query.ts`) 전부 이 티켓의 신규 파일이고 전부 웹 포팅에서 딸려 왔다.

**게이트 6종이 원리적으로 못 잡는 유형이다** — vitest는 Node에서 돌아 `toSorted`가 존재하고, typecheck는 `lib`에 ES2023이 있어 통과한다. "웹 포팅 + parity 테스트"라는 이 티켓의 방법론 자체가 구조적으로 못 거른다(양쪽 다 Node/브라우저에서 검증되므로).

수정은 `[...arr].sort(...)` — `sort`는 ES2019부터 안정 정렬이라 E7의 안정 정렬 전제가 깨지지 않는다.

**좌시프트 조치**: 같은 함정이 레포에 **이미 두 번 주석으로 문서화돼 있었는데도**(`gallery-groups.ts:37`, `region-cluster-overlay.ts:109`) 재발했다. 주석은 재발을 못 막는다는 것이 실증됐으므로 `.oxlintrc.json`에 `apps/mobile`·`packages/ui-native` 한정 차단 규칙을 신설했다 — `no-restricted-properties`(`toSorted`·`toReversed`·`toSpliced`·`Object.groupBy`·`Map.groupBy`·`Promise.withResolvers`) + `no-restricted-globals`(`structuredClone`). MSG-298·386의 "CI가 잡은 것은 로컬 게이트로 내린다" 원칙 적용. 규칙 실효성은 크래시 코드를 되돌려 검출되는 것을 확인해 검증했다(RED→GREEN).

### 2. 팝업 미션 상세에서 날짜 기간이 화면에서 사라짐 (D11)

`period` 한 값을 부제와 스탯에 겸용했는데 팝업 분기에서 그 값이 운영시간이라, 운영시간이 두 번 나오고 기간이 없어졌다. 스펙 D11(`{장소} · {기간}`)과 Figma 화면 6(`… · 7.31~8.14`)이 모두 기간을 요구한다. 순수 파생 `missionDetailPeriod(theme, dto)`를 신설해 부제(테마 무관 날짜 기간)와 스탯(팝업=운영시간 / 축제=축제 기간)을 분리했다. 목록 카드가 `formatOperationTime`을 쓰는 것은 D4·Figma 화면 5의 요구라 유지가 정답.

### 3. 지도를 움직이면 열려 있던 상세 시트가 사라짐 (codex 리뷰가 잡음, P1)

`useHomeMissions`가 선택 미션을 **현재 `/missions/active` 응답 목록에서만** 찾았다. 상세를 연 채 지도를 움직여 그 미션이 새 뷰포트 목록에서 빠지면 `selectedMission`이 `null`이 되는데 `selectedMissionId`는 남아 있어 시트 종류는 계속 상세였고, 결과적으로 `null`이 렌더됐다.

**`SheetHeader`(뒤로 `‹`·닫기 `✕`)가 상세 콘텐츠 컴포넌트 안에 있어서**, 이건 빈 시트가 아니라 **탈출 수단이 없는 빈 시트**였다. Android 하드웨어 백은 살아 있지만 iOS엔 그것도 없다.

조사 중 **두 번째 진입 경로**가 드러났다: `mission-selection.ts`가 모듈 싱글턴이라 탭 왕복으로 화면이 재마운트돼도 `selectedMissionId`가 살아남는데, 그 직후엔 목록이 비어 있고 래치 ref도 새 인스턴스라 뷰가 없다. 래치만으로는 못 막는다.

**수정**: 순수 함수 `pickSelectedView(views, selectedId, lastSelected)` + 커밋 후 ref 보관(래치)으로 뷰를 유지하고, 그래도 뷰가 없는 경우를 위해 `SheetDetailFallback`(헤더 + 로딩/실패)을 넣어 상세 분기의 `null` 렌더를 전부 제거했다. 회귀 테스트 7건(RED 확인 후 GREEN).

**진행도 staleness 처리**: 래치가 붙드는 뷰의 진행도는 목록 id 기반이라 함께 빈다. 그런데 상세 조회(`/missions/{id}`)는 선택 id로만 구동돼 살아 있고 명세상 같은 서버 계산의 진행도를 준다 — **추가 요청 없이** 그 값으로 뷰를 다시 만들었다. 낡은 값을 사실처럼 보여주지도, 과잉 억제하지도 않는다(D13 취지).

**부수 발견**: `progressFailed`가 스탯을 `확인 불가`로 바꾸기만 하고 재시도 수단이 없어 A7 미달이었다. 목록 시트가 쓰던 `SheetNotice`를 상세에도 얹어 복구 경로를 만들었다.

**이 결함은 정적 게이트로도 실기 검증으로도 안 잡혔을 유형이다** — 크래시가 아니라 특정 조작 순서(상세 열기 → 지도 이동)에서만 나타나고, 테스트가 그 상황을 덮지 않았다. 리뷰가 유일한 포착 경로였다.

### 4. 스팟 이름 로딩을 "이름 없음"으로 위장 (PR 리뷰가 잡음)

`useGridNamesQuery`의 `isPending`은 계산되고 인터페이스 주석에 목적까지 적혀 있었으나 **소비처가 0곳**이었다. `courseSpotLabel`이 `name === undefined`만 보므로 "아직 안 물어봄"과 "물어봤는데 없음"이 구분되지 않아, 코스 상세를 열 때마다 격자 조회(6~8건)가 끝나기 전까지 **모든 포토스팟이 `이름 없는 경유 지점`으로 표시**됐다.

같은 클래스의 결함을 `spotVisitLabel(visited, progressFailed)`은 이미 막고 있었다(실패 시 라벨 생략) — 한쪽만 처리된 상태였다.

**수정**: 판정을 순수 함수 `courseSpotListState(spotCount, namesPending)`로 뽑고 스팟 목록만 로딩으로 게이트했다. UI가 아니라 모델에 둔 이유는 모바일에 렌더 테스트가 없기 때문이다(MSG-292 확정 4) — UI 분기로 두면 같은 회귀를 다시 못 잡는다. RED 확인 후 GREEN.

웹은 같은 이유로 패널 전체를 막지만(`CourseDetailPanel`, "부분 렌더 금지") 모바일은 목록만 막는다 — 제목·진행도·거리는 이미 도착해 있다.

| 뷰포트 밖 선택 미션 | 래치(직전 뷰 유지) + `SheetDetailFallback` | ① 선택 자동 해제 — 사용자가 누르지 않은 이동이라 놀랍다 ② 상세를 `/missions/{id}` 쿼리로 구동하도록 재설계 — **더 옳지만** 카드 탭 직후 상세 도착 전 빈 시트가 번쩍여 결국 같은 폴백이 필요하고 범위가 크다. 진행도만 이번에 앞당기고 전체 전환은 후속 권장으로 남김 |
| 영상 카드 탭 | 배선하지 않음 | 재생 화면이 없어 목적지가 없다. `onPress`를 붙이면 `VideoCard`가 `accessibilityRole="button"`을 켜 스크린리더에 가짜 버튼이 노출된다(MSG-421 실기 검증이 잡았고 MSG-423·425가 같은 이유로 기각) |

## 확인불가 (22건) — 실기 화면 검증

병렬 워크트리 3곳이 패키지명 `kr.fillmap.app`과 에뮬레이터를 공유해, dev client가 다른 워크트리의 Metro 번들을 문다. 2회차에 번들 오염을 뚫는 데는 성공했으나 위 크래시로 화면이 뜨지 않아 관찰이 불가능했다 — **"화면을 확인했다"가 아니라 "화면이 안 뜬다는 것을 확인했다"** 이다. 크래시 수정 후 재검증은 사용자 실기기에서 하기로 결정.

특히 미확정으로 남는 항목: 코스 진행 바의 `!bg-theme-route`가 NativeWind 캐스케이드를 실제로 이기는지(근거·구현·회귀는 코드로 확정, 렌더 결과만 미관찰), 지도 오버레이 3종(B1·D9·E14).

재현 절차는 `_workspace/MSG-427/03_verify_report.md` §9.8에 있다.

## 후속 권장

- `mission-cells.ts ↔ occupied-grids.ts`의 스냅 규칙 복제 — 코드 주석 스스로 "같은 규칙이라야 교집합 판정이 성립한다"고 적는 **불변식**이라, 중복 베이스라인에 묻히면 위험이 안 보인다

- 워크트리별 패키지명·포트 분리 — 병렬 세션에서 모바일 실기 검증이 성립하지 않는 구조적 문제

# MSG-415: 영상 교체 연동

## 기획 요약

내 영상을 새 파일로 교체하는 기능을 연동한다 — `PUT /api/videos/{videoId}` (생성 SDK `replace`). 진입점은 MSG-411이 신설한 영상 더보기(⋯) 메뉴(내 영상 분기)에 "영상 교체" 항목을 추가하고, 교체 플로우는 기존 업로드 위저드 파이프라인(선택→선분석→하이라이트→미리보기→presign→S3 PUT→확정)을 **교체 모드**로 처음부터 다시 돈다 — 확정만 `POST /api/videos` 대신 `PUT /api/videos/{videoId}`다. 교체 직후 상태는 UPLOADED(재인코딩 대기)라 기존 블러 처리 폴링 워처를 그대로 잇는다.

> 지라 description이 공란이라 이 스펙의 기획 입력은 오케스트레이터가 전달한 사용자 컨텍스트다(`00_ticket.md`) — 리스크 1.

## 코드베이스 대조 결과 (스펙 전제)

- **생성 SDK `replace` 시그니처** (`shared/api/generated/sdk.gen.ts:48`, `types.gen.ts:10`): `PUT /api/videos/{videoId}`, body `VideoReplaceRequestDto = { s3Key, lat?, lng?, durationSec(1~30), recordedAt }`. 서버 명세: **좌표를 생략하면 격자를 유지하고 파일만 교체**, 좌표를 보내면 기존과 같은 격자여야 함(다르면 GRID_MISMATCH 거부). 응답 `{ videoId, processingStatus }` — 교체 직후 항상 UPLOADED.
- **더보기 메뉴는 이미 두 진입점에 부착돼 있다**: 도감 `GalleryVideoCard`(mine 고정)와 `VideoMiniPanel` 헤더(mine 분기) 모두 `features/video-actions/ui/VideoMoreMenu` 하나를 렌더한다 → **"영상 교체" 항목은 VideoMoreMenu 내부(MineMenuItems)에만 추가하면 두 진입점에 자동 적용** — pages/dex·widgets/video-mini-panel은 수정 불필요(병렬 경계에도 유리).
- **업로드 파이프라인 재사용 지점** (features/upload):
  - `model/upload-orchestration.ts` — presign→S3 PUT→확정 순수 상태 머신. `finalize` 이펙트가 주입식이라 **확정만 갈아끼우면 교체가 된다** (수정 없이 재사용).
  - `api/use-upload-mutations.ts` — `useConfirmUpload`가 미러 대상: presignEffect(purpose 미전송=UPLOAD)·`uploadToS3`·단계 실패 보존(UploadFlowError)·성공 시 `track()`(처리 폴링 등록) 패턴 그대로, finalize만 `replace` SDK 호출.
  - `ui/use-upload-wizard.ts` — 위저드 컨트롤러. `publish()`가 `confirm.mutateAsync`를 부르는 지점이 모드 분기점. 닫기 초기화(close)·재시도 단계 스킵·busy 차단 전부 재사용.
  - `model/upload-modal-store.ts` — 전역 열림 스토어. `target: LatLng`(지목 격자)은 있으나 교체 대상 videoId 개념이 없다 → 필드 추가 필요. 비로그인 게이트·영속 재개(pendingAfterLogin)는 교체와 무관(교체 진입점은 로그인 후 표면) — 영속화 불필요.
  - `model/processing-store.ts` + `api/use-processing-watcher.ts` — videoId 단위 getPlayback 폴링(UPLOADED→READY 전이 시 격자 무효화+통지). **교체 직후 UPLOADED 상태에 그대로 들어맞아 수정 없이 재사용.**
- **무효화 인프라**: `invalidateGridQueries(queryClient, gridId | null)`(광역 폴백 지원), video-actions `use-video-mutations.ts`의 도감 키 무효화 관례(`getRegionVideosQueryKey` 부분 키 등). `VideoActionTarget.gridId`는 `string | null`.
- **video-actions → upload cross-feature import 선례 있음** (MSG-411: `invalidateGridQueries`) — 메뉴 항목이 업로드 모달 스토어를 여는 방향(video-actions → upload)은 기존 방향과 동일.
- 브랜치: 현 워크트리가 `feat/msg-415-video-replace` 체크아웃 상태(사용자 생성 — 정본), 원격 동명 브랜치 없음.

## 수용 기준

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| 1 | 내 영상 더보기(⋯) 메뉴에 "영상 교체" 항목이 노출된다 — 위치는 공개 범위 섹션 구분선 아래·"영상 삭제" 위(추정 2). 두 진입점(도감 갤러리 카드·미니 패널 헤더) 모두에서 보이고, 타인 영상 메뉴(신고만)에는 노출되지 않는다 | 화면 | 브라우저 + vitest(스모크 — 기존 video-more-menu.smoke 확장) |
| 2 | "영상 교체" 선택 시 업로드 위저드가 교체 모드로 열리고, 기존 스텝열(선택→선분석 로딩→하이라이트→미리보기)을 동일하게 밟는다 — 선분석 실패 폴백·트리밍·재시도 동작 포함(기존 계약 재사용). 최종 버튼·완료 문구는 교체 표현(추정 3·4) | 화면 | 브라우저(파일 선택~미리보기까지) + 기존 위저드 스모크 유지 |
| 3 | 교체 확정 시 presign(purpose 미전송=UPLOAD)→S3 PUT→`PUT /api/videos/{videoId}` 단계열이 실행되고, PUT body는 `{s3Key, durationSec, recordedAt}` — **lat·lng 미전송**(좌표 생략=격자 유지, 추정 1). durationSec은 기존과 같은 1~30 클램프 | 로직 | vitest (stub-fetch로 메서드·URL·body 단정) |
| 4 | 교체 성공 시: ① 처리 대기 등록 `track(videoId)`(UPLOADED→READY 폴링·READY 통지·READY 시 격자 무효화는 기존 워처 재사용) ② 해당 videoId의 playback 쿼리 무효화(썸네일·상태 최신화) ③ 도감 동 영상 목록(region-videos 부분 키)·격자 영상 목록 무효화 ④ 완료 모달 표시 | 로직 | vitest (track 등록 + `getQueryState().isInvalidated` 관찰 — MSG-411 관례) |
| 5 | 교체 단계 실패(presign·S3 PUT·PUT) 시 단계 구분 실패 안내가 표시되고, 재클릭 재시도는 성공한 단계를 건너뛴다(UploadFlowError 상태 보존 재사용). 실패 시 track·무효화·닫힘이 실행되지 않는다 | 로직 | vitest |
| 6 | 일반 업로드 경로 회귀 없음 — 교체 모드가 아닐 때 확정은 기존 `POST /api/videos`(lat·lng 포함)로 발사된다. 위저드 닫기 시 교체 대상이 초기화돼 다음 일반 업로드가 교체로 오발사되지 않는다 | 로직 | vitest (기존 upload-wizard-flow 스모크 유지 + 모드 격리 단정) |
| 7 | 교체 모드 위저드를 확정 전에 닫으면(취소·✕·ESC) 어떤 쓰기 요청도 발사되지 않고 대상 영상이 변하지 않는다. 진행 중(선분석·트리밍·확정)에는 기존과 같이 닫기가 차단된다 | 화면 | 브라우저(확정 직전까지) + vitest |
| 8 | **검증 안전 제약(방법론)**: 브라우저 실검증은 교체 확정([교체하기] 클릭) 직전까지만 수행하고, `PUT /api/videos/{videoId}` 발사·성공 후속은 전부 vitest로 판정한다 — 실계정 영상을 실제로 교체하지 않는다(실데이터 비가역, MSG-407 기준 16·MSG-411 선례). 검증 리포트에 실서버 쓰기 요청 0건을 네트워크 로그로 확증한다 | 로직 | vitest + 네트워크 로그 확증 |

**검증 프로파일**: 화면 — 신규 UI(메뉴 항목·교체 모드 위저드 문구)와 화면 흐름이 기준. 단 Figma 시안이 없는 티켓이라 디자인 대조는 기존 스타일 준용 확인으로 대체하고(오탐 방지 목록), AC 3~5·8의 쓰기 경로는 vitest 한정(비가역 제약).

## 추정 및 질문 (사용자 확인 필요)

1. **[추정] PUT body에 좌표를 생략한다(격자 유지)**: 서버 명세상 좌표 생략=격자 유지, 좌표 전송=같은 격자 강제(다르면 GRID_MISMATCH 거부). 위저드의 위치 소스는 지도 뷰포트 중심이라 사용자가 다른 곳을 보고 있으면 교체가 거부된다 — 생략이 유일하게 안전하다. 이에 따라 교체 모드에서는 위치 라벨(SelectStep·PreviewStep의 "촬영 위치")을 지도 중심 대신 **대상 영상의 격자 라벨("서면 A-02"류, VideoActionTarget.zoneName/zoneCell)로 표기**한다(미확보 시 생략).
2. **[추정] 메뉴 항목 문구·위치**: "영상 교체", 공개 범위 구분선 아래·"영상 삭제" 위, 기본 foreground 색. Figma 시안 부재 — 기존 메뉴 스타일 준용.
3. **[추정] 확정 버튼 문구 "교체하기"**, 완료 모달 "교체 완료! 잠시 후 AI가 영상 블러 처리를 마치면 알림으로 알려드릴게요"류 — 교체 직후 UPLOADED라 기존 블러 안내가 그대로 유효.
4. **[질문] 교체 전 비가역 경고를 넣을지**: 기본안은 별도 확인 모달 없음 — 위저드 자체가 다단계(파일 선택→미리보기→확정)라 최종 [교체하기]가 확인 역할을 한다. 원하면 미리보기 스텝에 "기존 영상은 삭제되고 되돌릴 수 없어요" 한 줄 경고 또는 삭제 확인류 모달을 추가한다.
5. **[추정] 선분석(AI 하이라이트) 포함 풀 파이프라인 재사용**: 사용자 표현("처음부터 다시 도는 느낌") 근거 — 선택→선분석→하이라이트→트리밍 전 스텝을 동일하게 돈다. 교체 전용 축약(선분석 생략 등)은 하지 않는다.
6. **[질문] 지라 description 공란**: 티켓 본문이 비어 있어 오케스트레이터 전달 요지로 스펙을 썼다. 스펙 승인 후 이 내용을 지라 description에 채울지(티켓 워크플로 관례 — 기존 티켓 채우기) 확인 바란다.
7. **[추정] 교체 성공 직후 목록 썸네일 갱신 한계 수용**: 확정 직후 무효화 재조회 시점엔 서버가 재인코딩 전(UPLOADED)이라 목록 썸네일·재생본이 구 영상 기준으로 남을 수 있다 — READY 전이 시 워처의 격자 무효화가 최종 동기화한다. 도감 목록은 확정 직후 1회 무효화만 하고 READY 재무효화는 기존 워처 범위(격자 계열)를 넓히지 않는다(READY 시 도감 목록까지 갱신하려면 워처 수정 필요 — 범위 증가라 기본 제외).

## 리스크

- **티켓 정본 부재**: 지라 description이 공란(코멘트 0건) — 기획 입력은 오케스트레이터 전달 사용자 컨텍스트뿐이다. 이 스펙의 사용자 승인이 사실상의 정본 확정이다 (질문 6).
- **Figma 분석 생략**: 티켓에 Figma 링크가 없고 교체 메뉴 항목·교체 모드 문구 시안이 없다 — 신규 시각 요소는 기존 스타일 준용이며, page-verifier의 디자인 대조는 아래 오탐 방지 목록을 기준으로 한다.
- **실데이터 비가역**: 교체는 기존 영상을 덮어쓴다 — AC 8의 검증 안전 제약(브라우저는 확정 직전까지, PUT은 vitest)을 구현·검증 전 단계에서 게이트로 사용한다.
- **upload-modal-store 수정의 파급**: pendingAfterLogin(로그인 재개)·uploadIntentStorage 영속 로직과 같은 파일이다 — 교체 필드는 영속화하지 않고 구독 로직을 건드리지 않는 최소 추가로 격리한다(기존 스토어 테스트 유지가 회귀 게이트).
- **재인코딩 창의 표시 정합**: 추정 7 — UPLOADED 동안 구 썸네일이 남는 창은 서버 동작 의존. READY 통지 문구는 기존 "블러 처리 완료" 계열 재사용이라 교체 완료 표현과 어긋날 수 있다(문구 확인은 구현 중 판단, 워처 수정은 최소화).
- **병렬 웨이브 2 충돌**: 수정 파일이 features/upload·features/video-actions에 한정돼 MSG-409(notifications)·412(search)·413(dex 뱃지·프로필 헤더)과 물리적으로 분리된다 — 범위 밖 목록을 구현·검증 게이트로 사용.
- durationSec 1~30 제약은 업로드와 동일(MAX_TRIMMED_DURATION_SEC 클램프 재사용) — 교체 전용 추가 검증 없음.

## 기획 요약

QA 결함 리스트 중 파일이 겹치지 않는 웹 소규모 4건을 한 티켓으로 처리한다. ① 프로필의 "알림 받기" 토글·"알림 설정" 진입 행과 `/profile/notifications` 라우트를 제거(푸시 수신 표시·모바일 토글은 유지), ② 에러 화면 "홈으로" 버튼이 루트 에러 상태에서 실제로 홈을 띄우게 복구, ③ 100m 격자선·격자 오버레이의 부산 행정경계 절단을 해제해 전국에서 그려지게 하되 서버 제약(`MAX_VIEWPORT_SPAN_DEG=0.5`)과 기본 지역(서면)·mock은 불변, ④ 영상 길이 0:09 오표시는 BE(MSG-470) 원인이므로 FE는 "카드 대표 영상 vs 재생 첫 영상" 동일성만 코드로 판정하고 배포 후 실동작 확인을 기록한다.

### ② 에러 화면 "홈으로" 이동 복구

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| B1 | "홈으로" 클릭 시 `window.location.assign(ROUTES.home)`이 호출된다 (라우터 내부 `navigate` 미사용) | 로직 | vitest(신규 smoke — location.assign 스파이) |
| B2 | 무매칭 경로(예: `/profile/notifications` — A3와 연동) 진입 → 에러 화면 → "홈으로" 클릭 시 지도 홈이 실제로 렌더된다 | 화면 | 브라우저 |
| B3 | 홈 URL 자체에서 에러가 난 경우에도 클릭이 문서 전체 리로드(새로고침 효과)로 이어져 복구된다 — 하드 이동이므로 B1 충족 시 구조적으로 보장 | 화면 | 브라우저(재현 가능 시) / B1로 갈음 |

**원인 분석 (코드 근거)**: `RouteErrorBoundary.tsx:22`가 `navigate(ROUTES.home)`만 호출한다. react-router(v7)의 errorElement 렌더 에러 상태는 **location이 바뀔 때만** 리셋되는데, (a) 이미 홈(`/`)에서 에러가 난 경우 `navigate("/")`는 동일 location이라 에러 상태가 그대로 남고, (b) location이 바뀌어도 에러를 만든 앱/모듈 상태가 메모리에 남아 재렌더 시 같은 에러가 재발할 수 있다. **권장안: `window.location.assign(ROUTES.home)` 하드 이동** — 문서 리로드로 라우터·React·모듈 상태가 전부 초기화되어 두 케이스를 모두 덮고, 티켓의 "홈 URL에서 에러 → 새로고침 효과" 요구와 정확히 일치한다. 대안(에러 상태 리셋)은 react-router v7에 공식 reset API가 없어 same-location 케이스를 못 덮으므로 기각.

### ④ 격자 카드 영상 길이 표시 확인 (코드 판정 + 실동작 확인)

| # | 기준 | 유형 | 검증 방법 |
|---|------|------|----------|
| D1 | "카드 대표 영상 vs 재생 첫 영상" 동일성 판정 결론과 근거(파일:라인)가 스펙·검증 리포트에 기록된다 (아래 결론) | 로직 | 코드 감사(이 스펙이 산출물) |
| D2 | MSG-470 배포 후, 본인 영상이 없는 계정으로 격자 카드의 duration 뱃지가 재생되는 대표 영상의 실제 길이와 일치한다 (0초 시드 영상이면 "0:00") — BE 미배포면 "확인 불가(BE 대기)"로 리포트에 기록 | 화면 | 브라우저 |

**판정 결론: 두 경로는 조건부로 다른 영상이며, 그 다름은 의도된 설계다 → FE 코드 변경 없음.**

- 카드 대표 영상: `RegionGridCard.tsx:30·40·44~48`이 `GET /api/regions/{code}/grids` 응답 `ExploreGridResponseDto.coverThumbnailUrl·coverDurationSec`(`types.gen.ts:1360·1364`)을 그대로 렌더. 서버 명세가 "카드 커버는 격자 대표(cover)와 같은 영상"(`sdk.gen.ts:783`)이라 명시하고, cover 술어는 "공개·READY 중 조회수 → 최신"(`sdk.gen.ts` getGridCover 주석)이다. FE는 coverVideoId를 받지 않아 어느 videoId인지 알 수 없다(FE에서 getGridCover 호출처 0건 — MSG-326에서 목록 조회로 대체됨).
- 재생 첫 영상: 카드 클릭 → `RegionPanel.tsx:141` → `HomePanelSwitch.tsx:219` → `MapHomePage.tsx:283` → `useGridCardPlay.play` → 병합 목록 첫 항목(`use-grid-card-play.ts:55~58`). 병합은 `grid-videos.ts:80~86` `mergeFeedItems` — **내 영상(createdAt DESC)이 앞**, 그다음 전역(조회수 → 최신).
- 따라서: **보는 사용자가 그 격자에 본인 영상이 없으면** 전역 첫 항목 = cover와 같은 술어(조회수 → 최신)라 **같은 영상**. **본인 영상이 있으면** 내 최신 영상이 먼저 재생되어 카드 커버와 다르지만, 이는 MSG-277/326에서 승인된 "내 영상 우선" 정렬 관례다(`use-grid-card-play.ts:31` 주석). QA 결함(서면 I-7의 "0:09")의 원인은 영상 불일치가 아니라 커버 `durationSec` 값 자체(BE가 클라이언트 신고값 저장 — MSG-470)이므로, 티켓의 "다른 영상이라면 그때만 FE 수정" 조건은 **결함 원인으로서는 불성립** → 코드 변경 없이 이 판정 기록 + D2 실동작 확인이 산출물이다.

**검증 프로파일**: **화면** — ①(설정 UI 제거)·②(에러 화면 동작)·③(지도 오버레이)이 모두 시각 결과가 기준인 변경이고, 로직 항목(④)이 섞여도 넓은 쪽으로 판정. 단 Figma 신규 디자인은 없으므로 Figma 대조는 생략(제거·복구·확장 티켓), 브라우저 재현 + a11y(변경된 인터랙티브 요소 = 에러 화면 버튼·프로필 행) 중심.

### 추가 결정 — OpenAPI 스냅샷 갱신 (세션 중 사용자 지시로 제약 변경)

세션 시작 제약은 "`api:generate` 금지"였으나, 사용자가 진행 중 "openapi.ts 한번 씩 업그레이드하고 해줘"로 지시를 갱신했다. 라이브 명세(`https://api.fillmap.kr/v3/api-docs`)를 받아 재생성한 결과 **커밋 스냅샷이 뒤처져 있었고**, 정규화 diff 94줄에 다음 3건이 있었다:

1. **`PathShape.line`: `string | null` → `object | null`** — 코스 라인 GeoJSON을 문자열이 아니라 객체로 내린다. **웹 `features/map-home/model/mission.ts:136`이 `typeof shape.line === "string" ? shape.line : null` 가드라, 새 계약에서는 코스 라인이 전부 조용히 null로 떨어져 렌더되지 않는다.** → **MSG-473(코스 라인) 소관**. 477은 스냅샷·생성물만 싣고 파싱 대응은 하지 않는다(사용자 승인).
2. `RouteRecommendResponseDto.mentionedArea` + `MentionedAreaDto` 신설 (MSG-468 언급 지역 신호) — 소비처 없음, 타입만 추가.
3. `searchPlaces`에 `X-Viewer-Session` 선택 헤더 + "비로그인도 호출 가능" 서술 추가 — **MSG-474(비로그인 개방)의 BE 선행이 배포됐다는 신호**. 477은 사용하지 않는다.

**477의 처리**: `apps/web/openapi/api-docs.json` + `src/shared/api/generated/` 4파일을 갱신분으로 커밋에 포함. `PathShape.line` 타입 변경으로 typecheck가 깨지는 **테스트 픽스처 2곳**(`mission.test.ts:80`, `mission-view.test.ts:76`)만 최소 대응(문자열 픽스처 유지 + 새 DTO 타입으로의 좁은 캐스트 + MSG-473 참조 주석)하고, 런타임 파싱 로직(`mission.ts`)은 건드리지 않는다.

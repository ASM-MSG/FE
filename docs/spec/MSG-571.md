# MSG-571: [모바일] 지도 홈 시트 격자 카드 탭 → 격자 상세, "전체 보기" → 전체 지역 목록

## 기획 요약

지도 홈 시트 기본 화면(`default-sheet-content.tsx`)의 격자 카드와 "전체 보기"가 표시 전용으로 남아 있다(MSG-423 보류 자리, MSG-446 일괄 배선에서 누락). 카드 탭은 지도 셀 탭과 같은 경로(`setSelectedGridId` → `panel-branch` "grid-detail")로 격자 상세 시트를 열고, "전체 보기"는 시트 콘텐츠를 "전체 지역" 커서 무한 스크롤 목록으로 바꾼다. 지역 행 탭은 표시 지역(헤더 + 격자 목록)만 교체하고 지도는 움직이지 않는다. 웹 `RegionPanel`·`RegionListView`·`region-panel-store`·`use-explore-regions-query`의 이식이며 웹·packages·서버는 무수정이다.

## 코드 실측 (결정 근거)

오케스트레이터가 지정한 실측 4항목 + 모바일 현황.

| # | 질문 | 실측 결과 |
|---|------|----------|
| ① | 웹 `RegionGridCard` 탭에 게이트가 있나 | **없다.** `<button onClick={() => onSelect(grid.gridId)}>` — 무조건 발화. 목적지(미니 패널 재생)는 `MapHomePage`가 조립. 웹 `canOpenDetail`은 지도 셀 탭 전용이다 |
| ② | `selectRegion`이 지도를 움직이나 | **안 움직인다.** `selectRegion: (region) => set({ displayedRegion: region, mode: "grids" })` — `committedBounds` 불변(codex 리뷰 근거 주석: explore 응답에 좌표가 없고, 뷰포트 확정을 겸하면 "장소 불러오기로만 갱신" 우회로가 됨) |
| ③ | 웹 `resetMode`(mode→"grids") 호출 지점 | (a) `commit()` — 최초 채택·"장소 불러오기"·**칩 활성화** (b) `selectRegion()` — 지역 행 탭 (c) `SideRailNav.tsx:91` `closeRegionList()` — **사이드레일 섹션 전환**(홈 이탈). 웹에 "시트 닫기"는 없다 — 티켓의 "시트를 닫거나"는 (c)에 대응한다 |
| ④ | 웹 빈/실패 문구 | 첫 페이지 실패 `지역 목록을 불러오지 못했어요`(+재시도) · 로딩 `지역 목록 불러오는 중` · 빈 `아직 표시할 지역이 없어요.` · 이어받는 중 `다음 지역 불러오는 중` · 이어받기 실패 `다음 지역을 불러오지 못했어요`(+재시도, 목록 유지) · 행 `{regionName}` + `격자 {gridCount}개` · 헤더 `전체 지역` |

모바일 현황:
- **explore regions 쿼리 훅·`region-panel-store` 상당물 없음.** `grep exploreRegions apps/mobile/src` = 0건. 생성 SDK `getExploreRegionsInfiniteOptions`는 `shared/api/query-options.ts`(`export *`)로, DTO(`RegionGridCountResponseDto`·`ApiResponseDtoRegionExplorePageResponseDto`)는 `shared/api/sdk.ts`로 재수출된다 — **포팅만 하면 된다.** 무한 쿼리 선례: `features/event/{api/use-location-videos-query, model/location-videos-query}`(MSG-560) — 순수 파생을 model에 두고 훅은 배선만 하는 구조, `initialPageParam` 객체로 첫 페이지 커서 생략.
- **역지오코딩 표시 지역 상태 = 화면 로컬 파생, 스토어 없음.** `map-home-screen.tsx:142~145` `geocode = useReverseGeocodeQuery(viewport?.center)`, `regionGrids = useRegionGridsQuery(geocode.region?.regionCode)`, `regionName = geocode.region?.regionName`. 헤더는 지도 이동을 따라 **라이브**로 바뀐다(MSG-423 요구 2 — 웹 MSG-403의 고정 헤더와 다름). 따라서 "지역 행 탭 → 표시 지역 교체"는 **지오코딩 결과를 덮어쓰는 선택 지역 오버라이드**로 구현해야 하며, 그 상태는 탭 왕복 재마운트를 넘겨야 하므로 `grid-selection.ts`·`theme-selection.ts`·`event-selection` 관례(모듈 싱글턴 + `useSyncExternalStore`, zustand 미도입)를 따른다.
- **`canOpenDetail`의 `occupiedGridIds`는 뷰포트 범위**(`useOccupiedGridsQuery(bounds)` → `use-home-overlays.ts:76`)다. 지역 행 탭으로 뷰포트 밖 지역을 표시하면 그 카드들은 전부 게이트에 걸려 조용히 무반응이 된다 → 티켓 전제("서버가 준 점령 격자라 통과한다")는 **뷰포트 안일 때만 참**이다. 격자 상세 조회(`getCell`·`getStatByGrid`·`/videos`)는 gridId만 키로 쓰고 뷰포트에 의존하지 않는다.
- 시트 헤더 탭 불가 이력(MSG-445 C1): 종전 48dp 투명 오버레이가 헤더 행(26dp~)을 덮었고, 현재 `home-sheet.tsx:214`는 **핸들 바 자체가 Pressable + `hitSlop={{top:10,bottom:12}}`**로 0~26dp 밴드만 받는다. 콘텐츠 헤더 행(`gap-sm` 12 아래, y≥26)은 덮이지 않는다. Pan 제스처는 `activeOffsetY([-8,8])`라 탭은 통과한다.
- 뒤로가기 규칙: `goBack`(`map-home-screen.tsx:224`) → `stepBack` → 최상위면 `false`(화면 이탈). 하드웨어 back은 `event.handlers.back() || goBack()`. 전체 지역 모드는 `panel-branch`·`sheet-navigation`(웹 parity 대상)이 모르는 상태이므로 **화면의 `goBack` 선두에서 1회 가로챈다**(parity 파일 무수정).
- `VideoCard`(ui-native)는 `onPress`가 있을 때만 `accessibilityRole="button"`을 켜고 `accessibilityLabel`을 받는다 — 카드 a11y 요구는 prop 2개로 충족.
- 스크롤 계약: 콘텐츠 스크롤은 시트 **1단계에서만** 활성(`scrollEnabled: stage === 1`). `SheetScrollView`가 `onScroll`로 오프셋을 보고하므로 끝 근접 판정을 여기에 얹을 수 있다. 부분 실패 안내 `SheetNotice`(문구 + 다시 시도)와 상태 뷰 `SheetStatusView`(loading/empty/error)가 재사용 가능.
- 런북 **함정 11(Metro cwd)은 develop에 없다** — `origin/feat/MSG-567-mobile-blur-removal`(c55c2d59)에만 존재. 검증 절차에 명령을 인라인한다.

## 추정 및 질문

1. **카드 탭에 `canOpenDetail` 게이트를 두지 않는다 (항상 열기).** 근거: 웹 `RegionGridCard`도 게이트 없음(실측 ①), 게이트의 `occupiedGridIds`가 뷰포트 범위라 지역 행 탭 이후 카드가 전부 무반응이 됨, 상세 조회는 gridId만 필요. 티켓의 "비활성 표시" 대안은 기각 — 표시할 근거(왜 못 여는지)가 없다. — 사용자 확인 필요
2. **선택 지역 오버라이드는 지도 이동(뷰포트 변경)으로 풀린다.** 웹은 헤더가 고정이라 이 문제가 없지만 모바일 헤더는 라이브(MSG-423)다. 대안(다음 "장소 불러오기"까지 유지)은 모바일에 재검색 버튼이 없어 풀 방법이 없다. 내 위치 추적 중 위치 갱신도 뷰포트 변경이라 함께 풀린다. — 사용자 확인 필요
3. **전체 지역 모드 전환 시 시트 단계는 바꾸지 않는다**(현 단계 유지). `sheetStageFor`는 `panelKind` 기준이고 모드는 그 밖의 상태다. 목록 스크롤은 기존 계약대로 1단계에서만 된다 — 2단계에서 "전체 보기"를 누르면 목록 상단만 보이고 사용자가 시트를 끌어올려야 한다. 대안(모드 진입 시 1단계 스냅)은 셀 수 있는 한 줄이지만 웹 근거가 없어 보류. — 사용자 확인 필요
4. **상세 → 기본 시트 복귀 시 스크롤 위치는 0으로 돌아간다.** 티켓의 "같은 스크롤 위치"는 현 쉘 계약(콘텐츠 재마운트 시 오프셋 0 보고, `DefaultSheetContent`가 스위치 케이스 전환으로 언마운트)과 충돌한다. 기존 `sheet-navigation` 규칙이 보장하는 것은 "같은 시트 종류·같은 데이터(캐시)"이지 스크롤 위치가 아니다. 위치 보존은 쉘 계약 변경이 필요해 범위 밖으로 둔다. — 사용자 확인 필요
5. 스크롤 끝 임계 80px(웹 sentinel 대체). 마침표는 모바일 문구 관례대로 뺀다(`아직 표시할 지역이 없어요`).
6. 홈 포커스 이탈 시 목록 모드만 초기화(웹 `SideRailNav` 미러), 선택 지역은 유지(웹 `displayedRegion`이 섹션 전환에 유지되는 것과 같음).

# MSG-546: 행사 등록 위저드 셸 — 유형 선택 · 이벤트 시 선택 모달 · 기본 정보 3유형 · 대표 이미지 presign 업로드

## 기획 요약

`/org/submissions/new` 단일 라우트의 행사 등록 위저드(유형 선택 → 기본 정보 → 위치 영역 → 확인·제출) 셸과 앞 2개 스텝을 구현한다. 위저드 스토어·스텝 전이·확장점(스위치 한 파일 — MSG-516 EventRoomBodySwitch 선례)이 여기서 성립해 위치 스텝(MSG-547)·최종 검토(MSG-548)·재신청 수정 모드(MSG-550)가 얹힌다. 스텝 1은 유형 카드 3종(지역축제·팝업스토어·이벤트) + 이벤트 선택 시 시(市)→소속 이벤트(parentOccurrenceId) 선택 모달, 스텝 2는 유형별 기본 정보 폼 + 대표 이미지 presign 업로드다.

## 코드베이스 대조 결과 (스펙의 전제 — 전부 실측)

- **생성 SDK에 필요한 API가 전부 있다 (재생성 금지)**:
  - `submit`(POST /api/org/event-submissions) — body `EventSubmissionCreateRequestDto`: `type(FESTIVAL|POPUP|EVENT)` · `parentOccurrenceId?`(EVENT 전용 필수) · `title` · `organizerName` · `startsOn`/`endsOn`(KST 날짜, 종료일 오늘 이전 13433) · `operatingHours?`(POPUP 전용) · `programDescription?`(FESTIVAL 전용) · `participationMethod?`(EVENT 전용) · `description` · `imageS3Key`(필수) · `locations?`. 유형 밖 항목이 실리면 13439. **제출 자체는 MSG-548 범위** — 이 티켓은 DTO 필드를 수집·보관까지만.
  - `issueImagePresignedUrl`(POST /api/org/event-submissions/image/presigned-url) — 요청 `{extension(점 없이), contentType(확장자와 쌍), contentLength}`, jpg·jpeg·png만·10MB 상한. 응답 `{uploadUrl, s3Key, expiresInSec}` → S3 직접 PUT 후 s3Key를 imageS3Key로.
  - **이벤트 후보 조회 = `getApprovedEvents`(GET /api/org/events)** — 티켓 추정(event-occurrences 계열)과 달리 org 전용 API가 따로 있다. query `{city?, name?}`, 응답 `OrgEventListResponseDto { totalCount, cityCounts[{cityName, count}], events[{occurrenceId, name, cityName, startsAt, endsAt, placeLabel|null}] }`. API 주석: "참여 신청 모달의 재료 — 시·도 칩, 시·도별 건수, 이벤트 목록". totalCount·cityCounts는 필터 무관 고정, events에만 city·name 적용. 끝나지 않은 회차만 담기고 노출 시작 전 예정 회차도 담긴다. 없는 시·도 값은 빈 목록(실패 아님).
  - 생성 옵션: `getApprovedEventsOptions`·`submitMutation`·`issueImagePresignedUrlMutation`·`resubmitMutation` 전부 `@tanstack/react-query.gen.ts`에 존재.
- `features/upload/api/s3-upload.ts`의 `uploadToS3(uploadUrl, file)` — 전역 fetch·Content-Type 서명 일치, 그대로 재사용 가능(cross-feature import는 MSG-411 `invalidateGridQueries` 선례 있음).
- 이미지 검증·presign 파라미터 도출의 구조 선례 = `features/profile/model/profile-image.ts`(중립 후보 `{name,type,size}` → 검증·`toPresignParams`, 플랫폼 File 무참조). 단 값이 다르다(프로필: webp 허용·5MB / 이번: jpg·jpeg·png·10MB) — 재사용이 아니라 **선례 답습 신규**.
- 스텁 `pages/org/OrgSubmissionWizardPage.tsx`는 `ConsoleStub` 한 줄 — `/org/submissions/new`와 `/org/submissions/:submissionId/edit` 공용(라우터 배선 완료, MSG-541). 콘솔 셸(`widgets/console-shell/ConsoleShell`)은 72px 레일 + 280px `ConsoleSidebar` + `<main class="p-10">` Outlet — **사이드바에 하단 슬롯이 없다**(질문 1의 근거).
- 스위치 확장점 선례 = `pages/map-home/ui/EventRoomBodySwitch.tsx`(mode→본문 스위치 한 파일, props로 재료 주입, 후속 티켓은 분기 한두 줄).
- 스텝 전이 순수 모델 선례 = `features/upload/model/upload-wizard.ts`(UploadStep 유니언 + 전이 판정 순수 함수, RN 재사용 대상 주석).
- 브랜치: `*MSG-546*` 로컬·리모트 모두 없음 — 신규 생성.

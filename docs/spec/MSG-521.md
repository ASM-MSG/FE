# MSG-521: 행사 첫 영상 올리기 — 빈 행사 위치 CTA를 기존 업로드 파이프라인에 연결

## 기획 요약

영상이 없는 행사 위치의 "첫 영상 올리기" CTA(MSG-518이 no-op 렌더까지 해둠)를 누르면 기존 업로드 모달 위저드(선택→하이라이트→미리보기, presign→S3 PUT→확정)가 그대로 열리고, 확정만 행사·위치로 귀속되게 한다. 업로드 완료 후 행사방의 위치별 영상 목록에 새 영상이 반영돼야 하며, 비로그인은 기존 업로드와 동일한 로그인 모달 게이트를 탄다. 위저드 자체 동작 변경은 금지 — 진입 맥락 추가만.

## 핵심 질문 판정 — 행사·위치 맥락 전달 방식 (hey-api 생성물 실측)

**확정 body 필드도, 좌표 기반 자동 귀속도 아니다 — 전용 확정 엔드포인트의 URL path가 귀속을 결정한다.** 생성물에 이미 있어 **api:generate 재실행 불필요, 블로킹 없음**:

- `POST /api/event-occurrences/{occurrenceId}/locations/{locationId}/videos` — sdk `upload1`, `types.gen.ts` `Upload1Data`(5466행~)
- body `EventVideoUploadRequestDto` = `s3Key`·`durationSec`(1~30초)·`recordedAt`(미래 시각 거부, 5분 오차 허용)만 — **lat/lng 없음, visibility 없음** (일반 확정 `POST /api/videos`와 다른 DTO)
- 응답 `EventVideoUploadResponseDto` = `videoId`·`gridId`(서버가 지정한 대표 격자)·`processingStatus`·`occupied`·`newBadges` — 일반 업로드 응답과 동형이라 격자 점령·뱃지 파이프라인도 서버가 처리한다. 같은 s3Key 재전송은 멱등
- 생성 헬퍼도 전부 존재: `upload1Mutation`·`getLocationVideosInfiniteQueryKey`·`getLocationsQueryKey`

presign은 행사 전용이 없다(`/api/org/event-submissions/image/presigned-url`은 주최자 제출 이미지 전용). DTO 주석("presigned 발급 때 받은 S3 객체 키")에 따라 **기존 `issuePresignedUrl`(purpose 미전송=UPLOAD) 재사용** — 추정 1.

## 추정 및 질문 (2026-08-31 사용자 승인 — 5건 전부 기본안대로 확정)

1. **presign 재사용**: 행사 영상 전용 presign이 생성물에 없어 기존 `issuePresignedUrl`(purpose 미전송=UPLOAD)을 재사용한다. 서버가 행사 확정에 별도 purpose를 요구하면 실측 400으로 드러난다 — 그 경우 재생성 금지 규칙에 따라 확인불가/블로킹 보고
2. **헤더 "+ 영상 올리기"도 범위 포함**: 티켓 [동작 요구]는 빈 상태 CTA만 언급하지만, MSG-518이 두 버튼 모두에 "MSG-521 확장점: upload1 연결" 주석을 남겼고 다른 소유 티켓이 없다(MSG-520은 재생·좋아요·댓글). 포함이 맞는지 확인
3. **카카오 리다이렉트 재개의 행사 맥락 영속**: `uploadIntentStorage`를 행사 맥락까지 영속하도록 확장한다(지목 격자 선례 — 미영속 시 리다이렉트 복귀 재개가 일반 업로드로 열려 뷰포트 중심에 오귀속). 대안: 행사 게이트는 재개 미지원(로그인 후 CTA 재클릭 요구 — 코드 최소). **영속 확장을 기본안으로 제안**
4. **위저드 내 행사 안내 문구**: Figma의 안내 배너("해당 축제에 영상이 자동으로 업로드돼요"·"행사 영상은 공개로 등록돼요")를 모달에 재현하지 않고, 기존 위치 라벨 슬롯에 "행사명 · 위치명"만 표기한다 — "위저드 자체 동작 변경 없음" 제외 범위 준수. 배너까지 원하면 범위 재확인 필요
5. **확정·완료 문구 유지**: 확정 버튼 "업로드하기"·완료 "업로드 완료!" 등 기존 문구 그대로(Figma CTA "영상 올리기"로 바꾸지 않음 — 위저드 공용 문구라 모드 분기 최소화). 완료 안내 "영상이 지도에 등록됐어요"도 행사 업로드에 참(서버가 대표 격자에 저장)

## 리스크

- **서버 승인 행사 0건** (BE 시딩 MSG-500 대기) — 실서버 행사 경로 실동작은 확인불가 판정 예정. fetch 스텁 검증으로 대체, 시딩 후 재확인 권장 (MSG-517~519 동일 처지)
- **READY 폴링의 getPlayback 적용 여부 미확인** — `startReadyRefresh`는 `GET /api/videos/{videoId}/playback`으로 상태를 폴링하는데, 행사 영상 videoId에 이 엔드포인트가 동작하는지 서버 실측 불가(행사 0건). 응답 DTO가 일반 업로드와 동형(gridId·processingStatus)이라 동작한다고 추정하며, 실패해도 폴링은 조용히 멈추는 기존 설계라 회귀는 없다 — 확정 시점 무효화는 무조건 실행됨
- **업로드 마감(uploadClosesAt) 초과 확정의 developCode 미상** — UPLOAD_GRACE 종료 후 확정 시 서버 거부 코드가 명세에 없다. 티켓 AC대로 기존 finalize 실패 문구로 수렴시키고 전용 안내는 만들지 않는다
- **MSG-520 병렬 충돌면**: `EventRoomBodySwitch`·`EventVideoCard`·`use-location-videos-query`·widgets/video-mini-panel·좋아요(`/api/event-videos/{videoId}/helpful`)·댓글 코드 일절 무수정 계획 (AC 11로 감사). 무효화 키는 생성 헬퍼에서 직접 import해 MSG-518 파일을 건드리지 않는다
- **Figma 오탐 방지** (page-verifier 대조 기준):
  - Figma 15518:6850은 **388px 사이드 패널형 업로더**(전용 화면)를 그리지만, 티켓이 기존 **모달 위저드 재사용**을 명시 — 패널형 업로더는 의도적으로 구현하지 않는다. Figma 대조는 진입 버튼·모드 분기(라디오 미노출·위치 라벨)까지만
  - "촬영하기"(카메라 캡처) 버튼 — 웹 위저드에 없는 기능, 미구현 (티켓 범위 밖)

2. 행사 모드 `useUploadLocation` **활성 유지** 기각 — 확정이 좌표 미전송(URL path 귀속)이라 무의미한 네트워크, 교체 모드 `!replaceMode` 선례 확장
3. 두 버튼 배선 **props 관통** 기각 — `EventRoomBodySwitch` 수정이 필요해 MSG-520 충돌면 발생, 자급 컨테이너 관례 채택
4. 공용 테스트 헬퍼 `routeHappyPath` **직접 확장** 기각 — 기존 3 describe 스텁 표면 변경(수술적 변경 원칙), describe 로컬 `routeEventPath` 위임으로 대체
5. Figma 388px 패널형 업로더·촬영하기·"최대 60초"·안내 배너 2종 — 의도적 미구현(티켓이 모달 위저드 재사용 명시, durationSec 1~30 서버 계약과 모순되는 디자인 임시값)

### 확인불가 (BE 시딩 MSG-500 대기 — 시딩 후 재확인 권장)

- 실서버 행사 경로 전반 (승인 행사 0건 — 부산 bbox 실측)
- presign purpose 미전송이 행사 확정에 수용되는지 (거부 시 400으로 드러남 — 추정 1)
- `GET /api/videos/{videoId}/playback` READY 폴링의 행사 videoId 동작 여부 (실패해도 조용히 멈추는 설계라 회귀 없음)

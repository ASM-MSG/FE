# MSG-579: [모바일] 광역 줌에서 테마 칩 전환 시 직전 칩의 미션 목록이 그대로 표시됨

> 원문: https://soma17-msg.atlassian.net/browse/MSG-579 (하네스 생성, 2026-09-07 — 사용자 QA "경로추천인데 지역축제가 나온다" / "지역축제를 누르면 경로추천 코스가 뜬다")
> **수정 범위: `apps/mobile/src/features/map-home/api/` 3파일**(옵션 팩토리 신설 + 훅 배선 + 테스트). `apps/web`·`packages/**`·`map-query-policy.ts` 0줄.

## 기획 요약

경로추천 칩 아래에 지역축제(드론 라이트쇼)가 코스 카드로, 지역축제 칩 아래에 남파랑길·해파랑길 코스가 축제 카드로 뜬다. API 연결(칩→type) 오류로 보였으나 아니다.

## 0. 착수 실측 (develop `0055b0b`)

| 사실 | 실측 | 함의 |
|---|---|---|
| 칩→type 매핑 | `missionTypeParam` route→COURSE·festival→EVENT·popup→POPUP, 웹 `mission.ts`와 동일 | 요청 파라미터는 정상 |
| 서버 응답 | 같은 서버(api.fillmap.kr)에 웹 세션으로 COURSE 4회 호출 → 전부 `type: "COURSE"`(남파랑길 3·해파랑길 1·2) | 서버 필터 정상 |
| 재현 조건 | 광안리 zoom 16에선 두 칩 모두 정확. **bbox 한 변 0.5° 초과**로 줌아웃한 뒤 칩을 바꾸면 직전 칩 목록이 새 칩 모양으로 그려짐(양방향). 같은 화면의 집계 마커("부산 1")는 정확 | 목록 조회만 오염 |
| 원인 | `viewportQueryArgs`가 0.5° 초과에서 `enabled=false`. `@tanstack/query-core` 5.101.2 `queryObserver.js:265-274`는 비활성(pending·data 없음) 쿼리에도 `placeholderData` 함수를 부르고 인자로 **키·type 무관 `#lastQueryWithDefinedData`** 의 데이터를 준다. `mapQueryPolicy.placeholderData = keepPreviousData`라 직전 칩 목록이 그대로 반환 | 웹은 칩 활성 시 1km 고정 + 확정 영역 bbox라 이 경계에 도달하지 않는 모바일 전용 결함 |
| 선례 | `grid-aggregation-query.ts`가 같은 문제를 `unit` 기준으로 이미 풀었다(직전 쿼리 키의 unit이 같을 때만 placeholder, L13) | 같은 패턴을 `type` 기준으로 |

## 1. 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | `use-active-missions-query.ts`를 **옵션 팩토리(`active-missions-query.ts`) + 얇은 훅**으로 나눈다(MSG-426 2파일 구조). placeholder 규칙은 팩토리에 | 훅은 `auth-session`(expo-secure-store)을 끌고 와 vitest에서 열 수 없다 |
| D2 | `placeholderData = (prev, prevQuery) => enabled && prevQuery.queryKey[0].query.type === query.type ? prev : undefined` — **같은 칩(type)의 bbox 이동 중에만** 직전 목록 유지. 비활성이거나 type이 다르면 비운다 | keepPreviousData의 원래 목적(같은 칩 이동 깜빡임 방지)은 지키고 오염 경로 둘(비활성 구간·칩 전환 순간)만 막는다 |
| D3 | `map-query-policy.ts` 무수정 | 웹 복제본(parity 테스트). 정책을 펼친 뒤 placeholder만 덮어쓰는 grid-aggregation 관례 |
| D4 | `useHomeMissions`에서 DTO `type` 방어 필터는 넣지 않는다 | 원인 지점이 아니고, 서버가 type을 지키는 것을 실측 |

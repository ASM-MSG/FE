# MSG-542: ORG 인증 플로우 — 콘솔 로그인 · 첫 로그인 비밀번호 강제 설정 · 비밀번호 재설정 요청/발송 완료

## 기획 요약

행사 운영자가 관리자 발급 LOCAL 계정으로 콘솔에 들어오는 인증 전체 여정을 실구현한다. MSG-541이 세운 라우트 골격·가드·mustChange 게이트 위에서, 스텁 3장(`OrgLoginPage`·`OrgPasswordSetupPage`·`OrgPasswordResetPage`)을 로그인 → (첫 로그인이면) 비밀번호 강제 설정 → 홈 착지, 그리고 재설정 요청 → 발송 완료 → 링크 진입(새 비밀번호) → 로그인 안내의 실화면으로 교체한다. 로그인 성공 후 role별 착지 분기(ORG → `/org`, ADMIN → `/admin/review`)도 이 티켓 몫이다(MSG-541 추정 4의 위임).

## 코드베이스 대조 결과 (스펙의 전제)

- **로그인 API 호출은 이미 있다** — `features/auth/api/use-auth-mutations.ts`의 `useEmailLogin`(MSG-352)이 `POST /api/auth/login` SDK 직접 호출 + `X-Device-Id` 보관 + accessToken 스토어 저장 + `queryClient.clear()`까지 수행한다. **캐시 clear가 곧 세션 전환이다** — KAKAO 세션의 getMe 캐시가 비워지고 다음 getMe가 ORG role을 돌려준다. 이 티켓은 로그인 훅을 새로 만들지 않는다.
- **mustChange 강제 이동은 이미 배선돼 있다** — `app/console/use-must-change-gate.ts`(MSG-541 AC 9)가 콘솔 보호 라우트 어디로 진입해도 `/org/password/setup`으로 보낸다(착지 경로 자신·로딩·조회 실패는 null). 로그인 페이지가 status를 따로 조회할 필요가 없다 — 착지만 시키면 게이트가 처리한다.
- **비밀번호 API 3종은 생성 SDK에 전부 있다**(재생성 금지 — MSG-541이 독점 완료): `setInitialPasswordMutation`·`requestResetMutation`·`resetPasswordMutation`(react-query.gen), `getStatusQueryKey`/`getStatusOptions`. 응답 헤더가 필요 없어 생성 mutation 옵션을 그대로 쓸 수 있다(useEmailLogin과 달리 SDK 직접 호출 불필요).
- **서버 비밀번호 정책 (openapi request DTO 실측)**: `newPassword`는 `minLength: 8, maxLength: 64, pattern: ^(?=.*[A-Za-z])(?=.*\d).+$` — "영문과 숫자를 각각 하나 이상 포함한 8~64자". `PasswordResetRequestDto.email`은 `format: email, maxLength: 255`. `PasswordResetConfirmRequestDto`는 `token`(재설정 링크의 token 쿼리 값) + `newPassword`.
- **서버 명세의 동작 의미 (openapi description 실측)**:
  - `reset-request`: 계정이 있든 없든 **항상 같은 성공 응답**(가입 여부 은닉). 재요청 시 이전 링크 즉시 무효. 링크 유효 30분.
  - `reset`: 토큰은 1회용. **성공 시 그 계정의 모든 기기 로그인·기발급 액세스 토큰 즉시 무효**.
  - `initial`: 이미 설정을 마친 계정은 **developCode 2446** 거절(→ 비밀번호 변경 화면 안내), 소셜 계정은 **2445** 거절. 성공 시 강제 변경 상태 해제, 남은 재설정 링크 폐기, 로그인 세션 유지.
  - 로그인 실패·reset 토큰 만료/무효의 developCode는 **미문서화** — `ApiError`(status·developCode·message)의 서버 message로 안내한다(리스크 참조).
- **라우트 구조 (router.tsx 실측 — 수정 금지)**: `/org/login`·`/org/password/reset`은 `ConsoleRoot`(noindex) 바로 아래 **셸 밖** 공개 라우트 — Figma의 전면 센터 레이아웃과 정합. 반면 `/org/password/setup`은 `OrgConsoleLayout`(RequireOrgRole > ConsoleShell) **안** Outlet에 렌더된다 — Figma는 셸 없는 전면 레이아웃이라 어긋난다(추정 2·Figma 오탐 방지).
- `LoginResponseDto`에 `role`(USER|ORG|ADMIN)이 있다 — 착지 분기는 로그인 응답에서 바로 읽을 수 있다(getMe 대기 불필요). role의 정본은 getMe(MSG-541 추정 1)라는 원칙과 충돌하지 않는다 — 착지 판정 1회용으로만 쓰고 persist하지 않는다.
- pages가 `@/app`을 import하는 선례 있음(`ProfilePanel`·`DexPanel` 등) — 페이지에서 `CONSOLE_ROUTES` 읽기는 경계 규칙 안.
- 테스트 인프라: `src/test/console-session.ts`(role+mustChange fetch 스텁, MSG-541)·`stub-fetch`·`envelope-response` 재사용 가능.
- zod·react-hook-form 등 폼 라이브러리 없음 — 기존 관례대로 수제 폼 + 순수 검증 함수.
- MSG-542 브랜치는 로컬·리모트 모두 없음(신규 생성).

## 웨이브 1 공통 규칙 (위반 금지 — 스펙 구속)

- `app/router.tsx`·`app/console-routes.ts`·`shared/api/generated/**` 수정 금지. 재생성 금지.
- 이 티켓 소유 교체 파일은 `pages/org/OrgLoginPage.tsx`·`OrgPasswordSetupPage.tsx`·`OrgPasswordResetPage.tsx` 3개뿐. 신규 파일 추가는 자유(아래 계획), 병렬 티켓(546·545·552·554) 소유 파일 접촉 금지.
- 콘솔 셸·가드·`use-must-change-gate`·`use-session-role`은 MSG-541 산출물 재사용(훅 본체 수정 없음 — 테스트 조임만, 환류 4).
- `docs/STATUS.md`는 한 줄 append만.

1. **재설정 메일 링크의 URL 경로** — openapi는 파라미터명이 `token`(쿼리)인 것만 명시한다. 서버 메일 템플릿이 실제로 `https://{호스트}/org/password/reset?token={token}`으로 링크하는지 BE 확인이 필요하다. 다르면 FE가 맞출 수 없다(라우트 신설 불가). → **BE 확인 요청** (FE는 이 형식을 전제로 구현).
2. **setup 화면의 렌더 위치** — Figma(15836:357)는 셸 없는 전면 센터 레이아웃인데, 라우트가 `OrgConsoleLayout`(레일+사이드바+본문) 안에 있고 router.tsx는 수정 금지다. **기본안: 셸 본문 영역 안 센터 정렬 카드**(사이드바가 보이지만 게이트가 다른 메뉴 진입을 되돌리므로 기능상 무해). 대안은 페이지가 `fixed inset-0` 전면 레이어로 셸을 덮는 것(Figma 충실, 구조는 편법). → 기본안 승인 요청.

**추정 (이견 없으면 이대로):**

3. **로그인 화면 상단 "‹ 행사 운영자 안내" 백링크는 이번 티켓 생략** — 대상 화면(행사 운영자 안내)이 웨이브에 없고 유저 앱 진입 링크는 MSG-555 몫. 재설정 화면의 "‹ 행사 운영자 로그인" 백링크는 대상이 있으므로 구현한다.
4. **로그인 성공했지만 role이 ORG·ADMIN이 아니면(USER 등) 착지하지 않고 폼에 안내** — "일반 회원 계정으로는 콘솔을 이용할 수 없습니다" 류. MSG-541 추정 3이 "권한 없음 안내 문구는 MSG-542 몫"으로 위임한 지점이며, 가드 회송으로 로그인 화면에 온 USER 세션에도 같은 안내를 보여준다(가드 수정 없이 `useSessionRole`로 판별).
5. **이미 콘솔 세션(ORG·ADMIN)인 상태의 `/org/login` 접근도 폼을 그대로 렌더**(자동 회송 없음) — 티켓이 "세션이 있어도 폼이 정상 동작"을 요구하는 방향과 정합. 재로그인·계정 전환 용도.
6. **발송 완료 화면의 보낸 시각·유효 기간은 클라이언트 제출 시각 기준 계산**(+30분) — 서버 응답에 시각 정보 없음(200 unknown). Figma의 "2026. 9. 18. 10:24"는 디자인 예시값.
7. **reset 성공 시 로컬 세션 정리(auth-store 초기화)** — 서버가 전 기기 세션·액세스 토큰을 무효화하므로 스토어에 남은 토큰은 죽은 값이다. 로그아웃 API는 호출하지 않는다(세션이 이미 서버에서 소멸).
8. **충족 게이지는 강도 측정이 아니라 규칙 충족 기반 단순 표시** — 3개 요건(길이·영문·숫자) 충족 비율. Figma의 녹색 진행 막대를 이렇게 해석한다.
9. **2445(소셜 계정) 거절은 일반 오류 안내로 수렴** — 콘솔 로그인 경로로 소셜 계정이 initial에 도달하는 시나리오가 사실상 없어 전용 화면을 만들지 않는다(서버 message 표시).

## 리스크

- **로그인 실패·reset 토큰 오류의 developCode 미문서화** — openapi에 2445/2446(initial)만 명시. 로그인 자격 불일치·토큰 만료/무효는 서버 봉투 message를 그대로 표시하고 코드 분기를 만들지 않는다. 실서버 검증에서 message 품질이 나쁘면 FE 고정 문구로 교체하는 후속 여지.
- **reset-request는 가입 여부와 무관하게 항상 성공** (서버 은닉 정책) — "등록되지 않은 이메일" 오류를 FE가 표시할 수 없다. 발송 완료 화면이 항상 뜨는 것이 정상 동작이다 — 검증에서 결함으로 오탐 금지.
- **재설정 링크 URL 형식은 BE 협의 전까지 전제** (질문 1) — 어긋나면 서버 메일 템플릿 수정으로 해소해야 한다(FE 라우트 신설 불가).
- **role·mustChange 실계정 라이브 검증 제약** — MSG-541과 동일하게 서버 ORG/ADMIN 실계정이 없으면 vitest+스텁 대체(검증 프로파일 참조).
- **`use-must-change-gate.test.tsx` 수정은 MSG-541 산출물 접촉**이지만 병렬 티켓(546·545·552·554) 소유 파일이 아니고, 오케스트레이터 지시(환류 4 반영)에 따른 조임이다 — 훅 본체는 불변이라 병렬 충돌 면이 없다.
- **Figma 오탐 방지** (page-verifier 대조 기준):
  - `tourism@busan.go.kr`(로그인 입력값·발송 완료 이메일)·"2026. 9. 18. 10:24"·"10:54까지" — 디자인 시점 예시 데이터. 하드코딩 금지, 실입력·실제출 시각으로 대체. 단 재설정 요청 입력의 `name@organization.go.kr`은 실제 placeholder 속성 값으로 사용한다.
  - 로그인 상단 "‹ 행사 운영자 안내" 백링크 — 미구현(추정 3). 부재는 결함이 아니다.
  - `/org/password/setup`이 콘솔 셸 안에 렌더되는 것(사이드바·레일 노출) — Figma 전면 레이아웃과의 차이는 의도(질문 2 기본안). 본문 내 카드 구성만 15836:357과 대조한다.
  - reset 링크 진입(새 비밀번호 입력) 화면은 **Figma 노드가 없다** — 15836:357의 폼 구성(NewPasswordFields)을 준용하고 문구만 재설정 맥락. 별도 디자인 대조 비대상.
  - 충족 게이지는 규칙 충족 기반 단순 표시(추정 8) — 강도 알고리즘 부재는 결함이 아니다.
  - 문의 이메일 `contact@fillmap.kr`(로그인)·`support@fillmap.kr`(재설정) — Figma 문구 그대로 표기(실동작 mailto 여부는 빌더 재량, 검증 비대상).

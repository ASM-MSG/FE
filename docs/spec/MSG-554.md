# MSG-554: 관리자 승인 행사 관리 — 노출 중/예정/종료 목록 · 노출 중지(사유 필수)

## 기획 요약

승인되어 지도에 노출 중인 행사를 관리자가 모니터링하고 문제가 있으면 노출을 중지하는 `/admin/events` 화면. 상태 탭(노출 중/예정/종료 + 카운트) + 목록 테이블 + 행 선택 시 우측 상세 카드 구성이며, "지도에서 보기"로 유저 지도를 확인하고 "노출 중지"는 사유 필수 모달 → `POST /api/admin/events/{submissionId}/unpublish`로 확정한다. 노출 중지 후 재개 조작은 API가 없어 제외 범위다.

웨이브 1 (선행 MSG-541 머지됨, 병렬: MSG-545·552). **`app/router.tsx`·`app/console-routes.ts`·`shared/api/generated/**` 수정 금지, `widgets/console-shell`·`console-config` 무수정, 병렬 티켓 소유 파일 비접촉. 이 티켓 소유 스텁 = `pages/admin/AdminEventsPage.tsx`.**

## 코드베이스·API 대조 결과 (스펙의 전제 — 전부 2026-09-01 실측)

- **목록 API**: `getEvents`(GET /api/admin/events, 생성 SDK `getEventsOptions` 존재). query `status?`(EXPOSED·UPCOMING·ENDED, 기본 EXPOSED)·`page?`(0부터)·`size?`(1~100). 응답 `AdminApprovedEventListResponseDto` = `exposedCount`/`upcomingCount`/`endedCount`(탭 무관 전체 집계 — 뱃지에 그대로 사용) + `totalElements`/`page`/`size` + `events[]`(시작일 최신순 고정). 항목 `AdminApprovedEventItemResponseDto` = `submissionId`·`approvalNo`·`submissionNo`·`type`(FESTIVAL|POPUP|EVENT)·`title`·`organizerName`·`orgName|null`·`startsOn`·`endsOn`·`status`(KST 오늘 기준 파생 — 종료일 당일까지 노출 중)·`unpublished`·`unpublishedAt|null`·`unpublishReason|null`. **승인일·위치/칸 요약 필드가 없다** — Figma·티켓의 테이블 "위치 요약·승인일" 칼럼을 목록 API만으로 채울 수 없다(질문 1). 중지된 행사도 탭에 그대로 남고 unpublished로 구분된다(서버 doc 명시).
- **중지 API**: `unpublish`(POST …/unpublish, `unpublishMutation` 존재). body `AdminEventUnpublishRequestDto { reason: string }`(운영자에게 그대로 발송). 응답 `{ submissionId, unpublishedAt, emailSent }` — **emailSent=false여도 중지는 유지**(재발송 API 없음). 에러: 404(13430) 없거나 미승인, **409(13453) 이미 중지**.
- **상세 재료**: 티켓 명시 API는 위 2종뿐이나, 상세 카드의 대표 이미지·승인일·노출 범위 요약은 목록 DTO에 없다. `getSubmission1`(GET /api/admin/event-submissions/{submissionId}, `getSubmission1Options` 존재 — 심사 상세)이 `imageUrl`(presigned)·`locations[]`(order·zoneName·regionName·`cellCount`·`areaRects[]`)·`exposureRect`·`history[]`(status·changedAt — APPROVED 행에서 승인일 파생)를 제공한다. submissionId가 승인 행사 식별자와 동일(= 신청 id)이라 그대로 조회 가능(관리자 조회는 존재 은닉 없음, 404 13430). → 상세 카드는 **선택 행(목록 항목) + getSubmission1 합성**으로 채운다(추정 2).
- **노출 범위 요약 산식**: n곳 = `locations.length`, 사각형 n개 = Σ `areaRects.length`, 총 n칸 = Σ `cellCount`.
- **콘솔 기반(MSG-541)**: `/admin/events` 라우트·가드(RequireAdminRole)·셸·`ADMIN_CONSOLE` 메뉴("승인 행사")까지 전부 존재. 스텁 `AdminEventsPage.tsx`는 `ConsoleStub` 한 줄 — 본문만 교체하면 된다. 테스트는 `src/test/console-session.ts`(ADMIN role 스텁 세션) 재사용 가능.
- **유저 지도 딥링크 없음**: `useSearchParams` 사용처 0 (apps/web 전수 grep). "지도에서 보기"가 행사 위치로 이동하려면 유저 지도에 진입 파라미터 신설이 필요하다(추정 3). 좌표 변환 재료는 `entities/cell/model/grid.ts`(`cellCenterAt`·`gridNodeAt` — EPSG:5179 인덱스→위경도, `exposureRect`의 min/max GridX·Y 중심 산출 가능)가 이미 있다.
- **ui-web 재사용 가능**: `Button`·`DialogShell`(모달)·`Skeleton`(로딩)·`RetryNotice`(실패+재시도)·`Thumbnail`(대표 이미지 — 폴백 내장)·`cn`. **Tabs·Table·상태 배지·Textarea는 ui-web에 없다.** `Chip`은 active 시 Check 아이콘을 강제해(Figma 탭 필은 체크 없음, 모바일 MSG-423과 같은 기각 사유) 탭으로 부적합 — 로컬 구현.
- **MSG-554 브랜치 없음** (로컬·리모트 조회 0건) — 신규 생성.

3. **[추정 — 확인 필요] "지도에서 보기" = 새 탭 `/?focus={lat},{lng}` 딥링크 신설**: 유저 지도에 진입 파라미터가 없어(실측) 신설 없이는 "해당 행사가 노출된 지도 확인"이 성립하지 않는다(기본 진입은 항상 서면/이전 위치). 방식은 티켓이 스펙 재량으로 위임. 좌표는 상세 `exposureRect` 중심을 `cellCenterAt`으로 변환. **map-home 파일 1개 접촉이 필요**하다 — 이를 피하려면 대안 B(파라미터 없이 새 탭 `/`만 열기, 접촉 0이지만 행사 위치로 이동 불가). → **A/B 택일 확인 요청** (스펙은 A 기준으로 작성, B 채택 시 AC 6을 "새 탭으로 유저 지도가 열린다"로 축소).

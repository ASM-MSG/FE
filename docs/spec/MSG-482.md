# MSG-482: [모바일] "알림 받기" 토글이 다루는 알림 카테고리를 서버 8종으로 맞춘다 (웹 티켓의 모바일 재해석)

## 기획 요약
서버 알림 설정 카테고리는 8종(BADGE·HOTZONE·REMIND·VIDEO·WEEKLY·FRIEND·MISSION_NEARBY·EVENT, MODERATION은 거부 불가라 제외)인데 FE는 MSG-426 시점의 5종만 읽고 쓴다. 웹 설정 화면은 MSG-477에서 삭제됐으므로 남은 소비처인 모바일 프로필 "알림 받기" 단일 토글이 8종 전부를 표시 파생·일괄 PATCH 하게 한다. 화면 변경 0 — 상수와 그 소비 계약만 바뀐다.

## 코드베이스 현황
- `apps/mobile/src/features/profile/model/notification-toggle.ts` — `NOTIFICATION_CATEGORIES` 5종 리터럴, `readPreferences`(누락 → true 병합)·`deriveMasterToggle`(some)·`applyMasterToggle`(전 종 동일 값).
- `api/use-notification-toggle.ts` — `NOTIFICATION_CATEGORIES.map(PATCH …/preferences/{category})`, 낙관·롤백. 상수만 바뀌면 자동 추종.
- 생성 타입 `CategoryPreferenceDto["category"]`는 이미 8종 유니언 — **SDK 재생성 불필요**.
- 서버 응답은 항상 8종 전부(저장 행 없는 것은 true 합성)라 "부재 처리" 경로는 안전망일 뿐이다.
- 웹: preferences 소비처 0 (MSG-477). 웹 변경 없음.

## 결정
- **MISSION_NEARBY 포함**: 기기 로컬형이라 앱이 아직 발화 구현이 없지만(FR-NOTI-16 앱 몫 미착수) 서버 설정 행은 존재하고 "알림 받기 OFF = 전부 끔"이라는 마스터 토글 의미상 포함이 맞다. 나중에 앱이 발화를 구현할 때 이 설정을 읽으면 된다.
- **세분 토글 화면은 만들지 않는다**: MSG-429 결정("세분 설정은 단일 토글로 갈음")과 이 티켓의 "간단한 것부터" 지시에 따른다. 티켓 완료 조건 "8종 전부 조작"은 단일 토글로 8종을 일괄 조작하는 것으로 충족한다. 카테고리별 개별 토글 화면은 후속(지라 코멘트로 환류).
- 리터럴 배열 대신 `Record<NotificationCategory, true>` 키에서 배열을 파생: 다음 서버 확장이 조용히 지나가지 않게 컴파일 타임 누락 검출.

## 작업 로그
- **범위 재해석**: 티켓은 웹 `/profile/notifications`를 지목하지만 MSG-477 ①에서 삭제됐다. preferences API의 유일한 FE 소비처인 모바일 "알림 받기" 단일 토글(MSG-426)이 같은 5종 리터럴을 써 결함이 그대로 살아 있었다 → 모바일 수정. 웹 변경 0.
- **변경**: `NOTIFICATION_CATEGORIES` 5종 → 8종. 리터럴 배열 대신 `Record<NotificationCategory, true>`의 키에서 파생해 다음 서버 확장이 컴파일 에러로 드러나게 했다(MSG-416·418·442가 조용히 지나간 재발 방지). 테스트 3파일 기대값 8종, `profile-screen.tsx`는 주석만.
- **검증**: vitest 94/94, typecheck·lint·format·duplication 통과. Android 실기 ON(권한 프롬프트 → Allow) → OFF → 재진입 OFF 유지 → ON. 실기에서 PATCH 건수는 관측 불가라 훅 테스트의 요청 캡처(8건)로 닫음.
- **검토한 대안**: ① 서버 응답의 카테고리 목록을 그대로 순회(하드코딩 제거) — preferences 미로드 시 PATCH 대상이 없어지고 낙관 기록도 응답 의존이 돼 기각. ② 카테고리별 개별 토글 화면 — MSG-429 "세분 설정은 단일 토글로 갈음" 결정 유지, 후속으로 환류.
- **MISSION_NEARBY 포함 결정**: 앱의 로컬 발화(FR-NOTI-16)는 미구현이지만 마스터 토글 의미상 포함. 발화 구현 티켓이 이 설정을 읽으면 된다.
- WAIVED·확인불가: 없음.

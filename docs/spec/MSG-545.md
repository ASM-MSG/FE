# MSG-545: 운영자 홈 — 내 행사 신청 현황 대시보드 + 신청 없음 빈 상태

## 기획 요약

운영자 로그인 후 첫 화면(`/org`). `GET /api/org/event-submissions/my` 하나로 상태 카운트 카드 4종·최근 신청 목록·상태 필터 칩을 구성하고, 우측 요약 카드에 대표 신청(반려 우선)의 상태·반려 사유를 보여준다. 신청 0건이면 빈 상태 + 새 행사 등록 CTA. 상세·위저드 화면은 별도 티켓 — 이 티켓은 해당 스텁 라우트로의 라우팅만 배선한다. 추가로 MSG-541이 이 티켓으로 넘긴 콘솔 사이드바 실데이터(이메일·ORG 뱃지·행사 등록 권한 카드)를 비파괴 슬롯으로 채운다.

## 코드베이스·API 실측 (스펙의 전제)

- **`GET /api/org/event-submissions/my`** = 생성 SDK `getMySubmissions` / `getMySubmissionsOptions`(@tanstack). 응답 `EventSubmissionMyListResponseDto`:
  - `counts: EventSubmissionStatusCountsResponseDto` — **`inReview`·`approved`·`rejected` 3필드뿐, "전체" 필드 없음** (합산은 FE 몫 — 추정 2)
  - `submissions: EventSubmissionSummaryResponseDto[]` — 최신 제출 순, **페이지네이션 없음**(SDK 주석 실측 — 필터는 클라이언트 처리로 충분)
  - `EventSubmissionSummaryResponseDto` = `id`·`submissionNo`·`type`·`title`·`status`(**plain string** — enum 아님)·`startsOn`·`endsOn`·`updatedAt`. **위치 요약(위치 N곳·총 N칸)과 신청일·반려 사유가 없다** — Figma 오탐 방지·추정 4 참조
- **상태 값**: admin 큐 DTO가 `'IN_REVIEW' | 'APPROVED' | 'REJECTED'` enum(types.gen.ts:4584)으로 확정 — FE union의 근거
- **반려 사유·이력은 상세 API에만 있다**: `GET /api/org/event-submissions/{submissionId}` = `getSubmission` / `getSubmissionOptions`. `EventSubmissionDetailResponseDto.rejection: EventSubmissionRejectionResponseDto | null`(`reasonCodes`·`reasonText`, REJECTED일 때만), `history: EventSubmissionHistoryResponseDto[]`(발생 순, `changedAt`)
- **`GET /api/org/profile`** = `getProfile` / `getProfileOptions`. `OrgProfileResponseDto` = `email`·`contactName`·`contactPhone` — **조직명(orgName) 필드 없음**(orgName은 계정 발급 요청 DTO에만 존재, 실측) → 질문 1
- **console-shell 현황**: `ConsoleShell`(config 주입)·`ConsoleSidebar`(title+menu만 — 슬롯 없음)·`console-config.tsx`(`ConsoleConfig`에 `title`·`railLabel`·`rail`·`menu`). 사이드바 실데이터는 "후속 544·545 범위" 주석으로 명시돼 있다
- 콘솔 가드(`RequireOrgRole`)가 `/org` 세션을 보장하므로 페이지 쿼리에 별도 인증 게이트 불필요. 단 **ADMIN도 RequireOrgRole을 통과**하므로 `/api/org/profile`이 ADMIN에 실패할 수 있다 — 리스크 참조
- 재사용 가능 ui-web: `Skeleton`·`RetryNotice`·`Button`·`Chip`·`cn`. 봉투 언랩은 `shared/api/envelope.unwrapEnvelope`
- MSG-545 브랜치는 로컬·리모트 모두 없음(신규 생성). 현재 develop.

2. **전체 신청 = counts 3필드 합산 (추정)** — 응답에 전체 필드가 없다. `submissions.length`와 동치(페이지네이션 없음)지만 counts 기준으로 통일("상태 카운트는 counts DTO 사용" 티켓 문구 정합). → 이견 없으면 이대로
3. **대표 신청 선정 규칙 (추정)** — 티켓은 "반려 우선"만 명시. 목록 순서(최신 제출 순)상 첫 REJECTED → 반려 없으면 첫 행(최신 제출)으로 구체화. → 확인 요청
4. **반려 사유는 상세 API 병행 조회 (추정)** — 목록 응답에 사유가 없어(실측) 대표가 REJECTED일 때만 `getSubmission` 1건을 추가 조회한다. 이 훅은 MSG-549 상세 화면의 자산이 된다. → 이견 없으면 이대로
5. **요약 카드 일자 표기 (추정)** — 시안 "신청 2026. 8. 18. · 처리 8. 19."의 신청일·처리일이 목록 DTO에 없다. 상세 `history`(발생 순)의 첫 entry `changedAt`=신청, 마지막 상태 전이 `changedAt`=처리로 파생한다(상세를 어차피 조회하는 REJECTED 대표). **비반려 대표는 상세를 조회하지 않으므로 `updatedAt` 1개만 표기**한다. → 확인 요청
6. **미지 status 값 방어 (추정)** — 목록 DTO의 status가 plain string이라 미지 값은 칩 톤 없이 원문 라벨로 렌더하고 "전체" 필터에만 잡힌다
7. **필터 결과 0건 문구 (추정)** — 시안 없음. "해당 상태의 신청이 없어요" 수준의 한 줄 문구로 처리
8. **행 클릭 = 상세 스텁 라우팅 (오케스트레이터 지시 반영)** — 빈 상태 시안의 "신청을 선택하면…" 문구는 선택 상태머신이 아니라 빈 변형 문구로만 구현한다. 요약 카드는 항상 대표 신청(규칙 3) 고정
9. **정적 문구 2종 (추정)** — "운영자 문의 support@fillmap.kr"·"승인된 행사는 기존 행사방 데이터로…" 하단 안내는 FE 고정 문자열로 구현(시안 그대로). support@fillmap.kr이 실주소인지 확인 대상
10. **[질문] 사이드바 실데이터의 이번 티켓 포함 여부** — 셸 공유 파일 3개(`ConsoleSidebar`·`ConsoleShell`·`console-config.tsx`)를 만진다. 병렬 티켓(546·542·552·554)은 자기 페이지 스텁만 소유하고 셸 접촉 계획이 없어 **충돌 위험 낮음 → 포함을 권장**하나, 웨이브 1 이후(단독 후속 커밋)로 미루는 선택지도 있다. → 확정 필요

## 리스크

- **ADMIN 세션이 `/org` 진입 시 `/api/org/profile`·`/my` 실패 가능** — RequireOrgRole은 ADMIN도 통과시킨다(MSG-541). 서버가 ORG 전용으로 막으면 사이드바는 뱃지·메뉴만 남고(AC 10 실패 허용 경로), 본문은 RetryNotice로 수렴 — 결함이 아니라 서버 인가 정상 동작으로 판정한다
- **콘솔 세션 실계정 부재 가능성** — MSG-541 검증도 role 분기 일부를 vitest+스텁(`src/test/console-session`)으로 대체했다. 3-A 실동작은 스텁 세션(`console-session` 확장 — my 목록·상세·profile fetch 스텁 추가) 기반이 될 수 있다
- **status가 목록 DTO에서 plain string** — 서버가 새 상태를 추가하면 칩이 원문 라벨로 강등된다(추정 6 방어). 후속 환류 후보: 서버에 enum 명시 요청
- **Figma 오탐 방지** (page-verifier 대조 기준):
  - 목록 행 "기간·영역" 중 **영역 요약("위치 3곳 · 총 37칸"·"해운대 B-7 외 11개")은 미구현** — 목록 API에 위치 데이터가 없다(실측). 기간만 렌더하며 시안과의 이 차이는 결함이 아니다. 서버 필드 추가 환류 후보
  - 조직명 — 질문 1 확정 전 (b)면 미렌더. 시안 값 "부산광역시 관광마이스과"·"tourism@busan.go.kr"·목록 3행·카운트 3/1/1/1은 디자인 예시 데이터 — 하드코딩 금지
  - 요약 카드는 행 클릭 "선택"에 반응하지 않는다(추정 8) — 항상 대표 신청. 빈 상태 문구만 시안 채택
  - 비반려 대표일 때의 요약 카드 시안이 없다 — 사유 박스 없는 축소 변형(추정 5)은 시안 부재로 대조 비대상
  - 사이드바·레일 골격 자체는 MSG-541 검증 완료분 — 이번 대조는 신규 슬롯(조직 정보·권한 카드)과 본문에 한정

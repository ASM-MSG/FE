# MSG-516: 행사 기반 — hey-api 행사 API 반영 · 위치 기반 행사 칩(연결 캡슐) · 행사방 패널 셸 · 이벤트 도메인 골격

## 기획 요약

행사(이벤트) 웨이브 MSG-516~521의 뿌리 티켓(웨이브 1 단독). ① hey-api 스냅샷 재생성으로 행사 API를 들여오고(**재생성은 이 티켓 독점**), ② entities/event + features 이벤트 도메인 골격을 깔고, ③ 지도 홈 상단에 위치 기반 행사 칩(정본: "연결 캡슐" Figma 15806:3654)을 올리고, ④ 모든 행사 화면이 공유할 행사방 패널 셸(388px) + 모드 스위치 확장점을 남긴다. 개요/영상/빈/아카이브 본문은 MSG-517~519가 채운다. 웹 전용(apps/mobile 미포함).

## 코드베이스 실측 (스펙 전제)

- **행사 사용자 API 12경로는 이미 커밋 스냅샷에 있다** — MSG-488 재생성(d61e1cc) 때 유입돼 `sdk.gen.ts`에 `getOccurrencesInViewport`·`getOccurrenceDetail`·`getEventLocationsByGrid` 등이 이미 존재한다. 이번 재생성의 실변경분은 (a) `EventOccurrenceDetailResponseDto` 확장(`seriesId`·`notificationOn`·`previousOccurrences`·`uploadClosesAt`), (b) 신규 27경로(admin 이벤트 승인·org 운영자·auth/password 등 — 웹 사용자 앱 미사용, 전체 생성 처방이라 정상 유입).
- `GET /api/event-occurrences`: 뷰포트 bbox(swLat·swLng·neLat·neLng) 필수, **bbox 각 변 0.5도 상한**(초과 400/13401), 진행 중(LIVE) + 노출 기간(시작 2주 전~)에 든 예정(UPCOMING)만 반환, 정렬 시이름→시작일→id, 빈 범위는 빈 배열. **익명 200 실측**(2026-08-31, 부산 bbox → `{"developCode":200,"data":[]}`). D-day는 startsAt을 KST로 읽어 **클라이언트가 계산**(서버 명세 지시).
- 칩 DTO: `occurrenceId`·`title`("부산불꽃축제")·`cityName`("부산" — 시 칩 묶음 기준)·`startsAt`·`endsAt`·`status`(UPCOMING|LIVE 2값).
- 역지오코딩 `regionName`은 전체 경로("부산광역시 부산진구 부전2동") — 시 이름 축약 함수는 없다(신규 필요). 라이브 역지오코딩은 `useReverseGeocodeQuery`(500ms 디바운스, 익명 허용), 확정 지역은 `region-panel-store.displayedRegion`(장소 불러오기·칩 진입만 갱신).
- 상단 칩 바: `ThemeChipsBar`(pages/map-home/ui)를 `MapShell`이 홈 라우트에서 접힘 래퍼 밖에 렌더 — 접힘/미니 패널 위치 보정 포함. 좌측 패널 분기는 `panel-branch.homePanelKind`(순수) → `HomePanelSwitch`(렌더) 구조.
- 서버에 승인 행사 데이터가 아직 없다(부산 bbox 실측 빈 배열) — 실동작 검증은 스텁/시딩 필요.

## 추정 및 질문 (✅ 2026-08-31 사용자 승인 — "추정대로 승인": 아래 1~8 전부 추정안 채택 확정)

1. **칩 지역명 소스** — 티켓 문구가 "역지오코딩 **확정** 지역 재사용"과 "지도를 다른 시로 옮기면 바뀐다"를 함께 요구하는데, 확정 지역(`displayedRegion`)은 지도 이동으로 안 바뀐다(장소 불러오기·칩 진입만 갱신). **추정: 라이브 역지오코딩 결과(`useReverseGeocodeQuery`, 500ms 디바운스)의 시 축약을 쓴다** — "이동하면 바뀐다"를 충족하는 유일한 해석. 확정 지역을 쓰려면 "다른 시로 이동 시 갱신" 요구를 버려야 한다. 어느 쪽인가?
2. **행사 목록 bbox** — 지도 데이터 bbox 정본은 확정 영역(MSG-403 AC 12)이지만, 칩이 지도 이동을 따라가려면 뷰포트여야 한다. **추정: 뷰포트(디바운스) — 저줌 집계(MSG-410)와 같은 명시적 예외**로 기록.
3. **빈/실패 시 캡슐 자체 숨김** — 접힘 상태에 카운트 배지가 있는데 0건이면 눌러도 열 게 없다. **추정: 빈 배열·조회 실패·저줌 미발사 모두 캡슐 미렌더**(수용 기준 8). 접힘+`(0)` 표시를 원하면 알려달라.
4. **저줌(0.5도 초과) 처리** — 추정: 미발사+캡슐 숨김. 대안은 핫구역 집계처럼 bbox 클램프 조회(중심 기준 0.5도 절단 — 넓게 보면 중심 시의 행사만 담김). 미발사가 단순하고 서버 부하도 없어 추정으로 채택.
5. **행사방 진입 방식** — 추정: 홈 좌측 패널 상태 교체(URL 라우트 신설 없음 — 미션/코스 상세와 동일 패턴). 후속 티켓에서 딥링크 필요성이 생기면 그때 라우트화.
6. **행사방·테마 칩 공존** — 행사방이 열린 상태에서 테마 칩(핫구역 등)을 켜면? **추정: 테마 칩 활성화가 행사방을 닫는다**(panel-branch 우선순위상 상호 배타 — 유령 패널 방지). 반대로 테마 화면에서 세그먼트 클릭도 행사방으로 전환.
7. **셸 자리표시 문구** — 추정: "행사 정보를 준비 중이에요" 류 1줄(후속 티켓이 교체). 헤더 우측 ↗ 아이콘(Figma 15518:5707)은 용도 불명이라 이번 셸에서 제외(후속 티켓 몫).
8. **D-day 표기** — Figma상 UPCOMING만 "D-7", LIVE는 제목만. 추정으로 채택(수용 기준 6). D-0·당일 표기("D-day"?)는 `dDayLabel` 구현 시 "D-0"으로 통일 추정.

(웨이브 계획의 "스펙 단계 확인 4건" — 실시간 시청 인원 갱신 방식·아카이브 1개월 판정 주체·좋아요/댓글 범위·업로드 행사 귀속 — 은 전부 MSG-517~521 범위라 이 스펙에서는 다루지 않고 해당 티켓 스펙 단계로 넘긴다.)

## 리스크

- **티켓 전제와 코드 현실의 어긋남**: "행사 API 유입"의 사용자 경로 12개는 MSG-488 재생성 때 이미 들어와 있다. 이번 재생성의 실변경은 상세 DTO 확장 + admin/org/password 27경로다 — 재생성 독점 규칙 자체는 유효(상세 DTO가 바뀌므로 반드시 이 티켓에서 1회 실행).
- **서버에 승인 행사 없음**(부산 bbox 실측 빈 배열, 2026-08-31): 실동작 검증은 fetch 스텁 또는 BE 시딩(MSG-500 승인 행사 노출) 확인이 선행돼야 한다. 검증 리포트에 데이터 출처를 명시할 것.

# MSG-517: 행사 위치 개요 — 행사 선택 시 개요 패널 · 실시간 시청 인원 · 격자 클릭 소속 행사 표시

## 기획 요약

칩(연결 캡슐)에서 행사를 고르면 MSG-516이 남긴 행사방 패널 셸이 **위치 개요 모드**로 열리고, 행사명·기간·위치 목록과 **실시간 시청 인원**을 보여준다. 행사방이 열린 동안 지도에는 행사 위치 영역이 채색·라벨링되며, 그 격자를 눌러도 **소속 행사 표시만** 하고 상세(영상 피드)로는 들어가지 않는다. 웨이브 2 병렬 티켓(MSG-518 위치 영상·빈 상태, MSG-519 아카이브)의 소유 영역은 건드리지 않는다.

## 실시간 시청 인원 갱신 방식 — 폴링 30초로 확정 (티켓의 스펙 단계 확정 항목 ①)

hey-api 생성물(`shared/api/generated/sdk.gen.ts`) 실측 근거:

- **SSE/스트림 엔드포인트 없음** — 행사 관련 경로에 스트리밍 계약이 없다 (`core/serverSentEvents.gen.ts`는 hey-api 런타임 상비품일 뿐, 이를 쓰는 생성 SDK 함수 없음). 서버가 제공하는 수단은 GET 폴링뿐이다.
- `getViewerCount` — `GET /api/event-occurrences/{occurrenceId}/viewer-count`. "viewerCount 0은 아무도 없음(**표시**), null은 캐시 장애(**숨김**). 인증 없이 호출 가능." (`EventViewerCountResponseDto.viewerCount: number | null`)
- `heartbeat` — `POST /api/event-occurrences/{occurrenceId}/heartbeat`. "이벤트를 보는 동안 **30초 주기**로 보낸다. 마지막 신호가 **90초 이내**인 세션만 열람 인원에 센다. 비로그인은 `X-Viewer-Session` 헤더(공백 아님·최대 64자) 필수 — 없으면 400. 캐시 장애는 삼켜져 200이다."

**확정안**: 행사방 개요가 열려 있는 동안 ① `getViewerCount`를 TanStack Query `refetchInterval` **30초** 폴링(집계 창 90초·heartbeat 주기 30초와 정합 — 더 짧은 주기는 정밀도 이득 없이 부하만 늘린다), ② heartbeat를 **30초 주기 전송**(서버 처방 주기 그대로 — 이것이 있어야 웹 열람자 자신이 N에 잡힌다). 행사방을 닫으면 둘 다 중단. 폴링 실패·null은 인원 표시만 생략하고 다음 주기에 자연 재시도(개요 본문 무영향).

## 추정 및 질문 (2026-08-31 사용자 승인 완료 — 1~4 확정)

1. **[확정] 갱신 방식 = 30초 폴링** — 근거는 상단 섹션(SSE 부재·heartbeat 30초/90초 창). 사용자 승인.
2. **[확정] heartbeat 전송을 이 티켓 범위에 포함** — 행사방을 열어 둔 동안 30초 주기 전송. 이것이 없으면 웹 열람자가 "N명"에 영원히 잡히지 않아 기능이 반쪽이 된다. 서버 문서도 "이벤트를 보는 동안"이라 행사방 열람이 그 단위로 읽힌다. 사용자 승인(MSG-518로 미루지 않음).
3. **[확정] 비로그인 세션 id = sessionStorage UUID** — 탭 세션 단위 고유(브라우저 탭 2개면 2명으로 집계됨이 자연스럽다). 사용자 승인.
4. **[확정] 격자 클릭 소속 행사 표시는 행사방 열림 상태 한정** — Figma 정본이 이 상태만 제시하고, 위치 격자(`gridIds`)를 이미 손에 쥐고 있어 동기 판정이 가능하다. 평시(행사방 닫힘) 전 격자 클릭마다 `getEventLocationsByGrid` 비동기 조회를 거는 것은 범위·성능 확대라 제외했다(해당 API는 MSG-518의 피드 진입 경로이기도 하다). 사용자 승인(평시 확대 안 함).
5. **[추정] 시청 인원 문구 = "N명 보는 중"** (Figma 15518:5928 정본 — 파란 점 + 파란 텍스트). 티켓의 "지금 N명이 보고 있어요"는 예시 서술로 해석.
6. **[추정] 위치 카드는 표시 전용** — 클릭·선택은 MSG-518 소유라 이번엔 chevron만 그리고 onClick 없음(병렬 침범 방지).
7. **[추정] 모드 판정 status는 칩 값 유지** — 상세 응답의 서버 계산 status로의 교체(ARCHIVED 전환 등)는 아카이브 분기 주인인 MSG-519 몫.

## 리스크

- **서버 승인 행사 0건 실측**(부산 bbox 빈 배열, 2026-08-31 — BE 시딩 MSG-500 대기): 실동작 검증은 fetch 스텁(MSG-516 선례, 비침습 페이지 컨텍스트 스텁)으로 하고, 실데이터 확인은 **확인불가 판정** 예정. 리포트에 데이터 출처 명시.
- **heartbeat·행사 API의 익명 허용은 명세 서술 기반** — 생성물 security 표기는 bearer지만 서버 문서가 익명 허용을 서술(MSG-516 때 목록 API 무인증 200 실측). heartbeat 익명 400/401 실측이 다르면 로그인 한정으로 강등하고 환류.
- **공유 파일 병렬 충돌**: `event-room-store`·`EventRoomBodySwitch`·`grid-click-routing`은 MSG-518·519도 만질 수 있는 파일 — 이번 diff를 각각 필드 1개·case 1개·예외 1개로 최소화. 머지 순서에 따라 리베이스 시 재확인.
- 클릭 강조(보라 아웃라인) 색상이 design-tokens에 미등재일 수 있음 — 시안 실측 후 토큰 등재(event-tint 선등록 선례) 또는 기존 primary 계열 매핑, 구현 단계에서 `get_design_context`로 확정.
- **Figma 오탐 방지** (page-verifier 판정 기준):
  - **배너 이미지·D-7 뱃지 미구현이 정답** — 회차 상세 DTO에 배너 이미지 필드가 없다(위치 카드의 `imageUrl`은 참여형 위치 한정). 포켓몬 이미지는 디자인 샘플.

  - videos/empty/archive 모드 자리표시 잔존은 정답(MSG-518·519 범위).

### 검토한 대안 (기각 이유 포함)
- **SSE 구독** — 기각: 생성물에 행사 SSE/스트림 엔드포인트 부재(`serverSentEvents.gen.ts`는 런타임 상비품, 사용 SDK 0건). 서버 처방이 heartbeat 30s·집계 창 90s라 30초 폴링으로 정밀도 손실 없음.
- **쿼리 훅 쌍 공용 팩토리 추출**(`use-event-detail-query` ↔ `use-event-locations-query`, 19/23 클론) — 기각: 추출하면 MSG-518이 위치 훅 2종을 얹으며 수정할 공유 접점이 새로 생기고, 반환 타입·빈값 폴백(null vs [])이 달라 사용처 2곳짜리 4파라미터 추상화가 된다. 의도 중복으로 baseline 등재, **웨이브 2 머지 후 같은 꼴 훅 3개 이상이면 추출 재검토**.
- **event-tint hex 지도 채색** — 기각: MapCanvas가 셀 color에 자체 fillOpacity 0.4를 곱하는 계약이라 #E8F5FF는 백색 수렴. `semantic.primary` 전달이 Figma 정본(#06c 저투명)과 렌더 결과 일치.
- **평시(행사방 닫힘) 격자 클릭 소속 행사 표시** — 사용자 확정으로 제외: Figma 정본이 열림 상태만 제시, 평시는 전 격자 클릭마다 `getEventLocationsByGrid` 비동기 조회가 필요한 범위·성능 확대.
- **localStorage 세션 id** — 사용자 확정으로 sessionStorage(탭 단위 집계) 채택.
- **위치 영역 단일 사각 아웃라인**(시안 형태) — 기각: 영역 경계 폴리곤 합성은 MapCanvas 확장 필요, 기존 셀 단위 emphasized 테두리 재사용.

# MSG-449: [모바일] 하네스 모바일 검증 경로 추가 + dev client 빌드·실기 절차 정비

## 기획 요약

하네스(page-verification)의 "실동작 검증"이 웹 dev 서버 기준으로만 규정돼 있어, 모바일 티켓은 이 단계를 통째로 건너뛰고 정적 게이트(vitest·typecheck·lint)만으로 통과해 왔다 — 웨이브 0~3(MSG-419~431)이 전부 그랬다. 이 티켓은 ① page-verification에 **모바일 실동작 경로와 "확인불가" 판정 기준**을 추가하고, ② 2026-08-20 실기 시도에서 순차로 걸린 **함정 6가지 + 추가 실측 3건**을 재발 방지 런북으로 굳히고, ③ 빌드~설치~Metro~진입을 한 번에 수행하는 **스크립트**를 둔다. 앱 코드는 건드리지 않는다(문서·스킬·스크립트 + `.env.example` 주석 정정만).

**이 웨이브의 첫 티켓** — 후속 모바일 티켓(MSG-444·446)이 여기서 정한 절차로 검증하므로 먼저 머지한다.

## 추정 및 질문

1. **런북 파일명·위치**: `docs/MOBILE_RUNBOOK.md`로 추정. (대안: `docs/MOBILE_DEV.md`, `apps/mobile/README.md`) — `docs/`에 두면 CLAUDE.md 문서 지도에서 웹 문서들과 나란히 잡히고, 하네스가 읽는 문서 위치와 일치한다. **확인 필요**
2. **스크립트 위치**: `apps/mobile/scripts/dev-android.sh` + `pnpm --filter mobile android:dev`로 추정. 루트 `scripts/`를 신설하지 않는 이유는 웹 티켓과의 접촉면을 늘리지 않기 위함. **확인 필요**
3. **iOS**: 티켓 제외 범위 그대로 — 런북은 Android만 다루고, iOS는 "별도 티켓" 한 줄로 명시만 한다
4. **스크립트 기본 동작**: 파괴적 동작을 기본에서 뺀다고 추정 — `pm clear`는 로그인 세션까지 날리므로(SecureStore 토큰) 매번 돌리면 검증마다 재로그인이 필요해진다. 기본은 "설치 + Metro + 진입", 문제 시 `--clear`/`--clean`/`--purge-legacy` 플래그
5. **`.env.example`의 prebuild 안내 줄**: 기존 3번째 줄(`# 키를 넣거나 바꾼 뒤에는 npx expo prebuild -p android 재실행 + 네이티브 재빌드 필요`)은 사실이므로 **존치**한다. 지시된 교체 대상은 앞 2줄뿐
6. **에뮬레이터 실측 범위**: 이 워크트리에는 `android/`가 없어(gitignore) 스크립트 full path 실행은 prebuild + Gradle 빌드(수 분~십수 분)를 요구한다. 현재 에뮬레이터 2대가 붙어 있으므로 **사전 점검·Metro 기동·진입·플래그 분기까지는 실제로 실행해 확인**하고, Gradle 빌드 구간까지 완주할지는 시간을 보고 판단한다 — 미완주 시 리포트에 "부분 확인(사유)"으로 명시한다

## 리스크

- **문서 규칙 상한**: 하네스 원칙상 스킬은 500줄 이내([[harness-revfactory-principles]]). page-verification은 현재 ~120줄이라 여유가 있으나, 런북 본문을 스킬에 인라인하면 규칙을 위협한다 → **상세는 런북 파일에 두고 스킬은 포인터 + 판정 기준만** 담는다

- **실측 재료의 출처**: 함정 6가지·추가 3건은 전부 2026-08-20 실기/에뮬레이터 세션의 실측이다. 문서에 **관측 날짜와 기기**를 함께 적어, 나중에 Expo/Android 버전이 바뀌었을 때 스테일 판별이 가능하게 한다

### 실측 동작

**전 구간을 실제로 실행했다** — 이 티켓이 신설한 3-B 경로를 자기 자신에게 적용했다. 에뮬레이터 2대(`Pixel_8_2`·`Pixel_8`), Expo SDK 57.

`prebuild`(android/ 부재 → 자동) → Gradle `BUILD SUCCESSFUL in 1m 8s` → APK 설치 → Metro 8081 단독 기동 → `force-stop` → 패키지 명시 딥링크 → **온보딩 1장 정상 렌더**. 자동 게이트 6종 전부 통과(웹 177파일/1213테스트, 모바일 144파일/876테스트).

### 실행이 잡은 결함 4건

`bash -n`·리뷰로는 하나도 안 잡혔다.

1. **포트 점유 검사 오탐** — `lsof -ti tcp:8081`은 그 포트를 *듣는* 프로세스뿐 아니라 *연결한* 프로세스까지 매치한다. 에뮬레이터(`qemu-system-aarch64`·`netsimd`)가 잡혀 포트가 비었는데도 죽었다 → `-sTCP:LISTEN`
2. **cleanup이 Metro를 고아로 남김** — `npx expo start`는 Metro를 손자로 띄운다. 직계 자식만 죽이면 8081을 계속 물어 다음 실행이 막힌다 → `pkill -P` + LISTEN 정리
3. **`--device`가 에뮬레이터에서 실패** — 티켓 함정 5의 "모델명을 받는다"는 **물리 기기에만 맞다.** 에뮬레이터는 AVD 이름이다(`sdk_gphone16k_arm64` ✗ / `Pixel_8_2` ✓). 시리얼·모델명·expo 이름을 3열로 분리하고 에뮬레이터는 `adb emu avd name`으로 해석
4. **빌드·설치·Metro가 다 정상인데 화면이 검음** — `expo run:android`가 설치 직후 앱을 자동 실행하는데 그때는 Metro가 없다(`--no-bundler`로 분리했으므로). 그 인스턴스가 top으로 남으면 뒤이은 `am start`는 새 실행이 아니라 `onNewIntent` 전달로 끝나 다시 로드하지 않는다 → 진입 직전 `am force-stop`. **런북 함정 8 신설**

3·4는 티켓의 실측 절차를 그대로 따랐을 때 재현되는 것이라, 문서만 쓰고 끝냈으면 후속 모바일 티켓이 똑같이 걸렸다.

### 커밋 전 codex 리뷰가 잡은 정정 1건

**`expo prebuild --clean`은 SDK 57에 없는 플래그다.** `npx expo prebuild --help` 확인 결과 옵션은 `--no-clean`뿐이고,
**재생성이 기본 동작**이다. 티켓 본문과 초기 스펙(AC 15 문구 포함)이 `--clean`을 전제했지만 그건 잘못이었다.

실행해 보면 CLI가 알 수 없는 플래그를 조용히 무시한 채 정상 완료하므로(2026-08-20 실측이 성공했던 이유) 지금 당장 깨지지는
않는다. 그러나 런북에 있던 "`--clean` 없이는 안 풀린다"는 **사실과 반대**여서, 이걸 읽은 사람이 `--no-clean`을 붙이면
오히려 문제가 재현된다. 스크립트·런북의 모든 prebuild 명령에서 제거하고 의미를 뒤집어 적었다.

리뷰의 두 번째 지적(cleanup이 8081을 듣는 모든 프로세스를 죽인다)도 수용해, ppid 사슬로 `metro_pid`의 자손임을 확인한
PID만 죽이도록 고쳤다.

### push 전 codex 리뷰가 잡은 것 1건

리베이스로 들어온 develop 변경(codex 리뷰 시점을 push 전으로 이동)에 따라 한 번 더 돌렸고, P2 하나가 나왔다.

**같은 모델명 기기가 2대 이상이면 `--device`로 두 번째를 지정할 방법이 없었다** — awk가 첫 매치를 조용히 골라서,
expo 빌드 대상과 이어지는 시리얼 기반 `adb reverse`·`am start` 대상이 서로 다른 기기가 될 수 있었다.
`--device`가 **adb 시리얼**도 받게 하고(시리얼은 유일), 이름이 여러 대에 걸리면 거부하도록 고쳤다.

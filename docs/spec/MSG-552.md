# MSG-552: 관리자 행사 심사 큐 — 상태 탭 · 대기 목록 · 선택 신청 미리보기

## 기획 요약

관리자가 `/admin/review`에서 승인 전 신청들을 훑고 하나를 골라 상세 검토로 넘어가는 목록 화면. `GET /api/admin/event-submissions`로 상태 탭(심사 중/승인됨/반려됨 + 건수)과 신청 테이블을 그리고, 행을 선택하면 우측 미리보기 카드(대표 이미지·기간·위치 요약)가 채워지며, "상세에서 영역 검토"로 심사 상세(`/admin/review/:submissionId` — MSG-553 전까지 스텁)로 이동한다. 심사 상세·승인/반려 실행·승인 행사 관리는 제외 범위다.

## 코드베이스·API 대조 결과 (스펙의 전제 — 전부 실측)

- **목록 응답에 대표 이미지·영역 상세가 없다.** `AdminEventSubmissionItemResponseDto` = id · submissionNo · type(FESTIVAL|POPUP|EVENT) · status(IN_REVIEW|APPROVED|REJECTED) · title · organizerName(신청 폼 값) · orgName(계정 값, null 가능) · startsOn · endsOn · **locationCount** · createdAt(UTC) · updatedAt. **imageUrl 없음, 사각형 수·칸 수 없음.** → 미리보기 카드는 행 선택 시 상세 API 보강이 필연(추정 1).
- **대표 이미지는 상세 응답의 `imageUrl` = "열람용 presigned GET URL"** (`AdminEventSubmissionDetailResponseDto`, `GET /api/admin/event-submissions/{submissionId}` = 생성 SDK `getSubmission1`). 상세에는 locations 배열(각 항목: order·representativeGridId·zoneName/zoneCell/regionName(null 가능)·**cellCount**(≤81)·**areaRects[]**)도 있어 "사각형 n개(=areaRects 길이 합) · 총 n칸(=cellCount 합)"이 파생된다.
- **목록 API** `getSubmissions`: query `status?`(대소문자 무관, 기본 IN_REVIEW)·`page?`(0부터)·`size?`(1~100). 응답 `AdminEventSubmissionListResponseDto` = **counts(inReview/approved/rejected — 필터와 무관 항상 동봉)** · totalElements · page · size · submissions[]. **정렬은 접수 최신순 서버 고정.** 잘못된 status는 400(13455), page/size 범위 밖 400(13456) — FE는 정적 enum·상수만 보내므로 방어 불요.
- 생성 쿼리 옵션 존재: `getSubmissionsOptions`/`getSubmissionsQueryKey`, `getSubmission1Options` (`@tanstack/react-query.gen`). `unwrapEnvelope`(shared/api/envelope) 조합이 관례(MSG-323).
- SDK 주석: "organizerName은 신청 폼의 주최 기관, orgName은 계정 기관명 — 둘이 다르면 그 자체가 심사 신호". 대조 UI는 상세(MSG-553) 재료로 판단, 이 화면은 organizerName만 표시(추정 6).
- **콘솔 셸·가드는 완비**(MSG-541): `/admin/review`는 `RequireAdminRole` 안 `AdminConsoleLayout > ConsoleShell(ADMIN_CONSOLE)`의 Outlet에 이미 걸려 있고, 스텁 `pages/admin/AdminReviewQueuePage.tsx`(`ConsoleStub title="행사 심사"`)만 교체하면 된다. 본문은 `<main class="p-10">` 안, 폭 기준 = 1440 − 레일 72 − 사이드바 280.
- `CONSOLE_ROUTES.adminReviewDetail` = `/admin/review/:submissionId` 상수 존재 — 이동 시 id 치환만 하면 되고 router 수정은 없다(수정 금지 대상이기도 하다).
- **shared/format.ts 선례**: `formatRelativeTime`("N분 전")·`formatMonthDay`("7월 21일") 등 — 전부 `now` 주입 결정성 패턴, 단 **로컬 타임존 기준**이다. 티켓의 "오늘/어제/M.D HH:mm"은 KST 고정이어야 하므로 새 함수는 KST epoch 산술(upload-grass 선례)로 쓴다.
- ui-web `Chip`은 active에 Check 아이콘을 강제 — Figma 상태 탭(아이콘 없는 pill)과 어긋나 재사용 부적합, 탭은 페이지 로컬 버튼으로 만든다.
- ui-web `Thumbnail`은 onError·null 폴백이 격자 로고라 관리자 이미지 카드에 어색 — 미리보기 이미지는 로컬 `<img>` + 실패 시 `bg-surface` 자리표시로 처리(builder 재량, 폴백 존재가 기준).
- 검증 인프라: `src/test/console-session.ts`(getMe role 스텁)로 ADMIN 세션 브라우저/vitest 재현 가능(MSG-541 선례). 서버 실 ADMIN 계정 부재 시 MSG-541과 같은 대체 판정을 쓴다.
- MSG-552 브랜치는 로컬·리모트 모두 없음(신규 생성).

## 추정 및 질문

**추정 (스펙 반영 완료 — 이견 시 수정):**
1. **미리보기 카드는 상세 API 보강으로 채운다** — 목록 응답에 대표 이미지·사각형·칸 수가 없음(생성 타입 실측). 티켓이 조회 API를 목록 하나만 명시했으나 데이터상 행 선택 시 `getSubmission1` 조회가 필연. 대표 이미지 URL 전달 방식 실측 결과: **상세 응답 `imageUrl` = presigned GET URL**(key 아님, 목록에는 아예 없음).
2. **KST 함수는 `shared/format.ts`에 추가** — 크로스 도메인 표시 포맷 정본이자 RN 재사용 경로. MSG-551(아이디 변경 큐 접수 시각)·554도 쓸 가능성. 대안(features/admin-review/model 로컬)보다 공유 배치 선택.
3. **목록 도착 시 첫 행 자동 선택** — Figma가 항상 선택 상태를 그리고 있고 빈 미리보기 카드 상태의 시안이 없다. 탭 전환 시 선택 초기화 후 재선택.
4. **페이지네이션 미구현, size=100(서버 최대) 단일 페이지** — 티켓·Figma 모두 페이지네이션 없음. MVP 규모에서 상태당 100건 초과는 비현실 가정, 초과 대응은 후속 티켓 몫(totalElements는 응답에 있어 확장 여지 보존).
5. **type 라벨 매핑** = FESTIVAL→"지역축제" · POPUP→"팝업스토어" · EVENT→"이벤트 참여형"(생성 스키마의 한국어 주석 정본). Figma의 "공식 행사" 문구는 어느 type과도 일치하지 않는 디자인 플레이스홀더로 판정 — 하드코딩하지 않는다.
6. **주최 표시 = organizerName**(신청 폼 값). orgName(계정 값) 대조 노출은 심사 상세(MSG-553) 재료로 넘긴다 — SDK 주석의 "둘이 다르면 심사 신호"는 상세 검토 맥락.
7. **status 칩 톤** = 심사 중 warning · 승인됨 success · 반려됨 error(Figma에는 "심사 중" amber만 보임 — 나머지 두 상태 칩은 시안 부재, 시맨틱 토큰 관례 적용).
8. **다른 해 접수분도 `M.D HH:mm` 유지**(연도 미표기) — Figma 표기 그대로. 콘솔 특성상 연 단위 잔존 큐는 비현실 가정.
9. **탭 전환 중 counts 표시는 직전 데이터 유지 허용**(placeholderData 등 builder 재량) — 탭 뱃지가 전환마다 깜빡이며 사라지는 것 방지. 목록 영역은 로딩 표시.

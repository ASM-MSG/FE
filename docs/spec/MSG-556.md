### 1-3. 지도 표시 — 기존 `GridMap` prop 3종 재사용, 렌더 변경 0

`GridMap`은 이미 `themeColor` + `themeCells`(테마 색 채움 18%) + `hatchCells`(교집합 빗금) + `route={{ path, waypoints }}`(4px 폴리라인 + 28px 번호 마커)를 그린다 — MSG-427 코스 경로 렌더 그대로. AI 화면은 `themeColor = palette["theme-route"]`로 넘긴다. 마커·선·틴트 렌더는 그대로이고, **경유지 마커에 `onTap`·`active` 강조만 가산**한다(D8, 웹 MSG-488 §4-4 `MapCanvas` 확장의 모바일 대응). 결과 도착 시 카메라 이동·fit은 **없다**(D2, 웹 S6).

파생은 순수 모델 `features/ai-route/model/ai-route-overlay.ts`: `points, selectedOrder` → `{ gridIds(순서 유지·중복 제거), path(order 순 직선), waypoints(seq·coord + `active = order === selectedOrder`) }`. **마커 탭(D8)은 `GridMap`에 경유지 탭 콜백이 없어(클러스터 마커만 `onTap`) 최소 확장이 필요하다** — `route.onWaypointTap?(seq)`와 `RouteWaypoint.active?` 강조 스타일(§4). 셀 분류는 기존 `toMissionCells(gridIds)` + `classifyCells(·, occupiedCells)`(map-home/model/mission-cells)를 그대로 써 `themeOnly → themeCells`, `both → hatchCells`. 점령 격자는 기존 `useOccupiedGridsQuery(bounds)`(map-home/api) — AI 화면 뷰포트로 조회하며 홈과 같은 쿼리키라 캐시 히트.

"화면을 벗어나면 오버레이가 걷힌다"는 A안에서 구조적으로 성립한다 — 오버레이는 AI 화면의 지도에만 있고 홈 지도는 이 데이터를 모른다. 결과 모드 ←(dismiss)로 `points`가 비면 같은 화면의 지도에서도 걷힌다.

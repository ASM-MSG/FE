# MSG-543: 계정 발급 요청 — 비로그인 셀프 신청 폼 + 요청 완료 화면

## 기획 요약

행사 운영자 계정이 없는 기관 담당자가 콘솔 로그인 화면의 "계정 발급 요청하기" 링크로 들어와, 비로그인 상태에서 기관·담당자·행사 정보를 작성해 `POST /api/org-account-requests`로 제출하는 셀프 신청 경로. 성공 시 요청 완료 화면(처리 절차 안내 + "필맵 홈으로 돌아가기")으로 전환된다. 승인·발급은 관리자 몫(T10, 제외 범위)이고 로그인·비밀번호 플로우는 MSG-542(머지됨)다.

## 코드베이스 대조 결과 (스펙의 전제)

- **라우트·진입 링크는 이미 있다**: `/org/account-request`는 `ConsoleRoot` 바로 아래 셸 밖 공개 라우트(`console-routes.ts:19` `orgAccountRequest`, MSG-541 — router 수정 불필요·불가침). `OrgLoginPage.tsx:131`에 "계정 발급 요청하기 →" 링크가 **이미 존재**(MSG-542) — **OrgLoginPage 수정 없음**(오케스트레이터 조건부 허용 불발동).
- **request DTO 실측** (`OrgAccountRequestCreateRequestDto`, openapi `api-docs.json`) — 6필드 전부 required:
  | 필드 | 제약 | 예시(openapi) |
  |---|---|---|
  | `orgName` 기관명 | 1~100자 | 부산진구청 |
  | `contactName` 담당자 이름 | 2~20자 (승인 시 계정 담당자명 — 계정 설정과 같은 제약) | 김담당 |
  | `contactPhone` 연락처 | `^[0-9][0-9-]{7,18}[0-9]$` (숫자 시작·끝, 숫자·하이픈 9~20자) | 010-1234-5678 |
  | `email` 공식 이메일 | format: email, ≤255자 (승인 시 계정 아이디 + 초기 비밀번호 수신처) | event@busanjin.go.kr |
  | `eventName` 예정 행사명 | 1~200자 | 서면 겨울 축제 |
  | `content` 요청 내용 | 1~2000자 | (문장) |
- **중복 신청은 실패가 아니다 (openapi description 실측)**: "같은 공식 이메일의 대기 요청이 이미 있으면 그 요청이 **새 내용으로 갱신**된다 — 마지막 접수가 유효. 더블클릭 재제출·오타 정정 재접수가 한 건으로 수렴. **신청 번호는 부여하지 않는다**." → 중복 developCode는 존재하지 않고, 중복 전용 오류 UI를 만들 수 없다(티켓 문구 "(네트워크·중복 등)"과 어긋남 — 추정 1).
- **응답은 `200 OK` unknown** — 완료 화면에 쓸 서버 데이터가 없다. 요약 카드(기관·공식 이메일·예정 행사)는 제출값을 로컬로 보존해 구성한다.
- **생성 SDK에 mutation 옵션이 있다**: `createMutation`(`shared/api/generated/@tanstack/react-query.gen.ts:541`, url `/api/org-account-requests`) — 재생성 금지, 그대로 사용. 캐시 상호작용 없음(이 요청에 의존하는 쿼리 없음).
- **실패 표출 헬퍼 재사용 가능**: `pages/org/auth-error.ts`의 `authErrorMessage`(네트워크=status 없음 → 고정 문구 / 서버 거절 → 봉투 message / 빈 message → 폴백) — MSG-542 머지 자산, import만(수정 없음).
- **이메일 선검증 재사용 가능**: `features/auth/model/email-format.ts` `isEmailFormat` — import만.
- **Figma 레이아웃은 ConsoleAuthFrame과 다르다**: 두 노드 모두 **좌측 화이트 사이드 패널(워드마크+헤드라인+3단 절차 스텝+하단 안내 카드) + 우측 본문**의 분할 레이아웃 — ConsoleAuthFrame(센터 칼럼)은 부적합해 쓰지 않는다. `AuthInfoCard`(tone="outlined")는 좌측 하단 카드("계정 발급 안내 / 담당자 확인 후 발급 / 개인 이메일보다 기관 공식 이메일을 사용해 주세요.")에 재사용.
- **ui-web에 Textarea·Checkbox 없음** — `Input`만 있다. 요청 내용은 로컬 textarea(Input 토큰 준용, ai-route `RouteInputCard` 선례), 동의 체크는 로컬 체크박스.
- **콘솔 밖 이동 어댑터**: `shared/navigation.ts` `redirectTo`(하드 이동, RouteErrorBoundary "홈으로" 선례 MSG-477 ②)·`openInNewTab`. "필맵 홈으로 돌아가기"는 추정 2.
- **`console-routing.smoke.test.tsx`가 자기 라우트를 2곳에서 단정**: STUB_TITLES 행(42행 "계정 발급 요청")과 비로그인 공개 접근 테스트(88~92행, 같은 제목). h1이 Figma대로 바뀌면 둘 다 갱신 필요 — 둘 다 이 티켓 라우트 한정이라 병렬 충돌면 없음(추정 5).
- **문서 제목·페이지 관례**(MSG-542 실측): `useDocumentTitle(formatDocumentTitle(제목))`, 수제 폼 + `noValidate`(브라우저 기본 검증이 자체 안내를 막는 실결함 — MSG-542 검거) + 순수 검증 함수, 페이지 로컬 순수 모듈(`console-landing.ts` 선례).
- 테스트 인프라: `org-login.smoke.test.tsx` 패턴·`stub-fetch`·`envelope-response` 재사용.
- MSG-543 브랜치는 로컬·리모트 모두 없음(신규 생성).

## 추정 및 질문

**추정 (이견 없으면 이대로):**

1. **중복 신청 오류 UI는 만들지 않는다** — 서버가 같은 이메일의 대기 요청을 새 내용으로 갱신(upsert)하므로 중복은 실패가 아니다(openapi 실측 — 티켓의 "(중복 등)" 문구보다 서버 명세가 정본). 재제출도 같은 성공 경로로 완료 화면이 뜬다.
2. **"필맵 홈으로 돌아가기" = `redirectTo("/")` 하드 이동** — 같은 SPA라 라우터 navigate도 동작하지만, 콘솔은 유저 앱과 분리된 최상위 세계(단일 콘솔 청크 — 유저 앱 미로드 상태로 진입)라 역방향도 문서 이동이 대칭이고, RouteErrorBoundary "홈으로"(MSG-477 ②)와 같은 선례를 따른다. 비로그인 신청자가 콘솔 상태를 남길 이유도 없다.
3. **동의 체크는 제출 게이트로만** — DTO에 대응 필드가 없어 서버로 보내지 않는다. 미체크 제출 시 다른 필수값과 동일하게 안내 문구로 차단(버튼 disabled 방식보다 사유가 보이는 쪽).

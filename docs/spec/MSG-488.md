# MSG-488: AI 경로추천 화면 — 레일 항목·라우트·패널 4상태·1회 추천 요청·지도 표시

> 원문: `_workspace/MSG-488/00_ticket.md` · 전제: `_workspace/MSG-488/00_orchestrator_context.md`(재조사 없이 반영)
> 브랜치: **`feat/MSG-488-ai-route-page`** (이미 존재·체크아웃됨 — 새로 만들지 않는다. develop `107aa59` 위 리베이스 완료)

## 기획 요약

서버 추천 API(`POST /api/routes/recommend`, MSG-457·458·468)는 완료됐는데 소비 화면이 없다. 사이드 레일에 "AI 경로추천" 섹션을 신설하고, 문장 한 줄 + **현재 지도 뷰포트**로 추천을 1회 요청해 좌측 388px 패널의 네 상태(입력 대기 / 로딩 / 결과 / 결과 부족)와 지도 위 표시(순번 마커 · 격자 초록 틴트 · 순서대로 잇는 **직선** 폴리라인)를 그린다. 카드↔마커가 양방향으로 연동되고, 세션 동안 입력·결과·지도 표시가 유지된다. 자동 동작(출발지·지역 이동·축척 고정·2차 재요청·토스트)은 MSG-489, 실보행 경로·거리는 MSG-490이 뒤에 얹는다.

**웨이브 위치**: 웨이브 0(hey-api 스냅샷 `107aa59`) → **웨이브 1 = 이 티켓 단독** → 웨이브 2 = MSG-489 ∥ MSG-490. 따라서 이 스펙의 최우선 설계 제약은 **489와 490이 서로 다른 파일만 건드리도록 파일 경계를 미리 갈라 두는 것**이다(§4).

## 1. 확정 사항 (사용자 승인 대상)

### 1-1. 라우트 경로 — `/ai-route` 확정 (티켓 가칭 `/route`에서 변경 제안)

| 후보 | NavKey | 장점 | 단점 |
|---|---|---|---|
| **`/ai-route`** ✅ | `aiRoute` | 사용자 라벨("AI 경로추천")과 1:1 · 기존 `route` 식별자와 충돌 없음 · 디렉토리 `features/ai-route`가 `features/map-home`의 `route` 테마와 구분됨 | URL이 한 글자 길다 |
| `/route` (티켓 가칭) | `route` | 서버 도메인(`/api/routes/*`)과 같은 낱말 · 짧다 | **`route`가 코드베이스에서 이미 3중 의미** — ① `app/routes.ts`·`ROUTES`·`router.tsx`(react-router) ② `features/map-home/model/theme.ts`의 `ThemeId "route"` = **코스 미션 칩 "경로추천"**(MSG-395, 색도 같은 `theme-route` 초록) ③ `map-overlay-store.routes`(코스 폴리라인). `ROUTES.route` / `features/route` 는 ②와 사실상 구분 불가 |
| `/course` | — | — | 코스(MISSION_COURSE)는 이 화면의 결과 종류 중 **하나**라 오해를 부른다. 기각 |

**결론: `/ai-route`, `NavKey = "aiRoute"`, feature `features/ai-route/`, page `pages/ai-route/`.**
근거는 ②의 실재하는 동음이의다 — 기존 "경로추천 칩"이 같은 초록(`theme-route` #34C759)으로 코스 라인을 그리고 있어, 새 섹션까지 `route`로 부르면 리뷰·후속 티켓에서 두 기능이 계속 섞인다. (사용자가 `/route`를 고수하면 §7 Q1에서 되돌린다 — 그 경우 디렉토리만 `ai-route`로 두는 절충도 가능.)

부수 작업:
- `app/routes.ts` `ROUTES`에 `aiRoute: "/ai-route"` 추가 → `NavKey`가 5개로 자동 확장(`keyof typeof ROUTES`). `getActiveNavKey`는 무수정(`home` 외 전부 prefix 매칭).
- `public/robots.txt`에 `Disallow: /ai-route` 추가(로그인 전용 화면 — MSG-478이 세운 규칙). `app/seo-static.test.ts:111`의 `expect(disallows()).toEqual([...])` 배열도 함께 갱신 — **안 고치면 RED**.
- 문서 제목: `useDocumentTitle(formatDocumentTitle("AI 경로추천"))` → `"AI 경로추천 | 필맵"`.

### 1-2. 사이드 레일 순서·아이콘

`widgets/side-rail-nav/SideRailNav.tsx:25` `items`를 **홈 · AI 경로추천 · 업로드 · 도감 · 프로필** 순으로 확장.
- 아이콘: Figma 마스터 `Nav-AI 경로추천` 15688:810 = `icon/sparkles` → **lucide `Sparkles`** (`className="size-full"`, 기존 항목과 동일 관례).
- 라벨: `"AI 경로추천"` (Figma 텍스트 그대로 — 레일 라벨은 `text-[10px]`이라 5자도 한 줄에 든다).
- `onSelect` 분기: `(key === "profile" || key === "dex" || key === "aiRoute") && !isAuthenticated` → `openLoginModal()` (이동 없음). 기존 도감·프로필 분기에 키 하나만 추가한다.
- 재클릭 2단(`rail-action`): `sectionIsInitial("aiRoute")` = **"입력 대기 상태이고 입력이 비어 있음"**. `rail-action.ts`에 순수 판정자 `isAiRouteInitial({ status, text })` 신설, `resetSection("aiRoute")`는 `useAiRouteStore.getState().reset()` 호출(입력·결과·선택 초기화, 패널은 닫지 않음).

### 1-3. 로그인 게이트 (기존 `login-modal-store` 재사용)

오케스트레이터 실측: 익명 `POST /api/routes/recommend` → `401 {"developCode":2403}`. **로그인 전용**으로 확정하고 도감·프로필과 **완전히 같은 3중 게이트**를 쓴다 — 새 게이트 부품을 만들지 않는다.

| 진입 경로 | 처리 | 재사용물 |
|---|---|---|
| 레일 클릭 (비로그인) | 이동하지 않고 로그인 모달만 연다 (URL 불변) | `SideRailNav` 기존 분기 + `useLoginModalStore.openModal` |
| 주소창 직접 진입 / 새로고침 (비로그인) | 홈으로 `Navigate replace` + 로그인 모달 | `app/RequireAuth`를 `router.tsx`에서 그대로 래핑 |
| 세션 중 401(2403) 응답 | 결과 상태를 건드리지 않고 `openLoginModal()` 호출, 패널은 입력 문장 유지한 채 `idle` 복귀 | `route-error.ts` 매핑 + `login-modal-store` |

> `RequireAuth`는 **마운트 시점 1회 판정**이라 렌더 중 로그아웃 시 패널에 머문다 — 프로필·도감과 동일한 의도된 동작(MSG-46 후속 F2)이며 이 티켓에서 바꾸지 않는다.

### 1-4. 에러 처리 매핑 (developCode → UI 반응)

`features/ai-route/model/route-error.ts` — 순수 함수 `routeErrorNotice(error: unknown): RouteErrorNotice`.
정규화는 기존 `shared/api/api-error.ts`의 `ApiError`(`status`·`developCode`)를 그대로 쓴다(`video-actions/model/report.reportFailureNotice` 선례). mutation은 TanStack 기본 `retry: 0`이므로 **14429가 자동 재시도로 악화되지 않는다**(전역 `shouldRetryQuery`는 query 전용).

| 조건 | 문구 | 재시도 행 | 제출 버튼 | 입력 문장 | 부가 동작 |
|---|---|---|---|---|---|
| `developCode 14400` / `14401` (400) | 지도를 조금 더 확대하거나 다른 곳으로 옮긴 뒤 다시 시도해 주세요 | 표시 | 활성("다시 짜기") | 유지 | — |
| `developCode 14429` (429) | 잠시 후 다시 시도해 주세요 | 표시 | 활성 | 유지 | 클라이언트 쿨다운 없음(§7 Q7) |
| `developCode 14502` (502) | AI가 문장을 이해하지 못했어요. 다시 시도해 주세요 | 표시 | 활성 | 유지 | — |
| `developCode 14503` (503) | 지금은 경로 추천을 쓸 수 없어요 | **미표시** | **비활성 유지**(세션 동안) | 유지 | 스토어 `featureDisabled = true` |

### 1-5. 결과 부족 배너 (FE 고정 문구)

`notice !== null`이면 리스트 **위**에 배너. 문구는 서버 `notice`를 쓰지 않고 FE 고정:
`조건에 맞는 곳을 {points.length}곳만 찾았어요. 문장을 바꾸거나 다른 지역에서 다시 짜 보세요`
`points.length === 0`이면 카드·커넥터 없이 배너만(헤더는 "AI 추천 · 0곳"). 서버 `notice`는 **null 여부 신호로만** 판독한다.

## 8. 리스크

- **R1 · 오케스트레이터 전제 1건 정정**: "Skeleton = GalleryTabBody 로컬 구현의 두 번째 사용처" — 실측상 레포에 스켈레톤 구현이 없고 `GallerySkeleton`은 `DotsLoader` 래퍼다. ui-web `Skeleton`은 **신규**이며 GalleryTabBody는 미접촉(§3-2 A, §5). 검증자가 "승격 대상 첫 사용처 미개조"를 결함으로 잡지 않도록 명시.
- **R2 · 저줌에서 격자 틴트가 사라진다**: `MapShell`의 `gateFillCells(overlayCells, viewportZoom)`가 `zoom < GRID_MIN_ZOOM(16)`이면 채움 셀을 통째로 버린다. 마커·폴리라인은 남고 초록 격자만 사라진다. 488은 지도를 이동·확대하지 않으므로 **넓게 본 상태에서 요청하면 격자 강조가 안 보이는 것이 정상**이다(489의 1km 축척 고정이 들어오면 해소). AC S6은 zoom ≥ 16에서 판정한다.
- **R3 · 홈 테마 칩 잔류 상태의 교차 영향**: 홈에서 칩(핫/축제/팝업/경로추천)을 켠 채 `/ai-route`로 오면 `theme-filter-store.activeTheme`가 남아 `MapShell`이 점령 층을 비우고 집계 마커를 억제한다. 기존 크로스섹션 동작이며 이 티켓에서 바꾸지 않는다. 다만 **"경로추천 칩"이 켜져 있었다면 같은 초록 코스 라인이 남아 보일 수 있다** — `MapHomePage` 언마운트 시 `use-home-overlay-publish`가 `clear()`하므로 실제로는 걷히는 것이 기대값. **브라우저에서 실측 확인 대상**(AC S7의 파생).
- **R4 · 서버 `kind`·`notice`가 느슨한 타입**: 생성 타입에서 `kind: string`(enum 아님), `notice: string | null`. 미지 kind에 대한 방어(L2 태그 null)와 notice 문자열 미사용(L4)을 테스트로 못박는다.
- **R5 · `RetryNotice` 이동 diff**: `pages/map-home/ui/` 8개 파일의 import 한 줄씩이 바뀐다. 렌더 불변이라 기존 map-home 스모크가 안전망이지만, `nose`(중복 감지) 베이스라인이 흔들릴 수 있어 등재 시 무관 흡수를 확인한다(MSG-475·476 교훈).
- **R6 · 비로그인 정책은 실측 스냅샷**: 401(2403)은 2026-08-28 실측이다. 서버가 이후 익명 허용으로 바뀌면 §1-3 게이트를 되돌려야 한다(MSG-474가 정확히 그런 뒤집기였다).
- **R7 · 지도 SDK 경계**: 오버레이 파생은 전부 순수 함수(`route-overlay.ts`)에 두고 렌더는 `MapCanvas` 안에서만 한다 — `features/`·`model/`에서 `naver`·`react-naver-maps` import 금지(RN 경계, DESIGN_SYSTEM 규칙).

## 기획 요약
앱 프로필에서 웹은 붙었는데 모바일만 안 붙은 2건을 이식한다. ① 프로필 편집 화면 [변경]이 표시만이라 사진을 바꿀 길이 없다 → 갤러리 선택 → presign → S3 PUT → 확정 3단계(웹 MSG-378)를 붙인다. ② 프로필 "내 활동" 카드가 `MOCK_PROFILE` 리터럴(12일·부산 34%)을 보여준다 → `collections/summary.currentStreak` + `regions/stats` 합산(웹 MSG-395)으로 바꾼다. 웹·packages·서버 무수정, 카메라·크롭·리사이즈 없음, 프로필 레이아웃·설정 행 무수정.

## 추정 및 질문 (웹에 근거 없는 앱 고유 결정 — 사용자 확인 대상)

- **Q1. 업로드 진행 표시 형태** — **권장**: 아바타 위 반투명 오버레이(`absolute inset-0 rounded-full bg-background/60 items-center justify-center`) + `ActivityIndicator`, `upload.isPending`일 때만. 삭제·닉네임 저장 중은 현행대로 버튼 문구(`저장 중…`)만. 근거: 티켓 "아바타에 진행 표시", 레포 `ActivityIndicator` 선례 10곳, 신규 컴포넌트·배럴 export 0. 대안: 진행 표시 없이 버튼 잠금만(웹 방식) — 티켓이 명시 요구하므로 기각.
- **Q2. 픽커가 `fileSize`를 안 줄 때(Android `content://` 일부)** — **권장**: `fetch(uri)` → `arrayBuffer().byteLength`로 실측(1줄, `measureFileSize`). 근거: 프로필 이미지는 5MB 상한이라 메모리로 읽어도 문제 없고(영상 플로우가 null을 거부하는 이유는 500MB 메모리 적재), 정상 사진을 메타 누락으로 반려하는 쪽이 더 나쁜 UX. 대안: 영상 플로우처럼 거부(`FALLBACK_MESSAGE`).
- **Q3. 갤러리 권한 거부 UX** — **권장**: `PermissionAxis`에 `"gallery"` 추가 + `PermissionNoticeModal` 재사용(차단형). 근거: MSG-447 D5 — "사용자가 방금 누른 버튼이 아무 일도 안 한" 상황은 모달(위치 축과 동형), 알림처럼 부가 정보가 아니다. [권한 요청]은 픽커 재시도, [설정 열기]는 `openAppSettings`. 문구(추정): 제목 `갤러리 접근 권한이 필요해요` / request `프로필 사진을 고르려면 갤러리 접근 권한을 허용해주세요` / settings `프로필 사진을 바꾸려면 기기 설정에서 사진 접근 권한을 허용해주세요`. 대안: upload-screen처럼 인라인 텍스트만 — 재요청 CTA가 없어 `undetermined` 복구 불가, 티켓 "재요청/설정 열기" 요구에 미달이라 기각.
- **추정 A1.** 선택 직후 거부 캡션(기준 2)은 기존 오류 캡션 자리(`errorMessage`, `accessibilityRole="alert"`)를 공유한다 — 웹 `sizeError ?? upload.error ?? remove.error` 우선순위 미러.
- **추정 A2.** 실기 검증용 이미지는 에뮬레이터에 `adb push` + 미디어 스캔(`am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE`)으로 1장 심는다 — 런북에 없는 절차라 검증 리포트에 명령을 남긴다.

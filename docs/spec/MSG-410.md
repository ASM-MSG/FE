# MSG-410: 줌아웃 클러스터 서버 집계 전환

## 기획 요약

줌아웃(zoom < `GRID_MIN_ZOOM`=16) 시 점령 격자를 원형 배지로 접는 현행 FE 로컬 산술
(`cluster-overlay`의 윈도 스냅 클러스터링)을 서버 집계 `GET /api/grids/aggregation`으로
전환한다. 줌 구간별로 unit을 바꿔 부르고(축척 250m~500m=동, 1km~8km=구, 16km~=시),
응답 `items[]`를 "지역명+점령 격자 수" 마커로 렌더하며, 겹치는 마커는 count 합산으로
2차 병합한다. 축척 100m대(zoom ≥ 16)의 개별 격자(`GET /api/grids`)는 현행 유지, 업로드 후
쿼리 무효화에 집계 키를 추가한다. 디자인 정본: Figma `14599:7025`(마커 스펙+동/구/시 3화면).

**코드베이스 현황 확인 결과**: 생성 SDK에 엔드포인트가 **이미 있다**
(`getOccupiedAggregatesInViewport` + `getOccupiedAggregatesInViewportOptions/QueryKey`,
`GridAggregationResponseDto {currentRegion, items}`) — openapi 재생성 불요(드리프트 0 전제).
친구 집계(`getFriendGridAggregates`)도 생성돼 있으나 친구 기능 미구현으로 범위 밖.

## 티켓의 "결정 필요" 2건에 대한 결정

**① 공식 MarkerClustering 모듈 vs 자작 병합 → 자작 병합(순수 함수) 채택.**
- MarkerClustering은 별도 외부 스크립트(서브모듈)라 `naver-sdk-loader` SDK 격리 경계를
  넓히고, naver Marker 객체를 SDK 안에서 직접 묶어 vitest 검증·RN 재사용이 불가능하다.
- 우리 마커는 이름+개수 HTML 콘텐츠 + 클릭 줌 이동이 필요해 어차피 병합 결과의 표시·동작을
  자작해야 한다. 병합 자체는 Web Mercator 픽셀 투영(순수 수학)으로 SDK 없이 계산 가능 —
  기존 `cluster-overlay`(순수 함수, RN 재사용 대상) 관례와 일치한다.

**② 응답 `currentRegion`으로 패널 지역명 채택 여부 → 채택하지 않음.**
- MSG-403이 패널 헤더를 확정 지역명 고정으로 정리했다(AC 13, 라이브 동기화 폐기 —
  `region-header` 삭제까지 완료). `currentRegion`은 "뷰포트 중심"이 정의라 이를 헤더에 쓰면
  지도 이동마다 헤더가 바뀌는 MSG-403 이전 동작이 되돌아온다.
- 이번 티켓은 `currentRegion` 필드를 소비하지 않는다(마커는 `items[]`만 사용). 디자인
  프레임 좌측 패널의 "이 지역 격자 N개 · 영상 N개" 헤더는 이 필드의 소비처 후보지만 패널
  개편은 티켓 범위 밖 — 후속 티켓 후보로 작업 로그에 남긴다.

**bbox 정본 정합 (오케스트레이터 지시 사항)**: 집계 조회의 bbox는 **뷰포트**(idle 갱신)로
하고, MSG-403 확정 영역(committedBounds) 정본은 격자 줌 데이터(개별 격자·핫구역·미션·격자
리스트)에 한해 유지한다 — 즉 이 층 하나만 명시적 예외다. 근거는 추정 1 참조.
**사용자 확인 필요.**

## 추정 및 질문

1. **[핵심 결정 — 확인 필요] 집계 bbox = 뷰포트(idle 갱신), 확정 영역 정본의 명시적 예외** —
   MSG-403은 격자 줌 데이터의 재조회 소용돌이를 막기 위한 것이고, 저줌 집계는 성격이 다르다:
   ① "장소 불러오기" 버튼은 축척 2km 단(`MIN_RELOAD_ZOOM`)까지만 노출되어 4km~ 줌에서는
   확정 영역을 갱신할 수단 자체가 없다(확정 영역으로 묶으면 시 단위 줌에서 서면 일대 집계만
   영영 보인다). ② 서버 명세가 "클라이언트가 화면 축척에 맞춰 unit만 바꿔 부른다"로 뷰포트
   전제이고 bbox 상한(1/4/10도)도 뷰포트 규모다. ③ 마커 수십 개 갱신은 MSG-403이 막은 격자
   재렌더 비용과 무관하다. 개별 격자·핫구역·미션·격자 리스트는 종전대로 확정 영역 유지.
2. **병합 마커는 개수만 표시(이름 생략)** — 서로 다른 지역명을 합친 마커에 한 이름을 붙일 수
   없다. 디자인 노트의 "지역명 미판정 버킷은 이름 없이 카운트만 표시" 관례를 준용했다.
3. **마커 클릭 목표 줌** — 디자인 노트 "탭하면 해당 단위 안쪽 줌으로 이동"의 구체 값을
   시→4km 단(구 구간), 구→500m 단(동 구간), 동→`GRID_MIN_ZOOM`(개별 격자)으로 정했다
   (클릭 한 번에 다음 세부 단위가 실제로 보이는 줌). 축척 표 역산으로 구현.
4. **마커 크기 3단은 단위 기준(동<구<시)** — Figma 심볼 variant가 `단위=동/구/시`다. count
   기준 `tierOf` 3단은 폐기한다.
5. **시도명 축약 규칙** — 명세가 "클라이언트 몫"이라고만 해서, 접미(광역시·특별시·특별자치시·
   특별자치도) 제거 + 4자 도명은 관용 2자(경상남도→경남)로 정했다. 디자인 예시(부산·울산·경남)
   부합. 매핑 테이블은 순수 함수 + 테스트.
6. **저줌 이동 중 표시 정책** — 재조회 사이에는 placeholderData로 직전 마커를 유지한다(빈
   화면 깜빡임 방지). 로딩 스피너는 띄우지 않는다(지도 위 상시 층 관례).

## 리스크

- **MSG-411과 `invalidate-grid-queries.ts` 충돌 가능성** — 영상 삭제도 격자 무효화를 만질
  개연성이 있다. 변경을 이 파일 한 곳의 append 수준으로 최소화하고, 머지 순서에서 충돌 시
  수동 해소를 각오한다(웨이브 경계 문서에는 이 파일이 명시돼 있지 않음).
- **최소 줌(6, 128km)에서 경도 span이 시 상한 10도를 초과**할 수 있다 — 클램프(기준 3)로
  요청은 성립하지만 화면 가장자리 지역 마커가 빠질 수 있다. 전국 전체가 한 화면인 극단
  줌에서만 발생, 수용한다.
- **저줌 idle마다 재조회 트래픽** — staleTime(`mapQueryPolicy`)과 unit·bbox 키 캐시로 완화.
  검증 단계에서 네트워크 탭으로 폭주 없는지 실측한다.
- **e2e `cluster-zoom-gate` 개정 필수** — 스텁 소스가 `/api/grids`에서 `/api/grids/aggregation`
  으로 바뀐다. 갱신 없이는 CI가 깨진다(구 마커 title 셀렉터도 무효).
- **name null 버킷 실측 불가 가능성** — 부산 육지 데이터에서는 미판정 버킷이 안 나올 수 있어
  화면 검증은 스텁/유닛으로 대체될 수 있다(기준 4의 vitest가 정본).
- **Figma 오탐 방지**: ① 디자인 프레임 좌측 패널의 "이 지역 격자 131개 · 영상 892개" 헤더와
  격자 카드 수치·"전체 보기" 배치는 이 티켓 범위 밖의 주변 맥락(플레이스홀더) — 기존
  RegionPanel 유지가 정답이며 불일치로 판정하지 않는다. ② 상단 검색창·카테고리 칩도 각각
  MSG-412·기존 구현 영역이라 대조 대상 아님. ③ 대조 대상은 **클러스터 마커(14599:7041~7048)와
  줌 구간별 마커 단위 전환**뿐이다. ④ 마커 파랑은 hex 하드코딩이 아니라 `primary` 토큰 매핑.
  ⑤ 디자인의 예시 수치(31·118·348)·지명은 플레이스홀더 — 하드코딩 금지.

### WAIVED·확인불가·후속

- **(경미) 생성 타입 `GridAggregationResponseDto.currentRegion` non-nullable vs 주석 "해상이면 null"** — OpenAPI 명세 nullable 누락 의심. 이번 티켓 미소비라 무영향, 후속 소비 티켓에서 서버 명세 정정 확인 필요 — 지라 코멘트 환류 대상.
- **후속 티켓 후보**: ① 디자인 프레임 좌측 패널 "이 지역 격자 N개 · 영상 N개" 헤더(`currentRegion` 소비처 후보), ② 저줌에서 `/api/grids`(확정 영역) 조회가 클릭 라우팅(occupiedIds)에만 쓰이는 트래픽 최적화.
- **수용 리스크**: 최소 줌(128km)에서 경도 span이 시 상한 10도 초과 → 중심 기준 클램프로 요청은 성립, 화면 가장자리 마커 누락 가능(전국 한 화면 극단에서만).
- **환경**: 워크트리 `.env.local`(네이버 키) 부재로 메인 체크아웃에서 복사(미커밋). AC 13 검증으로 localhost:5173 세션 로그아웃됨 — 사용자 재로그인 필요.

### PR 리뷰 반영 (PR #61, 2026-08-18)

- **채택 (react-doctor `js-tosorted-immutable`)**: `mergeOverlappingMarkers`의 `[...markers].sort()` → `markers.toSorted()` — 불필요 복사 제거. TS target·lib ES2023이고 `toSorted`가 레포 기존 관용구(hot-region-summary·course 등)라 부합.
- **기각 (border-3 미생성 추정)**: "Tailwind v4도 border 고정 스케일만 지원"은 v3 기준 — v4는 `border-<number>` bare 값(px)을 지원하며, 빌드 산출 CSS에 `.border-3{border-width:3px}` 생성을 grep으로 실증. 재검증의 getComputedStyle 실측(3px 흰 링)과도 정합. 레포의 `border-[1.5px]`는 소수값(bare는 정수만)이라 임의값 문법이 필요했던 경우로 반례가 아님.
- **기각 유지 (그리디 병합 앵커 우선순위)**: 한 마커가 복수 그룹 임계 안에 들 때 "가장 가까운 앵커"가 아니라 "count 큰(먼저 생성된) 앵커"에 흡수되는 것은 의도된 설계 — JSDoc·결정 기록("count 큰 마커가 앵커가 되어 흡수")대로. 리뷰어도 의도면 무시 가능으로 표기.

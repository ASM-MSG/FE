# MSG-519: 종료 행사 아카이브 — 지난 행사 기록 표시 · 1개월 유지

## 기획 요약
행사가 종료된 뒤에도 한 달 동안 행사방을 "지난 행사 기록" 아카이브 모드로 열어 위치별 영상을 돌아볼 수 있게 한다. 활성 행사 상세와 구분되는 표기여야 하고, 업로드 유도 없이 조회만 가능하다. 1개월이 지난 행사는 목록·아카이브에서 보이지 않는다(서버가 걸러주면 FE는 표시만). 웨이브 2 — MSG-516(머지됨) 골격 위에, MSG-517(위치 개요)·MSG-518(위치별 영상)과 병렬.

## API 실측 — 1개월 판정 주체의 근거 (질문 1의 재료)

기존 hey-api 생성물(`apps/web/src/shared/api/generated/types.gen.ts`, MSG-516이 재생성·**재실행 금지**)을 직접 확인한 사실:

| 사실 | 근거 (types.gen.ts) |
|---|---|
| 상세 status는 서버 시각 기준 파생 4값 `UPCOMING\|LIVE\|UPLOAD_GRACE\|ARCHIVED` | `EventOccurrenceDetailResponseDto.status` L3742 — "서버 시각 기준 파생 상태" |
| **1개월 경계는 서버가 이미 계산한다** | `uploadClosesAt` L3738 "종료 30일 후 파생값" · `EventVideoDetailResponseDto.interactionLocked` L3644 "아카이브 전환(행사 종료 + 30일)부터 true" → **ARCHIVED = 종료+30일 이후, UPLOAD_GRACE = 종료~+30일** |
| 뷰포트 칩 목록은 종료 행사를 이미 거른다 | `EventOccurrenceChipResponseDto.status: 'UPCOMING'\|'LIVE'` L3702 — "이 목록에는 두 값만 담긴다". 상태 필터 쿼리 파라미터 없음(`GetOccurrencesInViewportData` — bbox 4개뿐) |
| ARCHIVED 뒤에도 조회는 열려 있고 입력만 잠긴다 | 영상 상세·댓글 API가 ARCHIVED 상태값을 정상 응답으로 명세(`occurrenceStatus` L3594) + `interactionLocked`가 "비활성화 여부"지 접근 차단이 아님 |
| 위치 목록에 영상 수가 있다 | `EventLocationResponseDto.videoCount` L3840 — Figma "영상 N" 재료 |
| 상세에 배너 이미지·지역 표기 필드가 **없다** | `EventOccurrenceDetailResponseDto` 전체 필드: occurrenceId·seriesId·title·startsAt·endsAt·uploadClosesAt·status·notificationOn·previousOccurrences — 이미지/city 계열 0 |

**명명 함정**: 티켓의 "아카이브(종료 후 1개월 유지)" 구간 = 서버 **UPLOAD_GRACE**. 서버 **ARCHIVED** = "1개월이 지난" 상태다. MSG-516 골격 `event-room-mode.ts`는 `ARCHIVED → "archive"`만 매핑해 두었으므로, 이대로면 **방금 종료된 행사(UPLOAD_GRACE)는 개요 모드로 렌더된다** — 이번 티켓의 핵심 수정이 `UPLOAD_GRACE → "archive"` 분기 추가다.

**권고안**: **판정 주체 = 서버 status 필드. FE 날짜 계산 0줄.** `status ∈ {UPLOAD_GRACE, ARCHIVED}` → 아카이브 모드. "1개월 지나면 목록에서 안 보인다"는 서버가 이미 충족(칩 목록 2값). ARCHIVED 상세에 도달한 잔여 경로(지난 회차 클릭 — MSG-517 몫 UI)는 그대로 아카이브를 보여준다 — 서버 데이터 모델("영구 조회, 입력만 잠금")·티켓 괄호("서버가 걸러주면 FE는 표시만")와 정합. → 승인 질문 1·2.

## 추정 및 질문 (사용자 승인 대상)

> **승인 결과 (2026-08-31)**: 질문 1~4 전부 권고안대로 승인 — ① 판정 주체 = 서버 status 필드(FE 날짜 계산 0줄), ② ARCHIVED 도달 시 A안(그대로 아카이브 표시), ③ EventRoomPanel 2줄 접촉 승인(상세 status 배선 + 헤더 "지난 행사 기록"), ④ 쿼리 훅은 519 자체 파일(use-event-archive-query.ts). 질문 5(위치 클릭 영상 목록 제외)와 추정 6~8은 이의 없이 통과.

1. **[핵심 확정 — 1개월 판정 주체] 서버 status 필드 판정을 권고** — FE 날짜 계산 0줄. 근거는 위 API 실측 표: 서버가 종료+30일 경계를 이미 계산해 status로 내려주고(`UPLOAD_GRACE`/`ARCHIVED`), 뷰포트 목록은 종료 행사를 이미 거른다. FE가 `endsAt`으로 재계산하면 클라이언트 시계·KST 자정 함정(MSG-516 use-kst-today가 겪은 그 문제)을 다시 만든다. **승인 요청.**
2. **[ARCHIVED(1개월 초과) 상세에 도달한 경우]** A안(권고): 그대로 아카이브 표시 — 진입 목록은 서버가 걸러서 "1개월 지나면 안 보인다"는 충족되고, 서버는 ARCHIVED 조회를 계속 제공(입력만 잠금)하며 상세의 `previousOccurrences`(연례 행사 작년 회차 = 필연적으로 1개월 초과)가 클릭 진입을 전제한다. B안(티켓 문면 엄격 해석): ARCHIVED면 본문 대신 "보관이 끝났어요" 안내. **A안 승인 요청** — B안이면 모드 1개·분기 1줄 추가.
3. **[EventRoomPanel 2줄 접촉]** 모드 입력(상세 status) 배선 + 헤더 타이틀("지난 행사 기록" — Figma 15518:7350 헤더가 "이벤트"가 아니다). MSG-517도 같은 파일을 만질 공산이 커서(개요도 상세 쿼리 필요) 머지 순서상 뒤쪽이 rebase로 수렴적 충돌을 푼다. 대안: 배선을 아예 미루고 잠복 분기만 남기기 — 먼저 머지 시 안전하지만 기준 3·5·6·9·10의 브라우저 검증이 전부 불가(컴포넌트 단위 vitest로 강등). **접촉 승인 요청.**
4. **[상세·위치 쿼리 훅을 519 자체 파일로]** MSG-517이 만들 훅과 기능이 겹치지만 파일명을 달리해 병렬 충돌을 피하고, 웨이브 2 완주 후 통합 정리(1커밋 거리). 대안(배선 지연)은 질문 3 대안과 같은 검증 강등. **승인 요청.**
5. **[위치 클릭 → 당시 영상 목록은 이번 스펙 제외]** 위치별 영상 목록·빈 상태는 MSG-518 소유(병렬 진행 중 — import할 파일이 아직 없다). 이번 티켓은 위치 목록 표시(+클릭 슬롯 없음, 행 비활성)까지. 아카이브에서의 영상 목록 연결은 518 머지 후 통합 시점(rebase) 또는 웨이브 3에서 1~2줄 배선 — 오케스트레이터 조율 필요. (영상 클릭 재생은 티켓 명시로 MSG-520 제외 범위)
6. **[추정] UPLOAD_GRACE 구간을 즉시 "지난 행사 기록"으로 표기** — 서버는 이 구간에 업로드를 허용하지만(업로드 유예가 존재 이유) 웹에는 행사 영상 업로드 UI가 없어 "조회 전용" 표기와 충돌하지 않는다. 모바일 업로드 정책과 어긋나면 기획 확인 필요.
7. **[추정] 기간 라벨 형식** "2026.7.17–8.9"(Figma 문자열 그대로, 0패딩 없음·연도 넘김 시 양쪽 연도). 위치 행 보조 표기는 `videoCount` 기반 "영상 N"만(Figma에 운영시간·유형 미표기).
8. **[추정] 익명 조회 허용** — 상세·위치 API 익명 발사(칩 목록 익명 200 실측 선례 + 영상 상세 DTO의 "비로그인 조회는 항상 false" 문구가 익명 조회를 전제). 구현 초기에 실서버 1회 확인, 401이면 로그인 게이트로 조정.

## 리스크

- **실동작 검증 확인불가 가능성 높음**: 서버 승인 행사 0건 실측(부산 bbox 빈 배열, 2026-08-31) — 종료 행사 데이터는 더더욱 없다. BE 시딩(MSG-500) 대기. 검증 기본 경로는 fetch 스텁(MSG-516 선례: 스텁+실서버 혼합), 리포트에 확인불가 판정 기준 명시.
- **아카이브 진입 경로가 병렬 구간에 없다**: 칩 목록은 UPCOMING·LIVE만, 지난 회차 클릭 UI는 MSG-517 몫. 브라우저 검증은 스텁으로 방을 강제 오픈해 수행. 머지 후 실제 진입은 517 산출물 의존 — 웨이브 2 완주 시 통합 확인 필요.

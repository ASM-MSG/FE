# MSG-489: 경로추천 자동 동작 — 출발지 자동 판정 · mentionedArea 지역 이동 + 1km 축척 고정 + 2차 자동 재요청 · 토스트

> 원문: `_workspace/MSG-489/00_ticket.md` (2026-08-28 FE 재작성본이 정본, 하단 `<details>`는 BE 초안)
> 선행: MSG-488(머지 완료, `docs/spec/MSG-488.md`) · 병렬: MSG-490(walk-paths — 다른 워크트리 동시 진행)

## 기획 요약

MSG-488이 만든 `/ai-route` 패널(문장 → `POST /api/routes/recommend` → 카드 + 지도 오버레이) 위에 **세 가지 자동 동작**을 얹는다. ① 요청 시점에 현위치가 뷰포트 안이면 `origin`을 자동으로 실어 보내고 입력 카드에 "현재 위치에서 출발" 상태를 표시한다(토글 아님·컨트롤 아님). ② 1차 응답에 `mentionedArea`가 실리면 **확인 없이** 그 중심으로 지도를 옮기고 줌을 `MAP_SCALE_1KM_ZOOM`으로 고정한 뒤 안내 토스트를 띄우고 **새 뷰포트로 2차 요청을 자동 발사**한다(1회 한정, 1차 결과는 그리지 않는다). ③ 1차 요청 전 뷰포트가 너무 넓으면 같은 1km 단으로 먼저 정규화해 서버 상한(14401)을 예방한다. 서버 API 계약은 그대로다.

### 4-2. 데이터 흐름

`AiRoutePage`가 `submit()`에서 ① `needsSpanNormalize(bounds)`면 `zoomTo(MAP_SCALE_1KM_ZOOM)`를 먼저 부르고 새 bounds를 기다린 뒤 ② `resolveRouteOrigin({ coords, bounds })`로 `origin`을 판정해 ③ `buildRecommendBody({ text, bounds, origin })`을 쏜다 → `use-route-recommend.onSuccess`가 `resolveAutoMove`를 물어 **null이면 종전대로 `succeed()`**, **비-null이면 결과를 버리고 `startSecondaryRequest()` + `onAutoMove(area)`** → `use-ai-route-auto-move`가 `moveTo(center)` + `zoomTo(MAP_SCALE_1KM_ZOOM)`를 실행하고 토스트를 세우며, `viewport-store.bounds`가 새 값으로 갱신되는 것을 보고 origin을 **재판정**해 2차 `mutate` 1회를 쏜다 → 2차 응답은 `alreadyMoved: true`라 `resolveAutoMove`가 항상 null → `succeed()`로 카드·오버레이가 그려진다.

## 6. 추정 (승인 대상 — 티켓에 없어 채운 것)

- **A1. 현위치 조회 어댑터 확장** — 티켓은 "권한 거부·미확보면 origin 생략"을 요구하는데, 현행 `shared/geolocation.getCurrentPosition()`은 **거부·실패를 삼키고 서면 좌표를 돌려준다**. MVP 지역이 서면이라 폴백 좌표가 뷰포트 안에 들어와 **거부한 사용자에게도 origin이 전송되는 오판정**이 난다. → `shared/geolocation.ts`에 **가산 export** `getCurrentPositionOrNull(): Promise<GeoCoords | null>`(실패 시 `null`)를 추가하고 기존 `getCurrentPosition`은 그 위에 폴백을 씌워 재구성한다. 기존 소비 3곳(`MapShell` 2·`use-region-stat-query` 1) 무수정. **파일 소유권 표에 없는 파일이라 명시 승인이 필요하다**(490 미접촉 확인됨).
- **A2. 0.5도 예방의 실행 방식** — 1차 요청 시점 뷰포트의 위도·경도 span 중 하나라도 0.5도를 넘으면, 요청 전에 현재 **중심 기준** `zoomTo(MAP_SCALE_1KM_ZOOM)`으로 맞추고 새 bounds가 `viewport-store`에 반영된 뒤 보낸다(bounds를 잘라 보내지 않는다 — 사용자가 보는 화면과 요청 범위를 어긋나게 두지 않기 위해). 이 경우 토스트는 띄우지 않는다(지역 이동이 아니므로).
- **A3. `kind` 미지 값 처리** — 생성 타입의 `kind`는 유니언이 아니라 `string`이다. `mentionedArea`가 non-null이면 **`kind` 값과 무관하게** 이동한다(MOVE·ZOOM_OUT이 동일 처리로 확정된 이상, 서버가 신호를 보냈다는 사실 자체가 판정 근거). 판정 함수는 `kind`를 반환값에 실어 두되 분기하지 않는다.
- **A4. 토스트 노출·중복** — 3초 자동 소멸(`use-auto-dismiss-toast` 기본값). 자동 이동은 요청 사이클당 최대 1회라 중복 토스트가 구조적으로 없지만, 연속 제출로 새 토스트가 오면 기존 것을 **대체**한다(동일 문구 연속도 타이머 재시작 — 훅이 보장).
- **A5. 2차 요청의 origin 재판정** — 새 뷰포트 기준으로 다시 판정한다. 1차에서 안이었어도 이동 후 밖이면 2차 body에 `origin`이 없고 입력 카드 표시도 사라진다. (오케스트레이터 지시대로 추정으로 기재)
- **A6. 2차 실패 처리** — 2차가 실패하면 **1차 결과를 복원하지 않고** 기존 에러 화면(488 `RouteErrorNotice`)으로 간다. 지도는 이미 이동한 자리에 있고 토스트도 이미 떴다(되돌리지 않는다). "다시 짜기"는 이동한 새 뷰포트로 1차부터 다시 시작한다.
- **A7. 섹션 이탈 중 2차** — 진행 중 다른 섹션으로 나가면 mutation은 그대로 완주하고 결과는 스토어에 게시된다(488 S11 "돌아오면 복원" 계약 유지). 지도 이동·토스트는 이탈 전에 이미 끝났다. 언마운트 시 오버레이만 `clear()`(488 기존 동작).
- **A8. 축척 1km 고정 후의 격자 게이트** — §8 R1 참조. 현행대로 두면 **AI 경로 격자 틴트는 zoom 13에서도 보인다**(색 보유 셀이라 게이트 통과). 다만 사용자 점령 격자·격자 선은 zoom 13에서 사라진다 — 이는 이 티켓이 만드는 회귀가 아니라 저줌 공통 동작이므로 **수용**한다.

### 13-1. P1 — 2차 요청에 로그인 처리가 안 붙어 있었다

**지적**: `use-ai-route-auto-move.ts`의 2차 mutation 인스턴스가 `useRouteRecommend({ secondary: true })`로만 만들어져 `onLoginRequired`가 없었다. 1차 성공과 **지연된 2차**(서버 10초 창 대기) 사이에 세션이 만료되면 2차가 401(2403)을 받는데, `fail()`이 패널을 입력 대기로 되돌릴 뿐 **로그인 모달이 뜨지 않는다** — 사용자는 결과가 왜 사라졌는지 알 수 없다.

**수정**: 1차와 같은 콜백을 2차 인스턴스에도 넘긴다(`useRouteRecommend({ secondary: true, onLoginRequired })`). `secondary`는 요청 **시작** 처리만 가르는 플래그이고 실패 처리는 원래 공통이라, 인증 실패 동작이 두 요청에서 같아진다.

**문서 정정**: §10 "후속 권장"의 "2차 인스턴스에 `onLoginRequired` 미부착"과 `docs/STATUS.md` MSG-489 줄의 "잔여 후속 후보" 서술은 **알려진 한계가 아니라 결함**이었다 — 반영 완료로 정정했다.

### 13-2. P2 — 2차 정착 상한이 무한히 밀렸다 (D13 계약 위반)

**지적**: 두 대기 이펙트는 `bounds`·`zoom` 갱신마다 재실행되면서 기존 타이머를 지우고 `setTimeout(fire, VIEWPORT_SETTLE_TIMEOUT_MS)`를 **처음부터 다시** 걸었다. 사용자가 계속 패닝·줌하면 목표 미도달 상태에서 종결이 무한히 연기돼 패널이 로딩에 갇힌다 — §11 **D13("영구 로딩 금지")과 정면 충돌**이고, 03c 검증도 이 경로를 짚지 못했다. **정규화 대기(`normalizePending`)도 같은 구조라 같은 결함**이었다(지적은 2차만 지목했으나 확인 결과 동일).

**수정**: 상한을 "재실행마다 다시 재는 타이머"에서 **대기 사이클당 절대 마감 1회**로 바꿨다.

| 계약 | 구현 |
|---|---|
| 마감은 사이클당 한 번만 선다 | 순수 함수 `advanceSettleDeadline({ deadline, now, visible, timeoutMs })`(`route-request.ts`) — `deadline === null`인 첫 호출만 `now + timeoutMs`를 정하고, 이후 재실행은 `remainingMs`만 돌려준다. 이펙트는 그 **남은 시간만** 스케줄한다 |
| 마감이 지났으면 즉시 종결 | `remainingMs === 0`이면 타이머를 걸지 않고 그 자리에서 `fire()` — 갱신이 매 프레임 들어와도 다음 재실행에서 반드시 종결한다(0ms 타이머는 갱신에 다시 취소될 수 있어 동기 발사로 뒀다) |
| 마감은 **가시 시간**만 소모한다 (§12 유지) | 같은 함수가 `visible: false` 구간을 `hiddenSince`로 기억하고, 복귀 시 숨어 있던 만큼 `deadlineAt`을 뒤로 민다. 숨은 동안에는 종전대로 타이머를 걸지 않는다 |
| 사이클이 끝나면 마감도 끝난다 | 예약 플래그가 내려간 이펙트 실행에서 `reset()` — 다음 대기는 새 상한을 받는다. 두 대기는 각자의 마감을 갖는다 |
| 종결은 여전히 두 결과 중 하나 | 유효 요청 1회 발사, 또는 `abortPending(VIEWPORT_TOO_WIDE_NOTICE)`. `send()`의 `exceedsViewportSpan` 가드(§12)는 그대로라 과대 뷰포트(14401)는 어떤 경로로도 나가지 않는다 |

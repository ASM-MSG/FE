# MSG-413: 대표 뱃지 설정 연동

## 기획 요약

도감 뱃지 탭에 **편집모드**를 신설해 대표 뱃지를 최대 2개 지정/해제하고, `PUT /api/badges/featured`(replaceFeatured)로 서버에 반영한다. 조회와 진열장 정렬(featuredRank 1·2 우선 — `orderBadges`)은 MSG-327에서 이미 연동돼 있고, **쓰기만 없는 상태**다. 디자인은 Figma 프레임 `14783:4202`("MSG-413 개인 도감 — 대표 뱃지 지정 (편집 모드)", 섹션 14783:3343 내) — 선택 뱃지에 primary 링+랭크 칩(1·2), 하단에 프로필 미리보기 카드와 "대표 뱃지 저장" 버튼.

## API 확인 (hey-api 생성 SDK — 실재 확인 완료)

- `PUT /api/badges/featured` — `replaceFeatured` (sdk.gen.ts:121), `replaceFeaturedMutation` (react-query.gen.ts:183)
- 요청 `FeaturedBadgeRequestDto`: `{ badgeIds: number[] }` — **최대 2개, 배열 순서 = 표시 순서, 빈 배열 = 전부 해제** (스키마 주석 명시)
- 응답 `ApiResponseDtoListFeaturedBadgeResponseDto`: 적용된 대표 뱃지 목록(badgeId·code·name·iconUrl)
- 갱신 대상 조회: `GET /api/badges`(`findMyBadges`) — `featuredRank: number | null` 포함, 키 `findMyBadgesQueryKey()`

## 추정 및 질문 (2026-08-18 사용자 승인 — A1~A5 전부 제안대로 확정)

- **A1. 편집모드 진입점** — 시안에 편집모드 프레임만 있고 진입 버튼이 없다. **제안**: 진열장 헤더 우측(기존 "전체 보기" 자리 옆)에 "대표 뱃지 지정" 텍스트 버튼. 다른 위치를 원하면 지정 필요
- **A2. "완료" vs "대표 뱃지 저장" 의미** — 시안에 둘 다 존재. **제안**: 저장 버튼 = PUT 커밋 + 성공 시 편집모드 종료 / "완료" = 서버 호출 없이 종료(미저장 변경 폐기 = 취소 역할). "완료"도 저장을 의미한다면 알려달라
- **A3. 2개 선택 찬 상태에서 세 번째 클릭** — 안내 문구가 "최대 2개"만 명시. **제안**: 무시(no-op). 대안: 가장 오래된 선택 교체
- **A4. 편집모드 뱃지 목록 범위** — 시안은 2행(8개)만 노출. **제안**: 편집모드에서는 전체 카탈로그를 스크롤 노출(획득 뱃지가 프리뷰 8개 밖에 있을 수 있어 선택 접근성 필요). 프리뷰+전체 보기 유지가 낫다면 지정 필요
- **A5. 저장 실패 안내 형태** — **제안**: 저장 버튼 위 인라인 에러 문구(기존 features/video-actions 토스트 훅의 cross-feature 재사용 회피). 토스트 선호 시 변경 가능

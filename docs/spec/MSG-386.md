# MSG-386: 린트 툴체인 oxlint로 단일화 및 TypeScript 버전 상향

## 기획 요약

typescript-eslint가 TS 컴파일러 API에 결합돼 TypeScript 7(네이티브 컴파일러) 상향을 차단한다(MSG-380 실측: TS 7.0.2에서 typecheck·test 그린, lint만 크래시). 현행 eslint 규칙 전부를 oxlint로 이식해 린트 툴체인을 단일화하고, eslint 계열 의존성을 제거한 뒤 TS catalog를 7.x 안정판으로 올린다. 속도 절감(lint 4.2s→0.39s)은 부수 효과이며 주 목적은 툴체인 단일화·업그레이드 자유도다. **토큰 규칙(better-tailwindcss 상당) 이식이 성공 조건 — 이식 불가 판명 시 전환 전체를 보류하고 티켓을 종료한다(현행 구성 유지).**

## 현행 구성 실측 (코드베이스 대조)

- **eslint 설정 4곳**: `apps/web/eslint.config.js` · `apps/mobile/eslint.config.mjs` · `packages/ui-web/eslint.config.js` · `packages/ui-native/eslint.config.js`. 공통 골격: js/tseslint recommended(type-aware 아님) + react-hooks recommended + better-tailwindcss/no-restricted-classes(토큰 규칙 2패턴, 한국어 메시지) + eslint-plugin-oxlint로 중복 규칙 비활성(하이브리드)
- **apps/web 고유**: react-refresh(vite 프리셋, only-export-components) · RN 경계 규칙 — `src/features/*/model/**`, `src/entities/*/model/**`, `src/widgets/**/*-store.*` 글롭 한정으로 no-restricted-imports(react-router*)·no-restricted-globals(window/document/localStorage), 전부 한국어 메시지. `dist`·`src/shared/api/generated` ignore
- **apps/mobile 고유**: `**/*.js`를 commonjs+node globals로 별도 처리, `.expo`·`dist`·`expo-env.d.ts`·`.rnstorybook/storybook.requires.ts` ignore. ui-web은 `storybook-static` ignore
- **스크립트**: 루트 `lint` = `pnpm -r run lint`(4패키지 각자 `eslint .`), 루트 `lint:oxlint` = 5개 src 대상 단일 실행(generated 제외). oxlint ^1.76.0은 루트 devDep
- **CI**(.github/workflows/ci.yml): `Lint (oxlint fast pass)` → `Lint`(eslint) 2단계. **훅**: pre-commit = react-doctor+format:check, pre-push = check:duplication — **eslint를 실행하는 훅은 없음**(훅 연속성 = 무변경 확인으로 충분)
- **TS catalog**(pnpm-workspace.yaml): `typescript: "~6.0.3"` — develop 머지 완료 (`e65728c`, PR #52)
- **oxlint 1.76 사전 실증**(이번 세션): no-restricted-imports/globals 네이티브 지원+한국어 메시지 동작 확인, exhaustive-deps는 react 플러그인으로 검출 확인, JS 플러그인 API는 `plugins-dev` export로 존재하나 **better-tailwindcss 이식 가능 여부는 미검증**

## 리스크

- **[핵심] 토큰 규칙 이식 미검증**: `plugins-dev` export는 이름대로 개발 단계 API — 문서·안정성 보장이 약하고 oxlint 마이너 업에 파손될 수 있다. 또한 기존 eslint-plugin-better-tailwindcss는 className 속성 외 유틸 호출(cva/cn 등 callees)의 클래스 문자열도 검사한다 — 자작 규칙이 이 커버리지를 놓치면 "그린이지만 덜 잡는" 조용한 약화가 된다. 수용 기준 #2의 위반 샘플에 callee 케이스를 포함해 상쇄한다. 이식 불가 판정 시 보류 절차는 수용 기준 #1에 명시
- ~~[선행 조건] TS catalog 통일(~6.0.3) 미머지~~ → **해소됨** (스펙 승인 시점 확인: `e65728c` 커밋이 PR #52로 develop 머지 완료 — catalog 기준선 정상)
- **recommended 세트 대체 정합성**: js/tseslint recommended(비 type-aware)를 oxlint 기본 카테고리로 대체할 때 1:1 동등이 아니다 — 일부 규칙은 oxlint에 없고, oxlint가 더 잡는 규칙도 있다. 티켓의 제외 범위(신규 규칙 확장 금지)에 따라 기존 소스 기준 신규 위반 0건(수용 기준 #3 방식)을 정합성 기준으로 삼고, 소실 규칙 목록은 리포트에 기록만 한다
- **react-refresh 상당 규칙 부재 가능성**: oxlint의 지원 여부 미확인 — 티켓 자체가 "불가 시 대체 방안 기록"으로 허용하므로 보류 사유는 아님 (수용 기준 #4)
- **훅은 eslint 무관**: pre-commit/pre-push 어디에도 eslint가 없음을 실측 확인 — "훅 게이트가 그대로 작동한다"는 무변경+동작 확인으로 충족되며, react-doctor 훅은 티켓 제외 범위대로 불간섭
- **Figma 오탐 방지**: 없음 (티켓에 Figma 링크 없음 — 화면 요소가 없는 툴체인 티켓이라 Figma 분석 자체가 해당 없음)

### 잔여·특이 (WAIVED 없음)

- exhaustive-deps는 기존 하이브리드에서 **어느 쪽도 검사하지 않던 공백** — 전환으로 warn 복원(기존 소스 위반 0)
- `no-undef`는 oxlint nursery라 소실 — TS 파일은 typecheck(TS2304)가 커버, 실질 공백은 mobile 순수 .js 설정 파일 수 개(기록만)
- eslint 바이너리는 react-doctor 전이 의존성으로만 잔존(티켓 제외 범위 — react-doctor 불간섭)
- oxlint `jsPlugins`는 alpha API — oxlint 버전 업 시 토큰 규칙 플러그인 동작 재확인 필요

### CI 환류 (머지 전 재작업 — 2026-08-13)

- **증상**: CI `pnpm openapi-ts`에서 hey-api가 `ts.SyntaxKind` undefined로 크래시 — hey-api도 TS의 JS 컴파일러 API 소비자(typescript-eslint와 같은 계열)인데 peer 지원이 `>=6.0.0`까지라 TS 7 미지원. 로컬 검증이 못 잡은 이유: openapi-ts 드리프트 게이트가 CI에만 있고 검증 스킬 풀 게이트에 없었음
- **수리**: hey-api를 apps/web devDep → **워크스페이스 루트 devDep으로 이전**하고 루트에 typescript `~6.0.3`을 둠 — 루트 인스턴스가 TS 6과 peer를 맺고(bin·config 임포트 모두 루트로 해석), 각 패키지 tsc는 catalog 7.0.2 유지. 재생성 diff 0(결정성 보존), lint·test 그린 재확인
- **기각한 대안**: pnpm scoped overrides(`parent>child`)·packageExtensions — 둘 다 peer 재지정이 안 됨을 클린 설치로 확증. Node 로더 훅으로 typescript 임포트 별칭 — 동작 가능하나 루트 이전이 무해킹으로 동일 효과

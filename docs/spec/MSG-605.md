# MSG-605: [모바일] 알림 딥링크 — 푸시 탭·알림함 행 탭으로 대상 화면 이동

## 기획 요약
서버(MSG-432, BE develop 머지)가 알림마다 `targetType`·`targetId`를 FCM `data`와 알림함 응답에 싣는다. 앱은 대상 종류로 화면을 정해 (1) 푸시 탭(포그라운드·백그라운드·콜드 스타트), (2) 알림함 행 탭에서 이동한다. 대상 없음·미지·형식 밖은 홈(푸시) 또는 읽음만(알림함).

## 코드베이스 현황
- 푸시 탭 라우팅은 MSG-567에서 삭제됐고 `push-foreground-handler`(배너 등록)만 남았다. 어댑터(`notifications-adapter.ts`)가 유일한 네이티브 접점이고 지연 로드·주입 관례(MSG-429 R6).
- 알림함 행(`notification-row.tsx`)은 `onRead(id)`만 받는다. 화면이 `useMarkRead`로 읽음 처리.
- 홈은 `/home?lat&lng&gridId&bounds&ts`를 `home-focus.ts`로 파싱해 카메라 이동·하이라이트한다. 빌더는 5키를 항상 싣는다(expo-router params 병합 함정).
- 행사방은 모듈 싱글턴 `event-selection.openEventRoom({occurrenceId,title,status})`. 상세는 `use-event-room-query`가 id로 조회하고 제목·상태는 `detail ?? selection` 폴백이라 id만으로도 열 수 있다.
- 도감 탭은 `dex-screen` 로컬 `useState(DEFAULT_DEX_TAB)`. 라우트 파라미터 없음.
- 생성 SDK는 웹 스냅샷(`apps/web/openapi/api-docs.json`, 2026-09-12)이라 `targetType`이 없다. 스냅샷은 basic auth 뒤라 로컬 BE(develop)에서 뽑는다.
- 루트 게이트: `_layout.tsx` `AppShell`이 `hydrated`·`isAuthenticated`·`showConsentGate`를 안다. 콜드 스타트는 `index.tsx`가 `/home`으로 Redirect한 뒤라 pathname이 `/`를 벗어난 시점에 이동해야 Redirect에 덮이지 않는다.

## 설계
- **순수 모델** `features/notifications/model/notification-route.ts`
  - `parseNotificationTarget(raw: {targetType?: unknown; targetId?: unknown}) → NotificationTarget | null`: 5종 + 식별자 형식(VIDEO·BADGE·EVENT_OCCURRENCE·USER 양의 정수, GRID `^\d+_\d+$`) 아니면 null.
  - `routeForTarget(target | null, ts) → Href | null`: VIDEO→`/video/{id}`, GRID→`{pathname:"/home", params: homeDeepLinkParams(grid)}`, BADGE→`{pathname:"/dex", params:{tab:"badges"}}`, EVENT_OCCURRENCE→`{pathname:"/home", params: homeDeepLinkParams(occurrence)}`, USER→`/home`, null→null.
  - `homeDeepLinkParams`: `homeFocusParams` 5키 + `occurrenceId`(빈 문자열 기본) — 홈 params 병합 함정 대응.
  - 푸시 경로는 `routeForTarget(...) ?? "/home"`, 알림함 경로는 null이면 이동 없음.
- **푸시 응답 오케스트레이션** `api/push-response-routing.ts`(순수, 의존 주입): 응답 `{id, data}` → 중복 id 무시 → `ready`가 아니면 보류(마지막 1건) → ready 되면 `navigate(routeForTarget(parse(data)) ?? "/home")`. 콜드 스타트는 `readLastResponse()`로 1회 읽고 처리 후 `clearLastResponse()`.
- **훅** `api/use-push-response.ts`: 어댑터 `addResponseListener`·`readLastResponse`·`clearLastResponse` + `router`·`usePathname` 배선. `ready = hydrated && isAuthenticated && !showConsentGate && pathname !== "/" && pathname !== "/login"`. `_layout.tsx` AppShell에 마운트(게이트 밖, 인자로 ready 전달).
- **어댑터** 3함수 추가(지연 로드, 실패 흡수).
- **알림함**: `NotificationRow`가 `onPress(item)`을 받는다. 화면: 안읽음이면 markRead, `routeForTarget(item)`이 있으면 `router.push`/`navigate`.
- **홈**: `occurrenceId` 파라미터 파싱(양의 정수) → `event.handlers.openRoom(id)` 신설(`onActivate()` 후 `openEventRoom({occurrenceId, title:"", status:"LIVE"})`). `ts` 재발화 규칙은 기존 focus effect와 공유.
- **도감**: `tab` 파라미터 → `parseDexTab(raw): DexTab | null`(dex-tab.ts) → 초기값·변경 시 `setTab`.

## 리스크
- R1 콜드 스타트에서 `router.push`가 index의 `Redirect`에 덮일 수 있다 → pathname 게이트로 Redirect 완료 후 이동. 실기로 확인(S3).
- R2 Android에서 launching 응답이 listener와 last response 양쪽에 올 수 있다 → id 중복 제거.
- R3 iOS 시뮬레이터 `simctl push` 페이로드의 커스텀 키가 `content.data`로 오는지 실측 필요.
- R4 로컬 BE에서 스펙을 뽑으면 배포본과 미세 차이가 있을 수 있다 → develop 머지 커밋 기준이라 동일 코드. 스냅샷 원문 그대로 저장.

### 2026-09-24 — 구현·검증 완료 (메인 스레드, 서버 MSG-432 머지 직후)

- **변경**: `notification-route.ts`(대상 파서·라우팅 표·홈 6키 params) · `push-response-routing.ts`(중복 제거·ready 대기·홈 폴백) · `use-push-response.ts`(어댑터+라우터 배선, 콜드 스타트 last response 처리 후 clear) · 어댑터 3함수 · `_layout.tsx` 마운트(ready = hydrated ∧ auth ∧ ¬consentGate ∧ pathname ∉ {/, /login}) · 알림함 행 `onPress(item)` + 화면에서 읽음+이동 · 홈 `occurrenceId` → `event.handlers.openRoom` · 도감 `tab` 파라미터 · SDK 스냅샷 외과 패치(항목 스키마만) + 재생성.
- **실측 정정 1 — iOS `content.data` null**: expo-notifications iOS는 원격 푸시의 `userInfo["body"]`만 `data`로 옮긴다(Expo 푸시 서비스 관례). FCM은 커스텀 키가 최상위라 null. push 트리거 `payload`(= userInfo 전체)를 병합해 해결. Android는 FCM data가 그대로 `content.data`.
- **실측 정정 2 — last response 재처리**: 실행 중 탭을 clear하지 않으면 다음 콜드 스타트에 `getLastNotificationResponse`가 같은 응답을 돌려줘 재이동했다. listener 경로도 처리 후 clear.
- **검토한 대안**: (a) RNFirebase `onNotificationOpenedApp`/`getInitialNotification`으로 iOS 탭 처리 — Android는 RNFirebase가 autolink 제외(MSG-604)라 플랫폼별 두 경로가 되어 기각. (b) `useLastNotificationResponse` 훅 — clear 타이밍을 오케스트레이션이 쥐어야 해 명령형 API 채택. (c) 스냅샷 전체 교체 — 배포본에만 있는 whoami·probe 3오퍼레이션이 사라져 무관 diff 130줄, 항목 스키마만 치환.
- **타입 갭**: hey-api가 `type:["string","null"]+enum`을 non-null 유니언으로 뽑아 `targetType`이 null을 잃는다. 파서는 `unknown` 입력이라 영향 없음. fixture는 단언. 후속 확인 대상.
- **검증**: 게이트 전부 통과(mobile 1,452건). iOS 시뮬레이터 `simctl push` — 실행 중 VIDEO 탭 → 영상 화면, 종료 상태 EVENT 탭 → 홈+행사방 시트, 종료 상태 REMIND 탭 → 홈. Android `am start` 딥링크 — 도감 뱃지 탭, 홈 행사방 시트, 알림함 무대상 행 탭 = 이동 없음. **확인불가**: 알림함 "대상 있는 행" 실기(배포 서버에 대상 행이 아직 없음) — 같은 `routeForTarget`를 푸시 경로가 실증. Android 실기기 FCM 탭은 후속.
- **WAIVED**: 없음. **호출 스킬**: fillmap-page-dev 절차를 메인 스레드가 직접 수행(에이전트 위임 없음). codex 브랜치 리뷰 아래 PR 기록.

# MSG-567: [모바일] 블러 안내·확인 경로 제거 + READY 재무효화를 웹 MSG-476 구조로 이식

> 재작성 2회차 (2026-09-04) — 승인 게이트에서 사용자 결정 "웹에서 하는 흐름으로 바꿔". 1회차(워처 존치·통지만 제거)는 폐기. 지라 본문도 같은 방향으로 갱신됨(`00_ticket.md` 13:59 갱신본).

## 기획 요약

서버가 블러를 껐는데(BE MSG-456) 모바일은 블러 안내 박스 → 완료 문구 → 토스트 → `/upload/blur` 확인 화면을 전부 보여준다. 웹 MSG-476의 **최종 구조를 그대로 이식**한다: 블러 파이프라인(폴링·대기 스토어·영속화·워처·통지·확인 화면·푸시 탭 라우팅)을 코드째 삭제하고, READY 전이 시 목록 재무효화 책임만 웹 `ready-poll`(백오프) + `start-ready-refresh`(모듈 소유 폴, 세션 경계) + `invalidate-upload-surfaces`(확정·READY 공용 집합)로 되살린다. BE 실측으로 FCM 푸시에 `data`가 없어 푸시 탭 라우팅은 원래 성립하지 않았고(Q1 해소), 포그라운드 배너 핸들러 등록만 남긴다. 문구 3곳(첫 화면 박스·완료 문구·권한 안내)은 1회차와 동일.

## 코드 실측 (스펙 근거)

- **웹 원본 3파일** (`apps/web/src/features/upload/`): `model/ready-poll.ts`(순수 — `readyPollDelayMs` 5·5·10·20→30초, 15분, `startReadyPoll({fetchStatus,onReady,onStop?,startedAtMs,now?})`, window/document 무의존 "RN 재사용 대상"으로 설계됨) · `api/start-ready-refresh.ts`(모듈 `Map<videoId, handle>`, 시작 가드 `useAuthStore.getState().isAuthenticated`, `useAuthStore.subscribe((state, previous) => …)` true→false에 `stopAll`, `restart` 옵션, `__resetReadyRefreshForTest`) · `api/invalidate-upload-surfaces.ts`(① `getPlayback` ② `invalidateGridQueries` ③ `getRegionVideos` 부분 키 ④ `getUploadHistory` ⑤ 행사 정확 키). 웹 테스트: `ready-poll.test.ts` 11케이스 · `start-ready-refresh.test.ts` 5케이스.
- **모바일 auth 스토어 API 차이** (`features/auth/model/auth-store.ts`): `subscribe(listener: () => void)` — zustand와 달리 **이전 상태를 넘겨주지 않는다**. true→false 전이 판정은 구독자가 직전 값을 스스로 들고 있어야 한다. `getState().isAuthenticated`는 동일. `logout()`이 세션 만료(`configure-auth.onSessionExpired`)·명시 로그아웃·계정 삭제 전부의 단일 지점이라 auth 구독 하나로 3경로를 덮는다.
- **auth-session 로드 제약** (MSG-426 이력, `delete-account-mutation.ts`·`end-local-session.ts` 주석): `auth-session.ts`를 import하는 모듈은 expo-secure-store가 파싱 단계에서 죽어 vitest에서 로드 불가 → **주입**이 관례. `settle-upload-success.test.ts`가 `use-upload-mutations`를 동적 import하므로 **`use-upload-mutations.ts`는 auth-session을 import하면 안 된다.** `_layout.tsx`는 이미 `bootstrapAuth()`·`authStore`를 들고 있다 → 부팅 시 배선 지점으로 적합.
- **hey-api 쿼리 키 함수 실측**: 모바일 `shared/api/query-options.ts`는 웹 생성물 `react-query.gen.ts`를 `export *`로 재수출 — `getPlaybackQueryKey`(61행)·`getRegionVideosQueryKey`(2837)·`getUploadHistoryQueryKey`(2857)·`getLocationVideosInfiniteQueryKey`(867)·`getLocationsQueryKey`(2815) 전부 사용 가능. 모바일 `invalidateGridQueries`는 이미 `getUploadHistoryQueryKey`를 포함한다(웹 ④와 중복 — 한 번만).
- **삭제 대상의 부수 책임** (`use-processing-watcher.ts` 실측): ① `hydrate` + `AppState active` 복귀 재수화·`checkNow` ② `isAuthenticated` false → 전 폴 중지(MSG-561) ③ `onReady` → `invalidateGridQueries(lastGridId)` + `invalidateEventSurfaces(null)`(MSG-560 codex P1) ④ 전이 시 `untrack` ⑤ 통지 적재. 새 구조 대응: ②→auth 구독, ③→`invalidateUploadSurfaces`(행사는 확정 시점에 이미 아는 `event`를 관통시켜 **정확 키** — 부분 키 전 위치보다 좁아진다), ①④⑤→소멸(영속화 삭제).

## 추정 및 질문

**추정 (웹 코드·MSG-476 결정으로 확정 — 승인 시 함께 확인)**

- **A1. 완료 화면** = 제목 유지 + 본문 웹 문구 교체 + 블러 Toast 삭제. "준비되면 알림으로 알려드릴게요"류 새 문장은 넣지 않는다(티켓 미요구). 알림 권한 프롬프트는 맥락 문장 없이 같은 자리에서 뜬다(MSG-447 흐름 불변 지시 — 수용).
- **A2. `configureReadyRefresh(authStore)`를 `_layout.tsx` 부팅 시 1회 호출**하는 배선 — 웹은 `useAuthStore`를 직접 import하지만 모바일은 `auth-session`을 import한 모듈이 vitest에서 로드 불가하고(`settle-upload-success.test`가 `use-upload-mutations`를 로드) `delete-account-mutation`·`end-local-session`이 주입 관례를 세웠다. 대안(`use-upload-mutations`가 직접 import) 기각 — 기존 테스트 5건 사망. 미배선(테스트·스토리북) 상태에서는 시작 가드가 폴을 걸지 않는다.
- **A3. `start-ready-refresh`는 parity 앵커 없이 로컬 단위 테스트** — 웹 원본이 zustand `subscribe((state, prev))`·`@/features/auth/model/auth-store`에 묶여 있어 모바일 러너에서 동등 대조가 성립하지 않는다. 웹 5케이스를 그대로 이식해 동작 동등성을 고정한다. 티켓의 "parity 테스트" 요구는 `ready-poll`(순수)에 적용.
- **A4. `invalidate-upload-surfaces`도 로컬 `_id` 집합 단정** — 시그니처 편차(`gridId: string`, `event: EventConfirmTarget | null`, 행사는 `invalidateEventSurfaces` 재사용, 잔디 이력은 `invalidateGridQueries`에 이미 포함). 결과 집합은 웹 ①~⑤와 같다.
- **A5. auth 구독의 전이 판정은 직전 `isAuthenticated`를 클로저에 보관** — 모바일 `subscribe(listener)`가 이전 상태를 넘기지 않는다. `setTokens`(회전)는 `isAuthenticated` 불변이라 웹과 같은 판정.
- **A6. 포그라운드 복귀 즉시 조회(구 `AppState` 구독) 미이식** — 웹 구조에 없다. Android 백그라운드에서 JS 타이머가 미뤄지면 복귀 시 발화하고, 15분 만료는 `startedAtMs` 절대 시각 기준이라 어긋나지 않는다(R9).

## 리스크

1. **테스트 로드 제약이 배선 형태를 정한다**(A2): `use-upload-mutations.ts`에 `auth-session`을 한 줄이라도 import하면 `settle-upload-success.test` 5건이 파싱 단계에서 죽는다. 빌더가 웹을 그대로 옮기면 바로 걸린다 — 스펙이 `configureReadyRefresh` 주입을 지정한 이유.
2. **부수 책임 유실 재발 방지**: 워처가 겸하던 5책임의 대응표(위) — READY 무효화는 AC 10·11, 세션 경계는 AC 8로 고정. 사라지는 것(재시작 재개·포그라운드 즉시 조회·대기 목록 보존)은 전부 웹 수용 결정 미러이며 DECISIONS에 기록.
3. **행사 무효화 범위 변화**: 구 워처는 videoId만 알아 부분 키로 **전 위치**를 무효화했고, 새 구조는 확정 시점 `event`를 관통시켜 **해당 위치만** 정확 무효화한다(웹 MSG-521 AC 5 동일). 좁아지는 것이 맞다 — 다른 위치 목록은 이 업로드로 안 바뀐다.
4. **서버 즉시 READY면 지연 창 미관측**: BE 실측이 "인코딩 완료 → `markReady` 즉시"라 15초 11MB 파일의 창이 수 초일 수 있다. 미관측 시 "지연 창 미관측(서버 즉시 READY)"로 표기하고 AC 11 판정은 vitest(7·8·10) + 코드 감사로 대체 — 확인불가(환경)와 구분.
5. **푸시 실동작은 검증 대상 아님**: 배너 핸들러 등록만 남고 탭은 앱 열기로 끝 — 실기 단계 삭제.

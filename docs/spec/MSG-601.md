# MSG-601: [모바일] 로그인 화면을 "A-1 찍는 순간 점령" 시안으로 교체 + iOS 애플 로그인(카카오 병행, Android는 카카오만)

## 기획 요약
모바일 로그인 화면(`features/auth/ui/login-screen.tsx`, Figma 14799:26461 구성)을 새 시안 16026:466 — 로고 락업 → 파란 히어로 스테이지(격자·촬영 카드·셔터·"+1 격자" 배지) → 헤드라인/서브 → 소셜 버튼 → 약관 — 으로 교체한다. 동시에 앱스토어 심사 4.8 대응으로 **iOS 빌드에만** "Apple로 계속하기" 검정 pill을 카카오 아래에 추가하고, `expo-apple-authentication` → `POST /api/auth/oauth/apple`(BE MSG-594 머지 완료) 흐름을 카카오 3층 구조(adapter → mutation → hook)에 미러링한다. Android는 카카오만 보인다. 웹 로그인 모달·revoke·약관 링크는 제외 범위다.

## 코드베이스 현황 (STATUS.md + 소스 대조)

### 2. 로직 (test-first, 순수 함수 → 어댑터 주입)
**신규**
- `model/apple-full-name.ts` — `assembleFullName(name: { familyName?: string | null; givenName?: string | null } | null | undefined): string | undefined` (공백 trim 후 `familyName + givenName`, 빈 문자열은 없는 것으로) + `createFullNameRetainer()` → `{ remember(fresh: string | undefined): string | undefined }` (fresh가 있으면 저장 후 반환, 없으면 저장값 반환). 플랫폼 무의존.
- `model/apple-nonce.ts` — `createAppleNonce(deps: { randomBytes: (n: number) => Uint8Array; sha256: (text: string) => Promise<string> }): Promise<{ raw: string; hashed: string }>`. hex 변환은 직접 구현(`Array.from(bytes, b => b.toString(16).padStart(2, "0")).join("")` — Hermes 안전, `toSorted` 류 금지 목록 준수). `hashed`는 `sha256(raw)` 결과를 **소문자로 정규화**해 돌려준다.
- `api/apple-adapter.ts` — 네이티브 경계. **정적 import 금지**(kakao-adapter 주석 그대로 승계). `requestAppleCredential(): Promise<OidcCredential>`:
  1. `Platform.OS !== "ios"` → `codedError("AppleUnavailable", …)` (모듈 로드 전).
  2. `const [apple, crypto] = await Promise.all([import("expo-apple-authentication"), import("expo-crypto")])`.
  3. `createAppleNonce({ randomBytes: crypto.getRandomBytes, sha256: t => crypto.digestStringAsync(crypto.CryptoDigestAlgorithm.SHA256, t) })`.
  4. `apple.signInAsync({ requestedScopes: [FULL_NAME, EMAIL], nonce: hashed })` — 취소는 `e.code === "ERR_REQUEST_CANCELED"`로 그대로 전파(판정은 model).
  5. `return { idToken: credential.identityToken, nonce: raw, authorizationCode: credential.authorizationCode, fullName: retainer.remember(assembleFullName(credential.fullName)) }` — `retainer`는 모듈 레벨 1개(L8 "세션 동안" = 프로세스 생존 동안. 성공 후 남아 있어도 서버가 기존 계정의 fullName을 무시하므로 무해).
- `api/use-apple-login.ts` — `use-kakao-login.ts` 미러(provider `"apple"`, `requestCredential: requestAppleCredential`).

**변경 (일반화 — 카카오 파이프라인을 provider 매개화)**
- `api/kakao-login-mutation.ts` → **`api/oidc-login-mutation.ts`**(git mv). `KakaoLoginDeps` → `OidcLoginDeps { provider: "kakao" | "apple"; requestCredential: () => Promise<OidcCredential>; setTokens; setDeviceId; onLoggedIn; queryClient }`. `OidcCredential = { idToken: string | null | undefined; nonce?: string; authorizationCode?: string | null; fullName?: string }`. `mutationFn`: idToken 없으면 기존 `MissingIdToken` 에러(문구를 provider 중립으로 — "소셜 제공자에서 ID 토큰을 받지 못했습니다"), 있으면 `oauthLogin({ path: { provider }, body: { idToken, nonce, authorizationCode: authorizationCode ?? undefined, fullName }, headers, throwOnError: true })`. `undefined` 필드는 JSON에서 빠지므로 카카오 body는 기존 테스트 `{ idToken }` 단정 그대로 통과. `onSuccess` 불변.
- `api/use-kakao-login.ts` — `requestCredential: async () => ({ idToken: await requestKakaoIdToken() })`, `provider: "kakao"`. `kakao-adapter.ts` 무수정.
- `model/kakao-login-failure.ts` → **`model/social-login-failure.ts`**(git mv, 테스트·parity 테스트 동반 이동). 변경점: `CANCELLED_CODES`에 `"ERR_REQUEST_CANCELED"`, `MISCONFIGURED_CODES`에 `"AppleUnavailable"`(상수 `APPLE_UNAVAILABLE`) 추가; `KAKAO_MISSING_ID_TOKEN` → `MISSING_ID_TOKEN`(값 `"MissingIdToken"` 불변, 카카오 전용이 아니게 됨), `KAKAO_NOT_CONFIGURED`는 이름 유지(카카오 앱 키 전용). `resolveKakaoLoginReason` → `resolveSocialLoginReason`(본문 불변), `kakaoLoginNotice(reason)` → `socialLoginNotice(reason, provider: SocialProvider)` — `NOTICES`를 provider 라벨("카카오"/"Apple") 보간 함수로. `SocialProvider = "kakao" | "apple"` 타입을 이 파일이 소유(mutation이 import). 웹 복제 함수 2종(`developCodeOf`·`toKakaoLoginFailure`)은 이름·본문 불변(parity 앵커).
- `api/kakao-login-mutation.test.ts` → `oidc-login-mutation.test.ts`: 기존 5케이스 유지(import 경로·deps 형태만) + apple 3케이스(L3·L4·L5 apple 변형). `kakao-adapter.test.ts` 무수정.

## 추정 (사용자 부재 — 추정값으로 진행, 승인 시 확정)
- **A1 — 카카오 파이프라인을 provider 매개화(파일 rename 2건)로 애플을 얹는다.** 대안 "apple-* 3파일 복제"는 mutation·실패 판정이 거의 바이트 동일해 nose 중복 게이트에 걸리고, 3am에 두 사본이 갈라지는 전형이다. rename(`oidc-login-mutation`·`social-login-failure`)은 diff는 늘지만 "kakao"라는 이름의 파일에 애플 로직을 넣는 것보다 정직하다. 근거: BE도 같은 DTO·같은 서비스(`OidcLoginService`)로 두 provider를 처리한다.
- **A2 — 히어로 색은 스크린샷 톤(레이어 opacity 추정)을 primary 알파로 표현한다**: 스테이지 `bg-primary/10`, 채움 칸 `bg-primary/50`, 빈 칸 `bg-white/60`. Figma CSS는 세 요소가 모두 primary 100%/white 100%인데 렌더 이미지는 연파랑·중간 파랑·반투명 흰색이라 "레이어 opacity가 CSS 추출에 빠졌다"가 가장 그럴듯한 해석이고, 그 경우 알파는 근사가 아니라 정확한 표현이다(`theme-*`·`grass-*`·`event-tint`의 "근사 금지" 선례는 Figma가 **불투명 실측값**을 준 경우). 시안이 실제로 100% primary 스테이지(진파랑 위 흰 격자)라면 `bg-primary` + 채움 칸 `bg-white/30`으로 뒤집으면 된다 — 클래스 3개 교체.
- **A3 — 타이포 토큰 2종(`display-lg` 28·`title-lg` 18) 신설.** 대안은 MSG-590 Q5식 다운스케일(28→20)인데 Δ8은 헤드라인 인상을 바꾸고, 이번 시안은 Figma가 **이름 붙인 텍스트 스타일**(FeelMap/display-lg·title-lg)이라 토큰 파일의 "Figma Text Styles와 1:1" 계약상 추가가 맞다. 웹 부작용 0(소비처 없음).
- **A4 — `apple-black` 원시 토큰 신설**(`kakao-black`과 값 동일). `bg-kakao-black`을 애플 버튼에 쓰는 것은 이름이 거짓이고, `bg-foreground`(#1D1D1F)는 HIG 규정색이 아니다.
- **A5 — 버튼 간 간격 `gap-sm`(12px).** 시안 미명시. 카카오 버튼 62px pill 두 개를 8로 붙이면 한 덩어리로 읽혀 12를 택했다. 16015:540에서 실측 가능해지면 교체.
- **A6 — 두 버튼은 어느 한쪽 진행 중이면 둘 다 disabled**, 새 시도 직전에 다른 mutation을 `reset()`해 마지막 실패만 토스트. 티켓은 "중복 탭 방지"(MSG-444 기준 15)만 말하지만 카카오 진행 중 애플을 열 수 있게 두면 두 시트가 겹친다.
- **A7 — `fullName` 보관은 어댑터 모듈 레벨 클로저(프로세스 생존 동안).** "그 세션 동안"을 앱 프로세스로 해석. 성공 후 비우지 않는다 — 기존 계정에 온 `fullName`은 서버가 무시한다(BE AC-594-05).
- **A8 — Android `Platform.OS !== "ios"` 호출은 `AppleUnavailable`(설정 오류 부류)로 던진다.** 버튼이 렌더되지 않으므로 도달 불가 경로지만, 어댑터가 자기 전제를 스스로 지키게 둔다. `ERR_REQUEST_UNKNOWN`·`ERR_REQUEST_FAILED` 등 나머지 애플 코드는 `unknown`("로그인에 실패했어요. 다시 시도해 주세요") — 티켓이 취소·네트워크·서버만 명시했다.
- **A9 — 셔터는 SVG 원본(`SvgXml`)에서 filter만 제거하고 그림자는 래퍼 `shadow-fab`으로.** react-native-svg 15의 `<filter>` 지원이 부분적이라 남겨두면 렌더가 갈릴 수 있다. Android는 배경 없는 래퍼에 elevation 그림자가 그려지지 않을 수 있다 → Figma 오탐 방지 5.
- **A10 — 사진 자산은 `.jpg`로 개명 + 가로 480 축소.** 내려받은 `cell-photo.png`는 실제로 JPEG(137KB)다. 확장자를 포맷에 맞추고 3x 커버 기준으로 줄인다(MSG-588에서 4x 265KB→99KB 축소 선례).
- **A11 — 루트를 `ScrollView`로.** Figma 844 기준 레이아웃이 iOS 17 시리즈(852 − 인셋 93 = 759) + 애플 버튼(+74)에서는 안 들어간다. 시안 iOS 변형(16015:540)은 카카오를 위로 올려 여백을 줄였는데 그 값은 미조회 → 세로 여백을 `flex-1`로 흡수하고 그래도 모자라면 스크롤. 고정 배치보다 안전하다.

## 리스크
- **R1 — iOS 실기 확인불가 가능성(높음).** `ios/` 미생성이라 `npx expo prebuild -p ios` + `pod install` + `expo run:ios`가 필요하고, `usesAppleSignIn`이 넣는 엔타이틀먼트는 **유료 개발자 팀 서명**이 있어야 빌드된다(Personal Team은 Sign in with Apple capability 불가 → 서명 단계 실패). 이 Mac의 Xcode에 어느 팀이 로그인돼 있는지 불명. 게다가 시뮬레이터 시트는 설정에서 Apple ID 로그인이 돼 있어야 뜬다. → 검증자는 15분 상한으로 시도하고 실패 사유를 리포트에 적되, S6·S7·S8(애플)은 **확인불가**로 남길 수 있다. 그 경우 L3~L9(vitest)와 S1(Android 미노출)이 이번 티켓의 애플 관련 통과 증거다.
- **R2 — 새 네이티브 모듈 2종 → Android 재빌드 필수.** `expo-crypto`는 Android에도 들어가므로 기존 dev client APK로는 애플 코드가 아니어도 `prebuild -p android --clean` + `run:android` 없이는 실기가 무의미하다(런북 2-1, MSG-429 `expo-notifications` 사고 동형). JS만 바뀐 것으로 착각하지 말 것.
- **R3 — 서버 nonce 대조 실패(2421)가 앱 버그로 보일 수 있다.** 해시 대신 원문을 시트에 넘기거나, 해시가 대문자 hex이면 서버가 항상 2421을 낸다. L2가 정확히 이 지점을 고정하고, `digestStringAsync`는 소문자 hex를 돌려준다(추가 정규화도 함). 그래도 실기 2421이 나오면 첫 의심은 여기다.
- **R4 — `border-dashed`·`rotate-6` NativeWind 선례 없음.** RN `borderStyle: "dashed"`는 배경/테두리 조합에 따라 Android에서 점선이 안 그려지는 알려진 케이스(radius+dashed)가 있다. 실기에서 점선이 실선으로 보이면 `rounded-xs`를 뺀 흰 칸으로 후퇴하고 오탐 방지에 등재.
- **R5 — 문서 드리프트**: `docs/MOBILE_RUNBOOK.md` L7 "Xcode 커맨드라인 도구 없음"은 현재와 다르다(Xcode 26.6·시뮬레이터·CocoaPods 존재). 이번 티켓에서 문구만 정정, iOS 런북 본문은 R1 결과에 따라 후속.
- **R6 — 파일 rename이 nose 베이스라인·parity 테스트 경로를 건드린다.** `kakao-login-failure.parity.test.ts`는 웹 원본을 동적 import하므로 이동 후에도 앵커는 그대로다(L10). nose는 접촉 패밀리만 교체.
- **R7 — `fullName` 세션 보관은 권장(필수 아님).** 실패 시 닉네임이 `필맵러XXXX`가 되는 것뿐이고 사용자가 바꿀 수 있다. L8이 깨지더라도 출시 차단 사유는 아니다.

# Task Retro — 티켓 회고 HTML 생성

머지된 티켓 하나의 "무엇을 했고, 왜 그 선택이었나"를 결정 단위로 재구성해 `/Users/ho/fillmaphtml/MSG-{번호}.html`로 남긴다 (레포 밖 개인 학습 폴더 — 2026-08-13 사용자 지정, 레포에 커밋하지 않는다). 세션 기억이 아니라 **영속 소스만** 재료로 쓴다 — 회고는 보통 작업 세션이 사라진 뒤에 요청되기 때문이다.

## 절차

### 0. 머지 확인

`gh pr list --state merged --search "MSG-{번호}"` 또는 develop 로그로 머지 여부를 확인한다. **미머지면 생성하지 않고 사용자에게 알린다** — 리뷰 반영으로 내용이 계속 바뀌는 시점의 회고는 곧 무효가 된다. (사용자가 알고도 원하면 "미머지 시점" 표기를 달고 진행)

### 1. 소스 수집 (체크리스트 — 없는 소스는 리포트에 "없음" 표기)

| 소스 | 얻는 것 |
|------|--------|
| `_workspace/MSG-{번호}/00_ticket.md`·`01_spec.md` | 기획 원문, 수용 기준, 추정·리스크(결정의 씨앗) |
| `_workspace/MSG-{번호}/02_build_report.md` | 변경 파일, RED 매핑, 트레이드오프·**검토한 대안** |
| `_workspace/MSG-{번호}/03_verify_report.md` | 기준별 판정, WAIVED·확인불가, 감사 결과 |
| `_workspace/MSG-{번호}/screenshots/` | 대표 스크린샷 (임베드 후보) |
| `docs/spec/MSG-{번호}.md` | 승격 스펙 + 작업 로그 (있으면 _workspace보다 우선) |
| `docs/decisions/DECISIONS.md` | 해당 티켓 결정 항목 |
| `git log` (티켓 커밋들) | 리뷰 반영 커밋 등 문서 밖 흐름 |
| PR 본문 + **인라인 리뷰 코멘트** (`gh pr view --comments`, `gh api .../pulls/{n}/comments`) | 리뷰 지적·반영 — 트레이드오프의 실전 기록 |

### 2. 합성 — 결정 단위 재구성

- 구성: 배경(왜 이 작업이 생겼나) → 진행한 것(변경 요약·검증 결과) → **결정 카드들** → 잔여 항목(WAIVED·후속 티켓·환류)
- 결정 카드 형식: 선택지 나열 → 선택 → 이유 → trade-off(**얻음 / 치름**) → 근거 출처(파일·PR 코멘트)
- **근거 규율**: 모든 서술은 1차 소스로 소급 가능해야 한다. 소스에 없는 재구성은 "추론"으로 명시 표기 — 회고가 기억을 발명하기 시작하면 면접 재료·팀 공유 자료로서의 신뢰가 무너진다

### 3. 출력

- 경로: `/Users/ho/fillmaphtml/MSG-{번호}.html` (폴더 없으면 생성) — 이미 있으면 덮어쓰기 전에 사용자에게 확인. **레포 안(docs/ 등)에 만들지 않는다** — 회고는 개인 학습 자산이라는 사용자 결정(2026-08-13, 초판을 docs/retro로 만들었다가 되돌린 이력)
- **자체 완결**: 스크린샷은 base64 임베드(대표 1~3장만 — 전부 넣으면 수 MB), CDN·외부 스타일시트·폰트 로드 금지. 순수 하이퍼링크(PR·지라)는 허용
- 언어는 한국어, 다크·라이트 양쪽에서 읽히는 색으로
- 레포 밖 산출물이므로 git 스테이징·커밋 없음 — 생성 경로만 보고한다

## 하지 않는 것

- 프로덕션 코드·테스트 수정, git 이력 조작, 지라 티켓 수정 (읽기만)
- 여러 티켓 묶음 회고 — 티켓 1개 = 회고 1개 (묶음이 필요하면 사용자와 범위 합의 먼저)
